  1. Nov 22, 2026
    Donefeature/aiv20261122_packages · a304cd753

    Package catalog: content is downloaded separately from the engine

    The terrain and vegetation PBR material libraries and their sources moved out of the engine into a package catalog. A project installs only what it needs with one command; the website has a new Catalog page.

    The catalog is a separate repository, AIVERSE-PACKAGES, with sections: templates, materials, textures, models, audio, effects, UI, scripts, plugins, tools. Every package has a description, previews, a licence and the minimum engine version.

    `aiverse_pkg.py add terrain-pbr --project <project>` downloads the package, checks its hash, puts the files into the project and adds the materials to its library. The version and file hashes go to `aiverse.lock`, so a cloned project is restored with `install`. A downloaded package is kept once per computer for all projects.

    Engine skills name the packages they need, and an agent installs them by itself.

    New packages are added by pull request to the catalog. Once merged, a package appears in the engine and on the Catalog page by itself: previews, description, engine version, a download button and the install command.

    Verified
    Four packages are published in the catalog and downloaded over the network on Linux; their textures are byte-identical to the former engine files, and the material map checks pass. The Catalog page was opened in Chrome at desktop and phone width and shows the packages from the catalog.
    Limitations
    There is no catalog window in Studio and no MCP commands yet: search and install run from the command line. The editor build with the changed empty project was not checked on macOS.

  2. Nov 22, 2026
    Donefeature/aiv20261122_packages · a304cd753

    Catalog viewer: shapes, LOD and STRATA, animated loading mark

    The 3D preview of catalog packages shows materials on a sphere, cube, cylinder or plane with textures at their own size, and models by LOD level or through STRATA. Every loading state on the site, in Studio and in web builds now shows the animated AIVERSE mark.

    Materials get a shape switch above the view. Texel density is the same on every shape, and spheres and cylinders get a whole number of repeats around, so the seam is gone. Textures arrive exactly as the package author published them: thin alpha-cut leaf edges no longer turn into blobs. The panel on the left lists every map — colour, normal, ORM, AO — with its size in pixels and its file size.

    Models: Auto LOD (the level the renderer picked at this distance is highlighted), any level by hand, or STRATA — clusters are built from the model on first request and the Clusters button colours them. Wireframe shows the edges of the shown level. The panel lists triangles per level, whether the engine generated the LODs, and STRATA's cluster count and build time.

    The loading mark is the same assembly of blades and diamond as the engine's splash: on the site (catalog, builds on the releases page), in the viewer, in Studio instead of spinners, and in web builds of games without their own splash.

    Verified
    Frames come from the desktop build of the viewer (Linux, OpenGL) on the terrain-pbr and vegetation-pbr packages and a 20k-triangle test rock; the loading mark was captured on the built site in Chrome.
    Limitations
    The web viewer is built in the catalog and checked after it is deployed. The catalog has no model packages yet, so LOD and STRATA appear on the site with the first one. STRATA is built on first request, which is a noticeable pause on a large model.
  3. Nov 22, 2026
    In progressfeature/aiv20261122_template_packages

    Project templates from the package catalog

    All 36 sample games of the engine are now official template packages in the AIVERSE-PACKAGES catalog. The Studio start screen lists them first, and More templates searches every template in the catalog, other authors' included.

    A template can now grow: its own textures, models and code live in its package, not in the engine repository. The catalog marks official packages with the official flag, which only the AIVERSE authors set.

    A project made from a template package is downloaded, checked against its hash and unpacked into the folder you pick; then the packages its game.json lists are installed. The start screen opens at once from the cache and refreshes the list in the background. Agents do the same through MCP: create_project with the template pkg:<package>.

    Every template in the catalog has a preview: a real engine frame of that template.

    Verified
    A Mushroom Clash project was created from the mushrooms package through MCP create_project and run in the client (Linux, OpenGL): first frame. The other frames are template previews taken by the engine client for the catalog.
    Limitations
    The new Studio start screen builds and passes type checks but has not been run in the native Studio on macOS. The templates/ folder stays in the engine for offline use and tests for now.

  4. Nov 22, 2026
    Donefeature/aiv20261122_model_packages · 6bc2fd9ed

    Catalog: TerraWeave rocks and trees, packages with dependencies, translations

    The catalog has its first model packs — 12 TerraWeave rocks and 10 tree species, three LODs each. A package can depend on another and use its textures instead of copies. Catalog texts are English with translations such as title-ru, and the catalog page explains how to add your own package.

    `terraweave-rocks` and `terraweave-trees` come from the engine tools aiverse_terraweave_rocks and aiverse_terraweave_vegetation. The models refer to the textures of terrain-pbr and vegetation-pbr, so the tree pack is 17 MB instead of 52. `aiverse_pkg.py add` installs the dependencies first, and the site's 3D preview takes the textures from them too.

    The catalog index is short now: the root lists only the sections and the folder of each package; the description is its aiverse.package.json and the published versions and hashes are in versions.json next to it. Plain keys are English, translations are title-ru, summary-zh-CN and so on; the catalog README exists in nine languages.

    The Catalog page has five steps for offering a package and a link to the full instructions in the docs.

    Verified
    Models with textures from their dependency packages were captured in the desktop viewer (Linux, OpenGL), including STRATA on the oak; installing with dependencies is covered by the aiverse_pkg test; the catalog page with the new index was checked in Chrome against a local copy of the catalog.
    Limitations
    The trees are for hand placement; the forest the engine grows and places itself is still built by TerraWeave. Package descriptions are translated into Russian only so far.
  5. Nov 21, 2026
    Donemain

    Client builds take only the engine modules they need

    game.json can choose which optional engine parts go into the packaged game, or leave it to detection: "engineModules": ["auto"].

    Every packaged game used to carry the whole engine: particles, Spine, gamepads, FBX and legacy model loaders, the city server client, traffic and map generation. Now a packaging.engineModules list, shared or per platform, can leave them out.

    "auto" looks into the project: Spine and gamepad from game.json, particles from effect files, loaders from source models, simulations from rules and maps. If the game uses something excluded, the packager refuses with a clear error; without the field everything builds as before.

    On a test macOS client build the executable shrank by about 7% just from linking only the code in use. Each disabled module removes from about a hundred kilobytes (gamepad) to a couple of megabytes (particles, legacy model loaders).

    Verified
    The packager checks the module choice for Web, Windows and macOS; sizes were measured on the macOS client.
    Limitations
    HTML5 build size and startup are not measured yet: Emscripten was missing on the build machine. Android, iOS, Windows and Linux have not been built with modules off either.
