# World Processes: plane, planet, moon and PHYSIS gravity contract

User requirement, 2026-11-24: all World Processes capabilities must support flat worlds and planetary surfaces, and consume PHYSIS gravity where physically applicable. This is a delivery requirement, not a claim that all adapters already work. Preserve existing plane checksums and legacy opt-in behavior.

## Shared coordinates and authority

- Use canonical GameCore Surface/CubeSphere (engine/game/Surface.h, Sphere.h, docs/planets.md), including body IDs, seam-aware neighbors, tangent frames, radial up, projection and ground distance. Never infer a planetary ground location by dropping Y or flattening six faces into one XZ rectangle.
- A body-local simulation position includes Surface::anchor(body). Render/orbit world position is not a substitute. Authored map placement uses at {body,face,x,y}; explicit links remain generation-safe Entity references. Separate bodies never interact through spatial proximity or coincident face coordinates; intentional graph links/transit are explicit owner policy.
- New shared WorldProcessSurfaceFrame.h adapts the existing surface and planar frame. Body-aware distance is a chord, not a geodesic or nav route length. Surface::offset/neighbor owns face seam steps; use the existing topology, not a second cube-sphere.
- PHYSIS owns gravityAt, GravitySettings and GravityField; PHYSIS fields are expressed in metres, acceleration m/s^2. Host resolves unit conversion and reference frame, not the render camera. Surface radial up is a geometric direction, not automatically the actual gravity vector. Default PHYSIS is uniform -Y; planetary radial fields must be explicitly authored/configured by the PHYSIS/game owner. Attract/Repel field weight fades with distance and overrideBaseline blends rather than replacing baseline at every point. Configure/calibrate zero baseline or body-specific fields as appropriate; do not synthesize another gravity solver here.
- WorldProcessGravity.h projects the sampled vector into a local frame. GRANULAR optional gravity-aware step reuses canonical settlement and quantizes the in-plane vector to a cardinal direction; zero/dead-zone holds mass. MORPH exposes local Force conversion with explicit impulse scale. These opt-in APIs are not automatically installed in the suite; native host must choose the gravity-aware path instead of legacy step, configure frames/units/fields, and retain save/rollback semantics.
- Box3D uses existing engine/physics/PhysisBox3D.h applyPhysisToBody before Scene::step; it subtracts built-in world gravity from PHYSIS acceleration. Do not apply both full gravity force and adapter, do not feed float physics into Fixed authority implicitly. FRACTURE support is a graph; PHYSIS NatureStress intentionally excludes gravity loading to avoid double load, actual weight/stress modeling is a separate owner contract. NEREID/TerraWeave remain canonical for water/soil.

## Acceptance / sequence

1. Finish shared surface locator and body-aware diagnostics/authoring. Verify planes, all six cube faces, face seams/corners, multiple bodies with identical face coordinates and transit; unknown/star/no-surface inputs fail safely.
2. Implement IMPRINT/CROWD/EVOLVE spatial adapters through existing Surface/MapGrid/NavMesh and TerraWeave, then granular patch/terrain/render/physics integration and gravity-aware native setup. Do not silently treat a planetary map as flat. Existing authored EVOLVE area hydration currently requires pos array and is not planet-ready.
3. Validate PHYSIS radial attraction, repulsion, zero gravity, tilted/uniform field, multiple body centers, changes between ticks, fixed-point units, source budgets and rollback. Verify actual Box3D integration without duplicate gravity; include real planet project/Studio scenes. Add skill and applicable native API/MCP/Studio integration per owner; do not claim standalone adapter proves end-to-end support.
4. Run focused tests, existing plane checksums, actual planet save/load/rollback and merged-tree native Mac gate. All tests presently NOT RUN; do not merge based on code inspection.

## Stage 90: planetary CROWD through existing movement owner
`CrowdSurfaceSlots.h` plans stable exclusive slot reservations using canonical Transform/Surface and same-body filtering, owner eligibility/passability callbacks and existing assignSlots. `CrowdGameCoreSurface.h` selects mobile grounded/non-air GameCore agents, sends normal Move orders only to idle non-combat actors with empty queues, and staggers retries for unchanged allocation at 16 ticks. Existing GameCore owns routes, speed, radius, obstacle checks, seam traversal, slope, tangent separation and position. Planet maps select this installer instead of legacy XZ CROWD/Route; flat host behavior unchanged. On planets author actual at/body/face placements and CrowdPreference references; legacy Agent/Slot x/z/goal/speed/radius and CrowdRoutes waypoint APIs are not planetary movement inputs. Never treat their x/z as live coordinates on planets. Use actual Transform and native Move command/route owner. PHYSIS gravity-aware dynamic locomotion is not yet wired; radial geometric projection does not imply actual gravity. Do not duplicate integration. See Stage90 handoff; test source added, not run.

## Stage 92: planetary GRANULAR section and native gravity
`GranularSurfaceField.h` maps the existing vertical-section Field onto canonical Surface: columns along the origin east great circle, rows from high to low radial altitude, ground sampled from Surface::project (the actual planet height source). Bounded patch query returns common Fixed positions, radial basis, canonical body/cell and mass/solid for future view and physics consumers, not a mesh or collider. Native GameCore planet maps select advanceSurfaceFields instead of legacy settlement, sampling actual PHYSIS gravity at each field Transform and projecting into local frame. Host must configure PHYSIS fields and metre scale; no automatic radial field synthesis, no magnitude-dependent or per-cell gravity, no cross-field transfers. Zero/reverse/lateral gravity follows the existing cardinal 2D policy. Flat path and Field schema unchanged. Current TerraWeave Earthworks runtime mass transfer is XZ only; planetary conservative soil mutation requires a canonical terrain owner API, not editor sculpt or a second soil map. Planet mesh/collider publication and transfer remain open. Regression source added, not run. See Stage92 handoff.

## Stage 93: MORPH gravity integration
`MorphGravityBinding.h` persists opt-in frame owner, unitsPerMetre, impulseMilli (1000 = one solver impulse unit per m/s^2), relative mode and enable flag. `MorphPhysisGravity.h` samples canonical PHYSIS at node position, using actual WorldTransform rotation or Transform yaw in the canonical surface frame. Relative mode subtracts owner acceleration (free-fall approximation); absolute mode for supported local structures. No duplicate rigid-body gravity, no mass/velocity physics solver, no automatic time-step calibration. `advanceWithLoad` adds load after continuous authored forces and before one-shot impacts inside original staged solver. Missing/stale owner rejects update before writes. Map MorphNode accepts optional gravityImpulseMilli and gravityRelative (default true), self frame owner, 100 node units/metre; native `morphGravity:true` reserves schema for dynamic bindings. Native setup installs one solver for both plane/planet only when requested; unbound nodes and legacy maps retain old behavior and schema. PHYSIS fields must be authored/persisted by their owner; no implicit radial gravity. Render/physics actual-frame and Studio UI acceptance remain pending. Tests authored, not run.

## Stage 94: optional AETHER PHYSIS stratification
`AetherPhysisStratification.h` provides `advanceWithStratification(world,surface,tick,settings)`. Native GameCore enables the alternative transport with `world_processes` config `{"aetherStratification":true}`; the legacy transport is not installed simultaneously. The existing ECS GasCell/GasDuct/GasFlux schemas stay unchanged. Each active duct endpoint needs canonical Transform, and PHYSIS gravity is sampled in simulation-space metres. Planets use existing Surface body identity; cross-body active ducts reject the staged tick. Zero-cap and disabled links remain inert. Effective buoyancy coefficients in permille default smoke +350, toxin -350, oxygen 0; they are gameplay coefficients, not molecular densities. Optional co-located PHYSIS Atmosphere temperature at both endpoints contributes mean-temperature buoyancy relative to 20 C, default 5 permille/degree. Missing temperature disables only the thermal correction. Gravity projection uses mean endpoint acceleration along the duct, bounded to +/-1 with 10 m/s² reference; zero gravity preserves concentration diffusion. Signed bias changes the single shared diffusion head, not a second transfer pass; reversed endpoints use exact opposite bias. Per-species duct cap, start-of-tick donor budget, stable order, mass conservation, atomic failure and flux-after-transport remain. Custom host calls the explicit API with deterministic settings, owns persistence/config identity and PHYSIS fields. This is a graph-based gameplay approximation, not pressure CFD, thermal energy transport or a full planetary atmosphere solver. Tests authored, not run. See Stage94 handoff.

## Stage 98: planetary GRANULAR soil-owner boundary

`GranularPlanetTerrainTransfer.h` exposes `planPlanetSoilTransfer` and `transferPlanetSoil` for native hosts. Explicit opt-in volume calibration: 1 mass unit = 1 cm³. A request supplies live Field entity, expected body ID, bottom-row column, cell size, direction, volume limit and expected terrain revision. Resolve actual Transform and existing Surface projection, reject airborne/underground base, stale sampled tick, disabled/solid cells, wrong body and zero budget. A bounded owner callback receives body/face/cell, ground, up and budget; the actual terrain owner computes conservative volume, including quantization and seam aliasing. Apply the owner's receipt and matching mass change to a staged World, publish by move only if valid, discard failures/no-op writes. The callback must not mutate external/shared mutable state, and may not alter the field or its position. Call only at a serialized fixed-tick barrier; no outstanding references survive publication. Host records requests for replay. Whole-World staging is not a per-grain hot path; profile before enabling frequent transfers.

**Integration blocked:** canonical Surface is immutable and existing TerraWeave Earthworks is planar. No planetary terrain owner adapter, terrain height edits, persistent soil volume, mesh, navigation or collider invalidation is supplied by this boundary. TerraWeave must provide a canonical atomic mutation path that updates the same ECS/persistence/geometry authority. Native fixture uses an explicitly test-only volume owner, not a real terrain simulation. Build/tests NOT RUN. See Stage98 handoff.

## Stage 99: body-aware planetary ecology sampling

`EvolvePlanetEcologySampling.h::samplePlanetEcology` takes up to 4096 owner-provided ground sites per synchronous batch, with stable body ID and existing TerraWeave ForestEcologyClimate baseline. It validates Surface contact and body, builds one existing SurfaceRegionIndex, and projects canonical Region fertility/pollution/succession into the existing climate type. Returns body/face/cell, contributing region count and optional PHYSIS observations (temperature, humidity, rain, wetness, snowpack, ice). Explicit host-mapped weather source must be on the same body and within the configured chord-distance limit; no implicit mapping from planar PHYSIS grid. Optional surface-wetness cap is an explicit gameplay approximation, not soil-water physics. Invalid inputs fail the entire read-only batch. No cache survives rollback, no new plant state or persistent schema. Inputs must remain stable for the synchronous owner barrier.

PlanetFlora is still cosmetic; authoritative TerraWeave ForestEcologyEcs currently uses planar roots, canopy and seed offsets. Real planetary growth, reproduction, mortality, persistent plant positions and render publication require the TerraWeave owner to generalize that lifecycle. Do not run planar ecology on cube-face coordinates or duplicate the plant registry. Native tests and authored demo sample assertions added; NOT RUN. See Stage99 handoff.

## Stage 100: PHYSIS-aware CROWD support eligibility

`SurfaceGravitySupport.h` exposes a shared Fixed-point, read-only classifier: actual PHYSIS acceleration, terrain normal, signed radial ground clearance, inward and tangential acceleration, and supported/airborne/weak/outward/steep status. Planetary sampling uses the existing Surface face normal and coordinates. The native World Processes option `"crowdGravitySupport": true` enables CROWD and requires a planetary Surface installer. It re-evaluates actor and destination support on each reservation tick, in addition to existing body isolation and grid passability, and withholds new CROWD Move orders or releases unsupported reservations. Defaults: 0.125 m ground tolerance, 0.05 m/s² minimum gravity and 0.5 minimum inward cosine. Existing maps remain unchanged by default. The authored planet demo enables the option.

No Transform, velocity, movement layer, existing route or player/AI order is changed by this classifier. Existing GameCore motion still projects actors onto the surface; falling, free flight, adhesion, slope slip, along-path support checks and dynamic collision integration are not implemented. The pure classifier accepts a host-provided normal for planar consumers, but the new GameCore native flag is planetary-only; planar native behavior is unchanged. Tests authored for all six faces, zero/reverse gravity, inclined acceleration, ground clearance, rollback and live reservation release/reacquisition in the demo; build/tests NOT RUN.
