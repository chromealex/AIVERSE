# Опциональная физика Box3D

Обычные RTS-проекты не требуют физического мира. Их Fixed-симуляция, навигация,
ORCA и сохранения остаются прежними. По умолчанию Box3D **выключен** и не линкуется
с игровым клиентом. Включение сборки библиотеки само по себе не меняет механику RTS
или FPS: C++ модуль игры явно создаёт и обновляет физический мир.

## Сборка и отдельный пример

```sh
cmake -S . -B build/.temp/physics -DCMAKE_BUILD_TYPE=Release \
  -DAIVERSE_ENABLE_PHYSICS=ON -DAIVERSE_BUILD_PHYSICS_DEMO=ON
cmake --build build/.temp/physics --target aiverse_physics_demo aiverse_physics_tests -j8
ctest --test-dir build/.temp/physics -R '^physics_runtime$' --output-on-failure
build/.temp/physics/aiverse_physics_demo
```

На macOS для нативной Apple Silicon сборки добавьте
`-DCMAKE_OSX_ARCHITECTURES=arm64`; для Xcode используйте `--config Release`.
Пример рассчитан на запуск из исходного дерева, использует обычный RHI AIVERSE
и читает `examples/physics/scene.json`. В нём есть стопка ящиков, наклонная
платформа, шар, капсула и маятник на distance joint. Кнопки позволяют поставить
симуляцию на паузу, подбросить шар, сбросить сцену, сохранить/восстановить состояние;
ползунки меняют камеру. Для русского интерфейса запустите с `--lang ru`. Это отдельная песочница, не RTS-шаблон и не редактор физики.

## Подключение к C++ модулю игры

```cmake
target_link_libraries(my_game_module PRIVATE AIVERSE::physics)
```

```cpp
#include "engine/physics/World.h"
// JSON загружает приложение через platform::readContentFile.
aiverse::physics::World physics(sceneJson, 1);
physics.step();                         // ровно один физический такт
physics.impulse("ball", {0, 3000, 0});  // импульс, Н·с
const auto* ball = physics.find("ball");
auto position = b3Body_GetPosition(ball->body);
```

У каждого мира один управляющий поток. `workers` (1..8) включает его самого;
на web допускается только 1. Частота такта задаётся сценой, по умолчанию 60 Гц
и 4 подшага. Единицы: метры, секунды, килограммы, радианы; вертикаль +Y.
Пример использует локальный аккумулятор времени. Авторитетный сервер должен
вызывать `step()` по своему расписанию тиков и передавать клиентам результаты.

Для RTS физику можно использовать отдельно для визуальных обломков. Если она
влияет на исход игры, требуется отдельная интеграция с командами, сохранениями
и сетевой моделью игры. Float-состояние Box3D нельзя просто включить в существующий
Fixed lockstep. Автоматической синхронизации с RTS ECS, FPS-мотором или Lua здесь нет.

## Формат сцены

Верхний уровень: `gravity` (по умолчанию `[0,-9.81,0]`), целые `tickRate` (10..240),
`substeps` (1..16), массив `bodies`, необязательный массив `joints`.
Максимум 4096 тел и 4096 ограничений.

| Ключ тела | Значение |
|---|---|
| `id` | Уникальная непустая строка |
| `motion` | `static`, `dynamic` (по умолчанию), `kinematic` |
| `shape` | `box` (по умолчанию), `sphere`, `capsule` |
| `position`, `velocity`, `angularVelocity` | Векторы из трёх чисел |
| `axis`, `angle` | Ось вращения (нормализуется) и угол в радианах |
| `size` | Полные размеры ящика; по умолчанию `[1,1,1]` |
| `radius`, `halfHeight` | Радиус сферы/капсулы, половина расстояния между центрами полусфер капсулы |
| `density`, `friction`, `restitution` | Плотность (1000), трение (0.5), упругость (0) |
| `linearDamping`, `angularDamping` | Затухание (0.05) |
| `sleep`, `bullet`, `sensor` | Сон (true), CCD bullet (false), датчик (false) |
| `color` | RGB 0..1, только отображение примера |

Ограничения: `kind: "distance"` или `"hinge"`, ссылки `a`/`b` на тела,
`anchorA`/`anchorB` в локальных координатах. Для distance задаётся `length`.
Hinge использует стандартную ось локальных кадров Box3D (Z).
Все остальные возможности Box3D доступны через его публичный C API и `nativeId()`:
raycast, overlap, события контактов/датчиков, дополнительные формы и joint API.
При использовании обёртки не удаляйте её тела и не меняйте состав мира напрямую:
манифест `objects()` и сопоставление тел при восстановлении должны оставаться неизменными.
Для полностью динамического состава мира используйте C API с собственным владением
и манифестом вместо `World`.

## Сохранения и проверка

`World::save/restore` использует полный seed snapshot публичного recording API
Box3D: внутреннее состояние решателя, контакты, ограничения, сон. Оболочка проверяет
ревизию, конфигурацию ABI, описание сцены и контрольную сумму. Использовать только
для доверенных локальных состояний **той же сборки**: внутренний формат содержит
сырые структуры и не является переносимым форматом игры или безопасным сетевым
протоколом. Контрольная сумма защищает от случайного повреждения, не от подделки.
После восстановления старые `b3BodyId` недействительны — получите новые через `find()`.
Не запускайте внешнюю запись Box3D одновременно с `save()`.

`trajectoryHash()` — диагностический хеш поз, скоростей и сна, не полный хеш симуляции.
Тесты проверяют совпадение траекторий при 1/4 рабочих потоках, продолжение после
snapshot, столкновения с землёй, импульс, удержание маятника, raycast, отбраковку
ошибочных сцен и повреждённых состояний. Эти тесты не доказывают lockstep между
разными процессорами и компиляторами.

Проверено: macOS arm64, AppleClang, Release; графический пример через Metal.
Windows, Linux, Android, iOS и web для этой интеграции пока не проверены.
