# S6g.6.3 — binary GLB resource repair (2026-11-24)

Owner Studio; branch feature/studio-html5. Base 11905d133b6c95663d1125a8a26301f3016c00cf; roadmap 2b7a8529b3edcbf97f453062b078d756e4862d65; implementation 8e2c0023df5eff4277d1c4202c9ee5668e2edfaf; replay budget and snapshot validation 6a0a22a37f58619b6b821e997cf5c251703b30ee.

## Implementation
- StudioModelRepairBytes.h: validates GLB v2 total length, aligned JSON and subsequent chunks; rejects duplicate JSON/truncated tables; typed JSON repair regenerates header and JSON padding while retaining following chunk headers, data and padding byte-for-byte. Text JSON .glb remains supported. Binary semantic comparison includes exact chunk tail.
- Existing repair planner handles stationary or moved GLB owners and nested moved folders via projected paths and directional file/tree digests. Original complete bytes retained; both input/output sides independently bounded at 4 MiB aggregate (8 MiB paired), max 32 documents. Refusal precedes publication if plan exceeds budget.
- Binary snapshot rows use bounded hex encoding in the asset history checkpoint and move journal v6. Existing textual rows and v1–v5 journal reader retained. Shared validation refuses any change to non-JSON chunks. Undo/Redo validates current bytes and regenerates typed expected repair, compares normalized JSON plus exact tail, then writes original/recorded bytes. Existing native transfer and MCP adapters reused.
- Regression scenarios: arbitrary NUL/non-UTF8 BIN and unknown chunk, exact hex roundtrip, corrupt binary rejection, stationary and moved GLB, reopened history, and pending v6 recovery at relocated owner. Existing CTest targets reused. Skill and MCP docs updated.

## Evidence / limits
GitHub source committed and read back; tests added but NOT RUN. No C++ compile, CTest, frontend, native MCP transport, UI or performance validation. No main merge. Full GLB bytes are retained in memory within the small repair budget, NOT a streaming rewrite of large models; discovery still streams JSON only. Large GLB requiring repair is explicitly refused. Production-size GLB streaming/chunk-only backup support remains an open functional item; do not report this stage as unrestricted format support. Lowercase .gltf/.glb only; unsupported/opaque formats, OBJ/MTL/DAE authoring, dynamic references, coordinated repaired history and global saved map atomicity remain open. Next S6g.6.4: supported OBJ/MTL and DAE path repair, preserving loader-specific semantics; follow with scalable binary repair storage, dependent transactions, durable cross-owner save, recovery/MCP extensions and final QA.
