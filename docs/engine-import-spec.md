# ТЗ: импорт проекта из другого движка (Unity → Godot → Unreal)

Дата: 2026-11-03. Ветка: `agent-engine-import` (подливать `master` перед каждым этапом, коммиты — в свою ветку, MAIN мержит).

## Цель

Пользователь указывает папку проекта Unity / Godot / Unreal и получает `.aiverse` нашего движка:
ассеты, карты и все распознанные данные переносятся **автоматически**, остальное описано в отчёте,
по которому ИИ-агент через MCP доделывает перенос. Это третий источник в кнопке «Сделать игру»
(рядом со «ссылкой на арт» и «папкой с контентом»).

Честная граница: логику на C# / GDScript / Blueprints механически не переводим. Автоматика переносит
**ассеты, сцены, параметры**; логику переносит ИИ-проход (блоки `rules.json` → Lua → C++-модуль).

## Что уже есть и на что опираться

- `tools/importers/unity_vfx`: парсер сериализованного YAML Unity без PyYAML (`unity_yaml.py`),
  GUID-индекс дерева ассетов, распаковка `.unitypackage`, иерархия префабов, вложенные префабы и
  варианты, формат отчёта «точно / приближённо / не перенесено» (`unity_scene.py`). **Переиспользовать,
  не копировать**: вынести общее в `tools/importers/lib/unity/`, импорт эффектов перевести на него.
- Модели: FBX (ufbx), glTF, OBJ, 3DS и др. грузятся движком напрямую, остальное — `modelconv`
  (`docs/models.md`). Свой конвертер моделей не писать.
- Ландшафт `heightfield` + `cornersFile` / детализация + сплат (`docs/terrain.md`), 2D-тайлы
  (`RtsTiles`, `templates/tiles2d`), Lua (`docs/scripting.md`), C++-модули (`docs/native-modules.md`),
  `.aiverse` (`apps/editor/core/ProjectFile.*`), звук `audio.json`, частицы `fx/`.
- Правило лицензий (AGENTS.md §3): ассеты чужих коммерческих игр не коммитить. Импорт работает с
  копией пользователя; в тесты — только синтетические проекты.

## Архитектура

```
tools/importers/
  lib/unity/          общий код Unity (из unity_vfx): yaml, guid-индекс, префабы, сцены
  lib/port/           общее для всех движков: модель «найденного» проекта, отчёт, запись .aiverse
  port/               CLI aiverse_port: определение движка, запуск нужного импортёра
  unity_project/      Unity
  godot_project/      Godot 3 / 4
  unreal_export/      плагин-экспортёр, запускается внутри Unreal (Python), + приёмник JSON
```

Python, только stdlib (как `unity_vfx`), чтобы работало из редактора на всех ОС без зависимостей.

Пайплайн для любого движка — три шага, у каждого JSON на выходе (чтобы MCP и тесты читали
промежуточные результаты):

1. **scan**: движок и версия, режим сериализации, список сцен / префабов / ассетов / скриптов,
   оценка объёма. Ничего не пишет.
2. **extract**: нейтральная модель `port.json`: ассеты (путь → тип), сущности-кандидаты (префаб → поля,
   компоненты, ссылки на модели / звук / эффекты), сцены (террейн, расстановка, точки старта),
   скрипты (путь, классы, поля, где используются).
3. **emit**: `port.json` → проект движка (`game.json`, `rules.json`, `maps/`, `models/`, `audio.json`,
   `fx/`, `scripts/`, `.aiverse`) + `port-report.json` / `port-report.md`.

Повторный запуск идемпотентен: перегенерирует только то, что не правил человек или ИИ (маркер
`"ported": true` у сгенерированных типов и карт; правка снимает маркер).

## Этап 1. Unity: ассеты и сцены

- Режим сериализации: Force Text поддерживается полностью. Binary / Mixed → понятная ошибка в scan
  с инструкцией (Edit → Project Settings → Editor → Asset Serialization → Force Text).
- Ассеты: текстуры (PNG / TGA / JPG как есть, PSD / TIF → PNG, иначе в отчёт), модели (FBX / OBJ / glTF
  как есть, импорт-настройки `.meta`: scale factor, оси, клипы анимаций по диапазонам кадров →
  `view.animations`), звук (WAV / OGG / MP3 как есть), материалы Standard / URP Lit / HDRP Lit → PBR
  (основной цвет, metallic / smoothness → roughness, normal, emission), шейдеры другие → приближённо.
- Эффекты частиц: вызывать существующий импорт `unity_vfx` и привязывать эффекты к сущностям.
- Террейн: `TerrainData` (высоты, разрешение, размер) → `heightfield` / `cornersFile` + детализация;
  слои террейна → материалы `terrain` (до 4, остальное — в отчёт); деревья / детали террейна →
  объекты карты или декор.
- Сцена: объекты с префабами → объекты карты (позиция → клетка, поворот), масштаб мира по размеру
  террейна (настройка в окне импорта).
- 2D: `Tilemap` → тайлы движка, `SpriteRenderer` / атласы спрайтов → спрайты.
- Аудио-микшер и музыка: AudioSource на камере / менеджере с loop → плейлист `match`.

## Этап 2. Unity: данные игры

- Кандидаты в типы: префабы с NavMeshAgent / Rigidbody / Collider / Animator / MonoBehaviour с
  «игровыми» полями.
- Поля MonoBehaviour (значения из префабов и вариантов) сопоставляются с блоками `rules.json` по
  таблице синонимов (`mapping.json`, расширяемая): `hp/health/maxHealth → health.max`,
  `speed/moveSpeed/NavMeshAgent.speed → move.speed`, `damage/attackDamage → weapons[0].damage`,
  `range/attackRange → weapons[0].range`, `cooldown/fireRate → reload`, `cost/price/gold → cost`,
  `buildTime/trainTime → cost.time` и т. д. Единицы пересчитываются (секунды → тики, метры → клетки).
- ScriptableObject-конфиги (базы юнитов / волн / уровней) → те же блоки.
- Каждое сопоставление попадает в отчёт со своей уверенностью; при низкой — в «приближённо».
- Скрипты C# не переводятся, но индексируются: класс → файл → какие префабы его используют → какие
  поля. Это главный вход для ИИ-прохода.

## Этап 3. ИИ-проход через MCP

MCP-операции (область редактора / MCP, согласовать с MAIN):

- `port_scan {path}`, `port_import {path, options}`, `port_report`: запуск шагов и чтение отчёта.
- `port_item {id}`: исходник пункта (фрагмент C#, поля, префаб) + что уже сгенерировано.
- `port_resolve {id, how}`: отметить пункт решённым (`rules` / `lua` / `native` / `dropped` + причина).

Порядок для агента (записать в справку MCP и `docs/engine-import.md`):

1. Пройти «не перенесено», для каждой механики: есть ли блок в `rules.json` (`rules_schema`) → данные;
   нет → Lua; Lua не тянет по скорости или API → C++-модуль.
2. Для каждого типа: `scenario_run` / матч ботов, сверить параметры с оригиналом (DPS, время
   производства, скорость), исправить расхождения.
3. Скриншоты сцены: свой вид против кадра из оригинала, если пользователь его дал.
4. Итог — отчёт, где «не перенесено» пусто или каждая позиция объяснена.

## Этап 4. Godot

- `.tscn` / `.tres` / `project.godot` (текстовые форматы 3.x и 4.x), `.import` для ассетов.
- Сцены → объекты карты, `TileMap` / `TileMapLayer` → тайлы, `GridMap` → объекты, `MeshInstance3D` →
  модели (glTF чаще всего уже есть), `AnimationPlayer` → клипы по возможности.
- Поля скриптов (`@export` / `export var`) из сцен → та же таблица синонимов.
- GDScript индексируется как C# в Unity и уходит в ИИ-проход.

## Этап 5. Unreal

- `.uasset` бинарный: без Unreal не читаем. Делаем экспортёр на Python для редактора Unreal
  (`unreal` module): уровни → JSON (акторы, трансформы, ландшафт → 16-битная карта высот), меши и
  анимации → FBX / glTF, текстуры → PNG, звук → WAV, Blueprint-переменные классов с дефолтами → JSON.
- Приёмник читает этот экспорт тем же emit-шагом. Логика Blueprints — только в ИИ-проход
  (экспортёр выгружает граф в текстовом виде, сколько получится).

## Окно и кнопка

- В окне «Сделать игру» источник «Проект другого движка»: путь, результат scan (движок, версия,
  объём, предупреждения), опции (масштаб мира, 2D / 3D, что импортировать), кнопка «Импортировать»,
  затем «Доделать с ИИ», которая запускает этап 3.
- Отдельно меню «Файл → Импорт проекта…» и `aiverse_port <путь> --out <папка>` в консоли.
- Строки интерфейса — через i18n (en + ru).

## Отчёт

`port-report.json` + `port-report.md`: по каждой позиции — исходник, результат, статус
(`exact` / `approx` / `missing` / `resolved`), причина, ссылка на файл. Сводка: сколько ассетов,
типов и карт перенесено, сколько механик ждёт ИИ. Формат статусов как у `unity_vfx`.

## Проверка и готовность

- Синтетические проекты в `tests/data/port/`: Unity (Force Text, 3D-террейн + юниты + постройки + UI,
  2D-тайлмап), Godot 4 (2D и 3D), экспорт Unreal (готовый JSON + FBX). Тесты Python на каждый шаг +
  тест «emit → `aiverse_headless` проходит матч ботов».
- Живая проверка на 2–3 открытых RTS-проектах с GitHub (Unity и Godot), не коммитить, результаты
  записать сюда: что перенеслось, что осталось ИИ.
- Импорт не трогает симуляцию; контрольные суммы шаблонов не меняются.
- Unreal-экспортёр без Unreal под рукой: проверка только приёмника на готовом экспорте — в статусе
  писать «экспортёр не запускался».

## Не делаем

Перевод C# / GDScript / Blueprints в Lua автоматом, бинарную сериализацию Unity, `.uasset` без
Unreal, шейдеры на HLSL / ShaderGraph (только приближение материалом + отчёт), сетевой код и
серверы исходного проекта.

## Порядок и оценка

1 → 2 → 3 (Unity целиком и ИИ-проход) — первый результат для поста «перенесли игру с Unity».
Затем 4 (Godot), затем 5 (Unreal). После каждого этапа — запись статуса в этот документ.
