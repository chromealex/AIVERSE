## Native lifecycle and ownership

1. During `GameModule::setup`, use `examples::terraweave_native::registerSystems(sim,cfg,callback,enableSlopeFailures,slopeSettings,autoFloodShoreline)` to register NEREID's water bodies, flood resource, bank soil, transport, canonical TerraWeave and optional auto shoreline revision resources in stable order.
2. The native game spawns its real `WaterBodyComponent` entities, then calls `seedFloodReservoir(ecs,cfg,NereidFloodGridRegion{rect,maxCells})` ONCE at a structural owner barrier after creating those bodies and before the first flood route tick. The window includes anticipated dry overflow locations. No accidental reseeding; future window migration must preserve cell volume separately.
3. On each fixed tick, NEREID flood routing moves water through open/permeable grid edges from higher hydraulic head to lower, NEREID water probes sample authored base AND any newly flooded cells, local bank erosion and sediment transport operate normally, TerraWeave applies soil and root/grass changes in one resource revision, then `TerraWeaveFloodGroundSyncSystem` updates flood cell bottom heights WITHOUT changing water volume. Finally the opt-in shoreline refresh system detects wet/dry or ground topology changes and registers/updates bank entities for the NEXT tick.
4. On the device/render owner phase `publishNativeTerraWeaveFrame` collects 2k dynamic visual flood tiles in the active region and passes copied `NereidFloodVisualCell` values into `WorldScene`. `WorldScene::update` uploads at most one batched overlay; `WorldScene::draw` submits it through existing Renderer3D.
5. Server owns and replicates the NEREID persistent flood resource plus bank ECS and TerraWeave resource via native ECS save/rollback; clients do NOT modify flood-volume state from Box3D float simulation. The resource's region/ground geometry must be the same across replica peers; use ordinary game networking snapshot/delta channels. Every native map can keep `enableFloodRouting=false` for original water behavior.

## Limitations / QA

**Local finite grid only**: exact sum of equal-area water-column volumes is conserved within explicitly seeded grid. It does NOT account for mass in static infinite/open NEREID water bodies, rainfall, streaming transfers, pumps, pressure-driven 3D hydraulics or river discharge boundaries. Original water footprint/surface remains authoritative as baseline and can visually underlay a higher flood overlay. Overflow becomes visible in the standard model renderer using a fallback translucent surface; it does not yet use the full NEREID refraction/foam shader or geometry with smooth edges. Up to 16k simulated flood cells and 4096 visible overlay quads. Flood source and native structural-write/raster bounds are provided by the game; none of this is automatically enabled in default RTS/FPS clients.
