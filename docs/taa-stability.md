# Sponza: резкость, мерцание и плавность просмотра

## Исправления

ScreenLighting теперь накапливает HDR в ограниченном по яркости пространстве.
Контрастный текущий пиксель больше не обнуляет вес истории: именно таким пикселям
на тонких свечах, листве и бликах нужно накопление субпиксельного покрытия.

Глубина истории проверяется отдельно для каждого texel, без билинейного смешивания
расстояний переднего и заднего планов. На границе учитывается диапазон глубин
текущего соседства 3×3 и присутствие неба. Цвет истории ограничивается текущим
соседством; сама история восстанавливается кубическим фильтром Catmull–Rom.
Он сохраняет детали лучше повторного билинейного переноса. В `full` оставлен TAA
без дополнительного FXAA, который слишком размягчал изображение. Все тела шейдеров
общие для GLSL/MSL. Low-путь не включает TAA.

Это ещё не полноценный temporal upscaler: нет motion vectors деформируемых объектов,
reactive mask прозрачности и плавного смешивания LOD. На движущихся персонажах
возможны шлейфы, на субпиксельной геометрии остаётся рябь. Устойчивость проверена
на замороженной сцене и просмотренных кадрах медленного движения камеры; это не
доказательство качества для любого движения/освещения.

## Проверка

GL, 1280×720, PhysCamera001, `full`, анимация заморожена в 2 с, 60 прогревочных
кадров, затем 16 последовательных захватов. Метрика — средняя абсолютная разность
RGB8 между соседними кадрами. При замороженных сцене и камере она характеризует
межкадровую рябь; при движении камеры применять её как метрику качества нельзя.

| Область | До | Финальный TAA | Изменение |
|---|---:|---:|---:|
| Весь кадр | 4.883 | 3.166 | -35.2% |
| Дальний участок (x=480..959, y=60..359) | 10.271 | 5.719 | -44.3% |

Сильнее сглаженный промежуточный вариант давал меньше ряби, но был отклонён после
проверки резкости. Финальные цифры выше относятся к кубическому восстановлению
без FXAA. Данные: `build/bench-results/autolod/taa-cubic-gl-static.json`,
изображение `taa-cubic-gl.png`; серии кадров на Kingston в `Sponza/validation/`.

Проверены по 7 HDR-проб и 22 варианта шейдеров в GL и Metal; Metal API Validation
не сообщил ошибок. 10 Python-тестов benchmark tooling проходят. Android/Web
для этого изменения не запускались. Исходные измерения авто-LOD в `autolod.md`
предшествуют этой правке TAA и исправлению native frame ownership; новые сравнения
производительности должны использовать одну и ту же финальную сборку.

## Режимы запуска

`--sequence <folder>` — проверка изображения с чтением 16 кадров с GPU. Требует
явного `--camera`. `--freeze-time 2` фиксирует анимацию; `--motion-yaw 0.0003`
задаёт детерминированный шаг поворота на кадр. Эти прогоны не подходят для оценки
плавности живого окна или производительности: readback/запись файлов влияют на ритм.

```sh
aiverse_renderbench_gl --scene /path/to/Sponza/scene-autolod.json --profile full \
  --camera 0 --warmup 60 --samples 30 --freeze-time 2 \
  --sequence /tmp/taa-series --output /tmp/taa-check.json
python3 tools/renderbench/temporal_noise.py /tmp/taa-series
```

`--preview-seconds 20 --motion-speed 0.018` — живой просмотр: поворот в радианах
в секунду по steady clock, анимация также по реальному времени. Прогрев происходит
до начала движения. Во время просмотра нет GPU timing queries и покадровых
захватов; `--sequence` с ним несовместим. Одиночный `--capture` выполняется только
после окончания пролёта. Preview не выдаёт статистику производительности.

```sh
aiverse_renderbench --scene /path/to/Sponza/scene-autolod.json --profile full \
  --camera 0 --warmup 60 --preview-seconds 20 --motion-speed 0.018 \
  --output /tmp/preview.json --capture /tmp/preview.ppm
```

Native benchmark/HDR fixture больше не открывают второй кадр внутри платформенного
`beginFrame/endFrame`. Offscreen GL по-прежнему управляет кадром сам. Комментарий
AppCallbacks приведён в соответствие с платформенным циклом клиента/редактора.
Metal capture использует текущий drawable сразу, если он уже readable; последовательный
захват ждёт callback предыдущего запроса и не перезаписывает его.

Подход к разделению накопления и валидации истории описан в обзоре NVIDIA:
https://research.nvidia.com/labs/rtr/publication/yang2020survey/.

## Следующие кандидаты для профилирования

1. SSR: сейчас дополнительный `renderModels(1)` повторно рисует непрозрачную
   геометрию. Компактный буфер normal/roughness/material и экранный resolve могут
   убрать этот проход, ценой bandwidth/MRT. Сначала замерить отдельный проход.
2. Инстансинг: лимит 32 экземпляра связан с 4 KB uniform block. Большие пакеты
   потребуют поточного instance/uniform buffer (на Metal нельзя просто увеличить
   `setVertexBytes` сверх 4 KB). Сохранить короткий путь простых моделей и текущий
   размер пакета на слабых устройствах.
3. Статичные тени: кэшировать архитектуру при неизменных матрице света и кастерах,
   обновляя динамическую геометрию отдельно. Движение камеры/света требует инвалидирования.
4. Экранный GI: half-resolution indirect-only target и depth-aware upsample.
   Нельзя уменьшать весь входной цвет перед TAA — это снова размыло бы сцену.
5. Отсечение: пространственные группы и затем консервативный occlusion culling там,
   где стоимость проверки ниже стоимости скрытой геометрии. Без CPU-readback depth
   каждый кадр и без обязательного тяжёлого пути для всех простых моделей.

Проценты ускорения для этих кандидатов ещё не измерены.
