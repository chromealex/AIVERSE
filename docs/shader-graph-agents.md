# Shader Graph: руководство для агентов

Используйте Shader Graph, когда нужно изменить цвет поверхности модели, итоговое
изображение сцены или цвет частиц средствами данных проекта AIVERSE. Формат и
ограничения: [shader-graph.md](shader-graph.md). Для обычного PBR-материала, готового
постэффекта или настройки движения частиц сначала используйте соответствующие
`material_*`, `postfx_*`, `fx_*`: граф нужен для вычисления фрагментного цвета.

## Перед изменениями

1. Вызовите `game_info`, проверьте `dir` и модуль открытого проекта. Для учебных
   экспериментов создайте отдельный проект из RTS-шаблона, не меняйте шаблон движка.
   Примеры назначения материалам ниже используют RTS-типы с моделями; наличие
   графического preview само по себе не доказывает интеграцию с FPS-объектами.
2. Получите `shader_graph_catalog`, `shader_graph_list` и прочитайте изменяемые
   графы через `shader_graph_get`. Сохраните исходные назначения через
   `material_list` / `material_get`, `postfx_get`, `fx_get` для возможного отката.
3. Используйте реальные схемы инструментов подключённого редактора. Имена ниже —
   имена операций AIVERSE; префикс MCP зависит от клиента. Если `shader_graph_*`
   отсутствуют, обновите редактор **и** aiversemcp, затем переподключите MCP.
   Не выдумывайте универсальный инструмент вызова и не считайте запись JSON
   подтверждением GPU-поддержки. Preview доступен только в графическом редакторе.

## Основной цикл

В примерах `G` означает **JSON-объект**, прочитанный из файла графа; это не имя
файла и не строка. Следующие строки — псевдокод вызовов инструментов:

```text
shader_graph_validate({graph: G})
shader_graph_set({name: "material_turquoise", graph: G})
shader_graph_preview({name: "material_turquoise"})
shader_graph_preview_status({})
```

`validate` возвращает `ok`, `graph`, `nodes`, `samples`, `glsl`, `msl`. Это проверка
структуры и генерация кода, не GPU-компиляция. После `preview` дождитесь отрисовки:
повторяйте `preview_status` с ограниченным таймаутом, пока `ready == true`, и
требуйте пустой `diagnostic`. Непустая диагностика означает ошибку, даже при
`ready == true`. Затем вызовите `view_screenshot` и **посмотрите** изображение.
Если таймаут истёк, проверьте, что окно графа видно и редактор рисует кадры.

`shader_graph_set` атомарно сохраняет `<project>/shaders/<name>.json`. Имя:
1–64 латинские буквы, цифры, `_`, `-`, без пути и расширения. Оно может заменить
существующий файл: для нового примера выбирайте свободное имя.

**Сохранить ≠ применить.** `shader_graph_apply` читает сохранённый файл и встраивает
снимок в материал, постэффект или эмиттер. После каждой правки повторите
`validate → set → preview → apply`. Изменение исходного файла не обновляет
встроенные снимки автоматически; примените ко всем нужным назначениям.

## Пример 1: бирюзовый материал

Готовый граф: [material_turquoise.json](../examples/shader_graph/material_turquoise.json).
Сохраните его через основной цикл с именем `material_turquoise`.

```text
Input ── Multiply(Tint) ── color
Constant(0.25) ─────────── roughness
Constant(0.65) ─────────── metallic
Constant(0.01,0.08,0.05,0) ─ emission
```

`Tint = [0.08, 0.8, 0.65, 1]`. Материал сохраняет исходный рисунок и прозрачность,
приобретает бирюзовый цвет, небольшой уровень шероховатости и слабое свечение.
Emission не создаёт источник света и сам по себе не включает bloom.

Применение:

```json
{"name":"material_turquoise","target":"demo_turquoise"}
```

Это аргументы `shader_graph_apply`: `target` здесь — **имя библиотечного
материала**, а не объекта. Операция создаёт/обновляет `materials.json`, сохраняя
остальные ключи существующего материала. Затем выберите реальный тип и имя
материала модели из `material_list` и вызовите `material_apply`:

```json
{"type":"TYPE_FROM_MATERIAL_LIST","material":"demo_turquoise","target":"*"}
```

Замените `TYPE_FROM_MATERIAL_LIST` на существующий тип с моделью. `*` применит
материал ко всем материалам модели; для одной части используйте её настоящее
имя. Здесь `target` уже означает **материал внутри модели**. Проверьте объект в
сцене: сфера preview не проверяет UV, текстуры и назначения вашей модели.

Что менять: `tint` — цвет; `rough` ближе к 0 — более гладкая поверхность,
ближе к 1 — шероховатая; `metal` — металлические свойства; `glow` — emission.

## Пример 2: тёплая тонировка сцены

Граф: [postfx_warm.json](../examples/shader_graph/postfx_warm.json), имя `postfx_warm`.

```text
Input ──────────────────── Mix ── color
Input × [1,0.72,0.42,1] ──┘
Constant(0.6) ───────────── amount
```

`amount = 0` оставляет исходную картинку, `1` полностью применяет оттенок.
Alpha сохраняется: у оттенка alpha равна 1. Граф выполняется в конце композиции
постэффектов над LDR-цветом; `Input` содержит текущий результат композиции,
а `texture` читает входную текстуру сцены, что не всегда одно и то же.

После `set` и preview вызовите `shader_graph_apply`:

```json
{"name":"postfx_warm","scope":"game"}
```

Это добавляет/заменяет единственный эффект типа `shaderGraph` в `game.json`.
`target` не нужен. Для одной открытой карты используйте `scope: "map"`, затем
`map_save({})`: изменение карты остаётся в документе до сохранения.
Переопределение карты имеет приоритет над эффектом игры того же типа.

Проверьте `postfx_get`, включите `view_postfx({quality:"medium",scene:true})`
и посмотрите сцену. По умолчанию графовый постэффект требует medium; на low он
может отсутствовать. Preview графа использует high и не заменяет проверку
целевого quality tier. Передайте пользователю предупреждения о стоимости,
если операции postfx их вернули.

## Пример 3: фиолетовые частицы

Граф: [particle_violet.json](../examples/shader_graph/particle_violet.json),
имя `particle_violet`. Цепочка: `Input × [0.65,0.15,1,1] → color`.
Она сохраняет исходную alpha частиц; замена всего выхода непрозрачной константой
может превратить мягкие спрайты в прямоугольники.

Создайте отдельный FX, например через `fx_templates`:

```json
{"template":"magic_aura","name":"demo_violet"}
```

Прочитайте `fx_get({name:"demo_violet"})`, проверьте массив `emitters`. Затем
после сохранения графа вызовите `shader_graph_apply`:

```json
{"name":"particle_violet","target":"demo_violet","emitter":0}
```

`target` — имя **существующего эффекта**, без `fx/` и `.json`; `emitter` — индекс
с нуля. В многослойном эффекте меняется только выбранный эмиттер. Для остальных
нужны отдельные вызовы. Оттенок умножается на исходный цвет: белый эмиттер даст
наиболее чистый фиолетовый. Для точного цвета сначала настройте цвет эмиттера
через `fx_get` / `fx_set`, сохранив остальные параметры.

Посмотрите настоящий эффект через `fx_preview({effect:"demo_violet"})` и
`view_screenshot`. Preview Shader Graph использует свой тестовый эмиттер:
он не проверяет текстуру, blend mode, все слои и масштаб вашего FX.
Для появления в игре отдельно задайте событие через `fx_bind`, выбрав реальный
тип/оружие/способность из проекта. Само применение графа событие не создаёт.
Движение, lifetime, размер и анимацию настраивайте в FX. Trails используют
прежний шейдер; граф применяется к billboard, mesh и sprite-frame частицам.

## Правила построения графа v1

- Все значения и порты — float4. Числовая константа `0.5` означает
  `[0.5,0.5,0.5,0.5]`; это важно для alpha. Вектор задаётся четырьмя числами.
- `inputs` содержит ID узлов в порядке аргументов операции. Для `mix` это
  `[a,b,t]`, для `step` — `[edge,x]`. `dot` и `length` учитывают все четыре
  компоненты: `uv` возвращает `[u,v,0,1]`, поэтому перед расчётом расстояний
  занулите лишние компоненты.
- Узлы `red`, `green`, `blue`, `alpha` размножают выбранный канал на RGBA.
  Допустимые операции и число входов всегда берите из `shader_graph_catalog`.
- `outputs.color` обязателен. Только material также поддерживает `roughness`
  и `metallic` (красный канал), `emission` (RGB). Материальные цвета — linear;
  postfx — существующий LDR composite; частицы — их существующий цветовой путь.
- `texture` принимает UV и читает уже привязанную базовую текстуру материала/
  частицы либо сцену для postfx. Собственных texture assets/sampler nodes нет.
- Нет time, particle age, normal/world position, vertex displacement, compute,
  пользовательского GLSL/MSL и импорта графов Unity/Unreal. Не обещайте эти
  возможности и не подменяйте их обновлением JSON каждый кадр.
- Максимум 128 узлов, 8 узлов texture, ID до 64 символов, файл до 256 KiB,
  конечные константы в пределах ±1 000 000. Циклы, повторные ID, отсутствующие
  ссылки и несовместимые выходы доменов — ошибки. `position:[x,y]` задаёт
  расположение узла на холсте, а не положение в игровом мире.

## Редактор, ошибки и откат

Окно: **Графика → Shader Graph**. Введите имя сохранённого ассета и загрузите.
Связь создаётся кликом по выходу, затем по входу; заголовок перетаскивает узел,
средняя кнопка перемещает холст. Выходы выбираются справа. После правок нажмите
«Сохранить и применить» с нужной целью; для материала затем назначьте библиотечный
материал модели. Несохранённые правки блокируют загрузку другого графа: сохраните
их или предложите пользователю отменить. Не сбрасывайте чужой черновик.

| Симптом | Проверка |
|---|---|
| Граф сохранён, вид не изменился | Повторить apply; проверить назначение материала, scope карты, emitter и quality |
| Preview показывает ошибку GPU | Сохранить diagnostic; не считать fallback успешным эффектом |
| Материал/FX слишком тёмный | Input уже содержит исходный цвет; Multiply затемняет его |
| Пропала прозрачность | Проверить alpha у constant и итоговый color |
| FX не появился в игре | Apply меняет шейдер, а fx_bind подключает эффект к событию |
| Нет shader_graph_preview | Нужен графический редактор с актуальным набором операций |

Для отката восстановите ранее прочитанный материал/FX или исходный блок postfx.
Для нового постэффекта используйте `postfx_remove({type:"shaderGraph",scope:"game"})`
(или map + map_save). Удаление `shaders/<name>.json` **не удаляет** встроенные
снимки. Не удаляйте общий материал/FX ради отката одного назначения.

В отчёте укажите файлы графов, реальные назначения, quality, результат CPU-
валидации, GPU diagnostic и просмотренный screenshot. Разделяйте проверку
preview и проверку сцены/игры. Проверенный Metal не означает проверенные
OpenGL/WebGL/Android. Проверка этих примеров не требует изменения C++ движка.
