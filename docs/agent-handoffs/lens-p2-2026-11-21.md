## What was added

**Physical lens** (`engine/render/CameraLensPhysics.h`):
- `cameraLensEV100`, `cameraLensExposureStops` (relative to the default lens
  f/2.8, 1/60 s, ISO 100, plus compensation; AIVERSE scenes are not photometric,
  so absolute EV would just black out the image).
- `cameraLensDepthOfField`: thin lens, hyperfocal distance, near/far sharp limits,
  background disc radius at infinity in render pixels; CoC = sensor height / 800
  unless `circleOfConfusionMm` > 0. `cameraLensDofPass` maps `[near, far]` to the
  symmetric PRISMA pass (centre, width; infinite far capped at 500 m; blur <= 16 px).
- `CameraLensComponent` appended fields: `driveExposure`, `driveDepthOfField`,
  `exposureCompensation`, `circleOfConfusionMm` (defaults keep old behaviour).
- PRISMA (additive, PRISMA stage 96): `Prisma::setViewDepthOfField /
  clearViewDepthOfField / viewDepthOfField`; per-view override of the authored
  `depthOfField` effect (forces metric focus), clamped, dropped by `retireView`.
- `CameraPostFxPool::prepare` pushes the lens into the camera's PRISMA instance
  (manual EV + defocus) only when the values change, so TAA/motion history is not
  reset every frame; clears on drive off, world rebind, dead entity. `lensState()`
  for diagnostics. Requirements unchanged: authored `autoExposure` (+HDR) for
  exposure, authored `depthOfField` + `AIVERSE_PRISMA_DOF=1` for defocus.

**Rails and shake** (`engine/render/CameraRailPath.h`, used by `CameraRigEvaluator`):
- Centripetal Catmull-Rom through all points, open (reflected end tangents) or
  closed loop; arc-length constant speed (16 samples/segment); smoothstep ease;
  tangent from the path, so an eased rail at rest still has a heading.
- `CameraRailComponent` appended: `interpolation`, `constantSpeed`, `ease`.
  Linear + no flags = the previous code path, bit for bit.
- Shake `style` Noise: seeded quintic value noise on 3 position + 3 rotation axes;
  `fadeExponent`; Sine keeps the previous formula (roll only).
- All are pure functions of absolute presentation seconds (seekable, no state).

**cameras.json** (`engine/sim/CameraSceneAsset.h`): `lens` drive keys; new `rail`
and `shake` blocks; unknown interpolation/ease/style, bad duration, negative
amplitudes, out-of-range seed reject the file before any entity is created.
MCP `lens_*` operations validate through the same loader, so they accept these.

**HDR capture** (`engine/render/CameraExr.h`, `CameraFrameRecorder.h`):
- OpenEXR single-part scanline, HALF A,B,G,R, NO_COMPRESSION, no dependency.
- `CameraHdrFrameRecorder` reads an RGBA16F target through `readTextureAsync`;
  rejects (never down-converts) non-RGBA16F results; counts rejected frames.
- Backend reality: Metal reads RGBA16F back; GL/WebGL accept RGBA8 only, so HDR
  recording is rejected there. Vulkan RGBA16F readback not checked.

**Studio**: LENS / Cameras window, Physical Lens section: drive toggles,
compensation, CoC, live EV100/stops and sharp-interval readout. No rail/shake UI
(author through cameras.json / MCP).

**GCC fix (outside LENS area)**: main did not compile with GCC because
`GiDynamicShaders.h` (included by `ModelShaders.h`) used raw strings spanning lines
inside `#define`. Rewritten mechanically; values proven identical (below).

## Known limits / risks

- DoF is PRISMA's 8-tap screen-space defocus; physical bokeh is not implemented.
- Exposure is relative, not photometric; `exposureCompensation` is the knob.
- `CameraPostFxPool` keeps lens-driven overrides per camera Prisma instance at
  `viewId()` 0 (one Prisma per camera); a host sharing one Prisma across views
  must call `setViewDepthOfField` itself.
- The GCC fix touches lighting/LumaWeave headers owned by other agents: content is
  unchanged, but merging their later edits will need the same no-raw-string form.
- Dev env: Ninja on this VM re-runs CMake every build (VerifyGlobs); sandboxed
  shell kills background jobs after each call, so long TUs must fit in 180 s.
