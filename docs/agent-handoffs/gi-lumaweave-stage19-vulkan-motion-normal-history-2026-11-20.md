## Runtime/host integration contract

`LumaNativeViewInput` remains fully **opt-in** with `enableVulkanDirect=true`, real immutable BVH revision and actual Renderer3D opaque material/surface receiver coverage (including native custom terrain). The host may additionally set:

```cpp
view.vulkanHistoryKey = stableCameraWorldKey;         // nonzero for temporal
view.vulkanHistoryEpoch = cameraCutOrReloadEpoch;
view.vulkanDynamicGeometryVisible = hasSkinnedOrAnimatedOpaqueObjects;
view.vulkanObjectMotion = MotionTextureInput::declared(
    actualObjectMotionRGBA16F, view.width, view.height,
    gfx::PixelFormat::RGBA16F);
view.vulkanMotionFrameSerial = device.frameSerial(); // current Vulkan frame
view.vulkanMotionViewKey = view.vulkanHistoryKey;
view.vulkanMotionViewEpoch = view.vulkanHistoryEpoch;
```

The actual velocity texture MUST be an already rendered, sampled current-view image with PRISMA's **current minus previous UV** encoding, and B>0.5 only for valid deformed/moving object pixels. A previous-frame texture (even if the handle is reused), wrong camera/world, epoch, size or format is invalid. If `vulkanDynamicGeometryVisible` is set and a pixel has no valid B-motion, the shader does not use temporal history for that pixel and shows current spatial GGX Direct, eliminating unsupported camera-only motion reuse on animated surfaces.

The host owns the borrowed motion GPU resource until the **actual Vulkan completedFrameSerial** confirms its sampling work finished. This input is not copied or destroyed by LumaWeave. The current Stage18 branch's Renderer3D lacks MAIN's complete PRISMA-generated motion pass: do not claim animated velocity is auto-produced in this isolated feature. On conflict-aware integration with current `main`/PRISMA, use their already implemented rigid/skinned/animated motion output (and reactive masks) rather than writing a duplicate renderer pipeline. In this isolated branch, an advanced native host can supply the image from its own genuine motion pass. Missing input + animated geometry forces current spatial-only, never fabricated motion.

## Technical limits and safety

- Temporal previous *normal* and previous *light* are **same history slot**, with identical captured frame serial, view key/epoch and BVH/source generations, and are both retained while a newer Vulkan frame samples them. Four screen slots remain the Stage18 limit; adding normal makes low-resolution per-slot images **3 RGBA16F images**, not a full-resolution third capture. All ownership still tracks read/write GPU frame fences; `shutdown` never frees in-flight slots.
- Camera cuts and world/source/BVH/size changes still invalidate temporal reuse. Previous normal equality is necessary but not sufficient for opaque-surface identity on disocclusion (two objects with identical normals could overlap); motion B validity and scene/BVH revisions reduce but do not eliminate this. No full per-pixel object-ID or previous-frame skinned deformation ID buffer is added here. Motion-history of transparent/FX objects is NOT claimed.
- The Vulkan RHI is still compiled from the existing GI 4-SSBO storage-image compute; only optional sampled descriptor cap grew 5→7. GPUs with insufficient sampled-descriptor limits fail pipeline creation; Vulkan Direct falls back to RAW current output. Do not claim this shader is supported by GLES/WebGL2 or Metal.
- No Vulkan GPU/frame metrics or FPS measured; 7 sampled inputs and a separate normals snapshot compute dispatch cost GPU time. Other agents' current RHI may differ substantially from the Stage18 branch; reconcile changes without force-overwriting newer texture/MDI/editor work.
