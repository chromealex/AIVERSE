# Play Mode Review bulk removals and profiler overhead

Code revision d327e0003. A native StudioSession fixture reviewed a map containing 2,000 entities, 1,999 roads and 200 deletions. On the preceding revision the preview took 62.907 ms and application took 97.404 ms. On the new revision they took 10.020 ms and 24.278 ms respectively. Both runs left 1,800 entities and 1,600 roads after applying, and one undo restored 2,000 entities and 1,999 roads. These are individual wall-time observations in the Debug build on the same Mac under load. Peak resident memory for the full test process was 49,319,936 bytes before and 47,075,328 bytes after. The permanent StudioSession fixture also exercised duplicate and out-of-order deletions, retained entity order, exact remapped road endpoints and undo. It passed. The new path allocates one integer per original ordinal when a removal is requested. It visits the map and its roads a bounded number of times per user action.

On the same Mac, six paired 120-tick runs alternated profiled and ordinary GameCore instances on mushrooms/duel after ten warmup ticks each. A capture covered 23 systems. Ordinary runs took 4.337–4.401 ms per window and captured runs 4.688–4.770 ms. Gameplay checksums matched in all six pairs. The 120-entry sample array retained its starting storage address throughout each capture. The process peaked at 18,624,512 resident bytes. These are simulation CPU-side wall times. Neither operation requires GPU timing.

An additional run of the compiled building exporter and QA validator produced all twenty recipes in 5.62 seconds, with the timing tool reporting a maximum resident set of 89,481,216 bytes. This measures offline generation, subprocess launches, validation and file output together. Interactive rendering and cross-platform acceptance are separate.
