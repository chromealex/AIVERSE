## Native view contract and exact composition

The host still calls one `gfx::Device::beginFrame/endFrame` around the view. Construct `LumaWeaveNativeDriver(device, renderer, existingLinearHdrPost)`, call `initialize`, provide `LumaNativeViewInput` with nonzero immutable `GiGpuBvh` geometry revision and stable LumaWeave direct lights, then call `driver.frame(input, output, submitScene)` after the ECS/FX presentation read barrier.

On Vulkan only, the default remains the existing legacy raster direct + optional separately owned CPU probe GI. To opt in, set **both**:
- `enableVulkanDirect=true`: feature intent.
- `vulkanReceiverCoverageConfirmed=true`: the HOST guarantees every intended opaque frontmost scene surface (including custom terrain/foliage) has matching material/surface receiver passes. Ordinary ModelDraw receives both through the existing native shader; custom opaque drawers must register `drawCustomMaterialReceiver` and `drawCustomSurfaceReceiver` callbacks before render. Missing receiver coverage must not be guessed from lit scene colour.

Route is selected only if Vulkan RHI compute and screen shader are ready, the downstream PostProcess is active/linear HDR, geometry and sources have been accepted transactionally, no prior GPU dispatch is in flight, current quality budget admits **the full registered light list**, existing point direct is absent, and scene sources have correct immutable revision. `LumaDirectRoute::VulkanGpu` means GPU publication was accepted, not necessarily that a final frame visually composited. `vulkanFrameComposited` and `vulkanSubmission` report actual encoding/composition; on last-moment refusal the route is marked Disabled rather than claiming a successful GPU frame.

`LumaWeaveVulkanPostProcess::scenePass` obtains the ACTUAL HDR scene color/depth from downstream. It requests two existing Renderer3D receivers, each with its own independent depth; after Renderer3D ends the scene pass, `resolve()` calls `LumaWeaveVulkanDirect::dispatchScreen` with those 5 textures. That kernel reconstructs actual Vulkan camera pixels from depth (including GL→Vulkan depth mapping), importance-samples direct point/spot lights, shadows against strict Stage62 BVH, and writes PBR-reflected GGX+diffuse RGB with scene depth in A. The Vulkan HDR fragment pipeline checks all three depths again, interpolates low-res samples without borrowing silhouettes and adds a single linear direct term. It uses a separate depth attachment so the original scene depth is only sampled, never simultaneously used as a writable attachment. It then calls downstream resolve, preserving tonemap, exposure, bloom and UI pipeline.

No default backend, ECS save/replication, gameplay or baked light changes. Metal GPU and GLES raster paths still work through the original owner APIs; a ready Metal cascade GI runtime remains independent bounced light. GLES3/WebGL2 do **not** gain compute support or a 4096-light GPU claim.
