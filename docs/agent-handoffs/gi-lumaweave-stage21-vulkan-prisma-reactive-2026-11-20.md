## Runtime API and exact ownership

The existing Vulkan Direct mode still defaults **OFF**. After main PRISMA producer is integrated conflict-aware, callers opting into Vulkan Direct may set:

```cpp
view.enableVulkanDirect=true;
view.vulkanReceiverCoverageConfirmed=true;
view.vulkanHistoryKey=stableCameraWorldKey; // nonzero for temporal
view.vulkanHistoryEpoch=cameraCutEpoch;
view.vulkanDynamicGeometryVisible=hasMovingRigidOrSkinnedMeshes;
view.vulkanReactiveGeometryVisible=hasAlphaMaskDissolveOrTranslucentFx;
view.vulkanDenoise.reactiveThreshold=.10f;
```

The current MAIN PRISMA renderer knows how to generate RGBA8 reactive coverage for alpha masks, moving LOD fade, actor reveal, dissolution, translucent moving mesh/water and skinned reactive silhouettes via the real `PostProcess::acceptMotionReactiveMask` callback. On the Stage20 isolated renderer, a genuine optional installed native `Renderer3D::setObjectMotionProducer` can trigger the same callback; **the full automatic MAIN GPU producer is NOT merged** in this child branch and must be conflict-aware reconciled, not copied wholesale.

`LumaWeaveVulkanPostProcess` verifies the typed input and makes an independent **RGBA8 current-frame GPU copy** in the exact owner receiver slot. The borrowed PRISMA source remains the producer's responsibility until Vulkan queue copy completes; the Luma private mask remains valid until its scene compute is retired via `completedFrameSerial`. Wrong/old/currently invalid reactive mask is not sampled as trusted. When reactive geometry is declared and no valid copied mask arrives, Stage21 denoiser drops temporal history and presents CURRENT spatial light instead, avoiding alpha/LOD ghosting. No invalidation of Metal, GLES, CPU L1 bounced GI, sun or baked light. The 8-sampler path is optional and fails to raw Direct on Vulkan devices with insufficient sampled-image descriptors.
