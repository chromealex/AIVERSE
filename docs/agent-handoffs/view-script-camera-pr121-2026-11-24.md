## Scope and acceptance

Move the existing client `runViewScripts` call before world streaming, camera jitter and `Renderer3D::beginScene`. A script that calls `view.set_camera` after host input must frame the world and `view.to_screen` in the same frame. Keep simulation authority, the script API and serialization unchanged. No new camera owner or genre branch is introduced.

`ViewScripts::vSetCamera` already updates its projection copy before later `view.to_screen` calls. The host applies the request in `runViewScripts`, now before world camera consumers. The debug `AIVERSE_CAM_FLY` override intentionally runs afterwards. Other presentation requests are still consumed later in the frame, although effects and entity appearance changes can now reach the current frame.
