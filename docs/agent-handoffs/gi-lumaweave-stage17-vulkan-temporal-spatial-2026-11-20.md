## Presentation architecture and public API

The Stage16 PBR GGX + BVH ray kernel still performs physically meaningful DIRECT light integration from the *real* Renderer3D HDR scene and independent material/surface receivers. It writes per-low-resolution pixel material-reflected RGB and current scene depth in A. Stage17 adds a **second Vulkan compute dispatch in the same VkQueue frame** before the additive HDR pass:

1. `LumaWeaveVulkanDirect::dispatchScreen(...,const DenoiseRequest* = nullptr)` encodes raw GGX direct; callers omitting denoising keep prior source/API behavior. The current scene depth/material/normal/depth remain owned by the current view.
2. If `DenoiseRequest.settings.enabled` and the optional denoise pipeline exist, `encodeDenoise()` creates/retains two separately owned low-res RGBA16F storage+sampled textures (max **16,384 pixels** each), selects a write slot distinct from the last accepted historical slot and updates the 192-byte `DenoiseView` in an RHI-fence-safe dynamic SSBO version. The original screen shader's earlier ScreenView SSBO remains valid for its in-flight compute commands.
3. Same GI-compatible Vulkan descriptor ABI: 4 SSBO bindings 0..3, RGBA16F write-only storage image binding 4, and sampled bindings **5=raw light, 6=previous filtered history (or raw when disabled), 7=current scene depth, 8=current surface normal/roughness, 9=current surface depth**. One 80-byte push block; workgroup size 64. Output stores FILTERED, already-PBR-reflected DIRECT RGB and CURRENT scene depth in A. No extra sun, GI/bounce or baked energy is added; the existing HDR composer simply adds this one result without another albedo multiply.
4. Spatial pass: reject clear depth/material gaps and silhouettes, 3×3 depth+normal-aware bilateral neighborhood, no renormalization with invalid/out-of-depth neighbors that would invent reflected light. Temporal pass requires a completed `previousHistory` texture and host-accepted `LumaVulkanHistoryPolicy`; reconstruct current world position from original GL-convention inverse VP using **depth×2−1**, project into prior GL-convention VP and compare **expected** old depth to the history alpha. Reject outside/frustum/disoccluded pixels, clamp accepted historical RGB to current spatial neighborhood range before bounded accumulation.
5. `poll()` is the **ONLY** point that promotes `pendingHistoryStamp` to reusable `historyStamp` and advances the ping-pong read index. It requires `gfx::Device::completedFrameSerial >= pendingFrameSerial` from the real Vulkan frame fence and a healthy device. `invalidateHistory()` increments a generation counter; a later successful in-flight GPU completion carrying the old generation cannot resurrect discarded history. `shutdown()` still refuses to free textures while GPU work is pending. Failed denoise encoding presents only the current raw result, not a stale previous texture.
6. Native input `LumaNativeViewInput::vulkanHistoryKey` defaults 0: spatial denoising but **NO temporal reuse**. Hosts may provide a stable nonzero camera+world identity and increment `vulkanHistoryEpoch` on hard cuts/teleports/scene reloads. `vulkanDenoise` exposes validated weights/tolerances. Source/BVH publication, view/size/epoch changes or camera teleports invalidate temporal reuse. `LumaNativeViewResult` reports `vulkanDenoiseEncoded`, `vulkanTemporalHistoryUsed` and `vulkanHistoryReason`.
7. Vulkan currently has two in-flight frame slots and the Direct owner deliberately permits only one uncompleted submission. During a BUSY frame, the native driver may select raster direct. To avoid losing ALL temporal reuse due to this transient skip, the PostProcess only preserves a pending history candidate when the requesting view/world key+epoch and registry/BVH generations match **exactly**; true scene/source/camera-route switches discard it. No shader can sample it before the real fence anyway.

## Safety and remaining limitations

- All changes are experimental presentation-only, off by default via `enableVulkanDirect=false`; no authoritative ECS/save/rollback/replication or genre dependency. Metal/SpectraFX/GLES shader paths were not changed.
- Host must supply accurate opaque receiver coverage, actual immutable BVH revisions, and nonzero unique view identities for temporal reuse. A dynamic occluder failing to advance geometry revision is a caller-contract violation; history cannot infer unknown animated geometry automatically.
- The history contains prior filtered RGB + depth, **not a separately recorded previous-frame normal/motion-vector GBuffer**. Reprojection relies on old depth, current normal spatial checks, view/world/source/BVH epochs and neighborhood color clipping. Moving skinned meshes and thin alpha-cutout FX require device-level ghosting evaluations; do not claim TAA-quality arbitrary motion-vector reconstruction.
- 3×3 filter adds bounded texture reads and two RGBA16F history images. No measured GPU milliseconds/VRAM were collected. The one-owner-in-flight design still temporarily falls back to raster under GPU pressure, not guaranteed 60FPS LumaWeave every frame. Future work: multi-frame render producer/per-view history ring, profiling and adaptive quality.
- The earlier full Vulkan/GLSL implementation and cross-branch `main` reconciliation remain unverified; the tests in this stage are *authored*, not observed passing.
