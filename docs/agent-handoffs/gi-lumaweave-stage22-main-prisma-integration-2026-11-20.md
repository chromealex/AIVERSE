## Runtime frame route and safe API

The MAIN native render path already calls `Renderer3D::renderObjectMotionVectors(*post)` after ending HDR scene pass and before `PostProcess::resolve`. That producer recognizes stable rigid/skinned/morphed/baked animation source objects, camera cuts, per-view ID/epoch, alpha/dissolve/LOD reactive silhouettes, and publishes typed current-frame `MotionTextureInput::declared` for **RGBA16F signed velocity** and **RGBA8 reactive mask**. Luma's Stage20/21 PostProcess now consumes BOTH callbacks without a duplicate producer. This is main-based code integration, not actual rendered-pixel acceptance.

The actual order is `beginScene` → author scene models/custom receivers → `Renderer3D.render(screen,&lumaVulkanPost)` → two PBR receiver passes (each independently depth-tested) → opaque HDR+translucency+FX scene → `resolvePrisma()` ends main color pass → MAIN's real object motion/reactive pass → PostProcess typed callbacks copy FP16 velocity and RGBA8 reactive into separately fenced Luma receiver frames → Vulkan low-res GGX + shared BVH shadows → spatial/temporal denoise with current dynamic motion, previous depth/normals and reactive mask rejection → one depth-aware additive HDR Direct composition → downstream PRISMA tonemap/bloom and UI.

To opt in, the host uses `LumaNativeViewInput::enableVulkanDirect=true`, `vulkanReceiverCoverageConfirmed=true` ONLY when every visible opaque surface has exact material+normal receiver coverage; nonzero `vulkanHistoryKey`, epoch increment on cut, `vulkanDynamicGeometryVisible` for moving models, `vulkanReactiveGeometryVisible` for alpha/dissolve/LOD/transparent silhouettes. Device own frame + real VkFence completion remain mandatory, and Direct never silently drops sources to meet full-registry work limits. Metal/GLES and plain legacy raster are not default changed.
