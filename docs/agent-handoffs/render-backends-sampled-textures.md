# Sampled RGBA8 textures

Implementation SHA 0476343cd5409818efd8aeb0e373bc415fcfd6f3. CPU and Direct3D support single-level RGBA8 repeat/clamp and nearest/linear sampling. CPU clip-space triangles carry a perspective-correct UV. The common model capture tool samples decoded model base textures using per-material UV scale, rotation and offset. First-stage exclusions and current scope are in docs/cpu-renderer.md and docs/direct3d.md. The paths and native/test evidence are in both feature manifests.

On Mac, rebuilt aiverse_cpu_device_tests and aiverse_cpu_capture through CMake on KINGSTON. CTest render_cpu_device and render_cpu_textured_model passed (2/2). The texture smoke generates a temporary OBJ, MTL and a PNG with separate red and green regions, imports that material through the public geometry capture path, decodes the rendered PNG and measures both regions. Exact counts and tested SHA are in docs/evidence/cpu-renderer-stage3-textures.json and its log. A separate clang++ -std=c++20 -Wall -Wextra -Werror compile and run of tests/render/cpu_device.cpp with GfxCpu.cpp passed.

Both aiverse_direct3d_device_tests and aiverse_direct3d_rhi_tests cross-built from the updated sources under platform/cmake/mingw-w64.cmake. The Windows model capture consumer also compiled with MinGW and -Werror. The Windows RHI smoke tests texture upload, sampling, region update and draw on two successive frames.
