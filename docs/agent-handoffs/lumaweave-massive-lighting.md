New explicit host API: During `beginScene` before `render` the game may call `Renderer3D::drawCustomMaterialReceiver(fn)` for a custom shader that writes RGBA16F {linear material diffuse base.r/g/b, metallic} and matching opaque depth; and `Renderer3D::drawCustomSurfaceReceiver(fn)` for a shader that writes RGBA16F {signed WORLD normal.xyz, perceptual roughness} and matching opaque depth. The callbacks are invoked only if an explicit PostProcess requests the associated pass and returns valid separate color/depth attachments; no default shader or draw changes. The game must submit the SAME physical geometry/frontmost surface and identical camera view-projection/depth/alpha discard conventions as its normal draw, or the consumer will reject on depth discrepancy. Built-in WorldScene/TerraWeave ModelDraw surfaces remain covered by existing automatic material capture. Water transparency, translucency and particles are intentionally NOT forced into opaque material capture.

Lifecycle: callbacks are cleared at every Renderer3D::beginScene so editor Game/Scene cameras and separate ECS worlds cannot leak previous-view pointers. This is a draw/graphics-thread callback only; does not write ECS, physics, navmesh, terra geometry or gameplay state. It does not implicitly enable LumaWeave or double-add legacy LightSystem direct. The use of custom shaders is still host-provided; the renderer cannot invent an artist's metallic/roughness for custom geometry.
