# Импорт проекта другого движка

Реализация живёт в `agent-engine-import`; исходное ТЗ —
[engine-import-spec.md](../engine-import-spec.md). Контрольные суммы симуляции и шаблонов не изменились.
Это рабочая основа импорта, **а не выполнение всех этапов ТЗ**. Покрытие и оставшаяся работа ниже — часть передачи MAIN.

## CLI и промежуточные данные

Python 3.8+; пакеты Python не нужны. Исполняемый запускатель —
`tools/importers/port/aiverse_port` (или явная форма через Python ниже):

```sh
python3 tools/importers/port/aiverse_port.py scan /path/to/UnityProject
python3 tools/importers/port/aiverse_port.py extract /path/to/UnityProject --out /tmp/port.json
python3 tools/importers/port/aiverse_port.py emit /tmp/port.json --out /path/to/Imported
python3 tools/importers/port/aiverse_port.py /path/to/UnityProject --out /path/to/Imported --scale 1 --mode auto
python3 tools/importers/port/aiverse_port.py report /path/to/Imported
python3 tools/importers/port/aiverse_port.py item /path/to/Imported --id ITEM_ID
python3 tools/importers/port/aiverse_port.py resolve /path/to/Imported --id ITEM_ID --how lua --reason 'Verified by scenario…'
```

Каждая команда печатает JSON; при ошибке выходит с кодом 2. `scan` ничего не пишет. Папки входа и выхода не должны
пересекаться. Не запускайте одновременно несколько импортов в одну папку назначения. `extract` записывает исходные
пути, полные сериализованные компоненты, поля, исходный код скриптов и их использование. `emit` пишет манифест игры,
правила, карты, `.rtsproj`, скопированные ассеты, при необходимости спрайты/тайлы/звук/эффекты, `port.json` и отчёты
JSON/Markdown. `sourceRoot` должен существовать во время emit скопированных ассетов. Сгенерированный `.rpakignore`
исключает из игровых паков промежуточный индекс скриптов и отчёты. Манифест помечает импортированный контент
`external: true`, и aiversebuild переносит этот флаг в ресурс-паки.

`--scale` — клеток на метр; `--mode auto|2d|3d` выбирает плоскость сцены и камеру. Unity 3D переворачивает Z; Unity 2D
проецирует XY на плоскость земли. Vector2 из Godot отображается в XZ. Начала координат сдвигаются, чтобы позиции на
карте были положительными. Владельцы не придумываются: отображается только явное поле Unity `owner`, с предупреждением
о приближении. Нумерацию игроков в исходнике нужно проверить.

`lib/port/mapping.json` задаёт псевдонимы полей. `--mapping FILE` добавляет или переопределяет псевдонимы для
поддерживаемых целей. `fireRate` трактуется как выстрелы в секунду (обратная величина к cooldown) и явно помечается как
приближение. Перезарядка и время стройки в JSON движка — в **секундах**, а не в тиках симуляции. У каждого выведенного
поля есть происхождение, уверенность и путь в цели.

### Повторный импорт

`.port-state.json` хранит хеши сгенерированных файлов/типов. Изменённые или уже существовавшие файлы сохраняются, в том
числе когда редактор оставил маркер `ported`. Правила сливаются по типам; изменённые типы теряют этот маркер. Новые
типы по-прежнему могут добавляться. Изменения пользователя в настройках уровня правил сохраняются. Карты и бинарные
файлы защищены целиком. Устаревшие сгенерированные файлы не удаляются. Манифест состояния принадлежит импортёру; не
редактируйте его.

Отметки о решении переживают повторный импорт, только пока элемент и отпечаток соответствующей исходной сущности/скрипта
не изменились. Изменённый исходник снова открывает элемент для проверки.

## Редактор и MCP

Откройте **Проект → Импорт проекта движка** или `editor_window {id:"project_import", open:true}`. Просканируйте исходник,
выберите папку назначения/масштаб/2D/3D, затем импортируйте. Интерфейс запускает импортёр вне потока рендера и может
открыть результат. **Скопировать задание для AI** копирует явное задание и открывает окно Agent; это не означает, что
агент запущен.

В текущей базовой ветке нет мастера «Сделать игру». Интеграция с отдельной веткой `agent-gamewizard` остаётся за MAIN;
посторонние ветки не сливались.

Зарегистрированные операции (настройки импорта можно также вложить в `options`):

- `port_scan {path}`: обнаружение исходника, проверка сериализации, списки ассетов/сцен/скриптов.
- `port_import {path,out,scale?,mode?,mapping?}`: запуск извлечения и записи.
- `port_report {path?}`: чтение отчёта в папке назначения (по умолчанию — открытый проект).
- `port_item {path?,id}`: исходный элемент, компоненты, связанные скрипты и сгенерированные типы.
- `port_resolve {path?,id,how,reason}`: отметить проверенную работу (`rules`, `lua`, `native`, `dropped`).

Импорт через MCP синхронный, как у существующего импортёра VFX; большие проекты могут занять время. `AIVERSE_PYTHON`
выбирает интерпретатор. Метасимволы оболочки Windows `%`, `!`, кавычки и переводы строк в аргументах команд
отклоняются, а не подставляются.

Порядок работы агента: изучить недостающие элементы, свериться с `rules_schema`, реализовать подходящие механики
данными, затем Lua, затем нативным модулем при необходимости. Использовать `scenario_run` и матчи ботов, чтобы сравнить
DPS, время производства и скорость движения. Сравнивать скриншоты, если дан исходный кадр. Отмечать решёнными только
проверенные элементы; объяснять намеренно отброшенное поведение. C#/GDScript/Blueprint механически не переводятся и не
исполняются.

с включённым плагином Python и новой папкой вывода. Справка по его API:
[AssetExportTask](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/AssetExportTask?application_version=5.6),
[EditorActorSubsystem](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/EditorActorSubsystem?application_version=5.6).
Он экспортирует загруженный сейчас уровень и ассеты `/Game`; незагруженные уровни не обходятся.
