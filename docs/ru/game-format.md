# Формат данных игры (AIVERSE)

Игра — это папка `<project>/`:

```
game.json        manifest: name, id, version, rules file, maps list, orientation, desktop window, icon, input
rules.json       resources, types (units/structures/objects), techs, factions, game rules, triggers
maps/*.json      terrain, players, objects, waves, triggers, areas, victory overrides
audio.json       sounds, music and which sound plays on which game event (optional: no file = silent)
models/ ui/ ...  assets (glTF models, textures, UI, sounds); 2D images may be packed into atlases (see Texture atlases)
```

JSON допускает комментарии `//`. **Числа — обычные десятичные** (`1.5`, никогда `1e3`): симуляция
работает в фиксированной точке и детерминирована. Секунды — игровые секунды, расстояния — клетки карты. Каждый блок
ниже необязателен — набор блоков у типа определяет, что он умеет.

## Постобработка сцены и камеры PRISMA

`game.json.postfx` сохраняет исходные глобальные настройки HDR/bloom/цветокоррекции. Необязательные `game.json.prismaVolumes` и `prismaVolumes` карты добавляют зависящий от позиции вид камеры (без изменения игровой/ECS-симуляции). Каждый блок содержит `{"volumes":[{"id":"area","shape":"sphere","center":[0,0,0],"radius":8,"blendDistance":3,"priority":4,"weight":1,"profile":{"effects":[{"type":"colorGrade","saturation":0.6}]}}]}`. Карта может переопределить объём игры с тем же `id` или задать `"replace":true`, чтобы отбросить объёмы игры. Поддерживаются формы global, sphere и box, выровненный по осям (center + halfExtents). Профиль использует существующую схему эффектов `postfx`. Только явные `hdr`/`enabled` в профиле переопределяют глобальный HDR или включение цепочки. Владельцы в C++ движка/рантайма: `engine/render/PrismaVolumeData.{h,cpp}` и `PrismaVolumes.h`; полная семантика и оговорки по качеству — в `docs/prisma.md`. Операции MCP `postfx_*` остаются совместимыми.

## game.json

```json
{ "name": "Iron and Gold", "id": "com.studio.ironandgold", "version": "0.1.0", "build": 1,
  "module": "game", "rules": "rules.json",
  "maps": [{ "file": "maps/valley.json", "title": "River Valley (1v1)" }],
  "orientation": "landscape", "icon": "icon.png" }
```
`"audio"`: другое имя файла звуков (по умолчанию `audio.json`).

`"module"`: игровой модуль — `"rts"`, `"fps"`, `"voxel"` или `"scene"`. У проекта `"scene"` нет игрового
модуля: ему нужен только `game.json` (`name`, `id`, `version`, `build`, `"module": "scene"`, необязательный
`"background": "#rrggbb"`). `aiversebuild` упаковывает его с минимальным клиентом сцены
(`apps/client/SceneMain.cpp`, CMake `AIVERSE_SCENE_CLIENT`): окно или canvas, пакет контента и пустая
сцена, залитая цветом фона, — без симуляции, рендерера, UI, скриптов и звука, и без
`engine/assets` в пакете. Web Release с настройками по умолчанию `-Oz` + LTO, 2026-11-21: около 150 KB на
загрузку (brotli: `index.wasm` 108 KB, `index.js` 40 KB). Проекты без `"module"` остаются RTS-проектами.

`"icons"` и `"splash"`: иконки игры для всех платформ и экран загрузки — см. «Иконки и
заставка» ниже (старый единственный `"icon"` по-прежнему работает как основная иконка).

Необязательный `"graphics"`: бэкенд RHI на Windows, Linux и Android — `"gl"` (по умолчанию) или `"vulkan"`,
либо по платформам `{"windows": "vulkan", "android": "gl"}`. Если на машине нет драйвера, Vulkan откатывается на GL;
`--gfx` и `AIVERSE_GFX` переопределяют значение (docs/vulkan.md). macOS / iOS используют Metal, веб — WebGL2.

Необязательный блок `"window"`: как открывается окно игры на десктопах (macOS, Windows, Linux; на телефонах и
планшетах всегда полноэкранный режим, веб-сборка заполняет страницу). Редактор: **Сборка → Окно игры** (окно «Сборка»).

```json
"window": { "mode": "windowed", "width": 1280, "height": 720, "minWidth": 960, "minHeight": 540,
            "keepAspect": false, "allowFullscreen": true, "macos": { "mode": "fullscreen" } }
```

| ключ | значение |
|---|---|
| `mode` | `windowed` (по умолчанию: обычное окно с изменяемым размером), `fixed` (ровно `width` × `height`, без изменения размера и разворачивания), `maximized` (вся рабочая область рабочего стола, но всё ещё окно), `fullscreen` (macOS: нативный полноэкранный режим в собственном Space; Windows / Linux: окно без рамки поверх монитора) |
| `width`, `height` | размер содержимого в пунктах (1280 × 720); также размер после выхода из полноэкранного / развёрнутого режима |
| `resizable` | только для windowed (true); `"mode": "fixed"` равнозначен `false` |
| `minWidth`, `minHeight` | наименьший размер при изменяемом размере (0 = без ограничения) |
| `keepAspect` | изменение размера сохраняет соотношение `width : height` |
| `allowFullscreen` | F11 (Windows, Linux), Alt+Enter (Windows) и зелёная кнопка (macOS) переключают полноэкранный режим (true) |
| `macos`, `windows`, `linux` | объекты с любыми из ключей выше, переопределяющие их на этой платформе |

Запуски с `AIVERSE_EXIT_AFTER_FRAMES` (скриншоты, CI) и `--size WxH` остаются оконными с запрошенным размером.
Код: `engine/platform/WindowSettings.h` (парсер, проверки), поля окна в `AppConfig`, `AppCallbacks::configure`.

Необязательный блок `"ui"`: как смешивается внутриигровой UI (документы RmlUi).
`"ui": {"blend": "linear"}` заставляет полупрозрачный UI смешиваться в линейном свете, как в проекте Unity с линейным цветовым пространством
(блёклые иконки, затемнения, свечения и мягкие края поверх более светлой графики получаются светлее, чем по умолчанию); `"srgb"` (по умолчанию,
также при отсутствии блока) смешивает значения в кодировке sRGB, побайтно идентично сборкам без ключа. В линейном режиме
цвета вершин (цвета CSS, `opacity`, вершинные градиенты) и изображения декодируются в линейный свет (изображения предумножаются
в линейном свете и загружаются как sRGB-текстуры), атласы шрифтов остаются покрытием (только альфа), UI смешивается в собственный
слой в кодировке sRGB, и один полноэкранный проход накладывает его на сцену в линейном свете (пропускается, если UI ничего
не рисует). GPU без sRGB-целей рендера молча остаются на значении по умолчанию. Код: `engine/ui/UiColor.h` (кривые, ключ),
`UiLinear.*` (слой + композиция, GLSL и MSL), RHI `PixelFormat::RGBA8_sRGB`, `Device::copyColor`.

Необязательный блок `"camera"` (2D-игры, см. «2D-игры» ниже):
`{"projection": "ortho", "pitch": 90, "yaw": 0, "fov": 43, "zoom": 20, "zoomMin": 8, "zoomMax": 40, "pixelsPerCell": 32, "rotate": false}`.
Блок может начинаться с пресета (`{"preset": "overhead-pixel"}`; список: [camera-behaviors.md](camera-behaviors.md)).

Необязательный `"playerColors"`: `[neutral, slot 1, ..., slot 8]` (синтаксис цвета оверлеев: `"#rrggbb"`, `[r, g, b]` 0..1 или
0..255; `null` оставляет слот как есть) заменяет встроенную палитру игроков, используемую для командных цветов, оверлеев и
цвета оверлея территории по умолчанию (`RtsOverlayData::configurePlayerColors`, применяется при старте матча в клиенте и редакторе).

Блок освещения (`"lighting"` в game.json / карте), ключи для плоской графики: `"day": {"sun", "sky", "ground", "fog": [r, g, b],
"sunK": k}` заменяет поля дневной палитры (пресета или рендерера), `"night"` (те же ключи) — ночную
палитру / палитру лунного света (`sunK` 0..1: сила луны, чтобы тени оставались различимыми ночью), `"fogDensity"` (0 = без дистанционного тумана),
`"tonemap": false` (освещённые шейдеры обрезают значения вместо аппроксимации ACES; при `sunK` 0 и белых sky / ground неосвещённый материал
показывает свой цвет без изменений), `"modelOutput": "srgb"` (шейдеры моделей кодируют линейный результат точной кривой sRGB,
как в проекте Unity с линейным цветовым пространством, вместо принятого в движке по умолчанию sqrt, при котором полутона темнее; GLSL
и MSL). Ключи карты важнее ключей игры.

Необязательный `"editor": {"hierarchy": {...}}`: как дерево мира редактора (Hierarchy / Inspector «Детали») показывает
объекты этой игры — `previewTicks` (сколько тиков после setup выполняется предпросмотр в режиме редактирования, по умолчанию 2), `label` (ключ `game.data(h)`,
дающий имя строки), `categories` (теги в порядке приоритета: категория объекта), `groupings` (`[{"title", "by": [keys]}]`,
ключи `owner`, `type`, `kind`, `category`, `origin`, `region`, `parent`, `tag`, `component`, `data:<key>`). Читает его только
редактор. Подробности: docs/editor-world-tree.md § Game hooks.

См. «Компьютерный игрок» |

## Разделение rules.json

Большая игра не держит всё в одном `rules.json`. Загрузчик собирает правила из нескольких
файлов и позволяет записям наследовать общие базы (`engine/data/JsonCompose.h`). Симуляция в любом случае видит один
документ: те же результаты, те же контрольные суммы, старые однофайловые игры загружаются без изменений.

**`include`** — дополнительные файлы, пути относительно файла, который их перечисляет (внутри папки игры):

```json
// rules.json
{"include": ["rules/resources.json", "rules/units.json", "rules/abilities.json"],
 "supplyCap": 200, "victory": "noStructures"}
// rules/units.json (may include further files itself)
{"types": {"footman": {...}, "archer": {...}}, "include": ["heroes.json"]}
```

- Объекты верхнего уровня (`types`, `techs`, `resources`, `ai`, ...) сливаются по ключам; массивы верхнего уровня
  (`playerAbilities`, `triggers`, ...) дописываются в порядке чтения (сначала собственное содержимое файла, затем его включения, в глубину);
  скаляры (`supplyCap`) задаются один раз.
- Записи сохраняют порядок чтения, а порядок `types` — часть игры (типы нумеруются в нём): перенос
  типов между файлами в другом порядке — это другая игра для реплеев и сетевых матчей.
- Ключ или элемент массива с `"id"`, определённый в двух файлах, — ошибка с указанием обоих (`rules/b.json: 'types.knight' is
  already defined in rules/a.json`); то же для цикла включений, отсутствующего файла и пути за пределами папки игры.
- Всё читает собранные правила: клиент, сетевой хост, headless, реплеи, `aiversebuild`, редактор.
  Хеши данных сети и реплеев охватывают все включённые файлы. Пакеты поставляют включённые файлы, как любые другие данные.
- Редактор и MCP правят правила как единый документ (`rules_get` / `rules_set` / `rules_merge`); при сохранении каждая
  запись пишется обратно в файл, откуда пришла, а неизменённые файлы не трогаются. Новая запись попадает в файл, где
  находится предыдущая запись её коллекции (новый тип оказывается рядом с другими типами). `rules_get` возвращает
  `files`, если правила разделены; `game_file_write` отказывается писать файлы правил (используйте операции правил).

**`extends` / `abstract`** — запись коллекции верхнего уровня (член объекта записей, например
`types`, `techs`, `statuses`, или элемент массива с `"id"`, например `playerAbilities`) начинается как копия своей
базы (баз) в той же коллекции; её собственные ключи кладутся сверху. Объекты сливаются по ключам, всё остальное (числа, строки,
массивы) заменяется. Записи с `"abstract": true` — только базы: они удаляются до загрузки (не являются типами, не попадают
в палитру игры в редакторе).

```json
"types": {
  "_infantry": {"abstract": true, "health": {"max": 420, "armor": 2}, "move": {"speed": 2.6, "radius": 0.4},
                "sight": 8, "cost": {"gold": 135, "time": 15, "supply": 2}},
  "footman":   {"extends": "_infantry", "name": "Footman", "weapons": [{"id": "sword", "range": 0.6, "damage": 12, "cooldown": 1.2}]},
  "spearman":  {"extends": "_infantry", "name": "Spearman", "health": {"armor": 1}, "weapons": [{"id": "spear", "range": 1.2, "damage": 10, "cooldown": 1.4}]}
}
```

`extends` принимает имя или список (применяется слева направо, затем сама запись); базы могут расширять другие базы.
Неизвестные базы и циклы — ошибки (`types 'knight': extends unknown 'cavalry'`). `rules_get {"resolved": true}`
показывает записи так, как их загружает игра; `rules_lint` проверяет разрешённые записи.

**Уровни — это переопределения.** `levels` способностей и способностей игрока уже сливаются с базовой записью (объекты —
по ключам, массивы одинаковой длины — поэлементно): пишите только то, что меняется на уровне,
`"levels": [{"cooldown": 37.5, "effects": [{"duration": 5.5}]}]`, никогда не полную копию способности.

## resources

```json
"resources": {
  "gold":   {"name": "Золото", "start": 500},
  "ore":    {"name": "Руда", "field": true, "regrow": 0.5, "cellMax": 100},              // Red Alert / Dune: harvested from map fields
  "metal":  {"kind": "flow", "start": 500, "storage": 1000},                               // Total Annihilation: income/expense per second, capped by storage
  "power":  {"kind": "capacity", "deficitProduction": 0.5, "deficitDisables": ["defense"]},// Red Alert power: provided vs consumed
  "spice":  {"capped": true, "storage": 1000},                                             // Dune silos: stock limited by storage
  "coins":  {"global": true, "start": 100},                                                // with "storage": "buildings": not a good, stays player-wide
  "ore2":   {"field": true, "convertsTo": {"credits": 4}}                                  // delivered ore is credited as 4 credits each
}
```
Виды: `stock` (по умолчанию: собирается/зарабатывается, тратится), `flow` (посекундный доход из `income`, тратится во время
строительства в прогрессивном режиме; при 0 и отрицательном доходе производство замедляется на `deficitProduction`),
`capacity` (сумма `provides` минус `consumes`; дефицит замедляет производство и отключает типы с
любым тегом из `deficitDisables`).

## Движение и тела

`"move": {"speed": 2.8, "radius": 0.4, "mass": 0.64, "layer": "ground", "maxSlope": 1.6}`

- `maxSlope` (только рельеф на карте высот): самая крутая клетка, на которую может зайти этот тип (подъём на клетку); по умолчанию
  `terrain.maxSlope` его слоя. Не более 15 разных значений на игру.

- `radius` — реальный размер тела (в клетках): юниты держатся на расстоянии `r1 + r2`, дальность оружия и способностей измеряется
  от края до края (`range` + оба радиуса, у строений — по их площади застройки), а пути сохраняют зазор от стен и
  зданий для тел больше половины клетки (узкие проходы стоят дороже; ничего не становится недостижимым).
- `mass` (по умолчанию `4 * radius²`) решает, кто уступает при перекрытии тел. Юниты, которые сражаются, удерживают
  позицию или работают (собирают, строят, копают), заякорены (x8) и почти не сдвигаются; движущиеся юниты (x2)
  отталкивают стоящих (x1) в сторону. Мёртвая зона 0.03 клетки и ограничение толчка за тик убирают дрожание.
- При `movement.avoidance: "rvo"` движущиеся юниты обходят друг друга с помощью взаимных скоростных препятствий
  (ближайшие `neighbors`, детерминированный порядок). Стоящих на пути союзников просят уступить: они отходят на свободную соседнюю
  клетку и возвращаются, когда путь свободен, так что юнит может пройти через щель между стоящими юнитами; юниты, заблокированные заякоренными,
  перестраивают путь в обход них.
- `movement.avoidance: "none"` отключает ORCA и разделение мобильных тел — для игр, где позиции задаёт
  Lua-логика построений. Это не отключает поиск пути по рельефу и бой. Сохраняйте
  реальные положительные радиусы тел; не имитируйте этот режим радиусами, близкими к нулю.
- Юниты ближнего боя (range < 2), атакующие цель, выбирают свободный слот на кольце вокруг неё (слоты по углу, занимаются
  отдельно для каждой цели, ничьи — по индексу сущности) и обходят уже сражающихся союзников вместо того, чтобы протискиваться в
  первый ряд; юниты дальнего боя останавливаются и стреляют. Группа, получившая атаку с движением, разворачивается дугой, фланги которой идут впереди.
- **Поля потока** (`movement.flowField`, выключены, пока игра или карта их не включит; docs/pathfinding.md): большие группы и
  орды используют одно общее поле интеграции на целевую область вместо отдельного поиска пути на каждый юнит.

  ```jsonc
  "movement": {"flowField": {"minGroup": 12,     // move / attack-move / patrol / right-click orders of >= 12 units (0 = never)
                             "minCells": 0,      // ... only for units at least this many cells from the goal (0 = all)
                             "waves": true,      // units released by map waves and lane waves march on fields
                             "spread": 0.4,      // goal area radius = 0.3 + spread * sqrt(units) (they arrive spread out)
                             "maxFields": 64, "budgetMB": 32}}   // cache: LRU of unreferenced fields beyond these
  ```
  Карта может содержать тот же блок (`"movement": {"flowField": {...}}` на верхнем уровне карты), чтобы включить поля
  только для себя (например, `templates/lastcolony/maps/horde_plain.json`, `templates/planets/maps/big_planet.json`).
  Летающие продолжают лететь напрямую; юниты, вытолкнутые с поля или многократно застрявшие, откатываются на собственный путь A*.
  Последователи располагаются вокруг цели изнутри наружу (заражение прибытием) и не блокируют друг друга.
- `movement.blockedGoals: "nearest"` (правила или карта, по умолчанию `"search"`): пути к цели внутри строения или препятствия
  (атака здания) заканчиваются в ближайшей к юниту свободной клетке вокруг него — намного дешевле для орд; клетки отличаются
  от классического поиска, поэтому это включается явно (включено в `templates/lastcolony/maps/horde_plain.json`).
- `movement.pathfinding: "navmesh"` (правила или карта, по умолчанию `"grid"`): пути юнитов на плоских картах берутся из
  навигационной сетки движка (`engine/nav`, docs/navmesh.md): проходимые клетки каждого слоя путей сливаются в прямоугольники, A* работает по
  ним, а funnel стягивает коридор в путь под любым углом (меньше точек маршрута, на ~7% короче путей по сетке в 8 направлениях,
  дёшево на картах 1024x1024). Обрывы, пандусы, склоны и строения учитываются; запросы, на которые сетка не может ответить (старт или цель
  вне сетки, недостижимые цели, пути с окружением союзников), используют поиск по сетке, как прежде. Планеты сохраняют сетку / HPA*.
  Точки маршрута отличаются от сетки, поэтому это включается явно.
- `movement.pathfinding: "hybrid"` (правила или карта): один граф порталов на карту (кластеры HPA* 16x16, при любом размере
  карты) и решатель на кластер — прямоугольники navmesh в открытых кластерах, A* по сетке в кластерах-лабиринтах (больше
  `movement.hybrid.mazeRatio` прямоугольников на клетку, по умолчанию 0.15: `"hybrid": {"mazeRatio": 0.15}`). Длинные маршруты идут
  по графу, участки используют решатель своего кластера, результат стягивается (string-pulling); поля потока используют тот же граф кластеров.
  Для больших или смешанных карт (города, пещеры, лабиринты рядом с открытой местностью); измерьте карту командой `aiverse_headless --bench-nav N`
  (docs/navmesh.md § Which solver where).
- `movement.airOverRock: false` (по умолчанию `true`): летающие ограничены открытыми клетками — землёй и водой — поэтому они
  следуют по туннелям, как все остальные, вместо пересечения невыкопанной породы и `#` (`MapGrid::airSolid`; их пути
  ищутся как у пеших, строения и юниты их по-прежнему не блокируют). Игры-подземелья (`underlord`).

## types — блоки

```json
"footman": {
  "name": "Пехотинец", "tags": ["infantry", "bio"],
  "health": {"max": 420, "armor": 2, "armorType": "heavy", "regen": 0},
  "move": {"speed": 2.8, "radius": 0.4, "layer": "ground"},          // layer: ground | air | naval | sand (sand: can't enter rock/ramps)
  "sight": 8,
  "weapons": [{"id": "sword", "range": 1.0, "minRange": 0, "damage": 12, "cooldown": 1.2,
               "targets": ["ground"], "projectileSpeed": 0, "splash": 0, "damageType": "normal"}],
  "cost": {"gold": 135, "time": 18, "supply": 1},
  "requires": ["barracks", "tech_id"],
  "xp": 20, "bounty": {"gold": 5}, "score": 1
}
```

| блок | значение |
|---|---|
| `structure` | `{"footprint": [w, h], "on": "geyser", "takesOverNode": true, "terrain": "rock"\|"creep"\|"any", "extendsBase": true}` — `on`: строится точно на объекте этого типа (очистительный завод на гейзере, экстрактор TA на месторождении металла); `takesOverNode` наследует его ресурс |
| `invulnerable` | не получает урона (деревья, шахты, декорации) |
| `collider` | `true`: сущности карты этого типа — статические круги (`move.radius`, слой типа), а не юниты: без затрат ECS, без модели. Пешие считают их препятствиями ORCA и никогда в них не заходят, разделение выталкивает перекрывающиеся юниты, герои с видом сверху и машины останавливаются о них, как о любое никогда не движущееся тело. Для тысяч невидимых столбиков / скамеек / клумб. Нужен `move.radius`, без `structure`; не для объектов, которые скрипты запрашивают или повреждают (`modules/rts/RtsColliders.h`) |
| `energy` | `{"max": 200, "regen": 0.5, "start": 50}` — мана для способностей |
| `abilities` | список, см. «Способности» |
| `hero` | `{"levels": [200, 500, 900], "perLevel": [{"stat": "maxHp", "add": 50}, {"stat": "damage", "add": 0.1}]}` — получает опыт от убийств поблизости; уникален для игрока |
| `unique` | не больше одного на игрока |
| `squad` | `{"members": 4, "reinforceCost": {"manpower": 25}, "reinforceTime": 4}` — отряды Company of Heroes: запас hp делится между членами, урон масштабируется по числу живых членов |
| `supply` | предоставляемое снабжение (фермы, дома, оверлорды) |
| `income` | `{"metal": 2, "energy": -5}` в секунду, пока достроено (и не отключено) |
| `storage` | `{"metal": 500}` повышает лимиты |
| `provides` / `consumes` | ресурсы ёмкости: `{"power": 100}` |
| `produces` | типы, которые оно обучает; **перечисленные здесь строения строятся в стиле Command & Conquer** (боковая панель: произвести, затем разместить командой Place) |
| `builds` | строения, которые может возводить рабочий |
| `researches` | id технологий |
| `upgrades` | типы строений, в которые оно может превратиться на месте (уровни L1 → L2) |
| `buildMode` | `walk` (по умолчанию: строитель строит; несколько строителей складываются), `warp` (Protoss: запускает стройку и уходит), `morph` (Zerg: строитель становится строением) |
| `buildPower` | множитель скорости строителя |
| `gather` | `{"gold": {"carry": 10, "time": 2}}` — что он собирает (узлы или поля); ресурсы потока (утилизация TA) зачисляются напрямую |
| `resourceNode` | `{"resource": "gold", "amount": 12000, "ownerOnly": false}` — `amount` < 0 = бесконечно (фермы); `ownerOnly`: собирать может только владелец (очистительный завод, ферма) |
| `dropoff` | ресурсы, принимаемые при возврате: `["gold", "wood"]` |
| `charges` | `{"max": 3, "interval": 11}` — личинки: параллельное производство, один заряд на единицу |
| `warpIn` | `{"field": 0, "time": 5}` — варп-врата (StarCraft II): команда обучения с флагом `kCmdAtPoint` (MCP `play_command` `"atPoint": true`) сразу ставит юнит в `point` в состоянии постройки, и он достраивается через `time` секунд вместо времени постройки. Точка должна находиться внутри своего `powerField` с этим id, быть проходимой для юнита и видимой; стоимость оплачивается сразу (только `costModel: upfront`). Сочетайте с `charges` (`{"max": 1, "interval": 20}`) для перезарядки врат. Команды обучения без флага ставятся в очередь как обычно |
| `creep` | радиус распространяемой слизи (строениям с `"terrain": "creep"` она нужна) |
| `fieldSpawner` | `{"resource": "ore", "rate": 10, "radius": 3}` — выращивает вокруг себя поле ресурса (рудник, всплеск специи) |
| `deploysTo` | юнит → строение (MCV → Construction Yard) |
| `wreck` | `{"metal": 100}` — оставляет тип `"wreck"` (определите его с `resourceNode`) для утилизации |
| `sellable` | по умолчанию true для строений |
| `garrison` | `{"max": 20, "unit": "mushroomling", "interval": 1.0, "capturable": true, "defense": 1.0, "decay": 1.0}` — Mushroom Wars: выращивает юниты внутри, отправляет их по дорогам |
| `entersGarrison` | юниты, которые по прибытии вливаются в гарнизоны или штурмуют их |
| `capture` | `{"time": 10, "radius": 3, "victoryPoint": false, "region": false}` — контрольная точка: захватывается стоянием рядом; `victoryPoint` списывает вражеские тикеты; `region` переворачивает свой регион и захватываемые строения в нём (флаги Z) |
| `neutral` | `{"leash": 10, "wander": false, "wanderRadius": 20}` — нейтральные монстры (владелец -1) возвращаются домой за пределами поводка; бродяги бродят (песчаный червь Dune) |
| `waveSpawn` | `{"unit": "trooper", "count": 2}` — выпускает юниты по `waveClock`; они атакуют с движением к базе врага |
| `worker` | подсказка для ИИ/UI (по умолчанию: есть gather или builds) |
| `key` | потеря всех ключевых объектов означает поражение в режимах `keyUnits`/`score` (командир, штаб) |
| `countsForVictory` | переопределение |
| `score` | очки команде убийцы (победа по очкам) |
| `view` | только представление: форма или модель, материалы, клипы, процедурная анимация (docs/models.md) |
| `sprite` | только представление: рисовать тип из листа спрайтов (2D-игры, см. ниже) |

Характеристики, доступные в модификаторах: `maxHp`, `armor`, `damage` (множитель), `range` (прибавка), `speed`, `sight`,
`gatherRate` (множитель; также скорость копания/захвата/работы, псевдоним `workRate`), `attackSpeed` (множитель),
`productionSpeed` (множитель скорости обучения/исследования/autoTrain у производителя).

Ещё блоки типов (управление подземельем и территория, см. раздел ниже):

| блок | значение |
|---|---|
| `digs` | `{"rate": 2}` — рабочий копает клетки, отмеченные владельцем (твёрдость в секунду); простаивающие копатели сами находят работу |
| `claimer` | `{"time": 0.5}` — рабочий идёт к ничейным клеткам рядом со своей территорией и захватывает их (секунд на клетку, x2 для вражеских клеток); при `territory.fortify` он также укрепляет породу рядом со своим полом |
| `claim` | `{"radius": 1.5, "rate": 2}` — юнит обращает клетки вокруг себя (клеток в секунду): только клетки, касающиеся своей территории, и никогда, пока на них стоят враждебные юниты (линия фронта войны за территорию) |
| `claimedByTerritory` | `true` — нейтральное строение (портал) присоединяется к игроку, владеющему территорией рядом с ним |
| `capturable` | `true` — при `territory`: строение переходит к тому, кто владеет землёй под его центром |
| `portal` | `{"interval": 20, "pool": ["goblin"]}` — нанимает одно привлечённое существо за интервал (пустой пул: каждый тип с `attractedBy`), до предела снабжения |
| `attractedBy` | `{"rooms": {"lair": 1, "library": 9}, "resources": {"gold": 500}, "weight": 1}` — когда портал может нанять этот тип (клетки комнат во владении, запас), выбор по весу |
| `needs` | потребности и мораль существ, см. ниже |
| `autoTrain` | `{"unit": "soldier", "interval": 4}` — строение непрерывно производит юниты, пока позволяет предел населения (оплачивает стоимость юнита, если она есть); они атакуют с движением к ближайшему фронту (ближайшая не своя клетка, касающаяся своей территории, иначе ближайший враг или точка сбора) и продолжают давить, когда простаивают |

### Способности

```json
"abilities": [
  {"id": "storm", "name": "Буря", "target": "point", "range": 9, "cooldown": 12, "energy": 75, "level": 1, "autocast": true,
   "effects": [{"type": "damage", "amount": 80, "radius": 2, "damageType": "magic", "affects": "enemies"}]},
```

## Карты

Компьютерный игрок на слот: `players[i].ai` = `{"preset": "rush", "firstAttackArmy": 3, ...}` — пресет (`easy`,
`normal`, `hard`, `rush`, `defender`, `economist`), затем любой параметр `ai` из правил (`workersPerBase`, `firstAttackArmy`,
`armyGrowth`, `maxAttackArmy`, `towers`, `scouts`, `invasionSize`, `climbWeight`, `exposureWeight`,
`escalateSeconds`, `terrain`), плюс `thinkTicks` (1..3600, время реакции) и `aggression` (0.1..4). Порядок: значения бота
по умолчанию, `ai` из правил, пресет слота, ключи слота. `"ai": true` (маркер компьютерного слота, который пишут импортёры) означает отсутствие переопределений. Неизвестные ключи и значения вне диапазона
приводят к ошибке загрузки `map players[i].ai...`. Меняются только решения, никогда характеристики; карты без этого блока играются точно как прежде. MCP:
`player_set {player, ai}`.

```json
{
  "name": "River Valley", "size": [64, 48],
  "players": [{"name": "Blue", "team": 1, "faction": "terran", "start": [8, 24], "resources": {"gold": 800}},
              {"name": "Zombies", "team": 9, "waves": true}],
  "terrain": {
    "rows":   ["....~~~~....", "..."],      // one char per cell: . ground ~ water # blocked , no-build = shallow / ramp R rock
    "levels": ["000011110000", "..."],      // cliff level per cell 0..9; units change level only over / ramps
    "heights": [0, 0, 16, ...],             // optional fine visual height per cell (1/16 units)
    "corners": [0, 0, 16, ...]              // optional heightfield: (w+1)*(h+1) corner heights, 1/16 units, row-major
    // or, for big maps: "cornersFile": "maps/<name>.r16"   raw int16 little-endian, (w+1)*(h+1) values
  },
  "fields": [{"resource": "ore", "rows": ["0000999000", "..."]}],   // density digits 1..9 of cellMax (or {"center": [x,z], "radius": 3})
  "regions": {"rows": ["AAAABBBB", "..."], "names": {"A": "Долина", "B": "Холмы"}},
  // entity keys: "facing": degrees clockwise on screen from north (0 north, 90 east = default, 180 south, 270 west)
  "entities": [{"type": "townhall", "owner": 1, "pos": [9, 24]}, {"type": "goldmine", "owner": 0, "pos": [6, 16], "amount": 8000},
               {"type": "ogre", "owner": -1, "pos": [32, 10]}],     // owner: 0 neutral, 1..N players, -1 hostile creeps
  "roads": [["base_a", "village_1"]],                                 // by entity id (Mushroom Wars)
  "roadsOnly": false,
  "areas": {"relic": [26, 4, 4, 4]},                                  // named rectangles [x, z, w, h] for triggers
  "waves": [{"time": 60, "player": 2, "at": [60, 24], "spread": 3, "spawn": [{"type": "zombie", "count": 10}],
             "every": 45, "growth": 1.3, "repeats": 10}],
  "victory": {"mode": "survive", "seconds": 900},                     // overrides rules.victory
  "rules": {"topDown": {"escape": null}},                              // per-map overrides of rules blocks (below)
  "triggers": []
}
```

### Переопределения правил на карте (`rules` карты)

Карта может переопределить настроечные блоки правил для своих матчей: `"rules": {"<block>": {...}}` сливается поверх rules.json
до того, как что-либо его разберёт (`modules/rts/RtsMapRules.cpp`), поэтому каждый блок проверяет объединённый результат со своими обычными
ошибками. Объекты сливаются по ключам (рекурсивно); любое другое значение — числа, строки, списки, например таблица опыта, —
заменяет значение из правил; `null` удаляет ключ (`"escape": null` отключает побег на этой карте).

```json
"rules": {
  "topDown": {"escape": {"cooldown": 45}, "squad": {"fireWhileMoving": true}, "bot": {"orbRange": "weapon"}},
  "raid": {"duration": 300, "pickupRadius": 2},
  "progression": {"offerAt": "summonPoints", "xp": {"toNext": [10, 20, 35]}, "pauseOnOffer": true},
  "encounters": {"mobs": {"zombie": {"aggroRange": 12}}, "preferTags": ["cargo"]}
}
```

Переопределяемые: `topDown.{respawn, move, aim, abilities, squad, escape, autoFire, bot}` (не `heroes`/`input`: они решают,
кем управляют и как квантуются команды), блоки `raid`, `progression` и `encounters` целиком. Любой другой
блок (types, resources, abilities, ...) — ошибка: `map rules.types: this block cannot be overridden per map
(allowed: ...)`. Собственный блок `raid` карты (точки, цели по id) и `progression.summonPoints` по-прежнему применяются поверх.

## audio.json

Только представление: ничего отсюда не попадает в симуляцию. Отсутствие файла или аудиоустройства означает просто
отсутствие звука. Неправильная структура — ошибка (`audio: sound 'x': unknown bus 'drums'`); отсутствующий или
недекодируемый звуковой файл, неизвестный ключ, тип, оружие или имя звука — предупреждение, и молчит только
этот звук.

```json
{
  "volume": {"master": 1, "sfx": 0.9, "ui": 0.7, "voice": 1, "music": 0.6, "ambient": 0.7},
  "spatial": {"minDistance": 10, "maxDistance": 55, "airAbsorption": 1500, "speedOfSound": 150,
              "reverb": {"size": 0.6, "damping": 0.45, "wet": 0.4, "near": 0.04, "far": 0.65}},
  "groups": {"melee": {"max": 6}, "ui": {"max": 3, "bus": "ui", "steal": "oldest"}},
  "sounds": {
    "swing": {"files": ["sfx/swing1.ogg", "sfx/swing2.ogg"], "pitch": [0.9, 1.1], "maxInstances": 4, "cooldown": 0.05, "group": "melee"},
    "alarm": {"file": "voice/under_attack.ogg", "bus": "voice", "priority": 10},
    "blip":  {"synth": {"wave": "square", "freq": [880, 440], "duration": 0.08}, "bus": "ui"},
    "boom":  {"file": "sfx/boom.ogg", "minDistance": 14, "maxDistance": 80, "far": {"sound": "boom_far", "from": 0.25}},
    "boom_far": {"file": "sfx/boom_far.ogg", "maxDistance": 120, "air": 0.5}
  },
  "music": {
    "menu":  "music/menu.ogg",
    "match": {"files": ["music/a.ogg", "music/b.ogg"], "shuffle": true, "loop": true, "volume": 0.8},
    "battle": ["music/fight.ogg"]
  },
  "events":    {"died": "death", "underAttack": "alarm", "notEnough": "need_more", "notEnough.gold": "need_gold"},
  "weapons":   {"sword": {"attack": "swing", "hit": "clang"}, "bow": {"attack": "bow", "hit": "arrow_hit"}},
  "abilities": {"storm": "thunder"},
  "types":     {"footman": {"select": "footman_what", "move": "footman_yes", "died": "death_human",
                            "weapons": {"sword": {"hit": "clang_heavy"}}, "abilities": {"roar": "roar"}}}
}
```

`volume`: уровень микса для каждой шины, 0..4 (по умолчанию 1); собственные настройки громкости игрока умножаются поверх
(модель данных клиента: `volume` master, `music`, `sfx` = все шины, кроме музыки, в процентах; `musicOn` / `sfxOn` 1 / 0 выключают
шину, не меняя её громкость; сохраняется в audio.cfg в папке пользователя).

`"scripted": true`: музыкой и звуками UI управляют скрипты игры (таблица `sound`, docs/scripting.md § Sound):
клиент никогда сам не проигрывает плейлисты `menu` / `match` / `battle` / `victory` / `defeat`, а начало или
выход из матча останавливает только голоса на шине `sfx`.

### spatial — 3D-звук и расстояние

Позиционные звуки размещаются в 3D вокруг слушателя (RTS-клиент ставит ухо на луче обзора
над точкой фокуса камеры; юниты на обрывах и летающие находятся выше). Расстояния — в мировых единицах
(клетках карты). При отдалении камеры ухо поднимается, поэтому битва звучит дальше; слышимая область
растёт как квадратный корень из масштаба.

| ключ | значение |
|---|---|
| `model` | кривая расстояния: `inverse` (по умолчанию, естественная), `linear`, `exponential` |
| `minDistance`, `maxDistance` | полная громкость до min, тишина на max (12, 60); последние 20 % диапазона всегда затухают |
| `rolloff` | крутизна кривой (1) |
| `airAbsorption` | Гц фильтра нижних частот на максимальном расстоянии: дальние звуки теряют высокие частоты (2500; `false` = выкл.) |
| `reverb` | `false` или `{"size": 0.5, "damping": 0.5, "wet": 0.35, "near": 0.05, "far": 0.6}` — `near` / `far` = посыл в реверберацию на min / max расстоянии: дальние звуки становятся объёмнее и теряют атаку |
| `speedOfSound` | мировых единиц в секунду; дальние звуки приходят с опозданием (0 = выкл.; не более 3 с) |
| `rear` | 0..1: источники позади слушателя становятся глуше и немного тише (0) |

Ключи расстояния (`model`, `minDistance`, `maxDistance`, `rolloff`) — значения по умолчанию для каждого звука;
звук может их переопределить и добавить множители `air` / `reverb` (ниже).

### sounds

| ключ | значение |
|---|---|
| `file` / `files` / `synth` | ровно один из них. Файлы: WAV, OGG Vorbis, MP3, FLAC, пути относительно папки игры; `files` = вариации, при каждом проигрывании случайная, никогда одна и та же дважды подряд |
| `bus` | `sfx` (по умолчанию), `ambient`, `voice`, `ui`, `music` |
| `spatial` | затухает и панорамируется вокруг камеры, если у события есть позиция; по умолчанию true для `sfx` / `ambient`, иначе false (объявления слышны везде) |
| `volume` | 0..4 (1) |
| `pitch` | число или `[min, max]`, случайно при каждом проигрывании (1) |
| `maxInstances` | не больше стольких экземпляров этого звука одновременно (4; 0 = без ограничения); `steal` решает, кто освобождает место |
| `steal` | для `maxInstances`: `farthest` (по умолчанию), `oldest`, `quietest`, `none` — см. «groups» |
| `group` | имя группы или массив до 4: ограничения, общие с другими звуками (см. «groups») |
| `cooldown` | секунд между двумя запусками (0) — 40 лучников, стреляющих разом, дают несколько звуков, а не 40 |
| `chance` | вероятность (0..1, по умолчанию 1), что проигрывание вообще начнётся — реплики и фоновые звуки, которые не должны звучать каждый раз; пропущенное проигрывание не запускает перезарядку |
| `priority` | -100..100 (0): когда все голоса заняты, останавливается самый низкий приоритет (сначала самый старый); новый звук ниже всего играющего отбрасывается |
| `loop` | зацикливается до остановки (false) |
| `model`, `minDistance`, `maxDistance`, `rolloff` | переопределяют значения `spatial` по умолчанию: мелкие звуки (шаги, мечи) затухают рано, взрывы слышны далеко |
| `air` | множитель поглощения воздухом, 0..4 (1; 0 = сохраняет высокие частоты на любом расстоянии) |
| `reverb` | множитель посыла дистанционной реверберации, 0..4 (1; 0 = всегда сухой) |
| `duckMusic` | 0..1: музыка приглушается на эту долю, пока звучит звук (0.4 на шине `voice`, иначе 0) |
| `sync` | `now` (по умолчанию), `beat`, `bar`: запуск по сетке музыки (стингеры) |
| `compress`, `quality` | кодек для файлов этого звука при сборке (см. «Сжатие при сборке») |
| `far` | дальний вариант: `"boom_far"` или `{"sound": "boom_far", "from": 0.3}` — оба звучат вместе с плавным переходом от `from` (доля диапазона расстояний этого звука) до максимального расстояния; дальний звук сохраняет свои расстояния, поэтому может быть слышен дальше (низкий гул вместо треска) |

`synth` — звук, создаваемый из параметров вместо файла (прототипы, плейаблы); объект или
массив слоёв, которые смешиваются:

| ключ | значение |
|---|---|
| `wave` | `sine` (по умолчанию), `square`, `saw`, `triangle`, `noise` |
| `freq` | Гц или `[start, end]` для экспоненциальной развёртки (440); для `noise` — частота зерна |
| `duration` | секунды, 0.001..10 (0.2) |
| `attack`, `release` | секунды нарастания / затухания (0.005, min(0.1, duration)) |
| `volume` | 0..4 (1) |
| `duty` | ширина прямоугольного импульса 0.02..0.98 (0.5) |
| `vibrato` | `[rate Hz, depth]`, глубина как доля частоты |
| `lowpass` | частота среза в Гц (выкл.) |
| `crush` | оставить только N бит, 1..15 (выкл.) |
| `delay` | секунд до начала этого слоя (0) |

### groups

Ограничения, общие для нескольких звуков, чтобы большая битва оставалась различимой: шесть мечей, ударивших одновременно,
звучат как схватка, шестьдесят — как шум, и они заглушают важные звуки.

```json
"groups": {
  "melee":      {"max": 6},
  "missiles":   {"max": 6, "cooldown": 0.02},
  "explosions": {"max": 4},
  "deaths":     {"max": 4, "steal": "quietest"},
  "ambient":    {"max": 5, "bus": "ambient"}
}
```

| ключ | значение |
|---|---|
| `max` | звуков группы одновременно (0 = без ограничения, только `cooldown`) |
| `cooldown` | секунд между двумя запусками любого звука группы (0) |
| `steal` | кто освобождает место, когда группа заполнена (ниже; по умолчанию `farthest`) |
| `bus` | каждый звук этой шины принадлежит группе: ограничение на шину |

Звуки присоединяются через `"group": "melee"` (или `["melee", "loud"]`: место должно быть в каждой группе).
Вариации (`files`) — это один звук; звук с вариантом `far` считается один раз, и его дальняя половина
останавливается вместе с ним.

| `steal` | при заполнении |
|---|---|
| `farthest` | останавливается звук, самый дальний от слушателя; новый звук дальше всех играющих не запускается — бой за кадром никогда не обрывает бой в кадре. Непозиционные звуки: самый старый |
| `oldest` | останавливается звук, запущенный первым |
| `quietest` | останавливается звук, который сейчас тише всех (громкость содержимого, измеренная при загрузке, громкость, шина, расстояние); новый звук тише всех них не запускается |
| `none` | ничего не останавливается: новый звук не запускается |

Играющий звук с более высоким `priority`, чем у нового, никогда не останавливается ради него; если
вся группа важнее, новый звук не запускается. Остановка происходит с затуханием за несколько мс (без щелчка).

### music

Музыка потоково читается из файлов (рекомендуется OGG Vorbis); смены выполняются с плавным переходом. Плейлисты, которые клиент
проигрывает по имени, все необязательны: `menu`, `match`, `battle` (заменяет `match`, пока рядом с камерой идёт
тяжёлый бой, возвращается после ~15 с затишья), `victory`, `defeat`. Плейлист с именем
`match.<map>` (имя файла карты без расширения, например `match.valley`) важнее `match` на этой
карте; то же для `battle`, `victory`, `defeat`.

```json
"music": {
  "menu":  "music/menu.ogg",
  "match": {"files": ["music/a.ogg", {"file": "music/b.ogg", "loopStart": 12.0}], "shuffle": true,
            "bpm": 96, "beatsPerBar": 4, "transition": "bar"},
  "match.valley": {"layers": [{"file": "music/valley_base.ogg"},
                              {"file": "music/valley_drums.ogg", "intensity": 0.3},
                              {"file": "music/valley_brass.ogg", "intensity": 0.7}],
                   "loopStart": 4.0, "loopEnd": 68.0, "bpm": 112}
}
```

Плейлист — это имя файла, массив записей или объект:

| ключ | значение |
|---|---|
| `files` | записи, проигрываемые по порядку: имя файла или `{"file", "loopStart", "loopEnd"}` (секунды). С `loopStart` трек один раз играет вступление, а затем бесшовно зацикливается от `loopStart` до `loopEnd` (по умолчанию: до конца), пока музыка не сменится |
| `layers` | адаптивная музыка вместо `files`: синхронизированные стемы одинаковой длины, зацикленные вместе (`loopStart` / `loopEnd` на плейлисте). Слой с `"intensity": x` плавно появляется, когда интенсивность музыки превышает x; в матче интенсивность следует за боем рядом с камерой, поэтому многослойный `match` нарастает, а не переключается на `battle` |
| `shuffle`, `loop` | перемешать записи (без немедленных повторов) / начать заново после последней (false, true) |
| `volume` | 0..4 (1) |
| `bpm`, `beatsPerBar`, `offset` | сетка долей (`offset`: секунд до первой доли); используется `transition` и синхронизированными стингерами |
| `transition` | переключение с этого плейлиста ждёт следующей `beat` или `bar` (по умолчанию `bar`, если задан `bpm`, иначе `now`) |

Стингеры — это звуки на шине `music`: `"sync": "beat"` или `"bar"` запускает их по сетке играющей
музыки. Любой звук может приглушать музыку, пока звучит: `"duckMusic": 0.5` снижает её вдвое
(по умолчанию 0.4 для шины `voice`, чтобы объявления всегда были слышны; иначе 0).

### Сжатие при сборке

`aiversebuild` перекодирует используемые файлы звуков и музыки для каждой цели перед упаковкой; папка
проекта никогда не меняется. Профили: `desktop` (macOS, Windows, Linux), `mobile` (iOS,
Android), `web`. `--audio mobile` принудительно задаёт профиль, `--audio off` поставляет файлы как есть;
`aiverse_audiopack --project <game> --profile mobile` показывает, что сделал бы профиль.

```json
"build": {
  "desktop": {"sounds": "keep", "music": "vorbis", "musicQuality": 0.6},
  "mobile":  {"sounds": "adpcm", "music": "vorbis", "musicQuality": 0.3, "maxRate": 32000},
  "web":     {"musicQuality": 0.25}
}
```

| ключ | значение |
|---|---|
| `sounds`, `music` | кодек: `keep` (файл как есть), `pcm` (16-битный WAV), `adpcm` (IMA ADPCM WAV: 4:1, декодирование почти бесплатно — короткие эффекты), `vorbis` (OGG: музыка, длинные звуки) |
| `soundQuality`, `musicQuality` | качество Vorbis -0.1..1 (0.5 / 0.4; mobile 0.4 / 0.3, web 0.4 / 0.25) |
| `maxRate` | передискретизировать всё, что выше этой частоты (0 = никогда; mobile и web 32000) |
| `monoSounds` | позиционные звуки становятся моно: микшер всё равно их панорамирует (true) |
| `longSound` | секунды: более длинные звуки (фоновые петли, стингеры) используют музыкальный кодек (8) |
| `reencodeLossy` | перекодировать также файлы, уже являющиеся OGG/MP3 (false: перекодирование с потерями в формат с потерями только ухудшает качество) |

Значения по умолчанию без секции `build`: `desktop` сохраняет всё как есть; `mobile` и `web` используют ADPCM для
звуков и Vorbis для музыки на 32 кГц. Звуки на шине `music` считаются музыкой. Звук или
плейлист может переопределить это через `"compress"` и `"quality"`. Перекодированные файлы получают расширение
своего кодека, и audio.json в сборке указывает на них; результат, который не меньше исходного, сохраняет
оригинал. Точки петель остаются точными (Vorbis точен до сэмпла; ADPCM дополняет петлю её собственным началом).

### events, types, weapons, abilities

Какой звук играет на каком игровом событии («сигнал», cue). Поиск для объекта: его запись в `types`, затем его
оружие / способность по id в `weapons` / `abilities`, затем `events`.

| сигнал | когда | кто слышит |
|---|---|---|
| `attack` | оружие стреляет (сначала `weapons.<id>.attack`) | все, кто видит это место |
| `hit` | урон нанесён (сначала `weapons.<id>.hit` типа стрелявшего) | все, кто видит это место |
| `miss` | выстрел промахнулся (вверх по склону) | все, кто видит это место |
| `died` | объект погибает (`types.<id>.died`) | все, кто видит это место |
| `spawned` | объект появляется | все, кто видит это место |
| `ability` | применена способность (сначала `abilities.<id>`) | все, кто видит это место |
| `captured` | игрок захватывает здание / точку; для остальных: кто-то захватил что-то в поле зрения | владелец |
| `lost` | здание / точку игрока захватили | прежний владелец |
| `trainStarted`, `ready` | производство начато / юнит готов | владелец |
| `buildPlaced`, `buildDone` | стройка размещена / завершена | владелец |
| `readyToPlace`, `sold`, `upgraded`, `researched`, `levelUp`, `regionClaimed`, `lowPower`, `gathered` | по названию | владелец |
| `notEnough`, `notEnough.<resource>` | не хватает средств (сначала специфичный для ресурса) | владелец |
| `notEnoughSupply`, `noRoom` | предел снабжения / нет места для автоматической постройки (запасные варианты: `notEnough`, `error`) | владелец |
| `underAttack`, `baseUnderAttack` | враг атакует юнит / строение игрока там, куда не смотрит камера; не чаще раза в 12 с | владелец |
| `select` | игрок выбирает свой юнит (`types.<id>.select`) | игрок |
| `move`, `attackOrder`, `buildOrder` | игрок отдаёт приказ (запасной вариант: `move`) | игрок |
| `victory`, `defeat`, `playerDefeated` | конец матча / другой игрок выбыл | игрок |
| `wave` | начинается скриптовая волна | все |
| `message` | сообщение триггера | его адресаты (все — для сообщения всем) |
| `click`, `error` | интерфейс | игрок |

«Все, кто видит это место» учитывает туман войны; наблюдатель слышит все звуки мира и не слышит
сигналов, адресованных только игроку.

## Управление подземельем и территория

О линиях фронта, управляемых из Lua, см. [Кисти территории и скриптовые построения](scripting.md#territory-brushes-and-scripted-formations).
Необязательный визуальный блок `terrain.territory` также поддерживает `smooth: true` (по умолчанию false),
`transition` (0..2 секунды, по умолчанию 0.2) и `lift` (0..2 мировых единицы, по умолчанию 0.045).
На плоских картах сглаженный режим фильтрует владение компактным биномиальным ядром, восстанавливает его билинейно, применяет мягкий порог контура
и интерполирует изменившиеся клетки в течение `transition` секунд. Он использует существующий конвейер мешей RHI
и на Metal, и на GL; качество материалов выбирает 4 подразделения на клетку (medium/high) или 2 (low).
Память тумана учитывается. Прежняя квадратная отрисовка территории/пола комнат остаётся по умолчанию;
сглаженный режим предназначен для поверхностей территории и не рисует оттенки пола комнат. Визуализация планет сохраняет
свой существующий рендерер. Подсчёты, проверки захвата и победа по-прежнему используют точное владение из симуляции.
Шейдер Metal наземных оверлеев использует общий блок освещения `LightU` (совпадающий с раскладкой U2 в GLSL);
старые сборки ссылались на устаревший тип MSL `U2` и молча теряли весь слой.
Сбои шейдеров/конвейеров теперь выводят ошибку бэкенда в stderr.

```json
"diggable": {"D": {"hardness": 3}, "G": {"hardness": 6, "yields": {"gold": 250}}, "J": {"hardness": 8, "yields": {"gold": 40}, "infinite": true}},
"territory": {"claimBy": "both", "startFromRegions": false, "startRadius": 3, "buildOnlyOwned": true},
"rooms": {
  "lair":     {"name": "Логово", "cost": {"gold": 10}, "supply": 1},
  "hatchery": {"cost": {"gold": 12}, "income": {"food": 0.05}},
  "treasury": {"cost": {"gold": 15}, "storage": {"gold": 500}},
  "library":  {"cost": {"gold": 20}, "income": {"research": 0.02}, "work": {"yields": {"research": 1}}},
  "training": {"cost": {"gold": 20}, "work": {"xp": 3, "cost": {"gold": 0.5}}}
},
"hand": {"max": 8, "ownTerritoryOnly": true, "slapDamage": 5, "slapDuration": 10, "slapSpeed": 1.5, "slapWork": 1.5},
"possession": {"cost": {"mana": 100}, "drain": {"mana": 2}}
```

- **Копаемый рельеф**: символы карты, перечисленные в `diggable` (один символ, не `. ~ # , = / R` и не цифра), — это
  твёрдые клетки. Игроки отмечают клетки командой копания; простаивающие рабочие с `digs` копают отмеченные клетки рядом с землёй, до которой
  могут дойти; клетка становится землёй (пути обновляются), и начисляется `yields` (`infinite`: жила остаётся).
- **Укреплённые стены** (`territory.fortify: {"time": 2.5}`, секунд на клетку; `"fortify": 2.5` тоже работает): простаивающие
  рабочие `claimer`, когда копать или захватывать больше нечего, укрепляют копаемую породу, 4-смежную со своим полом, превращая её в стены
  своего хранителя (`MapGrid::wall` = слот владельца, рисуется цветом владельца с рядами кладки). Никто другой не может
  отметить или прокопать такую стену — врагу сначала нужно захватить пол за ней: стена, которая больше не касается
  пола своего хранителя, в течение секунды снова становится простой породой (и затем её может укрепить тот, кто владеет полом).
  Хранитель прокапывает собственные стены как обычно. `diggable.<char>.fortifiable` (по умолчанию: true для простой породы, false
  для клеток с `yields` или `infinite`) указывает, какую породу можно укреплять. Событие `fortified` (value = клетка, player
  = новый владелец, 0, когда стена пала). Dungeon Keeper: бесы ИИ-хранителя делают это сами.
- **Территория** (слой владельца по клеткам, `MapGrid::territory`; `GameState::territoryCells[slot]` / `territoryTotal`
  для доли в HUD): начинается из `"territory": {"rows": ["..11..", ...]}` карты (цифры = слоты игроков), из принадлежащих
  регионов (`startFromRegions`) и `startRadius` клеток вокруг стартовых строений и стартовых точек. Захватывается
  рабочими `claimer` и/или юнитами с `claim` (`claimBy`: `workers`, `units`, `both`). `buildOnlyOwned`: каждая
  клетка площади застройки должна быть своей территорией. Потеря клетки удаляет нарисованную на ней комнату.
- **Комнаты** рисуются на своей территории (команда рисования с прямоугольником); `cost` — за клетку. Эффекты масштабируются по
  общему числу клеток этого типа у игрока: `supply` (вместимость существ), `income`, `storage`, `provides` на клетку; `work`
  зарабатывается за каждое существо, работающее внутри (`yields` в секунду, `xp` в секунду для типов с уровнями `hero`, `cost`
  в секунду). Рисование поверх другой комнаты заменяет её; стирание возвращает `sellRefund`.
- **Потребности существ** (`needs` у типа):
  ```json
  "needs": {"hunger": {"interval": 60, "room": "hatchery", "time": 4, "cost": {"food": 1}},
            "sleep": {"interval": 90, "room": "lair", "time": 8},
            "pay": {"interval": 120, "amount": {"gold": 50}},
            "works": ["library", "training"], "workTime": 10,
            "happiness": {"start": 1, "unmetPerSecond": 0.01, "recovery": 0.005, "slap": 0.1, "unpaid": 0.3, "leaveBelow": 0.2, "leaveAfter": 30}}
  ```
  Потребность становится активной через `interval`; простаивающее существо идёт к ближайшей своей комнате этого типа и остаётся там
  `time` секунд (оплачивая `cost`; сон лечит). В день выплаты списывается `amount`; невыплаченное жалованье, шлепки и неудовлетворённые потребности
  снижают счастье; ниже `leaveBelow` в течение `leaveAfter` секунд существо уходит через свой портал.
  Простаивающие существа работают в комнатах `works` (ИИ может забрать их с работы на бой).
- **Рука**: поднимать свои юниты (`max` в руке, вне карты: без приказов, без боя), опускать их на видимую свою
  клетку территории; шлепок: `slapDamage` (никогда не убивает), бафф скорости/работы на `slapDuration`, счастье снижается.
- **Вселение**: одним юнитом на игрока управляют напрямую (вектор направления за тик, кнопка огня); ИИ
  его игнорирует; `cost` однократно, `drain` в секунду (освобождается, когда не хватает средств).

## Экономика поселенцев (Knights and Merchants)

```json
"storage": "buildings",
"roadNetwork": {"cost": {"stone": 1}, "speed": 1.5},
"types": {
  "storehouse": {"structure": {"footprint": [3, 3]}, "storehouse": {"capacity": 2000}},
  "woodcutter": {"structure": {"footprint": [2, 2]}, "recipe": {"out": {"wood": 1}, "time": 10, "from": "wood", "radius": 8}, "cost": {"planks": 3, "stone": 2}},
  "sawmill":    {"structure": {"footprint": [2, 2]}, "recipe": {"in": {"wood": 1}, "out": {"planks": 2}, "time": 8, "buffer": 2}},
  "farm":       {"structure": {"footprint": [3, 3]}, "recipe": {"out": {"grain": 1}, "time": 12}},
  "serf":       {"move": {"speed": 3}, "carrier": {"capacity": 1}},
  "soldier":    {"trainFrom": "recruit", "cost": {"sword": 1, "armor": 1, "time": 6},
                 "needs": {"hunger": {"interval": 120, "at": "inn", "time": 3, "cost": {"food": 1}, "starve": 1}}}
}
```

- При `"storage": "buildings"` каждый ресурс `stock`, не помеченный `global`, — это **товар**: он хранится в
  инвентарях зданий. Запас товара у игрока — это сумма по его **складам** (`storehouse.capacity` = общий объём
  товаров); оплата забирает товары со складов, доход и награды кладутся на них. Стартовые товары (`start`
  ресурса, `resources` игрока на карте) попадают в первые склады; сущности карты могут нести `"inventory": {"wood": 5}`.
- **Рецепты**: рабочее место расходует `in` из собственного инвентаря и кладёт туда `out` каждые `time` секунд
  (действуют стат `productionSpeed` и питание); оно держит запас входов на `buffer` циклов и останавливается, когда
  ждут вывоза `buffer` циклов продукции. У добывающих зданий нет `in`; `from` + `radius` истощают ближайший узел
  ресурса или клетку поля этого ресурса (дерево из деревьев, камень из карьера, рыба из водных полей).
- **Носильщики** (`carrier.capacity` за ходку) возят по запросу, детерминированно (каждые 0,5 с, здания в порядке
  сущностей): сначала стройплощадки и входы рабочих мест (источник: выход рабочего места, иначе ближайший склад),
  затем выходы рабочих мест на ближайший склад со свободным местом. При `roadNetwork.required` источник и
  получатель должны касаться одной дорожной сети.
- **Строительство**: товары из `cost` постройки не оплачиваются сразу; носильщики доставляют их на площадку, и
  прогресс постройки не может превысить доставленную долю (строители всё равно строят). Прочие ресурсы
  оплачиваются заранее.
- **Дороги**: символ карты `+`, команда road (прямоугольник) или команда connect (симуляция прокладывает
  кратчайший путь от постройки до дорожной сети своего склада). Движение по клеткам дороги в `speed` раз быстрее.
- **Новобранцы**: `trainFrom` расходует свободную свою единицу этого типа в пределах 15 клеток от производителя.
- **Еда**: потребности с `"at": "<structure type>"` удовлетворяются в ближайшей своей постройке этого типа
  (стоимость берётся из запаса); пока потребность активна, теряется `starve` hp в секунду.

## Линии (Mushroom Wars 2)

`"lanes": {"left": 4, "right": 2, "spacing": 0.35}`: для каждой пары зданий-гарнизонов симуляция находит путь A*
в обход препятствий и других зданий, сглаживает его в сплайн Катмулла–Рома с фиксированной точкой (примерно два
отсчёта на клетку) и добавляет `left` + `right` параллельных линий на расстоянии `spacing` клеток (там, где они
задели бы препятствие, линии подтягиваются к главной). Отправленные юниты распределяются по линиям по кругу и
точно идут по своей линии. Линии перестраиваются при изменении зданий-гарнизонов или препятствий
(`GameState::lanes`, `lanesDirty`, событие `kEvLanesChanged`).

## Маршруты, группы, мультиэкран

Заданные вручную маршруты между гарнизонами, отправка рядами и окно игры размером с экран поверх большей карты
(`modules/rts/RtsRoutes*.cpp`). Длины — в клетках карты; каждое число — ключ правил / карты, который задаёт игра.

**`routes` карты** (если они есть на карте, они заменяют сгенерированные линии и включают `lanes`):

```json
"routes": [
  {"from": "village_1", "to": "base_a",                  // entity ids (or "#<index>" into "entities"), both garrisons
   "points": [[13.98, 2.62], [12.44, 2.2], {"at": [2.2, 4.58], "offsets": [0,0,0,0.2,0,0,0,0], "zone": 2, "slowdown": 1.5}, [1.74, 5]],
   "lines": [[[13.98, 2.62], [11.47, 1.92], ...], ...],  // optional raw nodes per line
   "blockers": ["rock_3"],                               // the route is closed while any of them is alive
   "towersCoverage": [{"point": "p7", "distances": [0, 0, 0.5, 1.2, 3.4]}],
   "flying": false}                                      // uses the fly column padding
]
```

- Каждый маршрут превращается в `lanes.routes.lines` линий: линия k идёт по своим сырым узлам, если их не меньше
  двух, иначе по контрольным точкам со смещением колонны k на внутренних точках (чётные линии слева, нечётные
  справа; 0,5, 1,5, 2,5 колонны `columnPadding` плюс `offsets[k]` точки); между точками — Катмулл–Ром со `smooth`
  узлами. При `trim` > 0 узлы ближе `trim` к обоим концам отрезаются (линии начинаются и кончаются чуть в стороне
  от точек). Линии сохраняют направление маршрута (`Lane::a` = `from`), смещения -1, +1, -2, +2... в порядке линий
  (`lanesBetween` возвращает линию 0 первой). Линии существуют весь матч (индексы стабильны).
- Для отправки нужен открытый маршрут: `kCmdSend` между гарнизонами без маршрута игнорируется; это сообщают
  `RtsModule::canSend` / `routeLength` (линия 0) / `routeAiLength` и Lua `game.can_send(a, b)` /
  `game.route_length(a, b)`. Закрытый маршрут (жив блокер) только отказывает в новых отправках; юниты, уже идущие
  по нему, продолжают путь. Встроенный ИИ отправляет только по маршрутам.
- Каждая линия проходится с прогрессом линии 0 (скорость линии x длина k / длина 0), поэтому ряд держится вровень
  на поворотах.
- Юниты на пересекающихся или общих маршрутах сами друг с другом не сражаются; навык может заставить идущих
  стрелять через `RtsModule::routeWalkerTargets` (враждебные идущие в эллипсе / переднем секторе, ближайшие
  первыми) и `routeWalkerDistances` (пройдено / осталось по линии). Идущие — обычные сущности юнитов с `LaneWalker`.
- Маршрута между сущностями, чьи `screenGroups` (ключ сущности карты, список целых) не совпадают, не существует:
  два пустых совпадают, один пустой — нет, иначе — любая общая группа.
- `zone` (биты, задаваемые игрой, 2 = замедление) / `slowdown` для точки влияют только на `routeAiLength`.
- `towersCoverage` (для компьютерных игроков): для каждой сущности-башни — длина маршрута внутри её радиуса для
  радиусов 0, 1, 2 ... x `routes.coverageStep` (не более 21 значения, последнее действует и дальше).
  `RtsModule::towerCoverage` интерполирует; `towerUnitsDamage` / `towerDamageBySpline` оценивают потери группы,
  проходящей мимо неё.
- Идущие получают случайное диагональное смещение (`routes.jitter`, одна выборка `sim.rng()` на юнит), которое
  нарастает на протяжении `routes.fade` от обоих концов маршрута; то же затухание — непрозрачность юнита в
  отображении (`SceneObject::fade`, `routeAlpha`).
- **Отправка по воздуху**: гарнизон со статусом с флагом `flying` отправляет по прямому воздушному маршруту,
  создаваемому при первом использовании для этой пары (точки входа / выхода `routes.inOut` от концов, колонны
  `flyColumnPadding`), даже там, где наземного маршрута нет или он закрыт; ряды идут через `flyRowSpacing`.
  `groups.flyAll`: такая отправка забирает весь гарнизон; `groups.flySingle`: одна воздушная группа на гарнизон
  одновременно. Это сообщает `RtsModule::sendsFlying(from)`.

**Правила** (все необязательные, внутри `"lanes"`):

| ключ | по умолчанию | |
|---|---|---|
| `routes.lines` | 6 | параллельных линий на маршрут = юнитов в ряду (1..8) |
| `routes.columnPadding` / `flyColumnPadding` | 0.5 / 1.125 | расстояние между колоннами |
| `routes.trim` | 0.25 | отрезается с обоих концов каждой линии |
| `routes.smooth` | 10 | узлов сплайна между контрольными точками |
| `routes.inOut` | 2.5 | воздушные маршруты: прямой участок на обоих концах |
| `routes.jitter` / `routes.fade` | 0.125 / 0.5 | смещение идущего / длина затухания на концах |
| `routes.coverageStep` | 1.25 | шаг радиуса для `towersCoverage` |
| `groups` | выкл. | `true` или `{"rowSpacing": 1.75, "flyRowSpacing": 3, "flyAll": false, "flySingle": false}` |

**Группы** (`lanes.groups`): отправка создаёт группу (`GameState::routes.groups`, id = `GroupTag`), которая выпускает
ряд до `lines` юнитов, по одному на линию, каждый раз, когда ряд впереди прошёл `rowSpacing` (первый ряд выходит
сразу). Гарнизон платит за каждый ряд (юниты остаются дома и обороняют его, пока не выйдут). Вторая отправка по
тому же маршруту и с той же стороны, пока группа открыта, сливается с ней (need = min(need + n - spawned, garrison) + spawned).
Группа закрывается, когда она укомплектована, когда гарнизону не хватает на полный ряд или когда
источник меняет владельца (остальные остаются дома). Без `groups` отправка работает как прежде (`pendingOut`, по
два за тик).

**`screen` карты**:

```json
"screen": {"size": [68, 38], "center": [34, 19], "bounds": [0, 20, 0, 0], "smooth": 10}
```

Игровое окно поверх большей карты: `size`, стартовый `center` (по умолчанию центр карты), `bounds` = [left, right,
top, bottom] — насколько центр может сместиться от старта (top = в сторону -z). Гарнизоны за пределами экрана не
растут; `RtsModule::onScreen` публичен (King of the Hill и Domination используют его, когда нет зон игроков). Карта
без `screen`, но с `mapScroller.screen` окружения использует этот экран для тех же проверок (`onScreen`,
`screenView`, `setScreenCenter`, Lua); если есть оба, скроллер двигает `screen` карты. Скрипты:
`game.set_screen(x, z)` (с ограничением), `game.screen()` -> x, z, w, h, `game.on_screen(x, z)`. Камера клиента следует за центром (`smooth` в секунду) и
меняет масштаб так, чтобы был виден весь экран. Центр экрана, группы, смещения идущих и концы маршрутов сохраняются и хешируются.

**Редактор / MCP**: `route_list`, `route_set` (добавить / заменить маршрут; точки, смещения, линии, блокеры; без
точек — прямой маршрут с точками входа / выхода), `route_delete`, `route_generate` (прямые маршруты между каждой
парой гарнизонов или в пределах `maxDistance`), `screen_set`; вид Scene рисует линии каждого маршрута (линия 0 ярче).

## Наложения на рельеф (визуальный блок `terrain`)

Только отображение (`modules/rts/view/RtsGroundFx.*`): вид читает слои территории, раскопок, комнат и дорог, а
также линии, и никогда их не записывает. Все ключи необязательны; поместите их в `terrain` в rules.json или
game.json (game.json имеет приоритет поблочно; ключи симуляции вроде `model` живут в том же блоке). Любой блок может
быть `false`, чтобы выключить наложение. Цвета — `[r, g, b]` (0..1) или `"#rrggbb"`. Пути `texture` проходят через
`TextureCache::resolve` (атласы работают); текстура накладывается в мировых координатах с периодом `textureScale`
единиц и смешивается с силой `textureStrength` (0..1).

```json
"terrain": {
  "territory": {"fill": 0.28, "border": 0.26, "glow": 0.85, "pulse": true, "colors": [[0.2,0.45,0.95], "#e83a33"],
                "rooms": {"lair": [0.62,0.32,0.22]}, "roomFill": 0.5, "texture": "terrain/floor.png", "textureScale": 2},
  "dig":       {"height": 1.15, "mark": [1,0.8,0.22], "progress": true,
                "kinds": {"D": {"rock": [0.4,0.35,0.3]}, "G": {"style": "vein", "vein": "#f9c238"}, "J": {"style": "gem", "vein": [0.35,0.85,0.95], "glow": 0.55}}},
  "lanes":     {"color": [0.74,0.63,0.44], "edge": [0.5,0.4,0.27], "alpha": 0.75, "width": 0, "sideLanes": false, "all": false},
  "roads":     {"color": [0.72,0.63,0.48], "edge": [0.4,0.33,0.24], "width": 0.7, "alpha": 0.96, "cobbles": true, "texture": ""}
}
```

| Блок | Что рисуется | Ключи |
|---|---|---|
| `territory` | цвет владельца на его клетках, светящаяся (на высоком качестве пульсирующая) граница по краям между владельцами, раскрашенные комнаты как оттенок пола | `fill` — прозрачность, `border` — ширина (в клетках), `glow` — свечение, `pulse`, `colors` по слотам игроков начиная с 1 (по умолчанию цвета игроков), `rooms` — оттенок по id комнаты, `roomFill` — прозрачность, `texture*` |
| `dig` | копаемые клетки как приподнятые каменные блоки со стенками (рельеф под ними остаётся плоским и открывается после раскопки); `style` для каждого копаемого символа: `plain`, `vein` (верх с золотым оттенком, самородки, прожилки на стенках), `gem` (светящиеся кристаллы). Стиль по умолчанию: без `yields` — plain, с `yields` — vein, `infinite` — gem. Метки раскопок локального игрока (подсветка в рамке) и прогресс раскопки (трещины + полоса) | `height` 0.2..1.25, цвет `mark`, `progress`, `kinds.<char>`: `rock`, `vein`, `style`, `glow` |
| `lanes` | линии (правила `lanes`) как одна мягкая лента пути на пару соседних зданий (пара пропускается, если между ними стоит третье здание), `roads` карты между зданиями как ленты | `color`, `edge`, `alpha`, `width` (0: покрывает все линии пары), `sideLanes` — тонкие колеи для каждой линии, `all` — рисовать каждую пару |
| `roads` | клетки дорог (`+` карты, постройка `roadNetwork`) как дорожное покрытие с краями, стыками, перекрёстками, скруглёнными углами и тупиками; брусчатка на высоком качестве | `color`, `edge`, `width` 0.2..1, `alpha`, `cobbles`, `texture*` |

То, что видит игрок, подчиняется туману войны: территория, комнаты, скала и дороги обновляются только там, где
клетка видна (в остальных местах запоминаются). Слабые GPU (`MaterialQuality::Low`; для проверки:
`AIVERSE_GROUNDFX=low`) не получают пульсации границы, геометрии жил/кристаллов (вместо неё оттенок), фасок скал,
краёв дорог, брусчатки и колей линий. Поверх 2D-карт из тайлов наложения не рисуются.

## Способности игрока

```json
"playerAbilities": [
  {"id": "nuke", "name": "Ядерный удар", "cost": {"money": 500}, "cooldown": 60, "target": "point",
   "effects": [{"type": "damage", "amount": 200, "radius": 3}]},
  {"id": "drone", "cost": {}, "cooldown": 5, "charges": {"max": 2, "rearmCost": {"money": 100}, "rearmTime": 20},
   "effects": [{"type": "damage", "amount": 60, "radius": 1.5}, {"type": "stun", "duration": 2, "radius": 1.5}]}
]
```
Не привязаны к юниту. Эффекты — это эффекты способностей (любой эффект, кроме `blink`; см. «Способности и эффекты»).
Заряды восстанавливаются по одному за `rearmTime` с оплатой `rearmCost`. ИИ применяет их по скоплениям врага.

## Способности и эффекты

Всё, что делает навык, — это список **эффектов** (*полезная нагрузка*). Эффекты могут нести собственную нагрузку
(`"effects": [...]`): снаряд доставляет её при попадании, область применяет при срабатывании, цепь — на каждом
прыжке, статус — на каждом тике, оружие — при попадании. Навыки — это композиции этих примитивов; ничего не
программируется под отдельный навык. Все ключи ниже необязательны; игра, не использующая ни одного из них,
работает в точности как прежде (побитово одинаковые реплеи).

### Способности (юнита) и способности игрока

```json
{"id": "barrage", "name": "Ракетный залп", "target": "point", "range": 10, "cooldown": 8, "energy": 40,
 "cost": {"gold": 25}, "initialCooldown": 3, "castTime": 0.5, "backswing": 0.3, "charges": 2,
 "requires": ["rocketry"], "level": 1, "autocast": true, "smart": "densestEnemy",
 "delivery": {"type": "projectile", "speed": 10, "arc": true, "arcHeight": 3, "scatter": 1.2},
 "effects": [{"type": "damage", "amount": [20, 30], "radius": 1.5, "falloff": 0.5}],
 "levels": [{"cooldown": 7, "effects": [{"amount": [30, 40]}]}, {"cooldown": 6, "effects": [{"amount": [40, 55]}]}]}
```

| ключ | значение |
|---|---|
| `target` | `none`, `self`, `unit`, `point`, `structure` (постройка, например гарнизон), `group` (юниты, отправленные вместе, на линии), `player` |
| `cost` | ресурсы (помимо `energy`); способности игрока используют только `cost` |
| `cooldown`, `initialCooldown` | секунды; стат `cooldownRate` ускоряет перезарядку |
| `charges` | способности юнита: N зарядов, один восстанавливается за `cooldown` (способности игрока: `{"max", "rearmCost", "rearmTime"}`) |
| `castTime`, `backswing` | замах перед эффектом (событие `kEvCastStart`; оглушение / немота / новый приказ отменяют его) и время, которое заклинатель остаётся занят после; способности игрока: `castTime` = задержка активации |
| `requires` | типы / технологии, которые должны существовать (способности, выдаваемые деревом технологий) |
| `level` | нужный уровень героя; `levels`: таблица для уровней 2, 3, ... — каждая запись переопределяет ключи способности (эффекты сливаются по индексу). Способности юнита используют уровень героя, способности игрока — уровень набора |
| `smart` | правило выбора цели для автоприменения / автонавыков / ИИ: `auto`, `lowestHpAlly`, `densestEnemy`, `strongestEnemyStructure`, `weakestOwnStructure`, `ownStructureUnderAttack`, `largestEnemyGroup`, `self`, `enemyPlayer`, `debuffedOwn` |
| `delivery` | как эффекты попадают к цели: `instant` (по умолчанию), `projectile`, `area` (отложенная / постоянная), `chain`, `channel`, `line`, `cone` (см. ниже) |
| `levels`, `aura`, `radius` | как прежде (`aura`: пассивное усиление вокруг владельца) |

Способности игрока принимают также `passive: true` + `status` (всегда действующий статус игрока, например бонусы
дохода), `autoEvery` (секунды: применяется сама по своей умной цели — навыки карты / таймера), а карты выдают
каждому игроку **набор**: `"players": [{"loadout": ["freeze", {"id": "nuke", "level": 3}]}]`
(без набора доступна любая способность игрока; `rules.loadoutSlots` ограничивает их число).
Триггеры могут применять их: `{"type": "castAbility", "ability": "storm", "at": [20, 8], "free": true}`.

### Доставка

| `delivery.type` | ключи | |
|---|---|---|
| `projectile` | `speed`, `homing`, `arc` + `arcHeight` (баллистика), `collide` (поражает первого врага на пути), `scatter` | нагрузка применяется при попадании (поражённый юнит — цель); используется сущность `Projectile` (`effList` / `effIndex` сообщают виду, какая это способность) |
| `area` | `delay`, `lifetime`, `interval`, `trigger` (`once`, `periodic`, `contact` + `maxTriggers`), `motion` (`static`, `toward`, `lane`, `wander`, `follow`) + `speed`, `sight` (обзор), `teleportTo` [dx, dz] (портал), `deathSpawn` (ловушка душ) | сущность `Area` (Transform + Area) — метки артиллерии, поля на земле, мины, движущиеся опасности, порталы |
| `chain` | `jumps`, `jumpRadius`, `jumpFalloff` | прыгает к ближайшей ещё не поражённой цели, прошедшей фильтр; величины умножаются на `jumpFalloff` на каждом прыжке |
| `channel` | `duration`, `interval` | повторяется, пока заклинатель стоит на месте; оглушение / немота / движение прерывают его |
| `line`, `cone` | `length`, `width` / `angle` | задаёт форму эффектам, у которых нет собственной формы |

Те же ключи работают внутри эффектов типа `projectile`, `area` и `chain` — так навыки вкладываются друг в друга
(снаряд, оставляющий горящую область, область, сбрасывающая снаряды каждую секунду, ...).

#### Объекты навыков (объекты, порождаемые из юнитов, цели, магниты, души)

Необязательные ключи доставки эффектов `area` / `projectile` и эффект `pull` (`modules/rts/RtsSkillObjects.cpp`):

| ключ | значение |
|---|---|
| `origins` | фильтр целей (`shape`, `radius`, `affects`, `kind`, `inTransit`, `maxTargets`, `sort`, ...): одна область / один снаряд **на каждого выбранного юнита**, начиная с места, где он стоит. Область с `motion: "lane"` продолжает собственную линию этого юнита от его положения и в его направлении (катящиеся камни) |
| `origins.consume` | выбранный юнит превращается в объект: он молча умирает (без эффектов смерти, без душ) |
| `goal` | `point`, `target` (выбранная кликом / сопровождаемая постройка, иначе ближайшая постройка), `groupTarget` / `groupSource` (куда исходный юнит шёл / откуда пришёл), `ownStructure` / `enemyStructure` (ближайшая), `caster`. Области движутся туда (`motion` становится `toward`), останавливаются и завершаются; снаряды наводятся на неё. Области с целью (или с линией и `onArrive`) живут, пока не прибудут |
| `onArrive` | нагрузка, когда область достигает цели или конца своей линии (цель = постройка-цель / постройка в конце линии) |
| `onExpire` | нагрузка, когда время жизни области истекает раньше, чем она прибыла или была израсходована (`maxTriggers`): самоуничтожающиеся мины |
| `onDeath` | нагрузка для каждого юнита, умершего внутри области (точка = место смерти, цель = сопровождаемый объект); `maxTriggers` ограничивает её (сборщик душ) |
| `lifetime: [min, max]` | выбирается ГСЧ симуляции |
| `start: "point"` | снаряд стартует из точки эффекта, а не от заклинателя (души, летящие с места смерти юнита) |

| `type` | ключи | что делает |
|---|---|---|
| `pull` | `goal` (по умолчанию `target`), `speed` (начальная скорость), `accel`, `minSpeed`, `maxSpeed` + фильтр | юниты летят прямо в постройку-цель: скорость += accel x dt с ограничением; по прибытии входят в неё (штурм / подкрепление). Одно особое движение за раз. Магнит: статус постройки с `tick.effects` [`pull` с `radius`] |

```json
{"id": "petrify", "target": "group", "effects": [{"type": "area", "motion": "lane", "speed": 3, "radius": 0.3,
  "origins": {"shape": "group", "consume": true}, "onArrive": [{"type": "garrisonKill", "amount": 2, "affects": "any"}]}]},
{"id": "mines", "target": "point", "effects": [{"type": "area", "trigger": "contact", "maxTriggers": 1, "radius": 0.6, "lifetime": [9, 11],
  "origins": {"radius": 4, "inTransit": true, "consume": true}, "effects": [{"type": "kill", "shape": "target"}]}]},
{"id": "souls", "target": "structure", "effects": [{"type": "area", "motion": "follow", "radius": 4, "lifetime": 30, "trigger": "periodic", "interval": 1000,
  "maxTriggers": 100, "affects": "any", "onDeath": [{"type": "projectile", "start": "point", "goal": "target", "speed": 3,
  "effects": [{"type": "garrisonAdd", "amount": 1, "affects": "own"}]}]}]}
```

Для вида: `Area::goal` / `Area::arrived`, `Pulled` (target, way, vel) у притягиваемых юнитов; события — как у областей / снарядов.

#### Ключи объектов навыков из порта Bunker Wars (этап 2)

Общие ключи, добавленные для порта 1:1 энергетических навыков BW (`docs/bunkerwars-skills.md`); их может
использовать любая игра.

| где | ключ | значение |
|---|---|---|
| эффект | `budget` | не более N целей за всё время жизни области / статуса, в котором работает эффект (BW `maxKills`, Amulet `maxReverseCount`) |
| эффект | `radius: "area"` | радиус области, в которой он работает (растущие области) |
| эффект | `duration: [min, max]` | выбирается для каждой цели |
| эффект | `every` | внутри тика области / статуса: только каждые N с её жизни |
| эффект | `targetChance` | каждая цель сохраняется с этой вероятностью (бросок на каждую цель; BW betrayal `chanceToKill`) |
| эффект `resource` | `levels` (число или `"max"`), `transfer` | изменение по уровням ресурса (звёзды морали, `resources.*.levels`); с `transfer` заклинатель получает фактически отнятые уровни по своей шкале |
| эффект `cooldown` | `slots` | только эти слоты набора |
| эффект `cast` | `stagger` | k-я цель получает нагрузку на k x stagger с позже |
| эффект `cast` | `offsets`, `shuffle`, `shots` | нагрузка срабатывает в фиксированных точках вокруг клика (клетки `[[x, z], ...]`), k-я — через k x stagger, порядок перемешивается один раз, `shots` проходит по ним по кругу (BW blizzard) |
| эффект `swap` | `with` (фильтр: `affects`, `tags`), `swapType`, `effects` | меняет владельца, гарнизон (и тип) со случайной постройкой из `with` (относительно заклинателя); затем `effects` выполняются на обеих |
| эффект `convert` | `effects` | нагрузка на каждого обращённого юнита (цель = он) |
| эффект `garrisonSend` | `percent`, `amount`, `maxPoints`, `runTo` (фильтр относительно владельца постройки) | гарнизон выходит к ближайшим (по длине маршрута) пунктам назначения, по ceil(units / count) в каждый (BW panic) |
| эффект | `defeat`, `closeGroups` | отфильтрованные игроки проигрывают; группы, ещё выходящие из построек, закрываются |
| фильтр | `aspect` | эллипс: радиус по z = radius x aspect (BW `world.aspectRatio`) |
| фильтр | `heading: "to" / "from"` | только юниты, идущие к цели эффекта / покинувшие её |
| фильтр | `affects: "neutral"` | только нейтральные объекты |
| область | `grow` | радиус = `radius` + grow x age (BW `rangeVelocity`) |
| область | `motion: "orbit"`, `orbit {a, b, speed, expand}` | кружит вокруг точки по эллипсу a x b (градусы / с), вырастая до полного размера за `expand` с (торнадо) |
| статус | `spreadChance` | `spreads`: вероятность, что носитель заразит постройку, в которую входит |
| статус | `slots` | немота игрока: только эти слоты набора |
| статус | `onSpawn` | постройка: нагрузка на каждого выпускаемого ею юнита |
| статус | `endOnCapture` | снимается без `onExpire`, когда постройка меняет владельца |
| статус | `command {capture, percent}` | владелец статуса может один раз отправить из постройки; с `capture` юниты становятся его (гипноз) |
| статус | `transfer {grab, fill, speed, percent}` | следующая отправка владельца из неё телепортирует юнитов (grab, путь длиной маршрута / speed, fill) |
| статус | `collect {addPerSecond}` | производство остальных построек владельца идёт в носителя; они вместо этого растут на addPerSecond (BW redirect) |
| статус | `hitCap` | попадания оружия по носителю поглощаются и сокращают оставшееся время до hitCap с (аура смерти) |
| статус | `endWhenEmpty` | постройка: завершается в положенный тик, когда её гарнизон пуст (содержание оплачивается эффектами `tick`) |
| статус | `deathGain {res: n}` | владелец юнита получает это, когда юнит убит или потрачен на штурм (жертва) |
| статус | `stacking: "keep"` | действующий остаётся как есть |
| статус | флаги `untargetable`, `skillImmune` | оружие его не выбирает; фильтры эффектов его пропускают |
| модификатор стата | `lerp`, `floor` | итоговое значение сдвигается к 1 на суммарный lerp; произведение множителей статусов остаётся >= floor |

### Эффекты

Общие ключи: `amount` (число или `[min, max]`, выбираемое ГСЧ симуляции), `percent`, `radius`, `duration`,
`chance`, `damageType`, `falloff` (сплэш: урон на краю = 1 - falloff) и **фильтр целей**:

| ключ фильтра | значение |
|---|---|
| `affects` | `enemies` (по умолчанию для вредных), `allies` (по умолчанию для полезных), `own`, `self`, `all`, `any` (+ нейтральные) |
| `shape` | `target`, `circle` (по умолчанию при `radius`), `line`, `cone`, `ring` (+ ширина `ring`), `map`, `group` |
| `layers` | `["ground", "air", "naval"]` |
| `kind` | `unit`, `structure`, `any`; `garrisons: true` (только постройки-гарнизоны); `inTransit: true` (только юниты, идущие к постройке) |
| `tags`, `ofType`, `level` | теги юнитов, один тип, диапазон уровня постройки `[min, max]` (у типов есть `"level": n`) |
| `sort`, `maxTargets`, `ownFirst` | `nearest`, `farthest`, `lowestHp`, `highestHp`, `levelLow`, `levelHigh`, `garrisonLow`, `garrisonHigh`, `random`; взять первые N |
| `area` | только внутри именованной области карты |

|---|---|---|

Chronosphere: способность игрока с `"target": "pointPair"`; Mass Teleport: способность юнита, `origin: caster`; Strategic Recall: `origin: point`, `destination: caster` |

### Статусы

```json
"statuses": {
  "poison": {"name": "Яд", "tags": ["debuff", "magic"], "tick": {"damage": 4, "interval": 1}, "stacking": "stack", "maxStacks": 5},
  "frost": {"tags": ["debuff", "magic"], "mods": [{"stat": "speed", "mul": 0.6}, {"stat": "attackSpeed", "mul": 0.8}]},
  "aegis": {"tags": ["buff"], "shield": 120, "view": {"color": [0.4, 0.7, 1]}}
}
```

| ключ | значение |
|---|---|
| `tags` | теги статуса для `dispel` (`buff`, `debuff`, `magic`, любое слово) |
| `flags` | `stun`, `silence`, `disarm`, `root`, `invulnerable`, `invisible`, `lock` (нет отправки / производства), `blind`, `hidden` (численность гарнизона скрыта), `flying` (с линии, прямо к цели), `fake`, `ignoreDefense`, `spreads` (отправленные юниты переносят его в постройку, в которую входят — чума), `freezeRegen`, `alert`, `revealed`, `hypnotised` (его заклинатель может один раз отправить из этого вражеского гарнизона: `sendShare`, `captureSent`) |
| `mods` | модификаторы статов на стек (`stat`, `add`, `mul`) — на игроках они действуют на все их объекты (ветер, глобальные бонусы) |
| `tick` | `damage` / `heal` на стек, `interval`, `effects` (нагрузка вокруг носителя: аура смерти, горение) |
| `shield` | поглощает урон (или штурмующих юнитов на гарнизоне); статус заканчивается, когда щит ломается |
| `stacking`, `maxStacks` | `refresh` (по умолчанию), `stack`, `independent` |
| `onExpire`, `onCaptured`, `onHit` | нагрузки: когда он истекает (двухэтапные навыки), когда постройку захватывают (месть), при каждом попадании оружия носителя (зачарованное оружие) |
| `incomeMult` | статусы игрока: `{"mana": 2}` умножает доход + регенерацию |
| `garrisonPerSecond` | постройка: юнитов в секунду (отрицательное: чума) |

Типы могут нести постоянные статусы (`"statuses": ["thorns"]`). Оружие принимает `"onHit": {"chance": 0.3,
"effects": [...]}` (или простой список эффектов) и `"chargeTime"` (заряжаемый выстрел: нужно оставаться на одной
цели). Новые статы: `energyRegen`, `defense` (множитель защиты гарнизона), `garrisonCap`, `cooldownRate`,
`upgradeCost`, `lifesteal`, `damageTaken`, `scale` (вид). Ресурсы принимают `"regen"` (в секунду для каждого
игрока: мана, мораль).

Для вида: `Statuses` (на объект: `list` из `StatusInst` с `def` = индекс в `Rules::statuses`,
`stacks`, `until`, `shield`), статусы игроков в `PlayerEconomy::statuses`, сущности `Area`, `Projectile`
способностей (`effList`), `GroupTag` (id группы юнитов, отправленных вместе). События: `kEvStatusStart` /
`kEvStatusEnd`, `kEvAreaStart` / `kEvAreaTrigger` / `kEvAreaEnd`, `kEvProjectileLaunch`, `kEvImpact`,
`kEvChainJump`, `kEvCastStart`, `kEvChannelStart` / `kEvChannelEnd`, `kEvAlert`, `kEvGarrisonChanged`.

ИИ применяет каждый навык через те же умные цели (лечение — на самого раненого союзника, урон по области — на самую
плотную группу врагов, навыки построек — на сильнейшую вражескую / свою атакуемую постройку, групповые навыки — на
самую большую группу в пути, развеивание — на свои объекты с ослаблениями), держит 20% ресурса с пределом в
резерве и оставляет навыкам с `autoEvery` срабатывать самим.

## Режимы матча (доминирование, царь горы, лимит времени, внезапная смерть, зоны)

Режимы победы на уровне правил и часы матча в виде данных (`RtsModes.cpp`). Каждый блок необязателен; игры без них
сохраняют свои точные контрольные суммы и формат сохранений.

```json
"modes": {
  "points": "garrison",                                     // what a "point" is: structures with a garrison (default) or "structures"
  "conquest": {"team": true},
  "domination": {"hold": 1.5, "rule": "auto", "type": "dom_tower", "garrison": 10},
  "kingOfTheHill": {"score": 300, "teamScore": 300, "rate": 1, "alarm": 100, "type": "koh_tower", "garrison": 10},
  "timeLimit": {"seconds": 120, "win": "maxPoints", "coefficient": 1, "speed": [{"remaining": 30, "speed": 1.5}, {"remaining": 10, "speed": 2}]},
  "suddenDeath": {"at": 300, "preview": 3, "previewSpeed": 0.5, "end": 60, "counter": 5, "status": "sudden_death",
                  "ruleSets": [[{"status": "fast_skills", "when": [{"from": 330, "to": 360}]}], [{"status": "double_income"}]]},
  "zones": {"start": [{"rect": [0, 0, 40, 30], "stay": 60, "move": 20, "next": 0}], "steps": [{"rect": [5, 5, 30, 20], "stay": 9999}],
            "neutralType": "village", "suddenDeathDelay": 30}
},
"matchModes": {"domination": {"modes": {"domination": {"hold": 1.5}}}, "koh": {"modes": {"kingOfTheHill": {}}, "victory": "noEntities"}},
"timedRules": [{"status": "rush", "when": [{"from": 60, "to": 90}, {"every": 30, "duration": 5}]},
               {"status": "underdog", "resource": "morale", "when": [{"levelBehind": 2}]}],
"ruleSets": {"league3": [{"status": "rush"}]},
"matchStats": true
```

Ключи карты: `"modes"` (заменяет ключи правил по одному, `false` выключает режим), `"matchMode": "<preset>"`
(запись `matchModes`, накладываемая поверх `modes` правил; её `victory` применяется, если у карты нет своего),
`"ruleSets": ["league3"]` (именованные наборы правил, включаемые для этого матча, например лобби), у сущности
`"modePoint": "domination" | "kingOfTheHill"` или список обоих (`"modePoint"` может нести и тип). Стороны — это
команды (каждый сам за себя = один игрок в команде; счёт царя горы общий для команды).

| блок | поведение |
|---|---|
| `conquest` | `team: true`: игрок, у которого ничего не осталось, остаётся в матче, пока у товарища по команде есть база (иначе обычный `victory` решает для каждого игрока) |
| `domination` | таймер `hold` точки перезапускается при каждой смене владельца и идёт, пока у неё есть владелец (точки, занятые на старте, начинают с идущим таймером). Когда все точки доминирования заняты (таймеры истекли, нейтральных нет; точки вне зоны или экрана своего владельца пропускаются): `holdAny` — стороны, не владеющие ни одной, выбывают; `holdAll` — побеждает сторона, владеющая всеми. `auto`: `holdAny`, когда в каждой команде один игрок. `type` / `garrison`: чем становятся отмеченные точки, пока режим включён |
| `kingOfTheHill` | каждая сторона начинает со `score` (`teamScore`, когда в команде несколько игроков) и теряет `rate` в секунду за каждую точку царя, которой владеет (внутри своей зоны); первая сторона, дошедшая до нуля, побеждает (наименьший счёт, затем наименьший id команды). Событие на `alarm` |
| `timeLimit` | отсчитывает `seconds` игрового времени; при `remaining` скорость игры становится `speed`. На нуле — по точкам каждой стороны: `maxPoints` — побеждает больше всех, ничья среди лучших — ничья; `compare` — побеждает единственная сторона, у которой points x `coefficient` > лучшего, иначе ничья. Стороны без точек не участвуют |
| `suddenDeath` | на `at` реальных секунд: предпросмотр (`preview` с, скорость игры `previewSpeed`), затем каждый игрок получает `status` (например, модификаторы `incomeMult` и `cooldownRate`). При `end` > 0 сторона с наибольшим числом точек побеждает через `end` с (все равны: ничья; равенство у части сторон: они побеждают, остальные — ничья; итог матча — ничья). За `counter` с до начала / конца включается `ModesState::sdCounter` (экран обратного отсчёта). Один из `ruleSets` выбирается ГСЧ матча и добавляется к `timedRules` (временные слоты сдвигаются на `zones.suddenDeathDelay`) |
| `zones` | зона каждого игрока — прямоугольник `start`, содержащий его первую постройку; прямоугольник держится `stay` с, затем линейно перетекает в `steps[next]` за `move` с (реальное время). Точка вне текущего прямоугольника своего владельца становится нейтральной (и превращается в `neutralType`; гарнизон сохраняется). Прямоугольники — `[x, z, w, h]` в клетках, полуоткрытые |

Часы: тик остаётся одним тиком. `RtsModule::speedScale()` (= скорость лимита времени x скорость предпросмотра)
заставляет `Simulation::advance` выполнять столько тиков за реальный тик; игровые таймеры (удержание, царь горы,
лимит времени) используют игровое время, зоны / внезапная смерть / `timedRules` используют `ModesState::realTime`
(сумма dt / speed). Сетевая игра: каждый клиент сообщает скорость своей симуляции (`Msg::ClockRate`); когда все
игроки просят одну и ту же скорость, сервер перебазирует часы матча и отвечает `Msg::ClockRateSet`, и сессии
идут в этом темпе (старые участники игнорируют оба сообщения и играют на номинальной скорости).

`timedRules` / `ruleSets`: каждый игрок имеет `status` (статус игрока: его `mods`, `incomeMult`, `flags`), пока
выполняется один из его слотов `when` (без слотов: всегда). Слот: `from` / `to` (реальные секунды включительно;
с `inverse` слот не выполняется вне окна, а внутри его может включить только `every`), `every` / `duration`
(t % every <= duration), `levelBehind` N (с `resource`: уровень игрока ровно на N ниже уровня лучшего игрока),
`everyAbilities` N (число применений способностей игрока — положительное кратное N). Правила, которым нужно
больше, чем статус (фильтры команд, собственные правила улучшений, скриптовые применения), относятся к нативному
модулю игры (docs/native-modules.md § Hooks).

`levels` ресурса (ступени запаса, например звёзды морали):

```json
"morale": {"start": 0, "min": 0, "capped": true, "storage": 8000, "levels": [
  {"at": 0},
  {"at": 1000, "mods": [{"stat": "damage", "mul": 1.1}, {"tags": ["village"], "stat": "defense", "mul": 1.1}, {"stat": "speed", "mul": 1.05}],
   "decay": {"every": 5, "amount": 50, "after": 3}}]}
```

Уровень игрока — последний, чьего `at` достиг запас (ниже первого — никакого); его `mods` действуют на объекты
игрока (не складываясь с более низкими уровнями). `decay`: каждые `every` секунд текущего уровня запас уменьшается
на `amount`, если более `after` секунд ничего не было получено.

`matchStats` (включается вместе с любым режимом): счётчики каждого игрока `ModesState::stats` (`MatchStat`: kills,
lost, produced, captured, capturedNeutral, structuresLost, upgrades, abilities, maxUnits, maxPoints, points,
levelUps, levelDowns, maxLevel, modeScore) и `abilityUses` по каждой способности игрока. `ModesState::outcome` для
каждого игрока: 1 — победа, 2 — поражение, 3 — ничья. Чтение через `RtsModule::matchStat`, `modeZone` (камера на
карте зон), `speedScale`; события `kEvModePhase` (`ModePhaseEvent`: отсчёт, предпросмотр, начало, конец, шаг
времени, время вышло, тревога царя горы, доминирование удержано, зона потеряна / изменилась); поражения от
режима несут `kDefeatMode`.

Переменные триггеров для наложений HUD (текст `{var:NAME}`, условия `var`), скриптов и компьютерных игроков:
`koth_<slot>` (счёт команды слота), `koth_max`, `dom_<slot>` (точки доминирования, удерживаемые с истёкшим
таймером), `mode_time_left`, `mode_speed`, `mode_sd_phase` (0 до, 1 предпросмотр, 2 внезапная смерть, 3 решено),
`mode_sd_left` (секунд до следующей фазы / конца), `mode_sd_counter`, `zone_<slot>_x` / `_z` / `_w` / `_h`. Пример
наложения: `{"id": "timer", "when": {"var": "mode_time_left", ">": 0}, "anchor": {"type": "screen", "at": [640, 24]},
"shape": "text", "text": "{var:mode_time_left}"}`.

Временная башня в точке: навык по точке `{"type": "spawn", "unit": "<static type>", "duration": 10}`; `rangeAspect`
оружия (по умолчанию 1) делает дальность оружия эллипсом с радиусом по z `range x rangeAspect` для поиска целей и
стрельбы (изометрические карты).

## Управление армией (agent-mech): стойки, отступление, транспорт

Необязательные блоки; игра без них играется в точности как прежде (стойки и команды отступления работают в любой
игре).

```json
"stances": {"defendRadius": 6},                          // defensive stance: chase at most this far from where it stood
"retreat": {"speed": 1.25, "damageTaken": 0.75},          // the Retreat command (Company of Heroes / Dawn of War II)
"types": {
  "hq":     {"retreatPoint": true, ...},                  // retreating units run to the nearest own one (else key / producer)
  "archer": {"stance": "defensive", ...},                 // default stance of the type: aggressive | defensive | hold | passive
  "apc":    {"transport": {"slots": 8, "accepts": ["infantry"], "layers": ["ground"], "unloadInterval": 0.5, "killOnDeath": 1}},
  "bunker": {"transport": {"slots": 4, "fireFrom": 4, "heal": 2}},                 // passengers shoot from inside
  "town_center": {"transport": {"slots": 15, "damagePerCargo": 0.2, "accepts": ["villager"]}},   // AoE: more arrows per garrisoned unit
  "ifv":    {"transport": {"slots": 1, "weaponFromCargo": true}},                  // the passenger's weapon fires (RA2 IFV)
  "tank":   {"cargoSize": 4, ...}                                                  // slots a passenger takes (default 1)
}
```

- **Стойки** (команда `kCmdStance`, параметр 0 — агрессивная, 1 — оборонительная, 2 — удержание, 3 — пассивная):
  агрессивная = поведение по умолчанию; оборонительная = сражается с врагами в пределах `stances.defendRadius` от
  своего места и возвращается; удержание = никогда не двигается сама (постоянный `kCmdHold`); пассивная = никогда
  не атакует сама (явные приказы атаковать работают).
- **Отступление** (`kCmdRetreat`, нужен блок `retreat`): юниты бегут к ближайшей своей `retreatPoint` (иначе к
  постройке `key`, иначе к производителю) со скоростью `speed` x скорость и уроном `damageTaken` x урон, не
  сражаясь; любой новый приказ прекращает его. ИИ отводит бойцов с менее чем 30% hp, которые видят врага.
- **Транспорт** (`transport` на юнитах или постройках): `kCmdLoad` (units = пассажиры, target = транспорт; правый
  клик по своему транспорту делает то же), `kCmdUnload` (units = транспорты; параметр 1 + точка: сначала доехать
  туда). Пассажиры находятся вне карты (`kUnitInCargo`): их нельзя выбрать целью, они не рисуются и не толкаются;
  они едут вместе с носителем. `accepts` (теги типов) и `layers` фильтруют пассажиров, `fireFrom` пассажиров с
  оружием стреляют изнутри с позиции носителя, `damagePerCargo` повышает собственный урон носителя за каждого
  пассажира, `heal` — hp/с внутри. Когда носитель погибает, `killOnDeath` пассажиров гибнут вместе с ним (по
  умолчанию 1 для юнитов, 0 для построек), а остальные выходят. События `kEvLoaded` / `kEvUnloaded` (a = пассажир,
  b = транспорт). ИИ заполняет стреляющие постройки (`fireFrom`: бойцы; `damagePerCargo`: рабочие), когда враги
  ближе 10 клеток, и выпускает рабочих, когда безопасно.

### Обнаружение, переключатели, ветеранство, охрана / следование, точки маршрута (agent-mech)

```json
"veterancy": {"xp": [100, 300, 700], "perLevel": [{"stat": "damage", "add": 0.1}, {"stat": "armor", "add": 1}], "healOnLevel": true, "fromCost": 1},
"statuses": {"cloak": {"flags": ["invisible"]}, "burrowed": {"flags": ["invisible", "root", "disarm"]}},
"types": {
  "observer": {"detects": 9, ...},                                   // reveals invisible enemies within 9 cells (allies share it)
  "ghost":    {"abilities": [{"id": "cloak", "target": "none", "toggle": {"status": "cloak", "drain": 1}}], ...},
  "lurker":   {"abilities": [{"id": "burrow", "target": "none", "toggle": {"status": "burrowed"}}], ...},
  "wall":     {"veterancy": false},                                   // or its own {"xp": [...], "perLevel": [...]}
  "tank":     {"xp": 50, ...}                                         // xp its killer gets (default: its cost x fromCost)
}
```

- **Обнаружение**: невидимые объекты (флаг статуса `invisible`) сторона может выбрать целью только когда они
  `revealed` или находятся в пределах `detects` одного из её (или союзных) детекторов. `RtsModule::canSee(sim, e,
  viewer)` — запрос для вида/интерфейса.
- **Переключаемые способности**: применение включает статус (до выключения) и выключает его; `drain` энергии в
  секунду выключает его, когда энергия кончается. Невидимость, закапывание, погружение, осадный режим (статус с
  модификаторами / флагами) — это данные.
- **Ветеранство** (обычные юниты; герои сохраняют `hero`): юнит, нанёсший последний удар, получает `xp` жертвы;
  звания применяют `perLevel` за каждое звание выше 1 и лечат при повышении; событие `kEvLevelUp` (value = звание).
- **Охрана / следование** (`kCmdGuard`, `kCmdFollow`, target = юнит): следовать в пределах ~3 клеток; охрана
  также сражается с врагами в пределах 6 клеток от охраняемого юнита.
- **Точки маршрута сбора**: `kCmdRally` с флагом очереди (Shift) добавляет точки маршрута после точки сбора; новые
  юниты проходят их по порядку. Обычный сбор очищает их. Сама очередь приказов (`kCmdQueue` на любой команде)
  была всегда.
- **Маршруты волн**: волны карты принимают `"route": ["gate", [30, 8]]` (имена областей или точки), проходимый
  перед целью.

### Модели боя и экономики (ключи agent-mech = псевдонимы блоков точности)

Эти ключи пришли от agent-mech; они разбираются в единственную реализацию каждой механики, описанную в
[Механиках точности](#fidelity-mechanics-play-like-the-original), и означают там то же самое.

```json
"armorModel": "percent",                                               // = "armor": {"model": "percent", "negative": "exponential"}; "factor" = perPoint
"armorModel": {"type": "subtract", "minFraction": 0.2, "min": 0},      // = "armor": {"model": "subtract", "minShare": 0.2, "minDamage": 0}
"armorModel": {"type": "classes", "base": ["melee", "pierce"], "min": 1},   // = "armor": {"model": "classes", "base": [...], "minDamage": 1}
"upkeepResources": ["gold"],                                            // = "resources" of every upkeep tier that names none (Warcraft III)
"types": {
  "spearman": {"weapons": [{"damage": 3, "attacks": {"melee": 3, "cavalry": 15}}], "armors": {"melee": 0, "pierce": 0, "infantry": 0}},
  "knight":   {"armors": {"melee": 2, "pierce": 2, "cavalry": 0}},
  "zealot":   {"shields": {"max": 50, "regen": 2, "delay": 10, "armor": 0}},   // StarCraft shields
  "goldmine": {"resourceNode": {"resource": "gold", "amount": 12500, "maxWorkers": 5}}
}
```

- **classes** (Age of Empires II): урон = max(`min`, сумма по `attacks` оружия от max(0, атака - броня этого
  класса)); классы `base` учитываются всегда (отсутствующая броня равна 0, улучшения брони повышают её), прочие
  классы — только против типов, перечисляющих их в `armors` (бонусный урон прибавляется, а не умножается). Оружие
  без `attacks` атакует первый базовый класс своим `damage`. Таблица урона в этой модели не используется. Без
  `min` / `minFraction` модель классов имеет нижнюю границу 1 и не имеет границы по доле.
- `armorModel` percent использует точную кривую Warcraft III для отрицательной брони (`2 - (1 - k)^-a`); `"armor"`
  сохраняет линейную `1 + min(-a·k, 0.71)`, если в нём не указано `"negative": "exponential"`.
- `"shields": {"max", "regen", "delay", "armor"}` типа = `health.shields` / `shieldRegen` / `shieldDelay` /
  `shieldArmor` (те же значения по умолчанию: regen 2/с, delay 10 с); один компонент щита (`Shield`) для обоих
  написаний.
- `resourceNode.maxWorkers` = `resourceNode.maxGatherers`: следующие рабочие ждут рядом с узлом или берут свободный
  узел того же ресурса поблизости.
### Жанровые механики (agent-mech, этап 2)

```json
"market": {"currency": "gold", "prices": {"wood": 100, "food": 100, "stone": 130}, "fee": 0.3, "step": 3, "lot": 100},
"tribute": {"fee": 0.3}, "diplomacy": true,
"items": {"potion": {"cost": {"gold": 50}, "use": {"heal": 200}, "charges": 1},
          "boots":  {"cost": {"gold": 100}, "mods": [{"stat": "speed", "add": 1}], "charges": 0, "consumable": false}},
"cycles": [{"id": "day", "length": 480, "phases": [{"id": "day", "until": 0.6}, {"id": "night", "until": 1, "status": "night"}]},
           {"id": "season", "length": 1200, "phases": [{"id": "summer", "until": 0.75}, {"id": "winter", "until": 1, "status": "winter"}]}],
"hazards": [{"field": "tiberium", "damage": 6, "tags": ["infantry"]}, {"area": "lava", "status": "burning"}],
"deck": {"hand": 4, "deployNear": 8, "ownHalf": true},
"types": {
  "wall":     {"wall": true, ...},                       // built in a line (kCmdBuildLine)
  "gate":     {"gate": "own" | "allies", ...},           // the owner walks through; enemies are stopped and attack it
  "bridge":   {"bridge": true, ...},                     // walkable ground over water while it stands (map-placed)
  "nydus":    {"transport": {"slots": 20}, "tunnel": "nydus"},   // load at one, unload at any tunnel of the network
  "hovercraft": {"move": {"layer": "amphibious", ...}},  // ground and water
  "harrier":  {"weapons": [{"ammo": 2, ...}]},           // empty: flies to the nearest own dock and rearms
  "airfield": {"dock": {"slots": 4, "rearmTime": 1}},
  "templar":  {"mergeInto": {"with": "templar", "result": "archon"}},   "archon": {"splitInto": {"type": "templar", "count": 2}},
  "market":   {"market": true}, "cart": {"trader": {"rate": 0.5}},     // currency per cell between the two markets per round trip
  "hero":     {"inventory": {"slots": 6}}, "shop": {"shop": {"sells": ["potion", "boots"], "radius": 4}},
  "kobold":   {"drops": [{"item": "potion", "chance": 0.3}]}
}
```
Игроки карты могут иметь `"deck": ["card ids..."]` (по умолчанию — все способности игрока). Команды: `kCmdFormation`
(параметр 0 — линия, 1 — каре, 2 — клин, 3 — рассыпной, -1 — разомкнуть; строй, получивший приказ идти в точку,
сохраняет форму и темп самого медленного участника), `kCmdBuildLine`, `kCmdMerge`, `kCmdSplit`, `kCmdTrade`
(продать / купить один лот; цены сдвигаются на `step` и общие для всех), `kCmdTradeRoute`, `kCmdTribute`,
`kCmdDiplomacy` (союзу нужно согласие обеих сторон; война переводит игрока в новую команду),
`kCmdBuyItem` / `kCmdUseItem` / `kCmdDropItem` / `kCmdPickItem`. Циклы применяют `status` своей фазы к каждому игроку
и задают переменную триггера `cycle.<id>` = индекс фазы (событие `kEvCyclePhase`). Прыжки через обрывы, реактивные
ранцы и мгновенные перемещения — это способности с эффектом `blink`; сети телепортов — эффекты `area` с
`teleportTo`. ИИ продаёт излишки / покупает недостающее, отправляет свободные повозки на самый дальний рынок,
покупает и пьёт зелья героями и объединяет свободные пары.
Через MCP (`scenario_run` / `play_command`) `trade`, `tribute` и `bounty` принимают читаемые поля вместо упакованного
параметра: `{"cmd": "trade", "units": [market], "resource": "wood", "sell": true}`,
`{"cmd": "tribute", "resource": "gold", "amount": 100, "to": 2}`, `{"cmd": "bounty", "target": id, "resource": "gold", "amount": 50}`.

## Тактика и общество (agent-mech, этап 3)

Необязательные блоки; игра без них загружается, играется и хешируется как раньше. Проверяются в `tests/tests_mech.inc`
(`mech_tactics`, `mech_society`, `mech_rounds`, `mech_ai_staffing`, `mech_designs`).

### Укрытия, подавление, секторы брони (Company of Heroes, Men of War)

```json
"cover": {"levels": {"1": 0.75, "2": 0.5}, "tags": ["infantry"]},
"suppression": {"decay": 5, "suppressed": 30, "pinned": 80, "suppressedSpeed": 0.5, "suppressedAttack": 0.5, "tags": ["infantry"]}
```

- `cover.levels`: множитель урона для каждого уровня укрытия 1..9. Юнит (с одним из `tags`, если они не заданы — любой) получает уровень своей
  клетки — карта `"cover": {"rows": ["0012..", ...]}` (по цифре на клетку) — или строения с `"givesCover": N` в пределах
  половины его площади + 1.5 клетки, смотря что выше.
- Оружие `"suppress": 10` добавляет подавление (0..100) за каждое попадание; оно спадает на `decay` в секунду. Выше `suppressed` юнит
  движется и атакует медленнее; выше `pinned` он не может двигаться.
- Тип `"armorArcs": {"side": 0.75, "rear": 0.5}`: множитель урона для попаданий сбоку / сзади относительно направления юнита.
- Оружие `"turret": {"turnRate": 90}` (градусов в секунду): оружие стреляет, только когда его башня смотрит на цель.
- Оружие `"crater": 1` (или `{"radius": 1}`): земля вокруг попадания становится укрытием уровня 1.

### Экипажи, давление, руины, заражение (Z, Men of War, C&C, They Are Billions)

- Экипажи — одна механика с ключами точности `crew` / `crews` / `killsCrew` (см. [Механики точности](#fidelity-mechanics-play-like-the-original)):
  `"crew": {"accepts": ["infantry"]}` (или `true`: любой подвижный юнит) — техника с экипажем, которую может занять любой юнит
  с подходящим тегом, без `"crews": true`. Оружие `"killsCrew": 1` (шанс при несмертельном попадании) оставляет её пустой и нейтральной
  (владелец 0); юнит, который может её занять, кликает по ней правой кнопкой (smart / `load`), подходит и становится экипажем: техника
  меняет владельца, солдат удаляется.
- `"crush": {"damage": 500, "tags": ["infantry"]}`: движущийся юнит наносит урон вражеским подвижным юнитам с этими тегами, которых касается.
- `"ruins": "rubble"`: тип, который появляется (нейтральным) там, где погиб этот.
- Оружие `"infect": "zombie"`: убитый им юнит восстаёт этим типом для владельца убийцы. Строение с
  `"infectable": {"spawns": "zombie", "count": 2}`, разрушенное таким оружием, порождает `count` юнитов `spawns`.

### Персонал, рост, поля энергии (Settlers, Stronghold, StarCraft, Anno)

- `"staff": {"count": 2, "accepts": ["worker"]}`: доход и производство масштабируются долей занятых мест (рабочие
  заходят через `load` / smart-клик; создаётся блок транспорта на `count` мест). ИИ отправляет простаивающих рабочих.
- `"grows": {"unit": "villager", "interval": 30, "cost": {"food": 20}}`: строение производит юнита каждые
  `interval` секунд, пока может заплатить и есть лимит.
- `"powerField": 6` (радиус) и `"needsPower": true`: строение, которому нужна энергия, работает и может быть поставлено только внутри
  готового поля своего владельца.

### Награды и самостоятельные герои (Majesty)

Юнитами с `"autonomous": true` нельзя командовать; они сами выбирают бои и предпочитают цели с наградой.
Команда `bounty` (цель, `param` = индекс ресурса | сумма << 8) выплачивает сумму, удерживаемую до гибели цели,
владельцу юнита, который её убил. MCP: `{"cmd": "bounty", "target": id, "resource": "gold", "amount": 100}`.

### Раунды (автобатлеры, дуэли в стиле Mushroom)

```json
"rounds": {"prepare": 20, "fight": 40, "rounds": 10, "reset": true, "lives": "lives", "damagePerUnit": 1, "income": {"gold": 5}}
```

Игра чередует фазу подготовки (никто не выбирает цели) и фазу боя. В конце боя каждая сторона теряет
`damagePerUnit` из `lives` за каждого выжившего вражеского юнита; при `reset` армии восстанавливаются по снимку, сделанному в
начале боя. Каждый получает `income` за раунд. После `rounds` раундов (или когда у стороны кончаются жизни) игра
заканчивается: побеждает сторона с наибольшим числом жизней.

### Улучшения за гарнизон (Mushroom Wars 2)

`"upgradeGarrison": 10` на целевом типе записи `upgrades` — псевдоним ключа точности `"cost": {"garrison": 10}`:
улучшение стоит столько юнитов гарнизона здания сверх своей стоимости в ресурсах (отказ, если гарнизон
меньше; юниты забираются только когда улучшение ставится в очередь).

## Конструкции юнитов (agent-mech, UD)

Типы можно собирать из шасси и деталей (Master of Orion, Galactic Civilizations, наборы Supreme Commander).
`loadRules` разворачивает их в обычные блоки типов до разбора (`expandDesigns`), поэтому все остальные ключи работают как обычно;
`rules_lint` проверяет развёрнутую копию.

```json
"designs": {
  "chassis": {"light": {"move": {"speed": 4}, "health": {"max": 100}, "cost": {"gold": 50}, "slots": {"weapon": 2, "system": 1}}},
  "parts": {
    "laser":   {"slot": "weapon", "weapons": [{"range": 5, "damage": 10, "cooldown": 1}], "cost": {"gold": 20}},
    "plating": {"slot": "system", "add": {"health.max": 60, "move.speed": -1}, "cost": {"gold": 30}, "health": {"armor": 2}}
  }
},
"types": {"scout": {"design": {"chassis": "light", "parts": ["laser", "laser", "plating"]}, "sight": 8}}
```

- Шасси копируется; детали применяются по порядку: `add` прибавляет числа по путям через точку, `cost` / `upkeep` прибавляются по ресурсам,
  `weapons`, `tags`, `abilities`, `upgrades` дописываются в конец, остальные ключи сливаются (объекты) или заменяются.
- `slots`: число или число для каждого вида `slot` детали; слишком много деталей — ошибка загрузки.
- Собственные ключи типа (кроме `design`) применяются последними.

## Полевые сражения, большие армии, логистика (agent-mech, этап 4)

Проверяются в `tests/tests_mech.inc` (`mech_battle`, `mech_flow_fields`, `mech_logistics`; `AIVERSE_BENCH_ARMY=1500` запускает
бенчмарк на 3000 юнитов).

### Мораль, бегство, усталость, натиск (Total War, Close Combat)

```json
"morale": {"max": 100, "regen": 2, "hitLoss": 100, "allyDeath": 6, "allyRadius": 6, "flankSide": 1.5, "flankRear": 2,
           "waver": 40, "rout": 20, "rally": 60, "routSpeed": 1.25, "waverAttack": 0.85, "tags": ["soldier"],
           "general": {"tags": ["general"], "radius": 10, "regen": 6, "death": 30}},
"fatigue": {"run": 2, "fight": 4, "recover": 5, "tired": 50, "exhausted": 85, "tiredMul": 0.85, "exhaustedMul": 0.6}
```

- Мораль (у каждого юнита; `"morale": 120` на типе переопределяет `max`) падает на `hitLoss` x долю максимального здоровья, снятую попаданием,
  умноженную на `flankSide` / `flankRear`, если атакующий находится сбоку / сзади относительно направления юнита; на `allyDeath`, когда свой юнит
  гибнет в пределах `allyRadius` (`general.death` в пределах удвоенного `general.radius`, когда гибнет генерал). Она восстанавливается на `regen`
  в секунду, плюс `general.regen` рядом со своим генералом.
- Ниже `waver` юнит колеблется (скорость атаки x `waverAttack`); ниже `rout` он бежит: сбрасывает приказы, убегает от
  ближайшего врага (скорость x `routSpeed`), не сражается и восстанавливается, только когда врагов не видно, до `rally`.
  Событие `morale` (значение 0 — стойкий, 1 — колеблется, 2 — бежит). ИИ ведёт свободных генералов к самым нестойким солдатам.
- Усталость 0..100 растёт на `run` в секунду при движении и на `fight` в секунду при стрельбе, падает на `recover` в покое; выше
  `tired` / `exhausted` скорость и скорость атаки умножаются на `tiredMul` / `exhaustedMul`.
- `"charge": {"bonus": 1.5, "run": 3, "shock": 15, "cooldown": 8}` на типе: после пробега `run` клеток первый удар
  наносит `bonus` x урона и отнимает у цели `shock` морали.
- Состояние MCP показывает `morale`, `moraleState`, `fatigue`, `supplied`.

### Линии снабжения (Rise of Nations, Hearts of Iron)

`"supply": {"tags": ["soldier"], "attrition": 0.01, "speed": 0.8, "attack": 0.8}` и `"supplyRadius": 12` на типах
складов: юниты дальше этого расстояния от всех готовых своих или союзных складов теряют `attrition` x максимального здоровья в секунду, а также двигаются
и атакуют медленнее.

### Большие армии (BA)

`"flowFields": true` (или `{"minCells": 8, "cache": 16}`) — псевдоним единой системы полей потока
(`movement.flowField`, см. Movement): означает `{"minGroup": 1, "minCells": 8, "maxFields": 16}` — каждый наземный приказ движения,
атаки с движением, патрулирования или правого клика юнита, находящегося не ближе `minCells` клеток от цели, следует
общему полю области цели (явный `movement.flowField` имеет приоритет). Кроме того, группы атаки с движением больше 24 юнитов выстраиваются блоком из
рядов вместо одной широкой дуги (каждый юнит идёт к своей точке в ряду своим путём). Поиск соседей для разделения и RVO
всегда использует сетку в одну клетку (результаты идентичны версии с пространственным хешем). Бенчмарк (ARM VM, -O3): 3000
сражающихся юнитов, около 13 мс на тик.

### Конвейеры, производители, крафтеры (Mindustry, Factorio)

```json
"belt":    {"structure": {"footprint": [1, 1]}, "conveyor": {"speed": 4}},
"drill":   {"structure": {"footprint": [2, 2]}, "beltOutput": {"resource": "ore", "amount": 1, "interval": 0.5}},
"smelter": {"structure": {"footprint": [2, 2]}, "craft": {"in": {"ore": 2}, "out": {"plate": 1}, "time": 1}},
"core":    {"structure": {"footprint": [2, 2]}, "beltInput": ["plate"]}
```

- Сегмент конвейера переносит по одному пакету на клетку со скоростью `speed` клеток в секунду в своём направлении (восток, юг, запад, север):
  задаётся через `build_line` (вдоль главной оси линии), сущность карты `"dir": "e"` или команду `rotate`
  (`{"cmd": "rotate", "units": [...], "dir": "n"}`; без `dir` поворачивает по часовой стрелке).
- Производители каждые `interval` кладут пакет на свободную соседнюю ленту, которая не направлена обратно в них; крафтеры берут
  входные ресурсы с лент (до двух партий), работают `time` секунд (с учётом персонала / энергии) и кладут продукцию на ленты.
- Строение с `beltInput` (список ресурсов или `"any"`) принимает пакеты в запас своего владельца (событие `delivered`).
- Ленты — обычные строения (блокирующие, разрушаемые); пакет на разрушенной ленте теряется. ИИ пока не прокладывает
  ленты. Состояние MCP: `dir` и `carries` ленты, `input` / `output` крафтера.

## Ходы, стратегическая карта, полёт в 3D (agent-mech, этап 5)

Проверяются в `tests/tests_mech.inc` (`mech_turns`, `mech_strategic`, `mech_space_flight`).

### Пошаговый режим (Heroes, XCOM, сражения Advance Wars)

`"turns": {"moveSeconds": 4, "attacks": 1, "timeLimit": 0}`: игроки действуют по очереди в одной и той же симуляции.
Во время хода двигаются (не дальше скорости типа x `moveSeconds` клеток) и стреляют (`attacks`
выстрелов на оружие) только юниты активного игрока; остальные стоят на месте и не отвечают огнём; команды других игроков игнорируются. Команда
`end_turn` (или `timeLimit` секунд) передаёт ход следующему живому игроку; событие `turn` (игрок, номер хода).
Боты раз за ход посылают своих бойцов на ближайшего врага и завершают ход, когда те перестают двигаться.

### Стратегическая карта (кампания Total War, Company of Heroes 3, Empire at War)

`engine/game/Strategic.h`: провинции и армии поверх `rules.json` игры; сражения рассчитываются автоматически
(квадратичный закон Ланчестера по здоровью x урону в секунду) или симулируются на RTS-симуляции с ботами, а выжившие возвращаются на карту.

```json
{"players": [{"name": "Red"}, {"name": "Blue"}], "start": {"gold": 100}, "movesPerTurn": 1,
 "recruit": {"spear": {}, "archer": {"gold": 40}},
 "battle": {"mode": "simulate", "seconds": 240, "size": [48, 32]},
 "provinces": [{"id": "a", "owner": 1, "income": {"gold": 40}, "adj": ["b"], "pos": [0, 0], "terrain": {"rows": [...]}},
               {"id": "b", "adj": ["c"]}, {"id": "c", "owner": 2}],
 "armies": [{"owner": 1, "at": "a", "units": {"spear": 12}}, {"owner": 2, "at": "c", "units": {"spear": 6}}]}
```

- Смежность симметрична. `recruit` с `{}` использует `cost` типа. Вход в провинцию с вражеской армией
  начинает сражение; пустая вражеская или нейтральная провинция захватывается. Свои армии в одной провинции сливаются.
- Доход принадлежащих провинций поступает в начале хода владельца; игрок без провинций и армий выбывает;
  побеждает последний оставшийся.
- MCP: `strategic_load` (`file` в проекте или `def`), `strategic_state`, `strategic_order`
  (`move` / `recruit` / `end_turn`), `strategic_bots` (боты играют N ходов; `battle`: auto | simulate),
  `strategic_battle_map` (RTS-карта сражения, чтобы сыграть вручную), `strategic_save`.

### Свободный полёт в 3D (Homeworld)

`"altitude": {"min": 0, "max": 30, "climb": 3, "start": 10}` на воздушном типе: юнит держит собственную высоту, набирает её или
снижается до `y` своих приказов движения (MCP `{"cmd": "move", "x", "z", "y"}`), следует высоте атакуемой
цели, а дальность оружия до него и от него измеряется в 3D. Пути и уклонение остаются двумерными. Представление пока не рисует
высоту.

## Радар, сонар и глушилки

Ключи типов (все необязательные; `modules/rts/RtsSensors.h`). Радиусы задаются в клетках.

```jsonc
"radar_tower": {"radar": 30, "income": {"energy": -20}},        // enemies inside the circle are contacts of its side
"sonar_buoy":  {"sonar": 25},                                    // the same for underwater units (radar does not see them)
"jammer":      {"jammer": 12},                                   // hides its own side's units inside the circle from enemy radar / sonar
"spy":         {"stealth": true},                                // never a radar contact (still seen in sight)
"submarine":   {"move": {"layer": "naval"}, "underwater": true,  // only weapons with "underwater": true hit it
                "weapons": [{"range": 6, "damage": 80, "underwater": true, "targets": ["naval"]}]},
// rules
"radar": {"targeting": true}   // units pick targets beyond their sight, up to weapon range, that their side sees or tracks
```

- Контакт — враг внутри круга радара (сонара, для подводных юнитов) наблюдателя или союзника, не находящийся внутри
  круга глушилки своей стороны и не скрытный. Обесточенные (`kUnitDisabled`), недостроенные или перевозимые источники отключены.
- Представление рисует контакты вне обзора красными точками (без модели: наблюдатель не знает тип). Нативный код:
  `RtsModule::sensors()->onRadar(sim, e, viewer)`, `blips(sim, viewer)`.
- `radar.targeting`: артиллерия и дальнобойные башни стреляют по тому, что видят радар или союзники. Без него ничего не меняется.
- Боты строят одно строение с `radar`, как только их база заработает (`RtsAI`); контакты служат целями для их дальнобойных орудий.
- Состояния нет: контакты пересчитываются по юнитам, поэтому сохранения и повторы ничего лишнего не несут; игры без этих
  ключей сохраняют свои контрольные суммы.

## Полевые операции

Необязательные блоки для войн с поточной экономикой (`modules/rts/RtsFieldOps.h`; состояние в ресурсе `FieldOpsStore`: хешируется,
сохраняется). У игр без них нет дополнительной системы, и их контрольные суммы не меняются.

```jsonc
// rules
"repair": {"cost": 0, "units": true},            // share of the cost for a full repair (default 0.3); mobile units too
"reclaim": {"units": true, "refund": 1},         // builders take units apart (own or enemy) for that share of their cost
"selfDestruct": {"time": 5},                     // kCmdSelfDestruct arms a countdown (again: disarms); death effects apply
"ambient": {"wind": {"min": 0, "max": 25, "every": [15, 45]}, "tidal": 18},   // the map's "ambient" overrides key by key
// types
"con_kbot":   {"assist": true, "patrolWork": true},   // guard a factory: adds build power; patrol: repairs / reclaims on the way
"wind_gen":   {"income": {"energy": 2}, "ambientIncome": {"wind": {"energy": 1}}},   // + wind strength x 1 energy/s
"tidal_gen":  {"ambientIncome": {"tidal": {"energy": 1}}},
"nuke_silo":  {"tags": ["nuke"], "stockpile": {"max": 5, "time": 90, "cost": {"metal": 1000, "energy": 20000}, "abilities": ["launch"]},
               "abilities": [{"id": "launch", "target": "point", "range": 200, "effects": [{"type": "projectile", ...}]}]},
"anti_nuke":  {"intercept": {"radius": 40, "tags": ["nuke"]}, "stockpile": {"max": 3, "time": 60, "cost": {"metal": 500}}},
"bomber":     {"move": {"layer": "air"}, "attackRun": {"overshoot": 5}, "seekRepair": 0.3,
               "weapons": [{"range": 1.5, "damage": 200, "targets": ["ground"]}]},
"air_pad":    {"repairPad": {"heal": 40, "radius": 1.5}}
```

- **Ремонт / разборка**: `kCmdRepair` (цель = повреждённый свой или союзный юнит; строения всегда, подвижные юниты — при
  `repair.units`), `kCmdReclaim` (цель = узел ресурса: приказ добычи; юнит: `OrderType::Reclaim`, со скоростью `buildPower` строителя
  относительно времени постройки цели, с выплатой стоимости x `refund` по мере его уменьшения; без обломков и без взрыва при гибели). Smart-клик
  по повреждённому своему юниту ремонтирует его, если включён `repair.units`.
- **Помощь**: строитель с `assist`, охраняющий (`kCmdGuard`) свой производитель в пределах 5 клеток, добавляет свой `buildPower` к
  `buildPower` производителя (`step x (1 + sum / producer buildPower)`); прогрессивная стоимость оплачивается в ускоренном темпе.
- **Работа в патруле**: строитель с `patrolWork` в патруле сначала ремонтирует повреждённых союзников в поле зрения, затем добывает поточные ресурсные
  узлы (обломки, камни, деревья), мимо которых проходит; патруль возобновляется после каждой работы.
- **Запас зарядов**: заряды строятся по одному за `time` секунд (медленнее при нехватке энергии), стоимость `cost` выплачивается по ходу постройки,
  а при нехватке средств постройка останавливается; способности из `abilities` (по умолчанию — все способности типа) требуют и тратят заряд.
  Бот использует их через `autocast` способности + наведение `smart`.
- **Перехват**: вражеские снаряды, выпущенные типами с любым из `tags`, уничтожаются внутри `radius`; при наличии запаса каждый
  перехват тратит заряд. Событие `kEvFieldOp` (значение `kFieldOpIntercepted`, a = перехватчик, b = снаряд).
- **Доход от среды**: ветер каждые `every` секунд меняется на случайную силу в [min, max] (RNG симуляции); `tidal`
  постоянен для карты. `ambientIncome` добавляет к доходу владельца силу x количество в секунду (готовые объекты с энергией).
  Оставляйте у таких типов небольшой фиксированный `income`, чтобы бот считал их зданиями дохода.
- **Заходы на атаку**: юнит с `attackRun` пролетает над целью и ещё `overshoot` клеток дальше, затем разворачивается для следующего
  захода; его оружие стреляет на пролёте (бомбы малой дальности).
- **Ремонтные площадки**: юниты, стоящие неподвижно в пределах `radius` от своей или союзной `repairPad`, бесплатно восстанавливают `heal` здоровья в секунду;
  `seekRepair` отправляет свободный юнит, у которого здоровье ниже этой доли, к ближайшей своей площадке.
- События `kEvFieldOp`: `value & 0xFF` = `kFieldOpArmed` (data = оставшиеся тики) / `Disarmed` / `Stockpiled` (data = заряды) /
  `Intercepted` / `Wind` (data = сила). Нативный код: `RtsModule::fieldOps()` (`stockpile`, `selfDestructAt`, `wind`).

## Сохранения состояния (agent-mech)

`Simulation::serialize()` возвращает всё динамическое состояние в виде байтов (с версией, little-endian, одинаково на всех
платформах: `engine/core/Archive.h`); `deserialize(bytes)` загружает его в симуляцию, настроенную по тем же правилам, карте и
seed, и проверяет контрольную сумму состояния, записанную в файле. Сохраняются: тик, RNG, игроки и команды, ожидающие и выполненные
команды (повторы продолжаются), аллокатор сущностей, все пулы компонентов в плотном порядке и динамическая часть
`GameState` (поклеточные слои кодируются RLE). Не сохраняются: правила, триггеры, поверхность планеты (из настройки) и производные
кэши (проходимость, HPA*, перестраиваются по требованию). Компьютерные игроки хранят свою память, поэтому боты продолжают с загруженного
состояния со свежими планами. Сторона модуля: `RtsModule::serializeState` (`modules/rts/RtsSave.cpp`); тип компонента, отсутствующий в
его списке, приводит к ошибке сохранения. `aiverse_headless --save F --save-at S` / `--load F`; MCP `match_run` с `saveCheck` (секунды).
Матч skirmish на 90 с занимает ~150 КБ. С версии сохранения 9 сохраняется и зафиксированный исход матча (`MatchOutcome`):
состояние до конца матча, загруженное в симуляцию, которая уже завершилась, больше не сохраняет старый результат (раньше
компьютерные игроки останавливались, а окна `--verify-restore-at`, пересекающие конец матча, расходились на сериализованном проходе);
старые сохранения загружаются без исхода, который снова фиксируется на следующем тике.

## Триггеры

Событие → условия → действия; вычисляются внутри детерминированной симуляции.

```json
{"id": "relic", "once": true, "enabled": true, "forEachPlayer": false,
 "event": {"type": "enterArea", "area": "relic", "player": 1, "unit": "hero"},
 "conditions": [{"type": "count", "player": "triggering", "kind": "structure", ">=": 3}],
 "actions": [{"type": "message", "text": "Реликвия найдена!"}, {"type": "give", "resource": "gold", "amount": 500}]}
```

События: `start`, `time` (`seconds`), `every` (`seconds`), `enterArea` / `leaveArea` (`area`, фильтр юнитов),
`unitDied`, `built`, `trained` (фильтр юнитов), `researched` (`tech`), `captured`, `wave`, `regionClaimed`,
`playerDefeated`, `ability`, `levelUp`, `resource` (`resource`, сравнение: срабатывает, когда оно становится истинным),
`variable` (`name`, сравнение). `player` события: номер слота, `"any"` (по умолчанию), `"creeps"`.

Фильтр юнитов (события, условия, действия): `"unit": "type"`, `"tags": [...]`, `"kind": "structure"|"unit"`, `"area": "name"` или `[x,z,w,h]`.

Сравнения: одно из `">=", ">", "<=", "<", "==", "!="` с числом.

Условия: `count` (объекты, подходящие под фильтр), `resource`, `variable`, `researched`, `random`
(`chance`), `time` (секунды), `alive`, `regions` (число принадлежащих). `"not": true` инвертирует.

Действия: `spawn` (`unit`, `count`, `at` [x,z] / `area`, `attackMove`), `give` / `take` (`resource`,
`amount`), `setOwner`, `kill`, `remove`, `damage`, `heal` (`amount`), `buff` (`stat`, `add`/`mul`,
`duration`), `message` (`text`), `setVariable` / `addVariable` (`name`, `value`), `research` (`tech`),
`enableType` / `disableType` (`unit`), `victory` / `defeat`, `enableTrigger` / `disableTrigger`
(`trigger`), `addScore` (`amount`), `setRegionOwner` (имя `region`), `attackMove` / `move` (юниты,
подходящие под фильтр, к `at` / `area`), `setTickets` (`amount`); триггеры ботов Bunker Wars (agent-bw-ai):
`setResource` (`resource`, `amount`: запас становится равным amount, например мораль), `resetCooldowns` (способности
игроков готовы), `setProduction` (`amount`: коэффициент скорости производства подходящих строений,
заменяющий предыдущий), `timeScale` (`amount`: скорость игры, требует режимов матча / `matchStats`).

`player` действия: `"triggering"` (по умолчанию: игрок события), `"all"`, `"enemies"`, `"allies"`,
`"creeps"`, `"neutral"` или номер слота. `"target": "triggeringUnit"` действует на юнита события.

### Проверка данных через MCP

`scenario_run` выполняет скриптовую проверку на копии открытой карты: именованные `spawn`, команды `commands` по времени (ключи
`play_command`), необязательные `bots`, проверки `checks` (pass/fail) и журналы `watch` / `events` / триггеров. Каждый сработавший триггер
— это также событие симуляции `kEvTriggerFired` (value = индекс триггера: сначала триггеры правил, затем триггеры карты;
player = слот, вызвавший срабатывание) — только для представления/инструментов, не хешируется. `rules_lint` перечисляет ключи, которые загрузчик никогда не читает;
`rules_schema` с `part: "keys"` перечисляет все ключи, которые загрузчик читает в каждом блоке, взятые из самого загрузчика.

### Модули C++ через MCP

`native_status` сравнивает `nativeModules` из rules.json с тем, что вкомпилировано в запущенный бинарник редактора
(`required`, `compiled`, `missing`), и описывает сборку редактора для проекта в `<project>/Builds/.temp/editor-<host>`
(`editor`, `headless`, `built`, `buildModules`, `upToDate`, `ready`, `why`). `native_build` конфигурирует и собирает там
`aiverse_editor` + `aiverse_headless` с `-DAIVERSE_CONTENT_DIR=<project>` (Release), выводя ход сборки в журнал сборки
(`build_status`); `wait: true` блокирует до её завершения и возвращает пути бинарников. См. docs/native-modules.md.

## Текстурные атласы (`atlas` в game.json, необязательно)

Окно Build редактора показывает слишком большие кандидаты в атлас в разделе «Не в атласе».
«Исправить размеры текстур» применяет предложенные максимальные размеры как точные правила
`packaging.targets.<platform>.files` с наивысшим приоритетом и обновляет оценку размера. Это уменьшает
детализацию изображений в собранном паке; исходные ассеты не меняются. Листам спрайтов, атласам тайлов и источникам UI `@spritesheet` в RCSS
с координатами в пикселях это исправление никогда не предлагается. Существующие правила изменения размера для этих источников
игнорируются при упаковке, чтобы сохранить координаты их кадров. Прочие исключения (повтор при заворачивании,
noAtlas, ошибки декодирования, единственное изображение в группе) требуют ручного решения. Пересчитайте устаревший
отчёт, прежде чем применять исправления; кнопка неактивна, пока настройки отличаются от отчёта.

При упаковке игры (`aiversebuild`, `assetpipe pack --atlas <profile>`) мелкие 2D-изображения
упаковываются в страницы атласа: меньше переключений текстур/вызовов отрисовки, обрезанные прозрачные края, одинаковые
изображения хранятся один раз, а страницы сжимаются zstd пака. Код игры продолжает использовать исходные
пути (`units/orc/grunt/walk_0.png`); поиск прозрачен во время выполнения. Сборки в виде папки с файлами
(`--no-pack`, редактор) используют изображения как есть. Весь блок необязателен:

```json
"atlas": {
  "enable": true,                                   // false (or aiversebuild --no-atlas): ship images as is
  "maxPage": { "web": 2048, "android": 2048, "default": 4096 },  // or a single number
  "pageSize": "mul4",          // page sides: multiples of 4 (default) or "pow2"
  "padding": 2,                // empty texels between images
  "extrude": 1,                // edge texels repeated around each image (no filtering seams)
  "trim": true,                // cut fully transparent borders (offsets are kept)
  "maxTextureSize": 0,         // larger images stay standalone; 0 = maxPage / 4
  "mipLevels": 2,              // groups with "mips": padding/alignment safe down to 2^levels
  "pageFormat": "rtex",        // "rtex" (raw RGBA, zstd in the pack, fastest load) or "png"
  "groups": { "units": { "rotate": false, "mips": true }, "tiles": { "trim": false } },
  "files": {                   // glob -> settings; `*` also matches '/'; later rules win
    "ui/splash/*": { "noAtlas": true },
    "units/orcs/*": { "group": "orcs" },
    "textures/water.png": { "wrap": "repeat" },
    "units/*/shadow.png": { "kind": "mask" }
  }
}
```

Профили — это цели aiversebuild (`macos`, `ios`, `android`, `web`, `windows`, `linux`); встроенные
ограничения страниц: 2048 для `web`/`android`, 4096 для остальных. Цели с одинаковыми настройками используют один пак.

**Что попадает вместе.** Ключ группы изображения — *группа использования* + *вид* (+ непрозрачное/с альфой, если
группа разделяется по альфе, + мипы). Изображения делят страницу только с изображениями с тем же ключом:

| группа использования | папки по умолчанию (первый компонент пути, префикс `engine/` игнорируется) | по умолчанию |
|---|---|---|
| `ui` | `ui/`, `icons/`, `portraits/`, `cursors/`, `hud/` | обрезка |
| `units` | `sprites/`, `units/`, `buildings/`, `structures/`, `characters/` | обрезка |
| `tiles` | `tiles/`, `tilesets/`, `terrain/` | без обрезки (сетки листов остаются целыми), непрозрачные тайлы и тайлы с альфой на разных страницах |
| `effects` | `effects/`, `fx/`, `vfx/`, `particles/` | обрезка |
| любое имя | задаётся через `"group"` (или `"atlasGroup"`) в `files` | как `units` |

Другие папки (`models/`, `textures/`, ...) не попадают в атлас, если правило `files` не задаёт группу:
3D-меши используют UV за пределами 0..1 и заворачивание. *Вид* — `color`, `normal` (`*_n`, `*_nrm`, `*_normal`,
`normals/`) или `mask` (`*_mask`) — карты нормалей и маски никогда не смешиваются с цветом и никогда не
обрезаются. Никогда не попадают в атлас: `noAtlas`, `"wrap": "repeat"` (а также `*_repeat`, `*_tiling`, `*_wrap`),
изображения больше `maxTextureSize` (после обрезки) и изображение, которое оказалось бы одно в своей группе
(одна страница = никакой экономии на переключении текстур, только отступы). Изображения, на которые где-либо в JSON игры ссылаются как на лист спрайтов
с сеткой кадров (`"sheet": "sprites/tank.png"`), никогда не обрезаются и не поворачиваются, поэтому
uv кадров линейно отображаются на область атласа. Внутри группы изображения одной папки (кадры одного юнита,
одна фракция) остаются на одной странице, если помещаются; страницы ужимаются до наименьшего размера,
который их вмещает. Ключи для файлов: `group`/`atlasGroup`, `noAtlas`, `wrap`, `kind`, `rotate` (разрешить
поворот на 90°, по умолчанию выключен, чтобы направления никогда не поворачивались), `trim`, `mips`, `splitAlpha`, `padding`,
`extrude`, `mesh`, `tight`, `frames`, `meshVertices`; те же ключи (кроме `group`) работают для групп
в `groups`.

**Меши, плотная упаковка, листы с кадрами** (по умолчанию всё выключено, только для цветных изображений):

```json
"files": { "sprites/*": { "frames": true, "tight": true, "rotate": true, "meshVertices": 8 } }
```

- `mesh` — выпуклый многоугольник вокруг видимых пикселей (alpha ≠ 0) каждого обрезанного изображения, не более
  примерно `meshVertices` вершин (4..32, по умолчанию 8), консервативный (каждый видимый пиксель внутри),
  сохраняется, только если экономит не менее ~12% прямоугольника. Спрайты рисуются этим многоугольником: меньше
  перерисовки на большей частью прозрачных изображениях.
- `tight` (подразумевает `mesh`) — упаковка по этим многоугольникам вместо прямоугольников: изображение может оказаться в
  пустом углу прямоугольника другого изображения (`padding` по-прежнему разделяет фигуры; тексели, которых касается
  многоугольник, плюс `max(extrude, 1)` вокруг него принадлежат его изображению). Раскладка прямоугольниками тоже
  вычисляется и сохраняется, если она не больше, так что страницы никогда не растут (обычно страницы на 15–20% меньше
  для диагональных / круглых спрайтов и почти без выигрыша для спрайтов, заполняющих свои прямоугольники). Страница плотной
  группы корректна только при отрисовке через меши. Выключено в группах с `mips`. Требует времени сборки:
  около секунды на 500 уникальных кадров (поиск по битовым строкам), прямоугольники занимают миллисекунды.
- `frames` — лист спрайтов (`"sheet"` + `"frame": [w, h]` в JSON игры, `h` = `w`, если
  не указано, без `frame` = всё изображение) разбивается на кадры, каждый из которых обрезается, поворачивается, получает меш
  и упаковывается отдельно. Лист, используемый с разными размерами кадров или размер кадра которого не
  делит его нацело, сохраняется целым (и без обрезки, с предупреждением при сборке).

Кто что рисует: 2D-рендерер спрайтов (блоки `sprite`, `Rts2DView`) рисует обрезанные, повёрнутые,
с мешами и разбитые на кадры изображения прямо со страниц (`TextureCache::resolveSprite` +
`SpriteBatch::spriteShape`: билборды, вертикальные и наземные спрайты, декали на неровной земле, отбрасыватели
солнечной тени). Все остальные потребители (`TextureCache::resolve`, UI, частицы, оверлеи) получают
такое изображение пересобранным в отдельную текстуру (через меш), как раньше — корректно, но без
экономии страницы; изображения, которые лежат на странице как есть, по-прежнему разрешаются в страницу.

**В паке.** Изображения, попавшие в атлас, удаляются; `_atlas/` зарезервирован и содержит страницы
(`_atlas/<group>-<n>.rtex`) и `_atlas/atlas.json`:

```json
{ "version": 1,
  "pages": [ { "file": "_atlas/units-0.rtex", "group": "units", "w": 1016, "h": 864, "alpha": true, "mips": false } ],
  "textures": { "units/orc/grunt/walk_0.png": [0, 3, 3, 30, 38, 33, 29, 96, 96, 0] } }
```

Необязательно, если используются: `"meshes": { "<path>": [x0, y0, x1, y1, ...] }` — выпуклый меш в пикселях
содержимого × 16 (сетка в 1/16 пикселя, исходная ориентация, начало координат в левом верхнем углу обрезанного содержимого), и
`"sheets": { "<sheet>": [cols, rows, sourceW, sourceH] }` — лист с кадрами, кадр `i` которого
(построчно) — это запись текстуры `"<sheet>#<i>"` (её `sourceW x sourceH` = один кадр, смещения
внутри кадра).

Запись текстуры: `[page, x, y, w, h, offsetX, offsetY, sourceW, sourceH, rotated]` — целые пиксели.
`(x, y, w, h)` — обрезанное содержимое на странице (при `rotated` = 1 оно занимает `h x w` с поворотом на 90°
по часовой стрелке); `(offsetX, offsetY)` — его положение в исходном изображении `sourceW x sourceH`, поэтому
опорные точки, заданные в пикселях исходного изображения, остаются верными. `.rtex`: 24-байтовый заголовок (`RTEX`, версия,
ширина, высота, флаги: 1 — альфа, 2 — мипы, 4 — строки с фильтром разности слева) + строки RGBA8 сверху вниз,
неумноженная альфа. Для одного и того же входа результат идентичен побайтно.

**API времени выполнения** (`engine/atlas/TextureLibrary.h`, линковать `aiverse_atlas`):

```cpp
atlas::TextureLibrary lib(dev, [](const std::string& p, std::string& o) { return platform::readContentFile(p, o); });
const atlas::TextureRef* t = lib.get("units/orc/grunt/walk_0.png");   // nullptr if missing
// quad: t->w x t->h source pixels at (t->offsetX, t->offsetY) from the original image's top-left
// (pivot in original pixels: pos - pivot + offset); UVs t->uv = TL, TR, BR, BL (rotation applied);
// t->texture equal for images on one page -> batch by it; t->opaque -> draw without blending.
// t->mesh != nullptr: draw that polygon (content pixels; + offset, map with mapUV), never the quad.
// A framed sheet comes back rebuilt as its own texture.
```

`atlas::mapUV(*t, px, py, u, v)` отображает точку в пикселях исходного изображения в текстуру (с учётом обрезки и
поворота) — например, углы кадров листа. Для рендерера, который уже отображает кадры через
прямоугольник (`u0 + (u1 - u0) * lu`), прямоугольник листа в атласе — это `t->uv[0..1]` .. `t->uv[4..5]`.
`render::TextureCache::resolve()` 2D-рендерера спрайтов/тайлов уже понимает атласы:
изображение в атласе разрешается в текстуру страницы + свой прямоугольник (листы спрайтов никогда не обрезаются, поэтому
uv кадров остаются точными); обрезанное, повёрнутое, с мешем или разбитое на кадры изображение пересобирается в отдельную текстуру.
`resolveSprite(path, nearest, base, frameW, frameH)` вместо этого возвращает его на своей странице
(`TextureRef::sprite`: кадры с областью, мешем и текстурой страницы) для рендереров, которые рисуют
`render::spriteShape(ref, uvRect, shape)` — выпуклый многоугольник в параметрах прямоугольника плюс аффинное отображение
в uv страницы (`SpriteBatch::quad` / `polygon` / `casterPolygon`).
Обычные изображения (не в атласе) возвращаются тем же способом (собственная текстура, полные UV, без обрезки). Пиксели CPU
исходного изображения: `lib.loadImage(path, img)` или `atlas::ImageSource` (его использует UI, поэтому RmlUi
`<img src>` и декораторы продолжают работать с файлами из атласа).

**Отчёт сборки.** `aiversebuild` выводит статистику атласа и записывает `size-report.json` рядом с
`size-report.txt` (`<out>/<target>/`): `pack` {rawBytes, packBytes, entries, duplicates, top[]} и
`atlas` {enabled, profile, maxPage, candidates, atlased (кадры листов с кадрами считаются по одному), framedSheets, duplicates, pages, occupancyPercent,
sourceBytes, atlasBytes, storedBytes, bytesSaved, gpuBytesBefore, gpuBytesAfter,
textureBindsBefore, textureBindsAfter, groups[] {group, textures, unique, pages,
occupancyPercent}, excluded[] {path, reason}}. Предпросмотр: `assetpipe atlas --profile web -o <dir>
<project> engine/assets=engine` записывает страницы в PNG вместе с манифестом и отчётом.

### splash

Все клиенты — обычный, акторы (от первого и третьего лица, гонки, королевская битва) и воксельные проекты —
показывают один и тот же экран загрузки при запуске и при загрузке карт (`engine/splash/SplashBoot.h`), а каким
он будет, решает только проект:

| Значение `"splash"` | Экран загрузки |
|---|---|
| нет, `null`, `true`, `"default"` | экран движка (собирающаяся отметка AIVERSE) |
| `false`, `"none"`, `{"enabled": false}` | никакого: игра грузится и сразу показывается (без логотипа, полосы и подписей) |
| `{"base": "engine", ...}` | экран движка с заменой этих ключей; объекты сливаются, так что `{"base": "engine", "progress": {"color": "#00c0ff"}}` только перекрашивает полосу, `"logos": [...]` меняет картинки, `"minSeconds": 0` уходит сразу после загрузки |
| любой другой объект | свой экран проекта (формат ниже); только фон — `{"background": "#000000", "progress": false}` |

`"mapLoading"` внутри блока выбирает экран последующих загрузок карт: `"same"` (по умолчанию), `false` (никакого)
или любое значение из таблицы. Картинки движка берутся из пакета (`content/engine`), а в запусках разработки
прямо на папке проекта — из `engine/assets` движка (`platform::setEngineAssetsDir`). Выбор:
`splash::resolveBlock` / `resolveMapBlock` / `projectSpec`, тест `splash_choice`.

```json
"splash": {
  "background": "#0a0f16",
  "image": "branding/splash_bg.png", "fit": "cover", "scale": 1,     // base layer (optional)
  "logos": [
    {"image": "branding/studio.png", "start": 0, "duration": 2.2, "scale": 0.34,
     "animation": {"fadeIn": 0.5, "fadeOut": 0.45, "zoom": {"from": 0.85, "duration": 0.8}}},
    {"image": "branding/logo.png", "start": 2.0, "scale": 0.55, "anchor": [0.5, 0.46],
     "animation": [{"t": 0, "opacity": 0, "scale": 0.7}, {"t": 0.6, "opacity": 1, "scale": 1, "ease": "out"}]},
    {"sheet": "branding/coin_sheet.png", "frame": [128, 128], "count": 8, "fps": 14, "start": 2.5, "scale": 0.2}
  ],
  "minSeconds": 3.5, "maxSeconds": 6, "loop": false, "skippable": true, "fadeOut": 0.5, "waitForContent": false,
  "progress": {"show": true, "color": "#e8b640", "track": "#ffffff26", "position": "bottom", "width": 0.36, "height": 5, "offset": 0.08},
  "native": {"image": "branding/logo.png", "background": "#0a0f16", "scale": 0.35, "androidIcon": "branding/splash_icon.xml"}
}
```

- **Слои** (сначала базовое изображение, затем `logo` / `logos` по порядку, последующие поверх): статичное `image`,
  анимация из `frames` (список изображений) или листа спрайтов `sheet` (`frame` [w, h], `count`, кадры по
  строкам слева направо), проигрываемая с частотой `fps` (`loopFrames`, по умолчанию true). `fit`: `contain` (по умолчанию для
  логотипов), `cover` (по умолчанию для базового слоя), `center` (пиксели изображения × dpi), `stretch`; `scale`
  умножает вписанный размер; `anchor` — центр на экране (в долях). `start` / `duration`
  в секундах (duration 0 = до конца заставки).
- **animation**: ключевые кадры `[{"t", "opacity", "scale", "x", "y", "rotate" (градусы), "ease":
  linear|in|out|inOut}]` (t от начала слоя; свойство интерполируется между ключами, которые его
  задают) или эффекты `{"fadeIn", "fadeOut", "fade", "pulse": amount | {"amount", "period"},
  "rotate": deg/s, "slide": "bottom" | {"from", "distance", "duration"}, "zoom": from | {"from",
  "duration"}, "keyframes": [...]}` — их можно сочетать.
- **Время**: заставка уходит, когда загрузка завершена и прошло `minSeconds` (по умолчанию: до
  конца последнего слоя с длительностью, так что последовательность логотип студии → логотип игры проигрывается один раз);
  `maxSeconds` ограничивает этот минимум (но никогда не загрузку). `loop`: повторять последовательность, пока загрузка
  длится дольше. `skippable`: касание / клик / клавиша прерывает минимум. `fadeOut`: плавный переход в меню.
- **Полоса прогресса**: реальный прогресс загрузки — шаги запуска клиента (правила, рендерер, модели
  и текстуры всех типов, эффекты, аудио, UI), а при `waitForContent` (раздельные сборки) — загрузка
  каждого фрагмента пака (`platform::contentProgress`).
- **Заставка в движке**: рисуется через RHI с первого кадра (`engine/splash`, один конвейер текстурированного
  квада, GLSL + MSL; изображения декодируются по одному за кадр и ограничены 2048 px), поэтому работает на
  любом GPU. `AIVERSE_SPLASH=off` загружает по-старому; с `--map` заставка показывается только на время загрузки
  (`AIVERSE_SPLASH=full` проигрывает её целиком).
- **Нативный экран запуска** (показывается ОС до старта движка; статичное изображение на цветном фоне —
  `native`, иначе первый логотип на `background`): iOS `LaunchScreen.storyboard` + `LaunchImage` /
  `LaunchBackground` в каталоге ассетов; тема заставки Android 12+ (`windowSplashScreenBackground`,
  `windowSplashScreenAnimatedIcon`: логотип или ваш анимированный векторный drawable `androidIcon`) и
  drawable `windowBackground` для версий до 12, тема activity `@style/AiverseLaunchTheme`; web: HTML/CSS-заставка
  в `platform/web/shell.html` с прогрессом загрузки `.data` до запуска wasm; macOS и
  Windows: цвет фона окна.
- Раздельные сборки всегда держат изображения заставки в базовом паке.
- **Значения по умолчанию**: игра без блока `splash` получает экран загрузки движка — собирающийся знак AIVERSE
  на `#0e0f11` с оранжевой полосой прогресса (`splash::defaultBlock()`, графика в
  `engine/assets/branding`); `"splash": false` теперь убирает экран загрузки совсем (раньше оставался только цвет фона: для этого пишите `{"background": "#..", "progress": false}`).
  Без `icons` сборка использует знак AIVERSE на белом (`branding::defaultIcon`). Оба
  рисуются из одной геометрии: `tools/branding/logo/make_logo.py` (также иконка редактора,
  `apps/editor/branding`).
- Пример: `templates/skirmish` (графика сгенерирована `tools/templates/brandart.py`, CC0).

- **Mushroom Wars 2**: деревни `garrison` + `lanes` вместо нарисованных вручную `roads`.
- **Война за территорию (State.io)**: `territory` с `claimBy: units` + `startFromRegions`, солдаты с `claim`, города `capturable`, казармы с `autoTrain`, `playerAbilities`, повторяемые технологии `levels`, `victory: territory`.

Размер карты: 4..2048 клеток по стороне. Редактор сохраняет `corners` прямо в карте до 256x256 клеток, а для больших — в
`cornersFile` (`maps/<map name>.r16`, рядом с картой); загрузчики (игра, headless, редактор, MCP) читают
файл через читатель контента, поэтому это работает и из паков.

## Материалы ландшафта (визуальный блок `terrain`)

Только представление (`modules/rts/view/RtsTerrainRender.*`). Необязательные ключи в том же блоке `terrain`, что и оверлеи
(rules.json или game.json; game.json побеждает по каждому ключу). **Без них каждая игра выглядит точно так же, как раньше** (вершинные
цвета по виду клетки, плато с резкими стенами утёсов, пандусы, мягкие переходы цвета, кромка, один лист воды).

```json
"terrain": {
  "layers": [                                   // up to 4 tiling splat layers (world-space, mipmapped, wrap)
    {"id": "snow",  "texture": "textures/terrain/snow_repeat.png", "normal": "textures/terrain/snow_n_repeat.png", "scale": 6, "tint": [1, 1, 1]},
    {"id": "earth", "texture": "textures/terrain/earth_repeat.png", "scale": 4}
  ],
  "cells": {"grass": {"layer": "snow", "color": [0.9, 0.93, 0.97]},  // layer id, or {layer, color (vertex colour override)}
            "sand": "earth", "ramp": "earth", "rock": "earth", "blocked": "earth", "lakebed": "earth", "shallows": "earth", "dug": "earth"},
  "cliff": {"texture": "textures/terrain/rock_repeat.png", "normal": "textures/terrain/rock_n_repeat.png",
            "scale": 3, "tint": [1, 1, 1], "slope": [0.3, 0.55]},     // blended in where 1 - normal.y is in that range
  "splatStrength": 1,                           // 0..1: mix of the textures over the vertex colours
  "water": {"mode": "auto", "color": [0.22, 0.45, 0.62, 0.78], "offset": -0.12},
  "lod": "auto", "lodRange": 128                // heightfield maps: CDLOD on above 256 cells per side ("on"/"off")
}
```

| ключ | значение |
|---|---|
| `layers` | слои сплата (≤ 4): альбедо `texture` (sRGB), необязательная `normal` (в касательном пространстве, +Y вверх), `scale` — мировых единиц на повтор, `tint`. Загружаются через `TextureCache::resolve(path, …, tiling)`: **никогда не берутся со страницы атласа** (называйте их `*_repeat.png`, чтобы упаковщик тоже их пропускал) |
| `cells` | вид клетки → id или индекс слоя; виды: `grass` (.), `sand` (, нельзя строить), `ramp` (/), `rock` (R), `blocked` (#), `lakebed` (~), `shallows` (=), `dug` (пол из выкопанной породы). `color` переопределяет вершинный цвет вида на всех уровнях качества |
| `cliff` | текстура на стенах утёсов и крутых склонах (Medium: одна проекция, High: трипланарная + карта нормалей) |
| `water.mode` | `sheet` = одна плоскость под всей картой (классика, по умолчанию для карт с уровнями утёсов), `bodies` = каждая связная водная область получает свою поверхность чуть ниже самого низкого берега (озёра на плато, долины на картах с полем высот; по умолчанию для карт с полем высот), `auto` |
| `lod`, `lodRange` | большие карты с полем высот: чанки рисуются с шагом 2^k клеток (k ≤ 4) в зависимости от расстояния до камеры, с геоморфингом в вершинном шейдере и юбками против трещин |

**Ключ карты `terrainMaterial`** (необязательный, визуальный): строки из `0`..`3` (индекс слоя) по клеткам, другие символы = по виду
клетки. Рисуется окном редактора **Рельеф** или `terrain_material`.

**Уровни качества** (меню паузы *Текстуры земли*, `Renderer3D::materialQuality()`, ограничен значением устройства по умолчанию;
`AIVERSE_TERRAIN=low|medium|high` переопределяет для тестирования): Low = вершинные цвета (слабые Mali / Adreno / PowerVR, а также любая
игра без `layers`), Medium = текстуры сплата + текстура утёсов, High = + карты нормалей и трипланарные утёсы. Шейдеры:
`modules/rts/view/RtsTerrainShaders.h` (GLSL + MSL, солнце + мягкие тени + точечные источники + облака, как в освещённом шейдере).

**Производительность**: ландшафт разрезан на чанки 32x32 клетки с отсечением по пирамиде видимости; редактор перестраивает только чанки, клетки которых
изменились; во время матча ничего не перестраивается: ресурсные поля, крип и (на картах с полем высот) туман войны читаются
шейдером из небольших поклеточных текстур. `AIVERSE_TERRAIN_STATS=1` выводит чанки / треугольники / время кадра. Пример:
`templates/frostcrown` (сгенерированные текстуры CC0, `tools/terrain/make_textures.py`).

**Редактор / MCP** (карты с полем высот, `apps/editor/core/TerrainOps.cpp`, окно **Рельеф**):
`terrain_sculpt {op: raise|lower|smooth|flatten|noise|set, x, y | points, radius, strength, seed}` (первая лепка
создаёт углы из видимой поверхности: уровни утёсов, пандусы, точные высоты), `terrain_heights {points | grid}`,
`terrain_material {layer, x, y, radius}`, `heightmap_export {file, scale?}` / `heightmap_import {file, scale, offset}`
(16-битный PNG в оттенках серого, `(w+1) x (h+1)` пикселей, высота = offset + value / 65535 * scale). Углы чисто визуальные, если только
`terrain.model` в правилах не равен `heightfield` (см. ниже).

### Детальная поверхность (рельеф мельче клетки)

`"terrain": {"style": "smooth"}` в rules.json / game.json рисует ландшафт по визуальной карте высот с несколькими
отсчётами на клетку вместо одной высоты на угол клетки: скошенные утёсы с органичными очертаниями, скруглённые плато и
пандусы на картах с уровнями утёсов, бикубический рельеф с мелким шумом на картах с полем высот, попиксельное освещение, смешивание материалов с
разрешением мельче клетки с автоматической скалой на крутых склонах. Значение по умолчанию `"classic"` сохраняет старый вид. Карта может нести
собственную нарисованную детализацию: `terrain.detail` = `{"scale": 4, "file": "maps/<name>.detail.r16", "splat": "..."}` (int16 LE,
1/16 единицы, `(w*k+1) x (h*k+1)`). Ключи настройки — `terrain.detailLook`. Редактор / MCP: `terrain_detail`, `terrain_sculpt`
(мельче клетки, эрозия, штамп), `terrain_paint_material`, `heightmap_import/export {detail: true}`. Полное описание и
числа: `docs/terrain.md` § Detail surface. Примеры: `starfall` (утёсы), `metaltide` (рельеф), `frostcrown`.

## Ландшафт с полем высот

`rules.terrain.model: "heightfield"` + карта с `terrain.corners` / `cornersFile` (без углов карта
играется как `"levels"`). Угол `(x, y)` — левый верхний угол клетки `(x, y)`; высоты в 1/16 мировой единицы.
Всё целочисленное / с фиксированной точкой и детерминированное.

- **Поверхность**: высота земли в любой точке — билинейная интерполяция между 4 углами её клетки; наземные юниты (и
  `y` каждого подвижного юнита) стоят на ней; снаряды стартуют с высоты земли стрелка + 0.6 и целятся в
  землю цели + 0.4.
- **Склоны**: крутизна клетки = max(длина градиента, самое крутое ребро клетки), в единицах высоты на клетку.
  Юнит не может войти в клетки круче его `move.maxSlope` (или `terrain.maxSlope` его слоя; `sand` для
  `layer: "sand"`); поиск пути, локальное уклонение и появление юнитов следуют тому же правилу. Правила утёсов/пандусов
  (`levels`, `/`) заменяются склонами. Строениям нужны клетки не круче `terrain.buildSlope`.
- **Скорость**: `speed * (1 - uphillSpeed * climb)` при подъёме, `* (1 + downhillSpeed * descent)` при спуске, где
  climb/descent = изменение высоты на клетку вдоль движения; ограничивается диапазоном 0.25..2.
- **Обзор**: линия видимости от `eyeHeight` над клеткой юнита до `targetHeight` над каждой клеткой в радиусе
  обзора; клетка за гребнем скрыта (`heights.blockVision: false` отключает это, воздушные юниты видят поверх).
  Наведение выбирает только врагов в клетке, которую видит игрок.
- **Уровень утёса** клетки = floor(высота клетки / `levelHeight`) (0..9), поэтому правила и триггеры, основанные на уровнях, продолжают
  работать. Бонусы дальности / урона / промаха используют точную разницу высот (см. `heights`).
- **Контрольные суммы**: углы и модель входят в хеш состояния только для игр с полем высот.
- **Большие карты** (256x256 клеток и больше): длинные пути используют иерархический поиск пути (кластеры 16x16 с входами
  на границах, уточнение A*), построенный в начале матча и перестраиваемый только вокруг строений, блокирующих клетки.
  `aiverse_headless --project DIR --bench-paths N` замеряет время запросов пути; `python3 tools/templates/mapgen.py --big 1024
  <scratch>/maps/big.json` записывает тестовую карту 1024x1024 (не кладите её в `templates/`).

MCP: `map_info.heightfield` (`corners`, `min`, `max`, `storage`, `model`), `map_heightfield {"enabled"}` добавляет плоское
поле высот или удаляет его, `map_validate` предупреждает, когда модель — heightfield, а у карты нет углов, и отмечает
юниты/строения, стоящие на слишком крутых для них склонах. Лепка: `terrain_sculpt`, импорт/экспорт PNG карты высот (см. «Материалы ландшафта»). Представление рисует рельеф по углам (два треугольника на клетку, диагональ (0,0)-(1,1)); `RtsView::heightAt` следует тем же треугольникам, поэтому модели и оверлеи стоят на нарисованной земле.

## Планеты: визуальные ключи (блок `world` карты)

Сами тела описаны в `docs/planets.md` §1-2 (`world.bodies`, `kind`, `radius`, `faceSize`,
`seaLevel`, `orbit`, `terrain.faces` / `terrain.corners`, `nereid` — море как водоём NEREID для плавучести и
течений, §1). Что читает только представление:

```jsonc
{"id": "terra", "kind": "planet", ...,
 "visual": {"color": [255, 220, 160],                        // stars: light colour and glow; others: far-away tint
            "atmosphere": {"color": [110, 170, 255], "height": 0.08}}}   // or false; default: on for planets, off for moons
```

- `visual.flora`: деревья и камни TerraWeave на теле (одно место на клетку суши, вид по климату сферы): `{"density": 0..1, "scale": мировых единиц на метр}` или `false`; по умолчанию плотность 0.22 на планетах, на лунах нет, масштаб 0.06.
- `visual.atmosphere.height`: толщина оболочки как доля радиуса (0.005..0.5). Оболочка и дымка используют этот
  цвет; оболочка рисуется начиная с уровня материалов Medium.
- `terrain.faces[f].material`: строки цифр `0`..`3` на каждую грань (`.` = по виду клетки), как
  `terrainMaterial` плоской карты; рисуется через `terrain_material` с `body`.
- Вид поверхности на планетах = визуальный блок `terrain` игры (слои по видам клеток, текстура скал, цвет воды).
- Наложения на поверхность планет используют те же визуальные блоки `terrain.territory` / `dig` / `roads` / `lanes`, что и плоские карты
  (заливка и границы территорий, каменные блоки с жилами / самоцветами и следами копания, клетки дорог, линии и дороги карты `roads` между
  зданиями, натянутые на поверхность). Территории, копаемая порода (символы `diggable` в `terrain.faces[f].rows`), комнаты,
  заявки, захват и линии работают на планетах с теми же ключами правил (docs/planets.md §3).
- Редактор / MCP: `planet_info`; `terrain_sculpt` / `terrain_paint` / `terrain_material` с `body` + `face` + `x`, `y`
  (клетки на этой грани) или `dir` [x, y, z] и `radius` в клетках (3D-кисть, переходит через швы граней).

## Планеты: ключи симуляции (блок `world` карты)

Карта с блоком `world` — это карта планет: тела заменяют `size` / `terrain` / `fields` (docs/planets.md).
Плоские карты не затрагиваются (те же контрольные суммы).

```jsonc
"world": {"start": "terra", "bodies": [
  {"id": "sun", "kind": "star", "radius": 40},
  {"id": "terra", "kind": "planet", "radius": 16, "faceSize": 24, "orbitAltitude": 4,     // shell of move.layer "orbit"
   "orbit": {"around": "sun", "radius": 400, "period": 1200, "phase": 0.1},               // seconds, turns
   "terrain": {"faces": [{"rows": [...], "levels": [...], "fields": {"metal": ["..19.."]}}, ... 6 faces],
               "corners": [ ... 6 * (N+1)^2 ... ] | "cornersFile": "maps/x.terra.r16"}}]},
"players": [{"name": "Blue", "start": {"body": "terra", "face": 4, "x": 12.5, "y": 12.5}}],
"entities": [{"type": "metal_spot", "at": {"body": "terra", "face": 4, "x": 7, "y": 8}}],
"waves": [{"at": {"body": "terra", "face": 0, "x": 3, "y": 3}, ...}]
```

- `kind`: `planet`, `moon` (поверхность: `faceSize` 2..512), `star` (без поверхности). `radius` 2..1200, radius + orbitAltitude
  <= 1500; `orbitAltitude` по умолчанию 0.15 x radius. `orbit.around` должен называть тело, объявленное раньше. Не более 16 тел.
- Визуальная детализация каждого тела (`docs/terrain.md` "Planets"): `terrain.style` (`smooth` / `classic`, по умолчанию как в игре),
  `terrain.detailLook {scale, roughness, craters}`, `terrain.detail {scale, file}` (int16 LE в единицах 1/256, 6 x
  (faceSize*scale+1)^2, пишется редактором). Только для представления: симуляция и контрольные суммы их игнорируют.
- Позиции на картах планет задаются как `{body, face, x, y}` (координаты клеток на этой грани, 0..faceSize); `[x, z]` — ошибка.
  Поля задаются на грань (`fields` в грани: строки цифр на каждый ресурс) или как `fields: [{center: {body, face, x, y}, radius}]`.
- Строки / уровни граней используют символы плоской карты; `rules terrain.model: "heightfield"` заставляет углы задавать уклоны
  (подъём на единицу мира), скорость и линию видимости — точно так же, как на плоских картах с картой высот.
- `cornersFile`: сырые int16 LE, грани 0..5, каждая (N+1)^2 по строкам; редактор пишет его для тел больше 257² углов.
  Углы на швах должны совпадать на каждой грани, которая их хранит (map_validate предупреждает; загрузчик усредняет).
- Юниты: `move.layer: "orbit"` (летает по орбитальной оболочке, свободно движется по большим кругам, видит поверхность под собой, может быть поражён
  только оружием, у которого в `targets` указано `"orbit"`), `move.transitSpeed` (единиц мира/с для перелётов; по умолчанию 10 x speed).
- Команда `kCmdTransit` (units = орбитальные юниты, `param` = индекс целевого тела): перелёт по времени, вычисленный по положениям тел
  в момент отправления, прибытие на обращённую сторону оболочки цели; события `kEvTransitStart` / `kEvTransitEnd`.
- Правило `movement.planetHpaCells` (по умолчанию 65536): тела, у которых не меньше клеток (6 x faceSize²), используют иерархический
  поиск пути для дальних поездок (0 = каждое тело).
- Сооружения стоят в пределах одной грани (контур, пересекающий шов, строить нельзя). Юниты на разных телах встречаются только
  через орбитальный слой. Пример: `templates/planets`.

## Генерация карт (`generate`)

Карту может сгенерировать движок вместо того, чтобы рисовать её вручную (или перед этим): детерминированный целочисленный код
(`modules/rts/gen/`), поэтому один и тот же запрос даёт **бит-в-бит одинаковую карту на каждой платформе**. Генерация выполняется при старте матча
(lockstep-мультиплеер, серверный арбитр, headless, повторы: каждый участник заново генерирует ту же карту из сида матча),
в редакторе (окно **Генерация**) и через MCP (`map_generate`, `gen_presets`), где результат можно запечь
в статическую карту.

```jsonc
"generate": {
  "preset": "continents",          // gen_presets: built-in + rules "mapgen.presets"
  "seed": "match",                 // "match" = the match seed (a new map every match), or a number (fixed map)
  "players": 4,                    // 1..8; the map's players array is resized to it (names/factions/teams kept)
  "symmetry": "auto",              // auto | none | point | mirror | mirror-y | mirror4 | rot4 | rotational
  "template": "maps/valley.json",  // optional: map whose player-1 objects are the start kit and whose neutral objects decide what is placed
  "params": {"water": 0.3, "trees": 1.5}   // overrides of the preset's params
}
```

- Плоские карты: `generate` верхнего уровня. Планеты: `world.bodies[].generate` (пресеты `rocky`, `ocean`, `moon`; см. docs/planets.md §4).
- Что пишет генератор: `size`, `terrain.rows` (`.` `~` `#` `,` `=` `/` `R`, копаемые символы для пещер), `terrain.levels`
  (правило `terrain.model` `levels`), `terrain.corners` (`heightfield`), `fields`, `entities`, `regions` (если они есть в шаблоне),
  `roads` (игры с гарнизонами), `terrainMaterial` (по биому и id визуальных `terrain.layers` игры: grass / forest / sand /
  dirt / earth / rock / snow / mud ...), `start` игроков и сводный блок `generated` (пресет, сид, симметрия, старты, длины путей
  между стартами, измеренные A* движка, `connected`, `pathSpread` в промилле, число объектов, `warnings`).
  Все прочие ключи карты (victory, triggers, waves, lighting, ...) сохраняются.
- **Объекты берутся из собственных типов игры**: объекты игрока 1 в шаблоне (или в самой карте) — это стартовый набор, он расставляется
  каждому игроку в симметричной системе координат (с поворотом на четверть оборота, чтобы контуры оставались выровненными); нейтральные объекты подсчитываются
  возле баз шаблона / вдали / в центре и расставляются так же (шахты и металлические точки возле каждой базы, леса в
  лесных биомах, лагеря крипов подальше от баз, здания-гарнизоны, порталы...). Без шаблона решают правила:
  сооружение, производящее рабочих, + 4 рабочих (или юнит `key`, или самый большой гарнизон), узлы ресурсов, места `structure.on`,
  порождатели полей, нейтральные крипы `neutral`. Ресурсные `fields` шаблона воспроизводятся (ближние сохраняют своё смещение).
- **Честные старты**: старт игрока 1 выбирается в фундаментальной области симметрии и копируется во все её образы; области
  баз выравниваются (один уровень скал / пологие углы, никогда не вода); старты связаны между собой (пандусы прорезаются сквозь скалы,
  отмели `=` — через воду, выровненная дорога — на картах высот, самый дешёвый маршрут — сквозь копаемую породу); объекты никогда не перекрывают
  маршрут между стартами (проход разблокировки их удаляет); результат проверяется поиском пути. `"connect": "none"`
  оставляет острова раздельными (морские / воздушные игры).
- **Детерминизм**: только целые числа / `Fixed` (никаких float), хеширование с сидом, упорядоченные контейнеры; генератор выполняется внутри
  `RtsModule::setup` до загрузки карты, поэтому повторы и серверный арбитр генерируют карту одинаково. Эталонные хеши
  пресетов лежат в `tests/tests.cpp` (`gen_golden_maps` и соседние): изменение вывода генератора будет видно там.
  Тот же сид + параметры + версия движка = та же карта.

### Пресеты

| `islands` | islands | морская / архипелаг | `size` [96,96], `water` 0.62, `islands` 4 (нейтральные острова), `islandSize`, `connect` shallows |
| `highlands` | highlands | любая | `size` [80,80], `ridged` 0.7, `levels` 2, `peaks` 0.9 (клетки выше этого квантиля суши становятся `#`), `relief` 10 |
| `canyons` | canyons | любая | `size` [80,80], инвертированный гребневый шум, `levels` 2, `plateau` 0.6, `scale` 30 |
| `classic` | classic | наземные карты Warcraft / Red Alert | `size` [64,64], `water` 0.1, `rivers` 0.4, `levels` 1, `plateau` 0.3 |
| `metal` | highlands | Total Annihilation (карта высот, металлические точки) | `size` [72,72], `relief` 6, `levels` 0, `baseRadius` 12, `thermal` 10, `erosion` 4 |
| `caves` | caves | Dungeon Keeper (`diggable`) | `size` [48,32], `gold` 0.03 / `gems` 0.004 (доля породы, которая является жилой / бесконечным пластом), `bedrock` 0.06, `caverns` 0.06 |
| `lanes` | lanes | lane battlers / MOBA | `size` [32,64], `lanes` 3, `laneWidth` 4, `bend` 0.35 (везде остальное — порода) |
| `field` | lanes, `open` | Mushroom Wars 2 (гарнизоны + дороги) | `size` [44,28], `obstacles` 0.12, `roads` из шаблона |
| `rocky` / `ocean` / `moon` | planet | целые карты планет или рельеф одного тела | `faceSize`, `water` 0.25 / 0.7 / 0, `relief`, `ice` (полярные шапки), `craters` (луна), `layout`, `moonResources`, `baseRadius` (луна 11), `heights` (`terraweave` по умолчанию: рельеф и климатические биомы TerraWeave; `fbm`: прежний шум) |

**Карты планет.** Планетный пресет в `generate` карты строит весь блок `world`: тела (и их орбиты,
визуальные параметры) берутся из `world` карты-шаблона (например, `templates/planets`), иначе — солнце + планета + луна. Каждое тело с поверхностью
получает `rows`, `corners`, `material` для каждой грани; игроки получают `start: {body, face, x, y}`; объекты записываются с `at`.
- `layout: "shared"` (по умолчанию): все игроки на стартовом теле, вращательная симметрия вокруг полярной оси: точная для 2 и 4
  игроков (повороты на половину / четверть оборота отображают кубосферу саму на себя, высоты симметризуются угол за углом), усреднённая по
  поворотам для 3, 5+ (`generated.symmetry`: `polar-exact` / `polar`). Старты у экватора в середине каждого сектора долготы,
  вдали от швов граней и неровной поверхности; области баз выравниваются; там, где поверхность не связана, прокладываются выровненные дамбы.
- `layout: "separate"`: каждый игрок на собственной одинаковой планете (тот же рельеф, те же объекты), планеты обращаются вокруг звезды с
  равными фазами; игроки встречаются через юниты орбитального слоя (предупреждение, если в правилах таких нет).
- Объекты: объекты игрока 1 шаблона (смещения измеряются на его теле, через швы граней) — это стартовый набор; нейтральные объекты
  возле баз шаблона / вдали / на лунах подсчитываются и воспроизводятся (`objects[].moon`, `objects[].pole`); луны получают
  `moonResources` (по умолчанию 2) x свою долю. `generated.nearResources` перечисляет ресурсные объекты в пределах `nearRadius` от
  каждого старта (равные по построению; иначе предупреждение).
- Честность: сгенерированная карта загружается в симуляцию, и `MapGrid::findPath` движка измеряет наземный путь
  между каждой парой стартов (`generated.paths`, `connected`, `pathSpread` = разброс расстояния каждого игрока до ближайшего
  соперника, в промилле).
- Только одно тело: `world.bodies[].generate` (рельеф + найденные места стартов, без объектов), как и раньше.

`aiverse_headless --project templates/planets --generate rocky --seed N --players 3 [--gen-params '{"layout": "separate"}']`.

Все параметры (любой пресет): `shape`, `size` [w, h] (16..1024; собственный размер карты важнее, если не задан `params.size`), `water`
(доля углов ниже уровня моря), `rivers` (0..1: накопление стока, прорезаемое в реки), `lakes` (глубина впадины, которая остаётся озером),
`shallows` (вода настолько близко к поверхности становится `=`), `levels` (уровни скал 0..9), `plateau`, `peaks`, `relief` (единицы мира),
`scale` (размер деталей в клетках), `octaves`, `roughness`, `ridged`, `warp` (искажение области), `thermal` / `talus` (термическая эрозия),
`erosion` / `erosionRate` (эрозия по мощности потока), `moisture`, `temperature`, `latitude` (биомы), `baseRadius`, `startSpread`
(0.2..1 от наибольшего возможного расстояния между стартами), `startJitter`, `starts` [[x, y], ...] (явно), `kit` [{type, offset,
count, garrison}], `objects` [{type, near, far, centre, owner, garrison, amount}] (переопределение по типу), `trees` / `resources`
(множители количества), `nearRadius`, `fieldRadius`, `fieldsFar`, `regions` / `regionsPerPlayer` (регионы Вороного), `roads`, `connect`
(`ground` | `shallows` | `none`), `border` (заблокированная кромка), `fineHeights` (визуальные высоты клеток внутри уровня), `visualCorners`
(писать углы в играх без карты высот), `maxPathSpread` (порог предупреждения без симметрии, в промилле).

Игры добавляют пресеты в rules.json: `"mapgen": {"presets": {"my_valley": {"title": "Долина", "base": "classic", "params": {"water": 0.2}}}}`.

**Инструменты**: `aiverse_headless --project DIR --generate PRESET [--seed N] [--players N] [--symmetry S] [--gen-params JSON] [--gen-out F]
[--max-seconds 0]` (открытая карта служит шаблоном; `--record` пишет `<replay>.map.json` рядом с повтором, чтобы `--replay` генерировал заново).
Редактор: окно **Генерация** (пресет, сид, игроки, симметрия, параметры; *Сгенерировать* запекает, *При старте матча* пишет
`"seed": "match"`). MCP: `gen_presets`, `map_generate {preset, seed, players, symmetry, params, mode: bake | match | fixed,
useTemplate, keepSize}`.
## Механики достоверности (игра как в оригинале)

Необязательные блоки, с которыми примеры игр играются как их оригиналы (`modules/rts/RtsOriginals*.cpp`). Игра, которая
не использует ни одного из них, сохраняет точно те же контрольные суммы. Эти блоки — единственная реализация своих механик:
написания тех же механик из agent-mech (`armorModel`, `shields` типа, `upkeepResources`, `resourceNode.maxWorkers`,
`"crew": {"accepts"}`, `upgradeGarrison`) — это псевдонимы, которые разбираются в них (см. разделы agent-mech выше).

| блок | где | смысл |
|---|---|---|
| `armor` (псевдоним `armorModel`) | rules | `{"model": "subtract" \| "percent" \| "classes", "perPoint": 0.06, "minDamage": 1, "minShare": 0.2, "negative": "linear" \| "exponential", "base": ["melee", "pierce"]}` — единый конвейер урона для любой игры: `bonus` оружия, щиты, затем модель. `subtract`: StarCraft / AoE с нижней границей (без полного блока: урон - броня, но не меньше урон / 5); `percent`: Warcraft III (снижение = a·k / (1 + a·k)); `classes`: атаки / броня по классам из AoE II (`armors` типа, `attacks` оружия, см. псевдонимы agent-mech выше) |
| объект `health.armor` | type | `{"melee": 1, "pierce": 2}` (или `health.pierceArmor`): два вида брони; оружие выбирает один через `"armorClass": "pierce"`; характеристика `pierceArmor` / `armor2` для технологий |
| `bonus` оружия | type | `{"cavalry": 15, "armored": 10}` дополнительный урон по типам с этим тегом, добавляется до брони (бонусы AoE / SC2) |
| `health.shields` (псевдоним `shields: {max, regen, delay, armor}` типа) | type | щиты поглощают урон первыми (после таблицы урона и бонусов оружия; за вычетом `shieldArmor`, но не меньше нижней границы брони), пробившая их доля идёт дальше в броню и hp; они восстанавливаются на `shieldRegen` в секунду (по умолчанию 2) через `shieldDelay` секунд (по умолчанию 10) без попаданий по щиту (StarCraft) |
| `heroes` | rules | `{"skills": true, "max": 3, "freeFirst": true, "tiers": ["hall", "keep", "castle"], "revive": {"costShare": 0.4, "perLevel": 0.1, "timeShare": 0.6, "maxTime": 110, "maxCost": {"gold": 700}}}` — очки навыков (одно на старте, по одному за уровень; команда `kCmdLearn`), способность `"learnAt": [1, 3, 5]` (по умолчанию) / `[6]` (ультимейт); герою n нужно сооружение из `tiers[n-1..]`; погибший герой снова тренируется как воскрешение (с его уровнем и навыками, дешевле) |
| `upkeep[].resources`, `incomeMult` (псевдоним `upkeepResources`) | rules | содержание только по некоторым ресурсам (золото WC3) и / или на доход в секунду (manpower CoH); правило `"upkeepResources": ["gold"]` — это `resources` по умолчанию для каждой ступени без собственного |
| `resourceNode.maxGatherers` (псевдоним `maxWorkers`) | type | рабочие, добывающие одновременно (рудник WC3 5, поле SC 1); остальные ждут или берут свободный узел поблизости |
| `powerField` / `structure.needsField` | type | `{"id": 0, "radius": 6.5}` на пилонах; сооружения с `needsField` ставятся и работают только внутри собственного поля |
| `queueSlots` | type | число одновременно производимых элементов (реактор) |
| `cost.garrison` (псевдоним `upgradeGarrison`) | type | улучшение / превращение в этот тип стоит юнитов гарнизона (Mushroom Wars 2) |
| `garrison.onCapture`, `garrison.keep` | type | тип, в который он падает при захвате (теряет уровень); юниты, которые при отправке всегда остаются дома (State.io) |
| `clash` | type | юниты в пути сражаются со встреченными враждебными юнитами |
| `playerMods` | type | `{"max": 4, "mods": [{"tags": [...], "stat": "damage", "mul": 1.08}]}` — каждый завершённый изменяет типы владельца (кузницы); мод с `"byCount": [1.5, 1.75, 1.9, 2]` умножает на элемент, соответствующий числу имеющихся (ограничено длиной списка), вместо `mul`^n (оружейные Bunker Wars) |
| `gain`, `perUnit`, `min` ресурса | rules | `"gain": {"kill": 1, "capture": 0.3, "captured": -0.4, "upgrade": 0.2, "lost": 0.45, "defended": 0.01}`; `"perUnit": [{"tags": [...], "stat": "damage", "mul": 1.06}]` за каждую целую единицу запаса (солнца морали) |
| `crew` / `crews` / `killsCrew` оружия | type | `"crew": "grunt"` (или `{"unit": "grunt"}`): машины и орудия с водителем; `killsCrew` (шанс на каждое несмертельное попадание) оставляет их без экипажа (владелец 0); юниты с `crews` занимают любую пустую (Z). `"crew": {"accepts": [tags]}` / `true` (псевдоним agent-mech): юниты с одним из тегов (любой подвижный юнит) тоже могут её занять |
| `infect` | type | `{"by": ["infected"], "spawn": "walker", "count": 3}` — убитый юнитом с тегом восстаёт как тип spawn для убийцы (They Are Billions) |
| `neutral.eats`, `neutral.resurface` | type | пожиратель погружается после стольких убийств и позже возвращается где-нибудь на своём слое (песчаный червь Dune) |
| `crush` | type | `{"tags": ["infantry"]}` — проезд по таким юнитам убивает их (танки по пехоте, юниты по цветкам пряности) |
| `deathField` | type | `{"resource": "spice", "radius": 4, "amount": 120}` — гибель разбрасывает поле ресурса (цветок пряности) |
| `onDeath` | type | нагрузка в месте гибели (взрыв командира) |
| `factions` | type | только эти фракции могут тренировать / строить его (дома Dune, стороны RA) |
| `requiresRegions` | type | тренируется только при таком числе собственных регионов (уровни фабрик Z) |
| `ownsRegion` | type | его регион (и клетки территории) принимают цвет его владельца (State.io) |
| `autoTrain.advance` | type | `false`: автоматически тренируемые юниты остаются дома (рождения Northgard) |
| `cost.growth` | type | стоимость × (1 + growth × число имеющихся) (бесы Dungeon Keeper) |
| `requiresAny` технологии | rules | `{"count": 2, "of": [types]}` — столько разных зданий (эпохи AoE) |
| `regions.requireExplored`, `clearFirst`, `supplyLines` | rules | захват только разведанных / очищенных от крипов регионов (Northgard); точки приносят доход только в секторах, связанных с собственным ключевым сооружением (CoH) |
| `territory.incomePerCell` | rules | доход за каждую собственную клетку (мана Dungeon Keeper) |

Рецепты игр с `storage: "player"` (без товаров в зданиях) берут входы из запаса игрока и зачисляют
выходы туда же: здания, которые собирают ресурсы вокруг себя (лесопилки They Are Billions, хижины Northgard).

### Фундаменты, ловушки, групповые телепорты, заряды (`RtsFidelity.cpp`)

```json
"foundation": {"startHp": 0.5, "decay": 0.25, "floor": 0.5, "lostWithBuilding": true},   // or just true
"types": {
  "concrete": {"structure": {"footprint": [1, 1], "terrain": "rock"}, "foundation": true, "cost": {"credits": 5, "time": 2}},
  "wall":     {"weathers": false, ...},
  "gas_trap": {"structure": {"footprint": [1, 1]}, "health": {"max": 200},
               "trap": {"radius": 0.8, "charges": 5, "rearm": 8, "armTime": 0, "hidden": true, "revealFor": 4, "removeWhenEmpty": true,
                        "layers": ["ground"], "tags": ["hero"],                          // trigger filter (effect filter keys; or "trigger": {...})
                        "effects": [{"type": "area", "radius": 2, "lifetime": 5, "trigger": "periodic", "effects": [{"type": "damage", "amount": 18}]}]}},
  "queen":    {"abilities": [{"id": "inject", "target": "unit", "energy": 25, "smart": "ownProducer",
                              "effects": [{"type": "status", "status": "injected", "duration": 29, "affects": "own", "kind": "structure"}]}]}
},
"statuses": {"injected": {"onExpire": [{"type": "addCharges", "amount": 3, "limit": 19, "affects": "own"}]}},
"playerAbilities": [{"id": "chronoshift", "target": "pointPair", "effects": [{"type": "teleportGroup", "radius": 1, "maxTargets": 1, "tags": ["vehicle"], "affects": "own", "duration": 180}]}]
```

- **Бетон (Dune II)**: поставленное сооружение `foundation` превращает свои клетки в бетон владельца (`MapGrid::foundation`,
  рисуется блоком `terrain.concrete` представления: `color`, `seam`, `alpha`, `texture`) и исчезает (событие `kEvPaved`).
  Бетон ничего не блокирует. Сооружение, достроенное при b = доле его клеток не на собственном бетоне, получает не больше
  `1 - b·(1 - startHp)` своего hp и выветривается на `decay·b` от максимального hp в минуту вплоть до `1 - b·(1 - floor)`
  (ремонт поднимает его, но выветривание продолжается). `weathers: false` освобождает тип от этого. Сооружения стартовой карты стоят на
  бетоне; разрушенное сооружение уносит свой бетон с собой (`lostWithBuilding`). Только плоские карты. ИИ держит несколько свободных
  забетонированных клеток возле базы и ставит здания в первую очередь на бетон.
- **Ловушки**: сооружение с `trap` применяет свои `effects` к ближайшему юниту, прошедшему фильтр срабатывания (по умолчанию вражеские наземные и воздушные
  юниты), в пределах `radius` (цель = жертва, точка = её позиция, заклинатель = ловушка), затем ждёт `rearm`
  секунд; `charges` (0 = без ограничений) заканчиваются, и ловушка исчезает (`removeWhenEmpty`). Ловушки `hidden` невидимы для
  врагов (по ним не стреляют, их не рисуют), кроме `revealFor` секунд после срабатывания и для детекторов. Событие `kEvTrapFired`
  (a = ловушка, b = жертва). ИИ строит несколько ловушек на переднем крае своей базы и больше по ходу матча.
- **Групповой телепорт**: см. эффект `teleportGroup`; способности игрока `pointPair` требуют двух щелчков (откуда, куда); вторая
  точка передаётся в битах 16..48 параметра `kCmdPlayerAbility` (`RtsModule::packPoint2`). Событие `kEvGroupTeleport` (a = юнит,
  value 1 = обратный путь). ИИ переносит свою самую большую подходящую группу к ближайшему вражескому сооружению.
- **Умное правило `ownProducer`**: цель автокаста / ИИ: собственное сооружение без статуса нагрузки, у которого есть
  заряды личинок (когда нагрузка или выдаваемый ею статус добавляет заряды) или что-то в производстве (хроноускорение:
  статус с `{"stat": "productionSpeed", "mul": 1.5}`).

## 2D-игры

Это всё тот же 3D-движок, но с ортографической камерой; объекты могут быть спрайтами, а поверхность —
тайловой картой. Два варианта, оба — только данные (примеры: `templates/tiles2d`, `templates/km2d`; их временная
графика генерируется `tools/art2d/make_samples.py`):

- **Тайловое 2D** (Red Alert, Dune II, Warcraft II): `camera` смотрит строго вниз (`pitch: 90`), слой карты
  `tiles` рисуется из тайлсета, юниты и здания — спрайты (`"mode": "ground"`).
- **3D-рельеф + спрайты** (Knights and Merchants): обычный рельеф (уровни, пандусы, высоты),
  `camera` под фиксированным углом (`pitch: 50`), спрайты-билборды стоят на поверхности.

### `camera` в game.json

| ключ | смысл |
|---|---|
| `projection` | `"ortho"` или `"perspective"` (по умолчанию) |
| `pitch`, `yaw`, `fov` | градусы; pitch 90 = строго вниз, yaw 0 = север сверху |
| `zoom`, `zoomMin`, `zoomMax` | начальное значение/пределы: видимые клетки карты по вертикали (ortho) или расстояние камеры (perspective); без `zoom` игра вписывает карту в кадр |
| `pixelsPerCell` | ortho: начальный масштаб, при котором одна единица мира равна стольким пикселям экрана (пиксель-в-пиксель для спрайтов, нарисованных с тем же `pixelsPerCell`) |
| `rotate` | разрешить вращение камеры (по умолчанию: false для ortho) |

Редактор использует проекцию и угол для своих видов Scene и Game.

### `sprite` типа

```json
"tank": { ...,
  "sprite": {"sheet": "sprites/tank.png", "frame": [32, 32], "facings": 8, "mirror": false,
             "mode": "billboard", "pixelsPerCell": 32, "anchor": [0.5, 1.0], "offset": [0, 0],
             "team": "magenta", "filter": "nearest", "depthBias": 1.0, "lift": 0,
             "shadow": {"size": [0.8, 0.45], "alpha": 0.35}, "corpseTime": 4,
             "actions": {"idle": [0, 1], "move": [1, 4, 8], "attack": {"start": 5, "count": 2, "fps": 6},
                         "work": [5, 2, 4], "build": {"start": 1, "count": 4, "loop": false}, "die": [7, 3, 6]}}}
```

| ключ | смысл |
|---|---|
| `sheet` | изображение (PNG/JPEG/TGA), обязательно. **Строки = направления** (строка 0 смотрит на восток/+X, далее по часовой стрелке на экране: SE, S, SW, W, ...), **столбцы = кадры анимации** |
| `frame` | размер кадра в пикселях (по умолчанию: вся ширина листа, квадрат — указывайте его для одиночных неквадратных изображений, иначе кадр выйдет за пределы изображения или не дотянется до его края) |
| `facings` | 1, 4, 8, 16, 32... строк; `mirror: true` хранит только север → восток → юг (`facings/2 + 1` строк) и отражает их для западной стороны |
| `actions` | диапазоны столбцов `[start, count, fps]` или `{"start", "count", "fps", "loop"}`. `idle`, `move`, `attack`, `work` (рабочие при сборе/строительстве), `build` (строящееся сооружение; без зацикливания = кадр следует за прогрессом), `die` (проигрывается там, где объект исчез, затем последний кадр остаётся на `corpseTime` с). Отсутствующие действия откатываются к `idle` (`work` → `attack` → `idle`) |
| `mode` | `billboard` (повёрнут к камере; по умолчанию), `upright` (вертикальный квад), `ground` (лежит на рельефе; игры с видом сверху) |
| `rotate` | режим ground с одним направлением: квад поворачивается вместе с объектом, верх изображения — его перёд (машины, видимые сверху) |
| `size` / `pixelsPerCell` / `scale` | размер в мире: `[w, h]` клеток или пиксели кадра / `pixelsPerCell`; ширина по умолчанию = ширина контура (сооружения) или 1 |
| `anchor` | точка опоры в кадре, 0..1 от левого верхнего угла (по умолчанию `[0.5, 1]`, в режиме ground `[0.5, 0.5]`) |
| `offset` | `[right, front]` клеток от центра объекта; по умолчанию для стоящих сооружений: передний край контура, чтобы рисунок в виде 3/4 стоял на своём контуре |
| `team` | `"magenta"` (по умолчанию): пиксели оттенков пурпурного (r = b, g = 0) становятся цветом игрока, умноженным на их яркость; `"none"` |
| `shadow` | `"cast"` (настоящая солнечная тень, см. ниже), `"blob"` (мягкий эллипс под спрайтом), `"none"`; `true` = blob, `false` = none; объектная форма `{"mode", "size": [w, h], "alpha"}` — это blob, если `mode` не говорит иначе (`size`/`alpha` также задают форму пятна, заменяющего отбрасываемую тень на низких уровнях). По умолчанию: `sprites.shadow` игры; при значении по умолчанию `"blob"` тень получают только юниты (как раньше), спрайты ground тень никогда не отбрасывают |
| `castHeight` | высота отбрасывающего тень объекта в мире (по умолчанию: нарисованная высота). Здания в виде 3/4, на рисунке которых видна крыша сверху, отбрасывают длинную тень полной высоты: укажите настоящую высоту стен + крыши |
| `shadowOffset` | `[right, front]` клеток, добавляемые к `offset` спрайта для отбрасывающего тень объекта (по умолчанию: он стоит там же, где рисуется спрайт — для зданий на переднем крае контура) |
| `castDepth` | здания отбрасывают тень как коробка: второй отбрасывающий объект на столько клеток позади первого (по умолчанию: глубина контура для сооружений, 0 для юнитов) |
| `lit` | переопределение `sprites.lit` игры для этого типа |
| `depthBias`, `lift` | смещение к камере, чтобы холмы не срезали спрайт; воздушные юниты парят на `lift` клеток (по умолчанию 1.2) над своей тенью |

Спрайты объединяются в пакеты (один вызов отрисовки на лист), проходят альфа-тест, тест глубины относительно 3D-сцены и
сортировку по алгоритму художника; текстуры читаются через `platform::readContentFile`. Типы без `sprite` сохраняют
свой 3D `view`, поэтому на одной карте можно смешивать оба вида.

### Тени и освещение спрайтов (блок `sprites`)

Значения по умолчанию для всей игры в `game.json` (имеет приоритет) или `rules.json`:

```json
"sprites": { "shadow": "cast", "lit": true }
```

| ключ | смысл |
|---|---|
| `shadow` | `shadow` по умолчанию для каждого типа спрайтов: `"blob"` (по умолчанию, классический вид), `"cast"`, `"none"` |
| `lit` | спрайты принимают свет сцены (по умолчанию `false`: нарисованные цвета, для приверженцев пиксель-арта): цвет солнца и неба, день/ночь и пресеты, точечные источники, тени облаков и (Medium/High) солнечные тени других объектов, падающие на них. При полном дневном свете по умолчанию освещённый спрайт сохраняет свои нарисованные цвета |

**Отбрасываемые тени**: спрайт рисуется в карту солнечных теней как вертикальный квад с альфа-тестом,
стоящий у его основания и повёрнутый по yaw камеры (развёрнутый к солнцу, когда солнце светит почти
вдоль него), с текущим кадром анимации и направлением; затем тень падает на рельеф, 3D-модели
и другие освещённые спрайты с направлением солнца, мягкостью и уровнями PCF из 3D-игр.

| `AIVERSE_SHADOWS` / уровень теней | спрайты с `"shadow": "cast"` |
|---|---|
| Off | только пятна (классический вид, без прохода теней) |
| Low | здания отбрасывают тень, юниты сохраняют пятна; спрайты не читают карту теней |
| Medium / High | тень отбрасывает всё (юниты сохраняют слабое контактное пятно); освещённые спрайты получают тени |

Куда падают тени, определяет направление солнца: `"lighting": {"sunDir": [x, y, z]}` (game.json или
карта, в сторону солнца в полдень; суточный цикл качается вокруг него). Плоские рисунки скрывают тени, которые
падают прямо за ними, а солнце позади сцены оставляет обращённые к камере стены скал неосвещёнными, поэтому
спрайтовым играм обычно нужно солнце сбоку и немного спереди (km2d: `[-1.0, 1.2, 0.45]`,
тени вправо). `"shadowSoftness"` (единицы мира, по умолчанию 0.22) — максимальный радиус полутени.
Солнечные тени Medium/High становятся резче у точки контакта и шире с ростом расстояния между отбрасывающим и принимающим объектом (PCSS);
игры в пиксель-арте выглядят чище с узкой полутенью (km2d 0.07): ядра в несколько текселей карты теней
фильтруются без попиксельного поворота шума, поэтому остаются гладкими на любом уровне.

**Пятна и спрайты ground проецируются**: пятно (и любой спрайт `"mode": "ground"`) вырезается из
треугольников поверхности под ним — точных треугольников сетки рельефа или тайловой карты — и рисуется
со смещением глубины, поэтому оно изгибается по склонам и краям скал и никогда не мерцает от z-конфликта и не висит в воздухе. Sprite
типы спрайтов не получают от системы освещения дополнительной декали контактной тени (эту работу выполняет их пятно).

### Тайлсеты (`tilesets/<name>.json`)

```json
{"name": "Desert", "atlas": "tilesets/desert.png", "tileSize": [32, 32], "columns": 8, "filter": "nearest",
 "terrains": [
   {"id": "sand",  "char": "s", "cell": ".", "color": [0.84, 0.71, 0.47], "tiles": [0, 1, {"tile": 2, "weight": 0.6}]},
   {"id": "spice", "char": "o", "cell": ".", "field": {"resource": "crystal", "density": 9},
    "under": "sand", "depleted": "sand", "tiles": [4, 5], "autotile": {"type": "corner16", "first": 104}},
   {"id": "rock",  "char": "r", "cell": "R", "level": 0, "under": "sand", "tiles": [6, 7], "autotile": {"type": "blob47", "first": 8}},
   {"id": "cliff", "char": "c", "cell": "#", "under": "sand", "autotile": {"type": "mask16", "first": 120}},
   {"id": "water", "char": "w", "cell": "~", "under": "sand", "autotile": {"type": "blob47", "tiles": [56, 57, "... 47 indices"], "with": ["deep"]}}]}
```

Тайл атласа `i` находится в столбце `i % columns`, строке `i / columns`. Для каждого вида поверхности:

| ключ | смысл |
|---|---|
| `char` | символ поверхности в `tiles.rows` карты |
| `cell`, `level`, `field` | **игровой процесс**: вид клетки (`. ~ # , = / R`, как в `terrain.rows`), уровень скал 0..9, ресурсное поле `{resource, density 1..9}` |
| `tiles` | базовые варианты (веса необязательны, по умолчанию 1; выбираются детерминированным хешем клетки) — также используются для внутренней части поверхности с автотайлингом |
| `autotile` | края/углы, выбираемые по 8 соседям. `mask16`: 4 края, индекс N=1 E=2 S=4 W=8. `corner16`: 4 угла (угол учитывается, когда его 3 клетки — одна и та же поверхность), индекс NE=1 SE=2 SW=4 NW=8. `blob47`: 8 соседей, угол учитывается только вместе с обоими своими краями; 47 форм в порядке возрастания маски N=1 NE=2 E=4 SE=8 S=16 SW=32 W=64 NW=128 (индекс 0 = изолированная, 46 = полная). `first` (последовательные тайлы) или `tiles` (явный список); `with`: другие поверхности, которые считаются той же. Соседи за пределами карты считаются той же поверхностью |
| `under` | поверхность, основа которой рисуется под прозрачными краевыми кусками |
| `depleted` | только представление: показывается, когда ресурсное поле клетки исчерпано |
| `color` | цвет в палитре (редактор) |

### `tiles` карты

```json
"tiles": {"tileset": "tilesets/desert.json", "rows": ["sssrrr", "..."], "fixed": [[x, y, tile]], "seed": 0}
```

Когда загружается карта с `tiles` (игра, headless, игра в редакторе), игровые свойства тайловых поверхностей
записываются в `terrain.rows`, `terrain.levels` и элемент `fields` (`"fromTiles": true`) до
старта симуляции — детерминированно и идемпотентно; сама симуляция ничего о тайлах не знает.
Редактор тоже запекает это при рисовании, поэтому сохранённые карты в любом случае содержат корректный рельеф. `fixed` ставит
точные тайлы атласа (автотайлинг выключен). Визуально: автотайл на каждую клетку, не более двух квадов на клетку (`under` +
тайл), одна статическая сетка.

Редактор: окно **Тайлы** (палитра, кисть, автотайлинг вкл/выкл, выбор из атласа; рисует в виде Scene).
Агенты: `tileset_list`, `tiles_init {tileset, fill | fromTerrain}`, `tile_paint {terrain, x, y, radius | rect, tile?}`,
`tile_info {x, y}`, `tiles_remove`.

## Окружение карты

Необязательный блок `"environment"` в rules.json (значения по умолчанию) и в карте (ключи карты важнее, по каждому ключу). Код:
`modules/rts/RtsEnv*.cpp`. У игры без этого блока нет состояния окружения, и она сохраняет свои контрольные суммы и
сохранения. Состояние: ресурс мира `EnvState` (хешируется, сохраняется после сеточных полей, откатывается вместе с миром).
Система `environment` выполняется перед `death` (только при наличии блока), `environment3` — после `vision` (только при
`fog`). Только плоские карты (планеты не поддерживаются).

Единицы: **позиции — это мировые координаты**; каждый ключ расстояния / скорости (`lightningKillRange`, силы ветра,
`velocity` сплайна, ...) делится на `"scale"` (авторские единицы расстояния на единицу мира, по умолчанию 1), поэтому
импортёр копирует исходные значения как есть и задаёт `scale`. Время — в секундах. Навыки — это id
`playerAbilities` из правил, применяемые за нейтрального игрока без стоимости.

```jsonc
"environment": {
  "scale": 30,
  "season": "winter", "weather": ["rain", "snow", "lightning", "blizzard"],
  "weatherParams": {"puddlesFillSpeed": 20, "puddlesDrySpeed": 20, "rainWaitTime": 60, "noRainWaitTime": 30,
    "snowRestoringSpeed": 0.005, "snowWaitTime": 30, "snowFillRandomFactor": 0.6, "snowFillTimeRange": [40, 60],
    "blizzardWaitTime": 30, "blizzardFillTime": 40, "blizzardUnitKillSpeed": 5, "blizzardUnitSpeedFactor": 0.5,
    "blizzardUnitKillFactor": [1, 2], "blizzardVar": "blizzard",
    "lightningKillTime": 2, "lightningKillFactor": 70, "lightningKillRange": 80,
    "lightningPointKillValue": 10, "lightningTime": 30, "lightningWaitTime": 30,
    "lightningBurn": {"field": "fire", "value": 100, "radius": 40},
    "grassRainBurnRandomFactor": 0.5},
  "wind": {"minIdleDuration": 5, "maxIdleDuration": 10, "minBlowDuration": 5, "maxBlowDuration": 10, "minForce": 40, "maxForce": 80},
  "zones": [{"id": "pond", "kind": "water", "poly": [[x, z], ...], "slowdown": 2}],   // water | road | any other tag; "rect" / "circle"
  "splines": [{"id": "lava", "points": [[x, z], ...], "loop": false,
               "skill": "moving_flame", "velocity": 100, "emitPeriod": 10, "firstEmissionCooldown": -1}],
  "trample": [{"field": "snow", "perSecond": 0.1, "speed": [[1, 1], [0.9, 1], [0.7, 0.9], [0.4, 0.75], [0.1, 0.5]], "snowRestore": true},
              {"field": "grass", "perSecond": -0.2, "lerpSpeed": 0.6, "killField": "fire", "hideStatus": "in_grass", "hideAbove": 0.3}],
  "fog": {"memory": false, "startFowSize": 3000, "startDuration": 3}
}
// rules.json
"fogOfWar": {"ellipse": 2}                                // sight discs dx^2 + (2 dz)^2 <= r^2 (isometric fog)
```

| блок | поведение |
|---|---|
| weather | дождь: лужи наполняются / ждут / высыхают / ждут; водные зоны замедляют на `lerp(slowdown, 1, 1 - puddles)` (без дождя: полное замедление; зимой: никогда). Снег (зима): ожидание, затем с вероятностью `snowFillRandomFactor` фаза восстановления, которая понижает каждое поле вытаптывания `snowRestore`. Метель: пешие юниты на линиях теряют здоровье от метели `dt / killSpeed / resist` (resist случаен для каждого юнита), замедляются на `blizzardUnitSpeedFactor` и погибают; переменная триггеров `blizzardVar` равна 1, пока метель дует (боты, скрипты). Молния: каждые `lightningKillTime` с вероятностью `lightningKillFactor` % погибает случайный юнит и всё в эллипсе (`range`, `range / 2`) вокруг него, либо здание теряет `lightningPointKillValue` юнитов гарнизона; `lightningBurn` задаёт там сеточное поле |
| wind | затишье, затем ветер дует в следующем из 8 направлений (угол = dir * 45 градусов от +z к +x) со случайной силой: speed + dot(facing, force) |
| zones | скорость / `slowdown` в первой зоне, содержащей наземный юнит; зоны дорог пропускают таблицы скоростей вытаптывания. `kind` сохраняется как тег зоны, поэтому нативный модуль игры может придать собственным видам смысл |
| splines | пути (Catmull-Rom через точки). Со `skill`: способность применяется в первой точке каждые `emitPeriod`, и её области движутся по сплайну со скоростью `velocity` (движущиеся опасности); на многоэкранных картах — только пока весь сплайн находится на экране |
| trample | движущиеся наземные юниты добавляют `perSecond` к сеточному полю (`docs/fields.md`); таблица `speed` (побеждает последняя строка со значением <= первого), `lerpSpeed`, `killField` (юниты на горящих клетках погибают; в дождь его ядра распространения срабатывают с вероятностью `grassRainBurnRandomFactor`, `GridFields::setSpreadScale`), `hideStatus` |
| fog | `memory: false` возвращает клетки, вышедшие из поля зрения, в неразведанные; `startFowSize` открывает диск вокруг первого здания каждого игрока, который сжимается до нуля за `startDuration`. `fogOfWar.ellipse` (правила) сплющивает каждый диск обзора (быстрый и эталонный проходы видимости) |

События: `kEvEnv` (value = `EnvEventKind << 16 | data`): фазы погоды, молния, ветер. `kEvGarrisonChanged`
для молний по зданиям.

Специфичные для игры действующие лица поверх окружения (боссы, скриптовые режиссёры, особые здания) — это нативные модули
(`docs/native-modules.md` § Gameplay hooks): они читают `RtsModule::environment()` (зоны, сплайны, состояние погоды,
`killedByWeather`) и собственные ключи того же блока карты через `mapData()`.

## Вид тумана войны

Визуальные ключи `"fogOfWar"` в rules.json (`"fogOfWar"` в game.json переопределяет их по ключам; окно редактора
**Туман войны** или `rules_merge {path: "fogOfWar", value: {...}}` через MCP):

```json
"fogOfWar": {
  "mode": "full",                 // simulation: full | explored | none (see rules table)
  "show": true,                   // false: no fog drawn (enemies outside sight stay hidden)
  "color": [8, 10, 14],           // 0..255 or 0..1
  "unexplored": 0.92, "explored": 0.47,   // opacity over never-seen / seen-before ground
  "style": "smooth",              // smooth | cells | grid (cells + lines) | pattern (dithered edge, classic)
  "softness": 2,                  // blur radius in cells (smooth, pattern)
  "fade": 0.3,                    // seconds for a cell to clear / fog over
  "noise": 0.0,                   // 0..1 cloudy moving edges
  "height": 1.3,                  // sheet height above the ground (covers units and low buildings)
  "grid": {"show": "fog", "color": [255, 255, 255], "alpha": 0.15}   // none | fog | all
}
```

Слабые GPU (качество теней off/low) рисуют `smooth` как `cells` без шума. Карты высот рисуют
туман в шейдере рельефа (цвет, прозрачность, клетки, сетка; `pattern` и `noise` доступны
только для слоя-полотна).

### 3D-линия видимости

С `"fogOfWar": {"lineOfSight": true}` (всегда включено для карт высот с `heights.blockVision`)
каждый наземный юнит видит клетку, только если прямая линия от его глаз до клетки проходит над каждой клеткой
между ними. Высоты: поверхность карты высот или уровень скал × `levelHeight` на картах с уровнями; плюс динамические
загораживающие объекты, пересчитываемые на каждом проходе видимости (5 тиков):

| Источник | Ключ | Высота над поверхностью |
|---|---|---|
| Тип юнита или сооружения (стены, леса, высокие здания) | `"vision": {"blocks": 3}` типа | над его контуром (сооружения) или его клеткой; исчезает, когда он погибает |
| Навыки дыма, пыли, стены тумана | доставка `{"type": "area", "radius": 2, "lifetime": 10, "blocksVision": 4}` | диск области, пока она существует |
| Невыкопанная порода | `fogOfWar.rockHeight` (2, 0 = прозрачная) | каждая клетка породы |

Глаза: `terrain.eyeHeight` + `"vision": {"eye": 6}` типа (сторожевые башни видят поверх стен и холмов);
для целей учитывается `terrain.targetHeight`. Воздушные юниты и типы с `"vision": {"seesOver": true}` видят
полный круг. Целочисленная математика, детерминированно; редактор: **Туман войны** → "3D: линия видимости".

## Оверлеи (вспомогательные элементы на экране и в мире)

Необязательный список `"overlays"` в rules.json; `"overlays"` в game.json добавляет записи или переопределяет их **по
id**. Оверлей — это условие (`when`), место (`anchor`), форма `shape` и стиль `style`, при необходимости
порождаемый событиями `event` симуляции. Только представление: оверлеи никогда не меняют симуляцию. Редактор:
окно **Оверлеи** (список, шаблоны, JSON, предпросмотр); MCP: `overlay_templates`, `overlay_list`,
`overlay_get`, `overlay_set`, `overlay_delete`, `overlay_preview` (+ `view_screenshot`).

```json
"overlays": [
  { "id": "build_grid", "when": "placing", "anchor": "ghost",
    "shape": {"type": "grid", "radius": 4, "predicate": "buildable"},
    "style": {"colors": {"true": "#3cff6450", "false": "#ff3c3c60"}, "lineColor": "#ffffff38", "outerAlpha": 0.55} }
]
```

**Встроенные оверлеи** — это обычные записи (тот вид, который у движка был всегда); любой ключ можно переопределить по id
(объекты сливаются глубоко, `"replace": true` заменяет запись целиком), или скрыть запись через
`{"id": "health_bars", "enabled": false}`. Игра без этого блока выглядит точно так же, как раньше.

| id | что |
|---|---|
| `selection` | кольцо под выбранными объектами (`#78ff78e6`; нейтральные объекты `#ffffa0e6`) |
| `hover` | кольцо под объектом под курсором, если он не выбран |
| `move_markers` | небольшое кольцо там, где был отдан приказ на движение |
| `placement` | контур размещаемого сооружения, зелёный / красный (`predicate: "ok"`) |
| `garrison_count` | число гарнизона в плашке цвета владельца |
| `health_bars` | полоса hp выбранных / наведённых / повреждённых объектов (26 px у юнитов, 46 px у сооружений) |
| `build_progress` | полоса строительства |

Ключи записи: `id` (обязателен, уникален), `enabled` (по умолчанию true), `order` (порядок отрисовки, по умолчанию 0, затем
порядок в списке), `when`, `anchor`, `shape`, `style`, `event`; `name` / `description` — произвольный текст.
Неизвестные ключи, типы, теги, статусы, цвета или невозможные сочетания — ошибки
(`overlay 'x'.anchor.types: unknown type 'dragon'`); при старте игры сломанная запись пропускается с
предупреждением, `overlay_set` её отклоняет.

### when

Строка, список (должны выполняться все) или объект (должен выполняться каждый ключ). Строки: `always`, `never`,
`placing`, `selected`, `hovered`, `cursor`, `playing`, `paused`, `over`.

| ключ | выполняется, когда |
|---|---|
| `always` | `true` / `false` |
| `placing` | `true`: размещается сооружение; `"id"` / `["id", "tag:x"]`: один из этих типов |
| `selected` | якоря-объекты: выбран **этот** объект (`false`: не выбран); прочие якоря: что-то выбрано. Объект-фильтр / список типов сужает условие: `{"selected": {"owner": "own", "flags": ["ranged"]}}` |
| `hovered` | то же для объекта под курсором |
| `entity` | фильтр объектов по объекту якоря (прочие якоря: подходит любой видимый объект) |
| `types`, `tags`, `owner`, `flags`, `status`, `hp` | сокращённая запись фильтра `entity` на верхнем уровне |
| `key` | зажатые клавиши: `"Alt"`, `["Shift", "Q"]` (A–Z, 0–9, F1–F12, Shift, Ctrl, Alt, Super, Space, Tab, Enter, стрелки) |
| `state` | `"playing"` / `"paused"` / `"over"` или список |
| `var` / `flag` | переменная триггеров: `"alarm"` (ненулевая) или `{"name": "alarm", ">=": 3}` (`==`, `!=`, `<`, `<=`, `>`, `>=`) |
| `zoom` | расстояние камеры в `[min, max]` |
| `cursor` | курсор находится над картой (`true` / `false`) |
| `mode` | режим ввода клиента: `normal`, `attack`, `patrol`, `place`, `rally`, `ability`, `claim` |
| `any` / `all` / `not` | сочетания |

**Фильтр объектов** (`when`, якоря-объекты): `types` (id или `"tag:x"`), `tags`, `owner` (`own`,
`ally`, `friendly`, `enemy`, `neutral`, `any` или список), `flags` (должны выполняться все, `!` отрицает:
`structure`, `unit`, `constructing`, `damaged` (hp < 99.9%), `garrison`, `moving`, `producing`,
`idle`, `hero`, `worker`, `invulnerable`, `air`, `carrying`, `attacking`, `resource`, `energy`,
`ranged` (оружие с дальностью > 1.5), `aura`), `status` (активен любой из этих статусов), `hp`
(доля `[min, max)`).

### anchor

`"name"` или `{"type": "name", ...}`.

| якорь | элементы находятся |
|---|---|
| `selected` | у каждого выбранного объекта (необязательные ключи фильтра объектов) |
| `hovered` | у объекта под курсором |
| `entities` | у каждого видимого объекта, подходящего под фильтр: `{"type": "entities", "owner": "own", "flags": ["structure"]}` |
| `cursor` | у курсора на поверхности (`"snap": true`: центр клетки) |
| `ghost` | у размещаемого сооружения (центр, его тип для контура / характеристик, `ok` = размещение допустимо) |
| `area` | `{"type": "area", "area": "gate"}` (область карты) или `"rect": [x, z, w, h]` |
| `point` | `{"type": "point", "at": [x, z]}` |
| `screen` | точка HUD `{"type": "screen", "at": [x, y]}` в пунктах; отрицательные = от правого / нижнего края; текстовые блоки свисают от этого угла |
| `orders` | линия через точки приказов в очереди у выбранных юнитов |
| `route` | текущий путь выбранных движущихся юнитов |
| `rally` | от выбранных производящих зданий к их точке сбора |
| `markers` | маркеры приказов на движение |
| `map` | цель камеры (для `cells`) |

У оверлеев событий нет якоря: они находятся там, где произошло событие.

### shape

`"name"` или `{"type": "name", ...}`.

| форма | ключи |
|---|---|
| `ring`, `circle` | `radius`: число (клетки) или характеристика типа якоря: `range` / `range:N` (оружие N, + радиус тела, + улучшения), `minRange`, `sight`, `aura` (`aura:N` = способность N), `buildRadius`, `selection`, `capture`, `claim`, `footprint`, `ability:N` (дальность применения), `leash`; `radiusScale`, `radiusAdd`. `circle` залит |
| `rect` | `size: [w, h]` вокруг якоря; у якорей-областей: сама область |
| `footprint` | контур типа призрака / объекта, `margin` клеток вокруг |
| `grid` | клетки в пределах `radius` вокруг якоря (у призрака: вокруг его контура; `square: true`), заливаемые по `predicate` (`colors.true` / `.false`), линии клеток цветом `style.lineColor`; `highlightFootprint` (по умолчанию true: клетки под призраком с полной альфой, остальные — `style.outerAlpha` с затуханием) |
| `cells` | каждая клетка в пределах `radius` (по умолчанию 24) от якоря, подходящая под `predicate`; `territoryEdge` рисует границы цвета владельца |
| `line`, `arrow` | от якоря к `to`: `target` (текущая цель атаки), `rally`, `cursor`, `order` (первая точка приказа), `[x, z]`; `head` = длина наконечника стрелки. С якорями `orders` / `route` / `rally`: путь |
| `path` | ломаная `orders` / `route` / `rally` |
| `text` | `text` с подстановками `{value}` (значение события; попадания: урон), `{amount}`, `{resource}`, `{name}`, `{hp}`, `{maxHp}`, `{energy}`, `{garrison}`, `{build}` (%), `{selected}` (количество), `{owner}`, `{player}`, `{var:NAME}`; `size` в высотах шрифта. Всегда в экранном пространстве |
| `icon` | `image` (путь к текстуре, атласы работают), `size` (единицы мира; пункты в экранном пространстве) |
| `bar` | `value`: `hp`, `energy`, `build`, `garrison`, `production`, `carry`, `capture`; `width`, `widthStructure`, `height` в пунктах. Только якоря-объекты, над объектом |

Предикаты: `ok` (размещение призрака допустимо), `buildable`, `blocked`, `buildRadius`, `walkable`,
`water`, `resource`, `creep`, `road`, `region`, `territory` (своя), `enemyTerritory`, `anyTerritory`,
`territoryEdge`, `visible`, `explored`, `fogged`, `unexplored`. Клетки, которые локальный игрок не
разведал, никогда не показывают ресурсы / территорию.

### style

| ключ | смысл |
|---|---|
| `color` | `[r, g, b, a]` (0..1 или 0..255), `"#rrggbb[aa]"`, имя (`white`, `red`, `gold`, ...) или `"player"` (цвет владельца) |
| `colors` | по результату предиката `true` / `false` и по отношению к владельцу `own`, `ally`, `enemy`, `neutral` |
| `stops` | полосы: `[[0.3, red], [0.6, yellow], [1, green]]` (первая точка >= значения) |
| `fillColor`, `lineColor` | заливка / контур, когда рисуются оба |
| `alpha`, `thickness` | толщина в единицах мира (0 = линия в 1 пиксель; экранное пространство: пункты) |
| `fill`, `outline` | значения по умолчанию зависят от формы (`circle`, `grid`, `cells` залиты; `ring`, `rect`, `footprint` — контуром) |
| `dash` | `[on, off]` в единицах мира; `scroll` = скорость штрихов в секунду |
| `pulse`, `pulseMin` | пульсация альфы в Гц до `pulseMin`; `rotate` радиан / с (кольца, иконки) |
| `fadeIn`, `fadeOut`, `fade` | секунды (условия якорей, не являющихся объектами, всплывающие элементы событий) |
| `onTop` | рисуется поверх всего (без теста глубины); `additive` / `blend: "add"` светится |
| `space` | `ground` (натянуто на рельеф), `billboard` (повёрнуто к камере), `screen` (наложение ImGui), `minimap` (кольца / диски / прямоугольники на мини-карте клиента) |
| `ground` | `follow` (каждая вершина на рельефе, по умолчанию), `flat` (высота под якорем), `zero` |
| `lift`, `segments`, `offset` | высота над поверхностью; сегменты кольца; экранное смещение `[x, y]` |
| `background`, `backgroundShade`, `backgroundAlpha`, `padding`, `rounding`, `border`, `shadow` | блоки текста / полос |
| `outerAlpha`, `falloff` | сетки / клетки: альфа вне контура, затухание к краю |

### event

`"hit"` или `{"on": "hit" | [...], "lifetime": 1.2, "rise": 0, "grow": 0, "spread": 0, "by": "own",
"owner": "enemy", "types": [...], "max": 32}`: каждое подходящее событие симуляции порождает всплывающий элемент в своей
позиции на `lifetime` секунд, поднимающийся на `rise` единиц / с, кольца / иконки растут на `grow` / с. `by` =
отношение игрока, вызвавшего событие, `owner` = отношение объекта, с которым оно произошло, `types` = его тип.
События: `hit`, `died`, `spawned`, `attack`, `gathered`, `delivered`, `produced`, `ability`, `cast`,
`impact`, `miss`, `built`, `placed`, `trained`, `researched`, `levelup`, `captured`, `sold`,
`upgraded`, `alert` (под атакой), `status`, `area`, `claimed`, `wave`, `message`, `ping` (пинги
клиента / редактора). Всплывающие элементы никогда не появляются в клетках, которые локальный игрок не видит.

**Уровни качества** (качество материалов рендерера; `AIVERSE_OVERLAYS=low|medium|high` для проверки): оверлеи
игры ограничены на каждый оверлей (48 / 192 / 1024 элемента), на каждую форму grid / cells (600 / 3000 /
12000 клеток) и по живым всплывающим элементам (24 / 96 / 256); low вдвое уменьшает число сегментов колец. Встроенные оверлеи
никогда не ограничиваются.

### Рецепты

```json
// 1. build grid while placing (any building), cells under the ghost brighter
{"id": "build_grid", "when": "placing", "anchor": "ghost",
 "shape": {"type": "grid", "radius": 4, "predicate": "buildable"},
 "style": {"colors": {"true": "#3cff6450", "false": "#ff3c3c60"}, "lineColor": "#ffffff38", "outerAlpha": 0.55, "lift": 0.07}}
// 2. attack range of selected own ranged units / towers, dashed and scrolling
{"id": "attack_range", "anchor": {"type": "selected", "owner": "own", "flags": ["ranged"]},
 "shape": {"type": "ring", "radius": "range"}, "style": {"color": "#ff6a4ac0", "thickness": 0.06, "dash": [0.6, 0.35], "scroll": 0.4, "segments": 64}}
// 3. range preview while placing a tower only
{"id": "tower_range", "when": {"placing": ["tower"]}, "anchor": "ghost", "shape": {"type": "ring", "radius": "range"},
 "style": {"color": "#ffd24ad0", "thickness": 0.05}}
// 4. aura radius
{"id": "aura_radius", "anchor": {"type": "selected", "flags": ["aura"]}, "shape": {"type": "circle", "radius": "aura"},
 "style": {"color": "#7ac8ff40", "outline": true, "lineColor": "#9ad8ffc0", "pulse": 0.5, "pulseMin": 0.6}}
```

## Постэффекты (`postfx`)

В `game.json` и картах может быть блок `"postfx"`: список полноэкранных эффектов (bloom, цветокоррекция,
LUT, виньетка, tilt-shift, солнечные лучи, FXAA, зерно, ...) с уровнями качества и моделью стоимости
кадра. Формат, параметры, уровни и инструменты MCP: `docs/postfx.md`.

### Начальные переменные скриптов (локальная настройка матча)

Необязательный объект карты `initialVars` содержит целочисленные переменные триггеров, которые загружаются до пользовательских скриптов. Пример: `"initialVars": {"loadout_support_1": 2}`. Не более 128 ключей из ASCII-букв, цифр, подчёркивания, точки и дефиса, длиной 1–128; целые числа в диапазоне −1000000..1000000. Значения попадают в обычное хеширование `trig.vars`. Клиентский UI может передать переопределения через `game.start(..., {initialVars=...})`; см. docs/ui-scripting.md. Сохранённая настройка карты или реплея хранит эти параметры, а без них сохраняется прежнее поведение.
## Компьютерный игрок (`RtsAI`, agent-ai-terrain)

Бот читает состояние и отправляет команды как игрок (реплеи его не перезапускают). Он общий для всех шаблонов;
настройки — в блоке правил `ai` (выше). Что он делает с рельефом:

- **Анализ в начале матча** (`RtsAITerrain.*`, целочисленный, после загрузки сохранения строится заново так же): для каждой клетки —
  высота в единицах преимущества по высоте (уровень обрыва либо высота heightfield / планеты, делённая на `levelHeight`),
  маска проходимости наземного слоя (только рельеф), ширина коридора (шаги до ближайшей стены: узкие места), `over`
  (насколько более высокая земля в пределах 4 клеток поднимается над клеткой) и `crest` (выраженность возвышения). Одинаково для плоских карт, heightfield и
  планет на кубосфере (соседи через швы граней).
- **Маршруты**: взвешенный Дейкстра от нашей базы до ближайшей вражеской: подъём к противнику и клетки, которые
  просматриваются с более высокой земли, стоят дороже (`climbWeight`, `exposureWeight`), поэтому волны идут через седловины и пандусы, а не
  вверх по хребту под огнём; запасной маршрут обходит главный коридор (используется на нечётных волнах при патовой ситуации).
- **Посты на маршруте**: точка сбора на самой высокой хорошо прикрытой земле в 9-14 шагах от базы (армия ждёт
  там, туда же собираются производящие здания); самая узкая клетка на нашей стороне (башни после набега); наблюдательный пост на самой
  выдающейся высоте в середине маршрута для разведчика (обзор через хребты). Бездействующие юниты не отправляются повторно к
  точке сбора (юнит, идущий обратно, не считался бы готовым к следующей волне).
- **Волны** идут по путевым точкам каждые 12 клеток, останавливаются на точке осады на возвышенности, не доходя до цели, затем атакуют;
  они выжидают до 30 с вместо штурма вверх по склону против более сильного противника (и подтягивают подкрепления), отступают к
  точке сбора, если их стало меньше 25% исходного размера без единого убийства (до уровня пата 3), выходят раньше с тем, что есть
  дома, когда наша армия вдвое больше всех вооружённых сил противника, останавливаются по сторожу застрявшей волны (30 с без движения), перенацеливаются на следующее здание, атакуют строительные площадки по имени.
- **Защита экономики**: собственные места под постройки (проходы между пунктами сдачи и ресурсами остаются свободными, область сбора
  остаётся свободной, случайный выбор при равенстве), застрявшие строители освобождаются, а их места избегаются, первое производящее армию здание строится рано, преобразователи
  (metal makers) — только при избытке, ещё одно производящее здание — когда ресурсы копятся, расширение (пункт сдачи у следующего
  месторождения), когда ближние месторождения исчерпаны, рабочие распределяются по переполненным месторождениям и появляются со стороны своего ресурса.
- **Выход из пата**: противника без вооружённых юнитов добивает вся армия (его самое слабое из учитываемых
  зданий); на уровне пата 1+ волну запускает меньший перевес сил, а на уровне 2+ волны ограничены 3/4 от
  `firstAttackArmy`; бот строит / исследует то, что открывает юнитов заметно лучше против самого прочного здания противника
  (таблица урона, бонусы, броня), и копит на это; при игре гарнизонами сначала отправляются полные гарнизоны, они стягиваются
  к фронту, а после 10 мин каждый гарнизон может присоединиться к наступлению; в поселенческих экономиках сначала строится основная
  цепочка производства материалов, затем то, что нужно армии; если заканчивается запас, который потребляет население, строительство жилья прекращается; к регионам,
  которые нужно сначала увидеть, отправляется разведчик; медленным сборщикам (без `workersPerBase` в правилах) выделяется больше рабочих.
- **Планеты**: орбитальный флот (`invasionSize` + 2 на каждое вторжение) переходит вместе на тело с вражескими
  зданиями и сражается там, пока тело не очищено, затем переходит к следующему телу; больше орбитальных верфей, когда до противника можно
  добраться только через орбиту; башни, бьющие по орбите, когда атаки идут оттуда.
- **Стили по слотам**: `players[i].ai` карты (см. «Карты») задаёт одному слоту пресет и собственные настройки; они применяются до
  первого размышления (и так же после загрузки), поэтому `thinkTicks` слота используется с самого начала.
- **Сохранение состояния**: `RtsAI::saveState()` / `loadState()` (headless `--save F` пишет `F.ai` рядом с состоянием симуляции,
  `--load F` читает его): восстановленный бот продолжает играть точно так же, как сохранённый.


## Герои с видом сверху

## Городской трафик

Блок правил `traffic` (вместе с `topDown` + `driving`): машины под управлением компьютера на полосах, построенных из символов тайлов
карты, регулируемые перекрёстки с моделями светофоров, пешеходы на тротуарах, которые переходят дорогу на «идите» и паникуют при
