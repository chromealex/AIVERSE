# Third-party notices in game builds

Every `aiversebuild` target emits `THIRD_PARTY_NOTICES.txt`. The same vendored
inventory is generated by direct CMake game builds, without Python or network
access. License generation errors fail the build; missing texts are never silently
skipped. The file is plain text outside `content.rpak`, including split/loose builds.

| Target | Delivered location |
|---|---|
| macOS | `<Game>.app/Contents/Resources/THIRD_PARTY_NOTICES.txt` and target output directory |
| iOS | App bundle resource; also beside the exported Xcode project |
| Android | APK/AAB asset `THIRD_PARTY_NOTICES.txt`, generated before Gradle merges assets; export/output sidecar |
| Windows / Linux | Beside the executable and in the target output directory |
| Web | Beside `index.html` (deploy this file with the site) |

Apple resource copying occurs before signing. Desktop builds copy even without a
relink. The Android Gradle task regenerates the asset from the exported sources,
independently of native ABI compilation. Source exports retain the engine's MIT
`LICENSE`, the audit manifest, original license sources and additional notices.

## Inventory and audit

`third_party/notices.json` is the authoritative audited inventory. It includes the
engine MIT license and a conservative superset of vendored runtime, optional,
editor and host-tool components, explicitly identified as such in the output.
This avoids omitting notices when optional modules or native consumers change
which libraries they link. It does not imply that every listed component ships.

| Vendored component | License(s) and embedded notices retained |
|---|---|
| Box3D | MIT; qsort (Alexey Tourbin), rapidhash (Nicolas De Carli), Verstable (Jackson L. Allan) |
| Dear ImGui | MIT; embedded stb MIT/Unlicense, ProggyClean/ProggyForever font attributions |
| Lua | MIT, including copyright in the vendored header |
| meshoptimizer | MIT |
| miniaudio | MIT-0 / Unlicense; current header and separate license (their copyright years differ) |
| stb, stb_image_write, stb_vorbis | MIT / Unlicense |
| Monocypher | BSD-2-Clause option selected; notices from both vendored source headers |
| RmlUi | MIT; original author notices, robin_hood, itlib, debugger font OFL-1.1 notice |
| ufbx | MIT / Unlicense |
| xatlas | MIT; Thekla/NVIDIA/Brandon Pelfrey attributions, OpenNL BSD-style notice |
| Zstandard | BSD option selected; Tino Reichardt, Yann Collet and libdivsufsort MIT attribution |
| Ogg / Vorbis | BSD-3-Clause; additional LPC notice for Jutta Degener / Carsten Bormann |
| Inter, Noto Sans Symbols 2, engine Noto Sans | SIL OFL-1.1 |
| Lucide / inherited Feather icons | ISC and MIT |

All standalone license files are included verbatim. Embedded licenses are extracted
from the actual source bytes, using offsets in LF-normalized text and a SHA-256
of that normalized source. A changed source fails generation until its notice is
reviewed and the manifest updated. No license text is replaced with a URL.
The regression test checks coverage of every vendored directory and standalone
license, original text preservation, missing/empty/changed sources, extra notices,
plugin isolation and license-only artifact rebuilds.

The README's earlier list was incomplete: ISC and MIT-0 are also present, and
nested dependencies carry additional notices. The inventory records these rather
than assuming that a parent library's LICENSE covers every embedded component.

## Game assets and native modules

`aiversebuild` collects original `LICENSE*`, `LICENCE*`, `COPYING*`, `NOTICE*`,
`OFL*` files and `THIRD_PARTY_NOTICES.txt` from the game project, sorted by path.
It skips build/log/cache directories, hidden directories and symlinks. Place
licenses beside asset packs or native dependencies, or supply a consolidated
`<project>/THIRD_PARTY_NOTICES.txt`. The collector does not infer authors or usage
rights from binaries. Preserve attribution/source/modification information that
an asset license requires. A license stored under an unrelated filename must be
included in the consolidated file.

Direct CMake builds accept `-DAIVERSE_PROJECT_NOTICES=/path/to/notices.txt` and
otherwise discover `<content>/THIRD_PARTY_NOTICES.txt`. The exported project carries
a consolidated `project-notices.txt`, so it no longer depends on the original game
folder. Newly added dependencies in an export need updated additional notices.

## External SDKs and toolchains

The plugin audit covers the manifests for AdMob, AppLovin, AppMetrica, AppsFlyer,
Facebook, GameAnalytics, Google Play Billing, LevelPlay, Firebase push, RuStore,
Steam, UMP, Yandex Ads and Yandex Games. Their SDKs are downloaded/resolved or supplied
by the game developer; they are **not** vendored under the engine's MIT license.
Pods with version ranges and Gradle transitive dependencies cannot be exhaustively
licensed from `plugin.json` alone. No unverified SDK license text is fabricated.

For selected plugins with external dependencies, libraries, runtime files or web
SDK scripts, packaging requires notice files. Supply the resolved SDK's original
licenses/NOTICEs and all required transitive notices (from its actual distribution,
lockfile/dependency report or provider acknowledgements):

```json
{
  "plugins": {
    "admob": {
      "notices": {
        "android": ["licenses/admob-android.txt"],
        "ios": ["licenses/admob-ios.txt"]
      }
    }
  }
}
```

Paths in game configuration are relative to the project; `plugin.json` can also
provide `notices` at its root and inside platform sections, relative to its own
folder. Supplied files are merged, checked for existence/nonempty content, and
copied into exports. Removing a plugin removes its SDK notices on the next build.
Supplying a file is not proof that its contents cover a resolved dependency graph.
System-framework-only adapters (App Store, ATT, iOS push) and engine-authored
web/URL adapters do not require an invented SDK license.

Assimp is an optional host-only converter; astcenc is an external encoding tool.
They are not copied into game artifacts. OS frameworks/system OpenSSL loaded on
Linux are not redistributed by the packager. Android builds also append the installed NDK `NOTICE` and `NOTICE.toolchain`.
Other compiler runtime licensing depends on the toolchain; Emscripten and
statically linked MinGW runtimes must be covered by supplied notices when required.
Direct CMake builds accept `AIVERSE_TOOLCHAIN_NOTICES` as a list of additional files.
Likewise, redistributing an optional converter or an SDK outside the game package
requires the notices for that actual distribution. The repository audit cannot
certify externally supplied binaries, private assets or arbitrary native modules.

## Validation and maintenance

Run `python3 tests/notices/notices_test.py`. After changing a vendored source,
review its full license and nested components before updating slice offsets and
hashes. Hash bytes after replacing CRLF with LF, so Windows and Unix checkouts
produce identical results. Add new components to the manifest in the same change.
The test is also run in Linux CI. Plugin CI fixtures contain explicitly labelled
synthetic notices for compile/export tests only and must not be distributed.

Validation included a full macOS client/tool build, five notice regression tests,
23 plugin export-isolation cases, an Android project export, and the actual Gradle
`generateAiverseNotices` / `mergeDebugAssets` tasks (the notice was present in merged
assets). Windows, Linux, web and iOS game binaries, and final APK/AAB signing, were
not built for this change. The existing GamepadApple.mm compiler warning was
unrelated to notices; the changed C++ code compiled without warnings.
