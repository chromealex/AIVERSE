## Architecture, API and scope

**Generic RHI:** `gfx::Device` scopes are optional. Desktop GL33 begins one `GL_TIME_ELAPSED` query around a bounded region of commands, closes it without CPU wait, and polls later for `GL_QUERY_RESULT_AVAILABLE`. The API deliberately keeps those results in a separate queue from `timeGpuFrame` (existing renderbench/Scene benchmark profiling); nested same-target elapsed queries are prohibited. If a whole-frame benchmark is active, the scoped timing is skipped. Metal currently exposes only a whole-command-buffer duration through `gpuFrameMs()`; it does **NOT** implement `beginGpuScope`. The Vulkan and GLES/WebGL interfaces also remain unsupported and correctly return false/empty. There is no fake approximate "per viewport" duration.

**Editor:** `AIVERSE_PRISMA_VIEWPORT_GPU_TIMING=1` turns on Scene (view ID 1) and Game (view ID 2) scoped attempts. The interval begins just before renderer GPU draw submission and ends after the viewport pass is complete, including shadow/map/opaque/translucent/FX and Prisma postprocessing done inside that region, but excluding any GPU commands already submitted earlier during scene preparation. The editor consumes only `takeGpuScopeTimings()` and calls `Prisma::acceptViewGpuTiming(viewId,ms)` for valid finished results. A monotonically increasing accepted sample sequence serves as the per-view completed-query token. No CPU-frame counter, time delta or raw "timeGpuFrame" result is misrepresented as scoped timing.

**Adaptive policy:** `Prisma::renderSizeForOutput()` observes a per-view scoped sample if available, otherwise the existing `Device::gpuFrameMs()` whole-frame metric and true `gpuCompletedFence()`. The existing authored `renderScale`, `minRenderScale`, `targetGpuMs`, full HDR/High opt-in and 1/16 scale changes are unchanged. Memory pressure computes **only known** `memoryStats().liveKnownBytes` plus `retirementStats().knownPendingBytes`, with saturation. This includes current Prisma-resident GPU textures and fenced retirement, not total device VRAM. It excludes unknown/unmeasurable driver allocations, some mips and unrelated renderer/editor resources. If counted known bytes exceed `maxPrismaMemoryMiB`, new confirmed GPU completions can produce slow-pressure samples even if GPU ms are unavailable. Fast recovery is blocked under pressure. No new GPU wait or premature destruction; existing GPU-fenced retirement remains the only release policy. Disabling adaptation or retiring a viewport clears pressure state.

**User-facing:** `PrismaStats` reports the chosen GPU metric source, last value if valid, known occupied+pending Prisma MiB and pressure limit; Editor Stats shows completed GL33 per-view samples only if available. No gameplay ECS, genre-specific simulation, source material/shader graph format, particle emitter logic, or default-on change is introduced. GPU scope timing is explicit opt-in and does not impose query overhead on existing projects.

## Known limitations, risks and next Stage 47

1. Scoped GPU timers are currently **real only for desktop GL33 on macOS/Windows**. To support Metal per-viewport data, implement supported Metal sample-counter buffers or separate genuine GPU-scoped timestamp mechanism; do not fabricate viewport values from whole-command-buffer `GPUEndTime-GPUStartTime`. Vulkan likewise needs timestamp query pools with proper queue submission/availability handling. The default unsupported functions are intentionally inert.
2. OpenGL only allows one elapsed query target active at a time. Stage 46 skips timing during whole-frame benchmark queries and vice versa; validate GL query state and context loss natively. Pending scope queries are capped at 64, no polling synchronization occurs. A completed query can be delayed or missing, in which case adaptation must not repeatedly count stale milliseconds.
3. Per-view timing includes shadow, 3D, FX and postprocessing **within the region**, but excludes resource streaming before render. Two views may independently measure shared shadow passes, so summing their durations is not a valid unique GPU total. Real queue utilization/busy time is distinct from elapsed GPU timeline.
4. `maxPrismaMemoryMiB` compares **lower-bound known** Prisma bytes only. Other renderer models, textures and driver allocations are outside the budget, and unaccounted bytes can be significant. Adding active renderer memory requires separately owned, reliable statistics to avoid double counting.
5. Test Stage 45 memory preflight + Stage 46 memory pressure together on low-VRAM devices: persistent 2× output-size HDR histories, transient output scratch, size-shared render targets and pending fences may produce extra allocation churn under renderScale changes. Never free in-flight textures to stay within budget; continue fence-based retirement.
