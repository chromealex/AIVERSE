## Owner use and limitations
At the existing physics owner step, sample from body-local feet and canonical selected body, supply reference +Z direction and existing frame-relative input yaw, call stepPlanetCharacter, then Scene::moveCharacterOriented with returned orientation and apply pushes; Scene::step remains single owner. The host supplies heading continuity and replication/recording of physics state, initializes oriented proxy before queries and resets on teleport/rollback. Gravity is held constant over one physics step; near-zero <=0.01 m/s² is treated as zero. Weak gravity disables ground jumping/adhesion. This is not a dedicated six-degree-of-freedom flight motor; existing air-control/braking remains. Character orientation changes are not swept continuously; steep surfaces, rotating platforms, planet seams and dynamic interactions require actual runtime validation. Existing CROWD ground support policy and GameCore::moveSphere kinematic movement remain unchanged; no competing Transform writer, automatic GameCore actor migration, network prediction/save integration or animation wiring. No new ECS schema, target or solver.
