# AIVERSE Building Generator: QA of 20 sizes and seeds

Four structural roles (barracks, command, factory, depot), each at five distinct
W/H/D and seed combinations, generated by the actual C++ GLB exporter.

## Run on Mac

~~~sh
cd ~/Projects/AIVERSE-buildings-qa
git fetch origin feature/aiv20261123_building-grammar
# Check git status --short is clean before updating the detached worktree:
git switch --detach origin/feature/aiv20261123_building-grammar
python3 tools/buildings/qa_batch_20.py --compile --allow-failures

# inspect five models of each type in the REAL ModelView / Metal:
sh build/buildings-qa/batch-20/view-barracks.command
sh build/buildings-qa/batch-20/view-command.command
sh build/buildings-qa/batch-20/view-factory.command
sh build/buildings-qa/batch-20/view-depot.command
~~~

Output: build/buildings-qa/batch-20/report.json, report.csv, one GLB
per successful request, and four executable viewer scripts.

The report checks the actual binary POSITION vertex buffers, exact requested
bounds (15 mm tolerance), finite positions, GLB format, triangle counts,
material counts and SHA-256. Unsupported dimensions remain FAILED; no silent
fallback to legacy size. Without --allow-failures the process exits 1
if any size fails, but the full report is still written.

The earlier screenshot showed floating geometry. Support legs were added in
commit 92b0a086, but their visual correctness has NOT been rechecked.
The stage-5 constructive fitter can also reject seemingly valid dimensions.

GitHub focused CI includes the 20-case batch report/artifact, but no actual
20/20 result has been observed in this conversation. Do not fabricate a gallery
or assert success. Real screenshots require the Mac ModelView or an actual
render of the produced GLB files.
