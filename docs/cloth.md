# XPBD-ткань AIVERSE

Опциональный модуль визуальной ткани: `AIVERSE::cloth` (CPU) и
`AIVERSE::cloth_render` (RHI). Не зависит от Box3D и не меняет RTS/FPS-симуляцию.
В существующий клиент, редактор, Lua и импорт одежды модуль автоматически не включается.

## Цель и устройство

Целевая сцена — сотни независимых тканей, около **10 тысяч отображаемых
треугольников на объект**. В примере сетка 71×71 ячейка даёт 10 082 треугольника
и 5184 отображаемые вершины. Для 256 объектов это 2 580 992 треугольника.

Плотность физики задаётся отдельно. Рекомендуемый начальный бюджет — 16×16 ячеек
(289 частиц); повышенное качество — 24×24 (625 частиц). Есть режим 71×71
(5184 частиц) для прямого сравнения. Более плотное отображение **не добавляет
физических складок или точности контакта**, которых нет на физической сетке:
положение вершины получается билинейной интерполяцией четырёх соседних частиц.
В текущей версии поддерживаются прямоугольные регулярные сетки, не произвольный
скроенный меш одежды или автоматическое связывание с glTF.

- XPBD: растяжение и сдвиг по рёбрам/диагоналям; отдельная податливость изгиба.
  Для изгиба используется дешёвое расстояние через два ребра, **не** полноценная
  энергия двугранного угла. Лямбды накапливаются в итерациях и сбрасываются на подшаге.
- Верхний край закреплён. Есть перемещение закреплений, сброс, затухание,
  гравитация и задаваемое ускорение ветра (упрощение, не аэродинамика).
- Контакт с плоскостью, сферами и капсулами; толщина ткани, предварительный
  AABB-отсев. Контакт дискретный, без CCD и трения. Быстро движущиеся препятствия
  могут пройти сквозь ткань. Самостолкновений, разрывов и контактов ткань–ткань нет.
- Постоянный пул потоков распределяет целые ткани; нет создания потоков или
  выделения памяти в шаге. В web поток один, без pthread-зависимости.
- RHI получает RGBA32F-текстуру общих физических форм и маленькую текстуру
  смещений/индексов экземпляров. Формы загружаются один раз на группу. Один instanced draw
  отображает весь набор плотных сеток; шейдеры есть в GLSL и MSL. Свет двусторонний,
  нормали геометрические, тени в примере отключены.
- `Cloth::active=false` замораживает объект без накопления пропущенного времени.
  Видимость, частоту симуляции и выбор качества контролирует вызывающий код.
  В исходных замерах **все** объекты активны: нет скрытого сна, отсечения или снижения LOD.
  Новые замеры LOD отмечены отдельно (`lod_mode`).
  Режим совместного расчёта учитывается отдельным параметром `sharing` и счётчиками групп.

Метод: [XPBD, Macklin / Müller / Chentanez](https://matthias-research.github.io/pages/publications/XPBD.pdf).
Код решателя написан в проекте; сторонняя библиотека ткани не подключается.

## Сборка

```sh
cmake -S . -B build/.temp/cloth -DCMAKE_BUILD_TYPE=Release \
  -DAIVERSE_ENABLE_CLOTH=ON
cmake --build build/.temp/cloth --target aiverse_cloth_demo aiverse_cloth_bench aiverse_cloth_tests aiverse_cloth_lod_tests aiverse_cloth_render_tests -j8
ctest --test-dir build/.temp/cloth -R '^cloth_' --output-on-failure
build/.temp/cloth/engine/cloth/aiverse_cloth_demo
```

На Mac с Apple Silicon добавьте `-DCMAKE_OSX_ARCHITECTURES=arm64`, особенно если
CMake запущен через Rosetta. Для Xcode добавьте `--config Release`, исполняемые
файлы находятся в подкаталоге `Release`.
По умолчанию `AIVERSE_ENABLE_CLOTH=OFF`; стандартные игры не линкуют модуль.

Пример рассчитан на запуск из исходного дерева (шрифт и локализация читаются через
`platform::readContentFile`). Параметры:

```sh
# 256 объектов: 10 082 треугольника и 289 физических частиц на каждый
build/.temp/cloth/engine/cloth/aiverse_cloth_demo --objects 256 --cells 16 --workers 8
# Одна ткань крупно
build/.temp/cloth/engine/cloth/aiverse_cloth_demo --objects 1 --cells 24 --workers 1
# Прямой расчёт плотной физической сетки
build/.temp/cloth/engine/cloth/aiverse_cloth_demo --objects 100 --cells 71 --workers 8
```

Дополнительно: `--render-cells 71`, `--lang en|ru`,
`--frames 180 --warmup 60 --report /tmp/cloth-frame.json`.
В измерительном режиме кнопки паузы/камеры отключены. Для сопоставимости каждый
отображаемый кадр делает ровно один шаг 1/60 с: при просадке FPS пример замедляет
виртуальное время, **не** выполняет скрытые дополнительные шаги. Игровой хост
должен выбрать собственную стратегию фиксированного шага/пропуска визуальных обновлений.

## Использование

```cpp
#include "engine/cloth/Cloth.h"
using namespace aiverse::cloth;
Settings settings;
settings.cells = 16;
auto grid = std::make_shared<Grid>(settings);
std::vector<Cloth> cloths;
cloths.emplace_back(grid, Vec{0, 3.5f, 0});
Batch batch(4); // включая вызывающий поток
Capsule obstacle{{1.5f,-1,0.3f}, {1.5f,-2,0.3f}, 0.4f};
Environment environment;
environment.capsules = {&obstacle, 1};
batch.step(cloths, 1.0f / 60, environment);
```

Размеры — метры, масса — килограммы, время — секунды, Y вверх. `origin` задаёт
мировое смещение отображения; частицы, закрепления и препятствия — в локальных
координатах ткани. Топология общая и после создания неизменна. В одном `Batch`
можно считать разные топологии; один `Renderer` требует одинакового размера сетки.
`workers` — 1..32, `cells` — 2..128, `substeps` — 1..16,
`iterations` — 1..32. `Environment` допускает не больше 32 коллайдеров.
Невалидный dt/число коллайдеров пропускает шаг, невалидный отдельный коллайдер игнорируется.

API вызывается одним владельцем. Пока `Batch::step` не вернулся, не меняйте объекты,
окружение или коллайдеры. `Renderer::upload(cloths, batch.representatives())` вызывается ровно один раз
за кадр после `Device::beginFrame`, до render pass; `draw` —
внутри него; `shutdown` — до уничтожения Device. Пример связи с Box3D: хост считывает
позы rigid bodies, преобразует их в локальные сферы/капсулы и передаёт в окружение.
Автоматического двустороннего воздействия на rigid bodies здесь нет.

Float-ткань служит визуальным эффектом. Совпадение результатов 1/4 потоков в тесте
не является обещанием сетевого lockstep между платформами. Сериализация состояния,
произвольные garment meshes и привязки к скелету пока не реализованы.

## Проверки и воспроизведение замеров

Тесты: сохранение закреплений, отсутствие проникновения в плоскость/сферу/капсулу,
отсутствие дрейфа в покое, устойчивость под ветром, ограничение растяжения,
битовое совпадение позиций при 1/4 потоках, freeze/reset, невалидные параметры.

```sh
python3 examples/cloth/run_bench.py \
  --binary "$PWD/build/.temp/cloth/engine/cloth/aiverse_cloth_bench" \
  --out /tmp/cloth-cpu.json
python3 examples/cloth/run_view_bench.py \
  --binary "$PWD/build/.temp/cloth/engine/cloth/aiverse_cloth_demo" \
  --out /tmp/cloth-view.json
```

Запускайте последовательно, без параллельной компиляции и других бенчмарков.
Независимые серии запускаются с выключенным sharing; дополнительная серия ниже
сравнивает группировку. CPU-тест не рисует кадры: измеряет только симуляцию, включая пробуждение работников.
GUI-тест измеряет симуляцию, подготовку/загрузку текстуры на CPU, весь callback
и реальные интервалы начала кадров. Последние включают планировщик ОС, ограничение
частоты экрана и ожидание GPU; это **не** GPU timestamps и не отдельное GPU-время.
Кадры после прогрева сохраняются, выводятся mean/p50/p95/p99. Снимки экрана
проверяются отдельно и не входят в измерительные прогоны.

## Совместный расчёт одинаковых тканей

`Batch(workers, true)` включает группировку; `setSharing(bool)` переключает её
без сброса состояния. В демонстрации она включена по умолчанию, в независимом
CPU-бенчмарке — выключена. Используйте `--share 0|1` в GUI и последний параметр
CPU-бенчмарка; `--wind-groups N` задаёт число вариантов внешнего ветра в примере.
`--wind-groups 1` даёт одинаковые условия, `16` — шестнадцать групп,
число групп, равное числу объектов, — индивидуальные условия.

Для объединения нужны:

1. Один общий неизменяемый `Grid` (топология, масса, податливость, шаги решателя).
2. Совпадающие локальные позиции **и скорости** частиц и совместимая история.
3. Совпадающие закрепления, множитель ветра, гравитация, ветер, плоскость и
   все локальные сферы/капсулы в том же порядке.

Мировое смещение и цвет не участвуют: в этой модели они не влияют на локальную
динамику. Для вращаемых или движущихся систем координат хост должен правильно
преобразовать гравитацию, ветер, коллайдеры и инерционные воздействия; текущий
пример поддерживает только мировое смещение. Разные масштабы/материалы/LOD нельзя
объединять как будто это одинаковые ткани.

После сортировки по сигнатуре кандидат проверяется точным сравнением состояния
и воздействий. Совпадение хеша **не** заменяет проверку. Решается один представитель,
его позиции и скорости копируются остальным; мировое положение экземпляра сохраняется.
`Batch::stats()` сообщает `activeObjects`, `simulatedObjects`, `copiedObjects`.
Копирование и поиск групп входят в измеряемое время симуляции.

Вариант `step(cloths, dt, common, perObject)` принимает окружение отдельно для
каждого объекта; `perObject` должен быть пустым либо иметь размер `cloths`.
При индивидуальном воздействии объект автоматически отделяется, сохраняя
накопленное состояние. Если воздействие исчезло, объект **не** подгоняется к
группе: его скорости и форма могут всё ещё отличаться. Сигнатура истории позволяет
дёшево отсеивать разные траектории; приблизительного или автоматического слияния
разных историй после затухания нет. Явный `reset()` возвращает совместимые объекты
в одинаковое состояние, после чего они могут снова объединиться.

Наивное правило «одинаковый ветер сейчас → один расчёт» неверно: оно теряет
различия после столкновений. Поэтому тест сопоставляет групповой и независимый
расчёт на каждом такте, включая разный ветер, разные коллайдеры, движение
закрепления, freeze, возобновление и reset/rejoin.

```sh
# Плотная физическая сетка, 256 объектов, 16 групп условий
build/.temp/cloth/engine/cloth/aiverse_cloth_demo --objects 256 --cells 71 --share 1 --wind-groups 16
python3 examples/cloth/run_sharing_bench.py --mode cpu \
  --binary "$PWD/build/.temp/cloth/engine/cloth/aiverse_cloth_bench" \
  --out /tmp/cloth-sharing-cpu.json
python3 examples/cloth/run_sharing_bench.py --mode view \
  --binary "$PWD/build/.temp/cloth/engine/cloth/aiverse_cloth_demo" \
  --out /tmp/cloth-sharing-view.json
```

Взаимодействия между тканями и двусторонние контакты с миром изменили бы критерии
объединения. Текущий sharing рассчитан на независимые декоративные ткани.
Он сокращает работу решателя, но **не** количество отображаемых треугольников.
GPU получает одну форму на группу и смещения экземпляров: объём загрузки падает
вместе с числом групп. Тройной набор текстур исключает перезапись данных,
которые ещё читает GPU (Metal RHI допускает три кадра в полёте). При разделении
групп текстуры увеличиваются по необходимости; уменьшаются только после повторной
инициализации. CPU по-прежнему хранит независимое состояние каждого экземпляра,
чтобы он мог отделиться без потери истории; эту память группировка не сокращает.

## Проверенные платформы и качество

Проверено на macOS arm64 / Metal: Release без предупреждений, обычные тесты,
AddressSanitizer + UndefinedBehaviorSanitizer для CPU-решателя, кадры с сотнями
объектов и крупный план. GLSL ES 3.00 прошёл компиляцию/линковку glslangValidator.
Проверена компиляция ветки без потоков с `__EMSCRIPTEN__`, но это не заменяет
настоящую web-сборку. Windows, Linux/GL, Android, iOS и web runtime не проверены.

Решатель намеренно простой. В throughput-бенчмарке используется 2 подшага × 4
итерации для всех разрешений; при 71×71 ячейках этого мало для жёсткой ткани.
`max_stretch_ratio` — максимальное отношение длины структурного/диагонального ребра
к исходной **в последнем состоянии**, не пик за всё время. В плотных сценариях
оно около 1.26–1.29, то есть локальное растяжение до 26–29%; в разреженных — около
1.02–1.05. Результаты производительности нельзя выдавать за стоимость более
жёсткой одежды, самостолкновений или сложных складок. Для таких требований нужны
другой бюджет подшагов/итераций и отдельные замеры качества.

## Частота обновления и автоматический LOD

`TemporalLod` вызывается раз в фиксированный визуальный тик 1/60 с. Расстояния
20/50/100 м дают частоты 60/30/15/10 Гц; границы и периоды настраиваются,
гистерезис по умолчанию 10%. Геометрия между обновлениями удерживается: интерполяции
во времени пока нет. Независимые группы разнесены по тикам (`stagger`), чтобы
не рассчитывать всю дальнюю ткань одновременно.

Для уже выбранного автоматического LOD передайте `LodHint` на каждый объект:
`level=0..3` заменяет дистанционный выбор, `-1` оставляет дистанцию запасным
вариантом. Таким образом большая на экране ткань в ортографической камере не
теряет частоту из-за расстояния. `visible=false` замораживает её без накопления
времени. `setMinimumLevel` задаёт ограничение от общего регулятора качества;
уровни объединяются через max, частоты не перемножаются. Внутри общей симуляции
побеждает самый требовательный видимый экземпляр. Изменившиеся внешние условия
или состояние отделяют экземпляр от группы, как и до добавления LOD.

Пример использует существующую политику размера на экране из RTS-анимации
(`render::projectedAnimationLod`, пороги не изменены) и существующий
`QualityGovernor`: каждые две ступени снижения качества добавляют один минимальный
уровень ткани. `AIVERSE_ADAPTIVE=off` отключает адаптацию к нагрузке.
В окне можно выключить автоматический выбор или весь временной LOD;
CLI: `--auto-lod 0|1`, `--lod 0|1`, оба включены по умолчанию.
Хост, который уже выбирает LOD меша/анимации, должен передавать своё итоговое
решение через `LodHint`, а не запускать второй независимый регулятор FPS.
Подключение одежды к моделям клиента/редактора по-прежнему не реализовано.

Накопленное время сохраняется при приближении и ручном выключении LOD.
`requestUpdate(index)` форсирует очередное обновление (например, после удара).
После перестановки/замены объектов требуется `reset()`. Скрытые и неактивные
объекты пропущенное время не догоняют. Внешние воздействия берутся на момент
обновления, история ветра/движения коллайдеров не воспроизводится.

Большой шаг разбивается на подшаги не длиннее исходного 60-Гц шага интеграции.
Для накопленного шага число итераций ограничений уменьшается вдвое, минимум до
двух (если настройка исходно меньше, она сохраняется). Поэтому экономия не равна
шестикратному сокращению всей физики: часть интеграции остаётся, но копирование
частиц и решатель запускаются реже. Это приближение с меньшей жёсткостью ткани;
для быстрых контактов используйте высокий уровень и принудительное обновление.
Точные копии состояния сохраняют общий токен происхождения, позволяя проверять
батч без повторного сравнения всех частиц. Прямой шаг и reset инвалидируют токен.

### Замер временного LOD (Apple M3 Ultra, arm64 Release)

512 объектов, по 5184 физических частицы (71×71 ячейка), 16 групп ветра,
8 потоков. Три повтора, 60 прогревочных + 180 измеряемых тиков, без рендера.
Ниже медианы трёх средних/P95; исходные выборки и команды:
`examples/cloth/results/macos-m3-ultra-arm64-lod-cpu.json`.

| Режим | CPU среднее, мс/тик | CPU P95, мс | Максимальное растяжение ребра |
|---|---:|---:|---:|
| LOD выключен | 8,66 | 8,83 | 1,26× |
| Смешанные расстояния | 8,60 | 8,79 | 1,26× |
| Все далеко, 10 Гц | 4,05 | 12,08 | 1,46× |

Дальний режим сокращает среднюю стоимость примерно в 2,1 раза, но P95 выше:
это редкие более тяжёлые шаги. В смешанном режиме каждый батч имеет ближнего
представителя и остаётся на 60 Гц — ускорения от расстояния нет. Дальний режим
также увеличивает растяжение; это измеренный компромисс качества, а не обещание
сохранить жёсткость. Эти числа относятся к CPU, не к полному времени кадра/FPS.
Автоматический регулятор и отсечение в CPU-замере не используются.
