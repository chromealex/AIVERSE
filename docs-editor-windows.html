Adding a window to the editor#

The editor (apps/editor) is a set of dockable Dear ImGui windows (docking branch). Every window is a small class; the editor creates one instance of each registered class, lists it in the top menu of its group (group(), see below), docks it into the default layout, saves the user's layout (<userDataDir>/editor_layout.ini) and lets agents open/close it over MCP (editor_windows, editor_window).

1. Create the file#

Put a .cpp file in apps/editor/windows/. Every file there is compiled into the editor automatically (CMake GLOB ... CONFIGURE_DEPENDS), nothing else to register.

// apps/editor/windows/BalanceWindow.cpp
#include "../Editor.h"
#include "../EditorUtil.h"     // ui::inputString, ui::inputMultiline, ui::help

namespace aiverse::editor {

class BalanceWindow : public EditorWindow {
public:
    const char* id() const override { return "balance"; }        // stable latin id (MCP, layout)
    const char* title() const override { return "Баланс"; }      // tab title, Russian (must be unique)
    const char* group() const override { return "logic"; }       // top menu: scene | world | look | logic | publish | service
    const char* dockArea() const override { return "bottom"; }   // left | left-bottom | right (Inspector) | right-bottom (rules, world / look tools) | center | bottom
    int order() const override { return 5; }                     // tab order in that area (0 = shown first)
    bool openByDefault() const override { return false; }        // hidden until opened from the menu

    void draw(Editor& ed) override {                             // called between ImGui::Begin/End
        for (auto& t : ed.rules().types) {
            if (t.cost.empty()) continue;
            ImGui::Text("%s: %lld hp", t.name.c_str(), (long long)t.maxHp.toInt());
        }
    }
    void update(Editor& ed, double dt) override {}              // optional: every frame, even when closed
};

AIVERSE_EDITOR_WINDOW(BalanceWindow);

} // namespace aiverse::editor

title() is the plain tab text (MCP editor_windows reports it). The ImGui name is imguiName() = "<icon> <title>###<id>": the ###id part keeps docking, saved layouts and focus stable. Use imguiName() (or ed.focusWindow("id")) whenever ImGui needs the window's name. The tab icon comes from windowIconFor(id()) in EditorIcons.h, or override icon().

Rebuild the editor; the window appears in the menu of its group. New windows join the tabs of their dockArea the first time they open; Вид → Сбросить раскладку rebuilds the default layout.

A workspace (Editor::openWorkspace(group)) opens the default windows plus every window of the group, rebuilds the layout and brings the group's tabs to the front. Clicking a window in a menu opens it and brings it to the front; clicking it again while it is in front hides it.

Other menus: Файл (projects, maps), Правка (undo, symmetry, ramps, map check), Вид (service windows, workspaces, what the Scene shows, theme). Shortcuts: Ctrl/Cmd+S save, Ctrl/Cmd+Z / Y undo/redo, F5 test, Ctrl/Cmd+B build window; in the Scene 1…0 pick tools, F focus, [ ] brush size, Delete removes.

Rules for windows:

  • Never write into the simulation (ed.sim()): it is deterministic and replayable; use commands.
  • Change rules and maps through ws().call(...) or doc().beginEdit() + edit + doc().touched().
  • Keep per-window state in members (one instance per window).
  • Russian UI text, English code and comments (see AGENTS.md).

3. Look: theme, icons, toolbars#

The editor style (dark / light, accent presets, menu Вид → Тема, MCP editor_theme) lives in apps/editor/EditorTheme.*; windows don't set colours of their own. Prefer the theme's colours (ImGui::GetStyle().Colors, ui::accentColor(), ed.theme().palette()) over hard-coded RGB, so both themes stay readable.

Icons: Lucide font merged into the UI font, constants in apps/editor/EditorIcons.h (ImGui::Button(ICON_PLAY " Играть")). Helpers in EditorUtil.h:

4. Exposing it to agents#

If the window adds an action an agent should be able to do, register an operation (in the window's constructor is too early; do it in update() once, or in EditorAgent.cpp):

ed.ws().registerOp({"balance_report", "Damage per cost of every unit type.", Json::parse("{}"),
                    [&ed](const Json&) { Json r = Json::object(); /* ... */ return r; }, true});

Operations appear in MCP tools/list for agents connected through aiversemcp (the tool list is the Workspace registry; GUI-only operations have guiOnly = true and fail politely without the editor window).

Game HUD#

The Game play-test renders ui/hud.rml and ui/howto.rml through RmlUi into its viewport after the scene. Missing documents, styles and images fall back to engine/assets/ui; game fonts (fonts/ui.ttf, fonts/title.ttf) follow the client. The editor selects the game language with the same saved-choice/system-language rules. Restart the play-test after editing RML, RCSS or fonts to reload them.

apps/client/UiModel.h owns the shared game model schema and change-only updates. apps/editor/GameHud adapts the editor simulation to that model: resource/status panels, script HUD cards, support actions and region ratios. Buttons issue Commands; pause/restart/stop operate on the editor play-test. Pointer coordinates are local to the viewport; RmlUi layout and projection use its framebuffer size and device density. World-space region markers remain editor overlays.

This is an embedded play-test HUD, not a second GameClient: client lobby/menu flow, UI Lua game APIs, audio playback and the client's full standard RTS command card/minimap are not hosted by the editor adapter. For those use Play as in the client below.

Play as in the client#

The Game window can also run the game exactly as AiverseGame does: the same GameClient (apps/client/GameClient*.cpp, Client*.cpp; AiverseGame's main.cpp adds only the entry point) hosted by apps/editor/ClientHost and rendered into the window's offscreen target, inside the device simulator frame. Everything is the client's: the game's menus / meta screens (ui/main.lua, ui.screen / ui.popup), launch parameters, battle -> result -> meta flow, view scripts (draw, camera, HUD documents, view.ui_call), script UI, input (rules mapClick tap on release, left-drag pan, wheel zoom, map-drag HUD elements, RmlUi clicks, keys), the pause screen and audio. The editor's own play-test tools (bots vs bots, player pick, speed, pause, stats) stay for the map play-test; the two never run at once.

  • Start: the gamepad button of the Game toolbar, «Как в клиенте» under the empty Game window, the play popup of the top bar, menu Логика → Тест, MCP play_start {"client": true}; F5 and the top-bar Play button start it for games with their own screens (ui/main.lua). Stop / restart in the Game toolbar, F5, play_stop; the game's own Quit stops it too.
  • «В отдельном окне клиента» (external-link button): the project in a separate AiverseGame window (AIVERSE_CONTENT = project), the one built next to this editor first (same C++ modules).
  • The project's C++ modules (rules nativeModules) must be in the editor binary, as for the play-test (the banner offers the per-project editor build).
  • Hosting: while the host calls into the client it sets platform::setHostedView (logical size of the device screen, framebuffer size, scale, safe area of the device preset, touch, content root = project, engine/... -> the engine assets; requestQuit / fullscreen are recorded, the window title is left alone) and restores the editor's ImGui context afterwards (every ImGuiLayer owns its context). Pointer events inside the device screen (or captured by a press inside) and keys while the Game window has focus are mapped into screen points and forwarded.
  • Profiles / saves go to the editor's user data dir (AIVERSE_UI_SAVE_DIR overrides, as in the client).
  • Command line (automated checks): aiverse_editor --project <dir> --play-client --device iphone-se:portrait --window game.
