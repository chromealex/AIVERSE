# Жанры и интеграция

Жанр проекта отделён от модуля симуляции. Tower Defense и lane battler относятся
к RTS. RPG, MOBA, выживание, колония и город могут переиспользовать RTS-механику.
FPS использует свой модуль. Наличие рецепта не означает готовую игру или интерфейс.

`libraries/include/aiverselib/app/Genre.h` содержит 16 рецептов, включая два поджанра
RTS. `allGenres` перечисляет их; `parseGenre` принимает стабильные ID и алиасы
`rts` / `rpg`. Старые значения enum и ID сохранены. `family` задаёт группировку,
`packages` — существующие пакеты, `acceptance` — обязательные игровые проверки,
`integration` — необходимые точки подключения конкретного проекта.

```sh
aiverse_app_tools genre examples/genres/recipes/platformer.json
```

CLI возвращает `coverage: "recipe"`: список требований, а не сертификат готовности.

## Объём расширения

| Рецепт | Существующая основа | Что требуется собрать и проверить |
|---|---|---|
| classic-rts | RTS, экономика, строительство, бой | Сбор → строительство → армия → победа |
| tower-defense (RTS) | Строительство, волны, оружие | Маршруты, жизни, улучшения, запрет перекрытия пути |
| lane-battler (RTS) | Линии, гарнизоны, способности | Выпуск волн, достижение базы, завершение матча |
| fps | FPS motor, оружие, authority | Клиент, попадания, восстановление состояния |
| action-rpg | Герои, XP, предметы, способности | Управление героем, добыча, экипировка, квесты, HUD |
| survivors | Массовое движение, бой, способности | Автоатака, нарастающие волны, выбор улучшений, босс |
| survival | Сбор, строительство, инвентарь, рецепты | Нужды, ремесло, убежище, сохранение мира |
| colony | Работы, логистика, нужды | Приоритеты жителей, производство, потребление |
| city-builder | Дороги, производство, ресурсы | Жильё, население, налоги, зоны обслуживания |
| turn-based | Встроенные turns, strategic map | UI хода, лимиты действий, ИИ, итог боя |
| moba | Герои, линии, предметы | Магазин, возрождение, командные правила, HUD |
| platformer | Fixed, collision, FPS motor | Боковое управление, платформы, ловушки, checkpoints |
| racing | Fixed, collision | Мотор автомобиля, трасса, checkpoints, круги, финиш |
| cards | RNG, команды, сохранения, UI | Зоны карт, оплата/эффекты, очередь ходов, рука |
| puzzle | Сетка, RNG, команды, сохранения | Перестановки, совпадения, падение, цели, лимит ходов |
| idle | Доход, ресурсы, улучшения, meta | Производство, покупка улучшений, milestones, профиль |

Механики и интерфейс проверяются раздельно. Для новых симуляций обязательны
отклонение некорректных команд, одинаковые результаты при одном seed, snapshot
rollback и продолжение после бинарного сохранения. Для интерфейса требуется
реальный запуск и визуальная проверка. Cross-platform проверка отдельно от host.

## Реализованный первый набор

- `modules/genres/BoardModule`: карточный бой (колода, рука, сброс, энергия,
  урон, защита, добор, смена хода, боты) и match-3 (валидная перестановка,
  совпадения, падение/заполнение, каскады по тикам, лимит ходов, цель).
- `modules/genres/MotionModule`: платформер поверх существующего FPS motor
  (движение, прыжок, препятствия, опасности, возрождение, checkpoints) и аркадное
  вождение (газ, тормоз, поворот, swept collision, порядок checkpoints, круги).
  Парковка внутри checkpoint не засчитывает новые круги.
- Оба модуля используют `Simulation`, команды и её RNG, хранят состояние в
  World, поддерживают snapshot rollback и бинарные сохранения. Новые пути
  загрузки проверяют размеры и диапазоны состояния.
- `apps/genres/client.cpp`: настольный reference-клиент четырёх новых режимов.
  Управление мышью/клавиатурой, пауза, сохранение/восстановление снимка в памяти,
  локализация en/ru. Снимок исчезает при закрытии программы.
- `examples/genres/rts/*`: 9 минимальных проектов на существующем RTS-модуле.
  Они открываются как обычные игровые проекты и работают в штатном клиенте.
  `tools/genres/create_samples.py` воспроизводит эти авторские примеры.
- `examples/genres/index.json`: маршруты запуска всех 16 рецептов, включая
  существующие RTS, FPS и lane battler.

### Сборка и запуск

Из корня движка (macOS/Linux; на Windows выбрать подходящий генератор):

```sh
cmake -S . -B build/.temp/host -DCMAKE_BUILD_TYPE=Release \
  -DAIVERSE_BUILD_CLIENT=ON -DAIVERSE_BUILD_GENRE_CLIENT=ON
cmake --build build/.temp/host --target aiverse_client aiverse_genre_client aiverse_genre_tests
python3 tools/genres/play.py list
python3 tools/genres/play.py puzzle
python3 tools/genres/play.py platformer
python3 tools/genres/play.py action-rpg
```

FPS запускается через существующий `aiverse_fps_client` (его опция
`AIVERSE_BUILD_FPS_CLIENT=ON`). Скрипт выбирает клиент по модулю и передаёт RTS-проект
через `AIVERSE_CONTENT`. Перед запуском создаёт временную копию проекта с общими
engine assets под `build/.temp`; удаляет её после выхода. Исходный проект не меняет
и shell-строки не выполняет.

### Проверки

```sh
cmake -S tests/genres -B build/.temp/genres -DCMAKE_BUILD_TYPE=Release
cmake --build build/.temp/genres
ctest --test-dir build/.temp/genres --output-on-failure
python3 tests/genres/aiverse_samples.py --headless build/.temp/host/aiverse_headless
```

Проверяются чужой ход, некорректные команды, нехватка энергии, ограничение цепочек
бесплатных карт, сброс защиты, некорректная перестановка, каскады, прыжок в воздухе,
остановка у стены, неподвижность внутри checkpoint, повторяемость и продолжение
после сохранения. Для 9 RTS-проектов проверяются завершение бот-партии, отсутствие
ошибок Lua и snapshot/serialized/fresh-serialized restore со сравнением каждого тика.

### Границы покрытия

Это минимальные рабочие механики и образцы, а не завершённые коммерческие игры.
Рецепты `acceptance` шире этих smoke/restore-проверок. В частности, квестовый журнал,
редактор колод, развитая модель населения/городских служб, физика подвески/шин,
большой бесшовный survival-мир и постоянный офлайн-прогресс idle здесь не добавлены.
Потребности, предметы, прогрессия, экономика и пошаговый режим используют существующие
RTS-системы; шаблоны не заменяют их параллельными реализациями.

## Редактор и упаковка

Хаб содержит 14 категорий: RTS (включая Tower Defense и lane battler), FPS и остальные
12 жанров. Каталог включает 13 новых проектов из `examples/genres` и существующие
RTS/FPS-шаблоны. Создание проекта копирует все его данные в выбранную папку.

Для `board` и `motion` окно Genres редактирует JSON правил и карты. «Проверить и применить»
проверяет оба документа настоящим модулем перед сохранением. Play/F5 открывает отдельный
клиент с выбранной картой; это не встроенный симулятор устройств. RTS использует обычный
клиент и редактор, FPS сохраняет существующий отдельный запуск.

`aiversebuild` передаёт `game.json.module` в `AIVERSE_GAME_MODULE` и собирает штатный
платформенный target с нужной точкой входа. Экспорт исходников включает FPS и жанровый
клиент. Данные и ресурсы загружаются после инициализации платформы, включая `content.rpak`.
Без manifest старые низкоуровневые fixtures `rules.json` + `map.json` продолжают работать.
На карте board/motion поле `module` сохраняет её JSON без преобразования в RTS-формат.

Сетевой протокол FPS не подключён к board/motion. Android/iOS/Windows/web требуют
отдельной проверки SDK; наличие CMake-пути не означает проверенную сборку.

## Проверка интеграции (macOS, AppleClang 17)

- Полный `aiverse_tests`: 6083 проверки, 0 ошибок. Для проверки локальных сокетов
  запуск выполнен вне ограничивающей сеть песочницы.
- Фильтр детерминизма: 350 проверок, 0 ошибок; отдельные board/motion-тесты прошли.
- `genre_projects`: создание, открытие и сохранность карт всех 13 новых проектов.
- Все 9 RTS-образцов: победитель и совпадение snapshot/serialized/fresh restore.
- Все 30 существующих шаблонов: headless seed 3 без ошибок процесса и Lua.
- Все 9 библиотечных наборов, CLI жанров, 73 записи каталога и внешний native/export
  consumer прошли. Заголовки библиотек прошли самостоятельную компиляцию.
- Все 16 рецептов прошли настоящую упаковку ресурсов (`aiversebuild --estimate`).
- Windows и Android: экспорт исходников с правильным модулем; Windows-экспорт
  конфигурируется как самостоятельное CMake-дерево на Mac.
- Пакет `.app` с `content.rpak` запущен вне папки исходников. Проверены cards, puzzle,
  platformer, racing и FPS, реальная отрисовка осмотрена на скриншотах.
- В редакторе проверено окно правил/карты и запуск платформера через Play.

Повторная ручная проверка хаба выполнена: видны все 14 категорий, список прокручивается,
выбор RPG и головоломок корректно фильтрует шаблоны. Tower Defense и линии объединены с RTS.
Windows/Android/iOS/web-бинарники и их управление не проверены; экспорт проекта
не заменяет сборку и запуск на целевой платформе. Новых шейдеров нет.
Изменения находятся в `codex/genre-integration`; публикация и перенос в main не выполнялись.
