How the engine works

Three pillars around one game

01 · data

A project is text

game.json, rules.json, levels, UI, audio and effects are readable files. No binary scenes: people and agents edit the same thing.

02 · mechanics

Gameplay is built in

Armies, characters, vehicles and racing, combat, movement, stealth, dialogue, cards, puzzles, economy — 88 deterministic libraries that work in any project.

03 · agent

The AI checks its own work

Bot matches, scenarios with checks, balance matrices, a rules linter and screenshots: the agent sees the result instead of working blind.

From idea to store

Describe the idea and point at a folder of art — the pipeline does the rest

  1. 1Idea, art, musicA text description and assets are all the input it needs.
  2. 2“Make a game” wizardOr an agent through MCP: levels, tutorial, meta, shop, icon, splash.
  3. 3Project = datagame.json · rules.json · levels · ui · fx · audio.
  4. 4Verification ↺Bots play the tutorial and every level; findings go back into fixes.
  5. 5aiversebuild.app, Xcode, Gradle/APK, web and .exe in one command.

Data instead of code

An object is a description

The worker from the skirmish RTS template: gathers gold and wood, builds five structures and fights with a pick. Not a line of C++.

your own mechanic

No ready-made mechanic? The AI writes a plugin for your game

Lua

Scripts live in the game folder and are listed in rules.json. They run inside the deterministic simulation — in network play and in replays — or only on the player's screen. They are edited in the editor with hot reload, no engine rebuild.

C++

Game modules in the native/ folder with their own components, systems and engine hooks. Built together with the game, the editor and the server on every platform, iOS, Android and web included. The engine sources stay untouched.

Good-looking even on a weak mobile GPU

Shadows, particles, terrain and post-effects have quality tiers and adapt to the GPU, from old Mali and Adreno to Apple Silicon. Own RHI: Metal, GLES3/WebGL2, GL 3.3, Vulkan.

Network, server and meta

Bit for bit on every platform

Fixed-point instead of floats, its own RNG and checksums: the same match on an iPhone, an Android phone and in a browser produces the same hash. So you can pick the network model that fits the genre — and host your own server.

network · model 1

Rollback lockstep

Only commands go over the network. Input rollback with hash checks, correction smoothing, reconnect and late join.

network · model 2

Authoritative server

A client and a server that decides everything: large streamed worlds up to 100 players and bots on the server.

self-hosted

Your own battle server

aiverse_server on your machine: encrypted UDP and WebSocket, match tickets, server pings, Elo matchmaking, replay-based verdicts.

meta · LiveOps

Meta service

Shop, currencies, quests, passes, energy, leaderboards, chat, friends and clans, tournaments — from JSON, with its own backend and a ready client.

Quick start

01 — Build the engine 
cmake -S . -B build/mac -DCMAKE_BUILD_TYPE=Release
cmake --build build/mac -j 8
open build/mac/AiverseEditor.app
Prefer not to compile? Download a prebuilt editor.
02 — Make a game
In the hub click Make a game or create a project from a template. Play against bots right away in the Game window.
03 — Connect an agent
The editor’s Agent window shows a ready aiversemcp config — paste it into Claude Code or another MCP client.

Describe the game.
The rest is data.
