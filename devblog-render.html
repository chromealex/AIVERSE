    Projectile and trail share one position

    Model, trail and light consume one position sample. Ricochet and split continue from contact or branch positions.

    The demo has four scenes: straight, arc, ricochet and split. The launcher fires automatically; map=0…3 selects the scene.

    At retirement the trail receives the final endpoint, including projectiles born and removed between rendered frames.

    Verified
    Four scenes checked on Metal and loaded in WebGL. Real flight frames and browser ricochet/split captures are retained.
    Limitations
    Static frames do not prove every-frame alignment. Windows and Vulkan are untested.

  3. Nov 25, 2026
    Donecodex/render-capabilities-20261125 · d45befebc

    Quake III levels with textures and baked lighting

    AIVERSE opened the original Egyptian Trouble level from OpenArena. Materials use their diffuse images and each lightmapped surface receives its own baked page.

    The camera uses the viewpoint authored in the map. Its visibility cluster admits 1,408 of the 3,073 surfaces. Curved patches preserve both UV sets through tessellation.

    Akom74 and Neon_Knight created the map. Simon “sock” O’Callaghan created the Egyptian textures. The map and textures are distributed under GPL-2.0-or-later.

    In the web sample the native CatalogView reads the original BSP through WebAssembly. Orbit, zoom and switch the diffuse or lightmap layer independently.

    Verified
    Two Mac tests passed. In the 800×500 Metal frame, disabling diffuse textures changed 400,000 pixels and disabling lightmaps changed 396,284. In Chromium WebGL2, toggling diffuse changed 191,422 of 210,000 sampled pixels, toggling irradiance changed 207,126, and orbiting changed 174,849.
    Limitations
    The importer translates static material stages. It omits animated stages, sky portals, Quake collision and game logic. The minimal scene client omits legacy model import.

    Projectile impact height

    Each target type can set its impact height. The visible projectile and its trail follow the same line from the muzzle to that point.

    The orange band on each range target marks its impact height. Select the launcher and right-click another target to switch.

    Verified
    Both frames were captured with the AIVERSE Mac client from the same camera position.
    Limitations
    Applies to ordinary straight shots on flat maps. Heights are measured from the target base in world units.

  7. Nov 25, 2026
    In progresscodex/cpu-d3d-render-20261125 · 965f7c674

    Model thumbnails on CPU and Direct3D

    The model viewer can save a PNG thumbnail without opening a window. Choose the CPU rasterizer or either Direct3D backend on Windows.

    The knot contains 16,384 triangles. Its loops overlap on screen, so the depth buffer determines which surface appears closest to the camera. Lighting reveals the curvature. All three images use the same mesh, material and camera.

    The --headless-capture argument selects the renderer when starting the viewer. For textured models, the preview also applies the base color, UV coordinates and vertex colors.

    Verified
    The 512 × 512 thumbnails were captured on the CPU on macOS and through Direct3D 9 HAL and Direct3D 11 WARP on Windows Server 2022.
    Limitations
    The capture tool runs against files on the desktop. The browser build does not expose this command-line mode or the Windows Direct3D APIs. The images show the model in its bind pose.

  8. Nov 22, 2026
    Donemain

    Vulkan catches up with GLES on a phone: shader optimizer and an on-disk cache

    On a Galaxy A05s Vulkan was a third slower than GLES because shaders reached the driver unoptimized. The engine now optimizes SPIR-V itself and keeps the result on disk: the 20-sphere STRATA test runs at 60 fps on Vulkan too.

    Same scene: 20 spheres of a million triangles, STRATA budget 60 k triangles, rendering at 1200×540. To find the gap, the Vulkan backend got per-pass GPU timing (AIVERSE_VK_GPU_TIMING=1).

    Pass synchronization, depth write-back and the frame rotation added up to less than a millisecond. Almost all the time was the main pass: 19.9 ms on Vulkan. At a quarter of the pixels Vulkan stayed slower than GLES by the same ratio, so the shader code itself was the cost.

    The engine compiles GLSL to SPIR-V at run time and the optimizer was off. The Adreno driver hardly optimizes such code itself. The SPIRV-Tools optimizer is now part of the engine: every program goes through the performance passes. Main pass: 14.7 ms instead of 19.9.

    Optimizing adds time to the first load, so the finished SPIR-V is stored in the app folder and read from disk on later launches.

    Also fixed: interface text missing on Vulkan. Font glyphs rasterized during the frame are now uploaded before the frame.

    Verified
    Samsung Galaxy A05s (Adreno 610, 1200×540), 60 k triangle budget: Vulkan 59.9 fps (61.7–62.8 uncapped, 15.9 ms GPU per frame) versus 47.4 fps without the optimizer; GLES 59.9 fps (66.7 uncapped). Load to first frame on Vulkan: 15.7 s on first launch, 9.4 s with the cache (10.6 s without the optimizer).
    Limitations
    The first Vulkan launch takes 5 seconds longer: shaders are optimized once. Frame rotation costs 1.2 ms of GPU on this phone. Checked on one phone; Windows and Linux Vulkan were not run after this change.
