    Vulkan catches up with GLES on a phone: shader optimizer and an on-disk cache

    On a Galaxy A05s Vulkan was a third slower than GLES because shaders reached the driver unoptimized. The engine now optimizes SPIR-V itself and keeps the result on disk: the 20-sphere STRATA test runs at 60 fps on Vulkan too.

    Same scene: 20 spheres of a million triangles, STRATA budget 60 k triangles, rendering at 1200×540. To find the gap, the Vulkan backend got per-pass GPU timing (AIVERSE_VK_GPU_TIMING=1).

    Pass synchronization, depth write-back and the frame rotation added up to less than a millisecond. Almost all the time was the main pass: 19.9 ms on Vulkan. At a quarter of the pixels Vulkan stayed slower than GLES by the same ratio, so the shader code itself was the cost.

    The engine compiles GLSL to SPIR-V at run time and the optimizer was off. The Adreno driver hardly optimizes such code itself. The SPIRV-Tools optimizer is now part of the engine: every program goes through the performance passes. Main pass: 14.7 ms instead of 19.9.

    Optimizing adds time to the first load, so the finished SPIR-V is stored in the app folder and read from disk on later launches.

    Also fixed: interface text missing on Vulkan. Font glyphs rasterized during the frame are now uploaded before the frame.

    Verified
    Samsung Galaxy A05s (Adreno 610, 1200×540), 60 k triangle budget: Vulkan 59.9 fps (61.7–62.8 uncapped, 15.9 ms GPU per frame) versus 47.4 fps without the optimizer; GLES 59.9 fps (66.7 uncapped). Load to first frame on Vulkan: 15.7 s on first launch, 9.4 s with the cache (10.6 s without the optimizer).
    Limitations
    The first Vulkan launch takes 5 seconds longer: shaders are optimized once. Frame rotation costs 1.2 ms of GPU on this phone. Checked on one phone; Windows and Linux Vulkan were not run after this change.

    Studio, the editor, now for Windows too

    AIVERSE Studio builds for Windows: the same interface, Scene, brushes and Play as on the Mac, running on WebView2 and Vulkan. Mac and Windows share one editor core, so new features reach both systems at once.

    On Windows, Studio is the AiverseStudio.exe application. The interface is the same as on the Mac: workspaces, panels, the project hub and the loading screen. The Scene and Game views are drawn by the engine with Vulkan right over their panels, with no frame copying through the browser.

    Everything except the window, system dialogs and input is shared between Mac and Windows: opening projects, selection and transforms, the terrain, tile, field, object, road and river brushes, Play, asset previews and the Agent panel. On both systems the Scene renders on its own render thread, so the interface never waits for a frame.

    To build the editor on Windows, run studio_windows.cmd at the repository root. It needs the WebView2 Runtime (built into Windows 11) and a Vulkan-capable driver.

    Along the way, Console text can now be selected and copied in both editors, and long operations no longer fail with a timeout error.

    Verified
    On the Mac the editor on the shared core was checked on screen: the Scene on its render thread, object selection, gizmos and the Edit menu. The Windows version builds into a complete application but has not been run on Windows yet.
    Limitations
    Windows does not have floating panel windows yet, nor dragging files from Explorer or assets into the Scene, the device frame in the Game view, or a fallback without Vulkan. The first run on a real Windows machine is still ahead.

    Catalog window in Studio and packages over MCP

    Studio has a Catalog window: search the package catalog, see a package and install it into the open project with one button. Agents do the same through the package_* MCP commands.

    Verified

    Planets on TerraWeave: relief, biomes, trees and rocks

    Planet relief is now built by TerraWeave fields carried over to the sphere, and TerraWeave trees and rocks grow on land according to the climate of each place.

    The planet generator (rocky, ocean and moon presets) takes heights and biomes from TerraWeave: the same octave sum and climate model as on flat maps, with the fields evaluated in 3D on the sphere. Cube faces therefore join without seams, and the poles are colder than the equator.

    Trees and rocks now cover the land: spruce and pine in cold places, oak and birch in forests and grassland, willow in wetlands, boulders and slabs in deserts and on rock. The models come from the Arbor tree generator and the TerraWeave rock generator; the place and species for every cell are chosen deterministically. Density and scale are set in the map with visual.flora.

    Verified
    Frames taken in the game client (OpenGL) on the regenerated Big Planet; generator checks — face seams, separated starts, symmetry and determinism — pass with the new reference hashes.
    Limitations
    Planet seas are still their own, not NEREID: no waves or shore foam yet. Trees ignore fog of war, and the Metal shaders have not been run on a Mac yet.

    Планеты и генерация картDonemain · 4230eff56

    Planet seas became NEREID water bodies

    The sea of any sphere — a planet, a moon or anything else — is now a NEREID water body: depth, up, current, waves and buoyancy follow the radius, and ships get splashes and wakes.

    NEREID gained sphere water bodies: a shell around the planet's centre with the surface at sea level and the floor at a set depth. For any point they return the radial depth, the direction up from the centre and a current flowing east around an axis.

    The same buoyancy components as for flat water push an object along the radius on a sphere. A map turns this on with a single nereid key on a body; without the key nothing is registered, and saves and checksums of old maps stay the same. Big Planet already has it on.

    Waves now exist in the simulation too: the sea level on a sphere rises and falls with a set amplitude and period, and depth and buoyancy follow it. Objects in the water get entry, exit and wake events — the same as for flat water, so splash effects read them unchanged. This is shared NEREID code for any game, not only strategy: one flag in the water pipeline turns it on.

    Verified
    The new ecs_nereid_sphere_water_test (sampling, current, buoyancy, determinism, saves) passes; a bot match on Big Planet plays to a winner, the save restore check passes, and the planets template checksums match the baseline.
    Limitations
    Simulation waves and the waves on screen do not match exactly yet: the picture has its own, the simulation its own. Built-in RTS ships get probes automatically but do not drift with the current yet — movement stays with the host.
    docs/planets.md

    Планеты и генерация картDonemain · d04505b80

    Planet seas on NEREID waves

    Water on planets is now drawn with NEREID's wave model — the same as rivers and lakes on flat maps: turquoise shallows, deep blue and foam along the coast.

    NEREID's waves moved into a shared set of shader functions used by both flat water and planet seas. On a sphere the same waves are evaluated in three projections and blended by the surface direction, so cube faces show no seams.

    The sea colour follows the depth under every point: light and clear near the shore, darker further out. Foam runs along the land's edge, and the edge itself follows the relief.

    Verified
    Frames taken in the game client (OpenGL) on Big Planet; flat water on an ordinary map draws as before after the functions moved.
    Limitations
    This is the look. NEREID water bodies on spheres do not exist yet: planet seas have no buoyancy, currents or water contact so far. The shader has not been run on Metal yet.

    Planets: coasts that follow the relief instead of square seas

    The sea on a planet is now cut by the ground height at every pixel, and the Big Planet map is built by the engine's generator: noise relief, bays and islands.

    Big Planet used to have seas with straight edges. The cause was the map itself: its heights came from a hand-made formula with latitude bands, and lowlands on the cube faces came out rectangular. The map is now built by the engine's generator with the rocky preset — the same one as in the Generation window: noise relief, sea level by water share, flat base areas and fair starts.

    The water itself is neater too: every sea pixel checks whether the ground under it is above sea level, and the water turns shallow towards the coast. The coastline follows the relief exactly at any level of detail and no longer depends on depth buffer precision.

    Verified
    Frames taken in the game client (OpenGL); a bot match on the new map plays to a winner.
    Limitations
    The Metal shader is updated but has not been run on a Mac yet. The small Two Worlds map keeps its old heights for now: tests depend on it.
    docs/planets.md

    Жанры и механикиDonefeature/aiv20261121_no-genre

    One engine for every game: no split by genre

    Strategy games, shooters, races and cities now run through one core, GameCore: gameplay systems live in engine/, and project data, not a genre module, decides what is on.

    The engine used to keep two separate hosts: modules/rts for grid games and modules/fps for metre maps. Every system of the grid host (combat, economy, traffic, driving, arsenal, raids, commerce, careers, sensors, progression) moved to engine/game, the view to engine/view/game, sound and effects to engine/audio and engine/fx.

    Actor systems (characters, weapons, projectiles, vehicles, battle royale, races, bots) are now part of the same core: GameCore runs them when the map is in world coordinates. A map of either kind is one scene document; the editor and Studio treat it the same way, and there is one client.

    Data-format names no longer name a genre: game.json "module" is "game" or "actor", the actor rules block is "actor", the native Lua library is core, and the bot packages are bots-commander, bots-combatant and action-bots.

    Verified
    Full Mac build and all 434 tests; checksums of every sample match the previous ones except the known boss_arena seed 2.
    Limitations
    Old projects, replays and saves with the previous names do not load. The GTA2 port is separate work.

    Сборка и платформыDonefeature/aiv20261122_packages · a304cd753

    Package catalog: content is downloaded separately from the engine

    The terrain and vegetation PBR material libraries and their sources moved out of the engine into a package catalog. A project installs only what it needs with one command; the website has a new Catalog page.

    The catalog is a separate repository, AIVERSE-PACKAGES, with sections: templates, materials, textures, models, audio, effects, UI, scripts, plugins, tools. Every package has a description, previews, a licence and the minimum engine version.

    `aiverse_pkg.py add terrain-pbr --project <project>` downloads the package, checks its hash, puts the files into the project and adds the materials to its library. The version and file hashes go to `aiverse.lock`, so a cloned project is restored with `install`. A downloaded package is kept once per computer for all projects.

    Engine skills name the packages they need, and an agent installs them by itself.

    New packages are added by pull request to the catalog. Once merged, a package appears in the engine and on the Catalog page by itself: previews, description, engine version, a download button and the install command.

    Verified
    Four packages are published in the catalog and downloaded over the network on Linux; their textures are byte-identical to the former engine files, and the material map checks pass. The Catalog page was opened in Chrome at desktop and phone width and shows the packages from the catalog.
    Limitations
    There is no catalog window in Studio and no MCP commands yet: search and install run from the command line. The editor build with the changed empty project was not checked on macOS.

    Catalog viewer: shapes, LOD and STRATA, animated loading mark

    The 3D preview of catalog packages shows materials on a sphere, cube, cylinder or plane with textures at their own size, and models by LOD level or through STRATA. Every loading state on the site, in Studio and in web builds now shows the animated AIVERSE mark.

    Materials get a shape switch above the view. Texel density is the same on every shape, and spheres and cylinders get a whole number of repeats around, so the seam is gone. Textures arrive exactly as the package author published them: thin alpha-cut leaf edges no longer turn into blobs. The panel on the left lists every map — colour, normal, ORM, AO — with its size in pixels and its file size.

    Models: Auto LOD (the level the renderer picked at this distance is highlighted), any level by hand, or STRATA — clusters are built from the model on first request and the Clusters button colours them. Wireframe shows the edges of the shown level. The panel lists triangles per level, whether the engine generated the LODs, and STRATA's cluster count and build time.

    The loading mark is the same assembly of blades and diamond as the engine's splash: on the site (catalog, builds on the releases page), in the viewer, in Studio instead of spinners, and in web builds of games without their own splash.

    Verified
    Frames come from the desktop build of the viewer (Linux, OpenGL) on the terrain-pbr and vegetation-pbr packages and a 20k-triangle test rock; the loading mark was captured on the built site in Chrome.
    Limitations
    The web viewer is built in the catalog and checked after it is deployed. The catalog has no model packages yet, so LOD and STRATA appear on the site with the first one. STRATA is built on first request, which is a noticeable pause on a large model.

    The catalog has its first model packs — 12 TerraWeave rocks and 10 tree species, three LODs each. A package can depend on another and use its textures instead of copies. Catalog texts are English with translations such as title-ru, and the catalog page explains how to add your own package.

    Жанры и механикиDonemain · dcba54d8c

    Races in any project

    A map with a "race" block turns its cars into a race: countdown, gates, laps, standings, bots on the track, a HUD and a chase camera.

    A race is map data: checkpoint gates in driving order (the last one is the finish), a starting grid and a closed line for the bots. Rules set the countdown, the time to finish after the winner, a timeout and crash damage.

    Gates count only in order, so shortcuts gain nothing. A car that is stuck, going the wrong way, wrecked or fallen off the world returns to its last gate. The race decides the match: the team in first place wins.

    The same race, HUD and camera run on two kinds of maps: metre maps with colliders and grid maps with heroes. Controls, car physics and spline roads are shared. There are two sample games: the Oval Sprint oval and the Road Circuit along a spline road with trucks whose wheels roll and steer.

    Verified
    Bots complete three laps on both samples; a save in the middle of a race continues exactly as without it; other metre-map games play as before.
    Limitations
    Getting in and the look of the cars still differ between the two map kinds: on metre maps cars are drawn as boxes.

    Сборка и платформыDonemain

    Client builds take only the engine modules they need

    game.json can choose which optional engine parts go into the packaged game, or leave it to detection: "engineModules": ["auto"].

    Every packaged game used to carry the whole engine: particles, Spine, gamepads, FBX and legacy model loaders, the city server client, traffic and map generation. Now a packaging.engineModules list, shared or per platform, can leave them out.

    "auto" looks into the project: Spine and gamepad from game.json, particles from effect files, loaders from source models, simulations from rules and maps. If the game uses something excluded, the packager refuses with a clear error; without the field everything builds as before.

    On a test macOS client build the executable shrank by about 7% just from linking only the code in use. Each disabled module removes from about a hundred kilobytes (gamepad) to a couple of megabytes (particles, legacy model loaders).

    Verified
    The packager checks the module choice for Web, Windows and macOS; sizes were measured on the macOS client.
    Limitations
    HTML5 build size and startup are not measured yet: Emscripten was missing on the build machine. Android, iOS, Windows and Linux have not been built with modules off either.
