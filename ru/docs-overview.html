AIVERSE — подробный обзор#

Справочник по всем частям движка: состав, сборка, форматы, подсистемы, платформы и статус проверки. Короткое введение — зачем движок и какие задачи он решает — в README (English). Правила для агентов, которые меняют движок, — в AGENTS.md.

Быстрый старт (macOS)#

cmake -S . -B build/mac -DCMAKE_BUILD_TYPE=Release      # нужны Xcode и CMake
cmake --build build/mac -j 8
open build/mac/AiverseEditor.app                              # редактор (проект ~/.aiverse/packages/templates/skirmish)
open build/mac/AiverseGame.app                                # игра
./build/mac/aiverse_tests

Другую игру в редакторе: AiverseEditor.app/Contents/MacOS/AiverseEditor --project ~/.aiverse/packages/templates/mushrooms. Чтобы игра запускалась с другим набором данных, задайте -DAIVERSE_CONTENT_DIR=~/.aiverse/packages/templates/mushrooms.

Несколько редакторов одновременно#

Каждый процесс редактора может открыть свой проект через --project <папка>. Без --listen первый экземпляр занимает MCP-порт 47321, а при занятом порте ОС автоматически выделяет свободный. Фактический порт показан в строке состояния; окно Agent добавляет его в конфигурацию подключения (aiversemcp --port <порт>). Автоматически выделенный порт может измениться после перезапуска редактора. --listen <порт> закрепляет точный порт (при конфликте MCP не запускается), --listen 0 отключает MCP. Существующие MCP-клиенты сами между окнами не переключаются.

Сборка под платформы — aiversebuild#

./build/mac/aiversebuild --project ~/.aiverse/packages/templates/skirmish --target macos     # Builds/macos/<Name>.app (подписан ad-hoc)
./build/mac/aiversebuild --project ~/.aiverse/packages/templates/skirmish --target ios       # Builds/ios/xcode/AIVERSE.xcodeproj + сборка для симулятора
./build/mac/aiversebuild --project ~/.aiverse/packages/templates/skirmish --target android   # Builds/android/<Name>-release.apk, если есть SDK/NDK и gradle
./build/mac/aiversebuild --project ~/.aiverse/packages/templates/skirmish --target web       # Builds/web (нужен emsdk)
./build/mac/aiversebuild --project ~/.aiverse/packages/templates/skirmish --target windows   # .exe через mingw-w64 (brew install mingw-w64) или исходники + build.bat
./build/mac/aiversebuild --project ~/.aiverse/packages/templates/skirmish --target all

Результат кладётся в <проект>/Builds/<платформа>/ — там только готовые сборки и отчёт о размере. Всё промежуточное (деревья CMake, паки, перекодированный звук, Gradle-проект, данные xcodebuild, оценка размера из редактора) лежит в скрытой Builds/.temp/; её можно удалить в любой момент. С --generate-only Gradle-проект для Android Studio кладётся в Builds/android/<Name>. Старые видимые _build, _pack, _audio, _estimate сборщик убирает сам.

То же самое доступно в редакторе: меню Сборка. Сгенерированные проекты iOS и Android самодостаточны (в них скопированы исходники движка и контент), их можно отдавать дальше. Для iOS на устройство: откройте проект в Xcode и выберите команду в Signing (или --team <TeamID>, или "appleTeamId" в game.json).

Идентификатор, название, версия, ориентация и иконка (icon.png, 1024×1024; если нет — генерируется) — в game.json.

Инструменты сборки: проверка и автоустановка#

Перед сборкой aiversebuild проверяет, что нужно платформе, и ищет это не только в PATH (редактор, запущенный из Finder, видит лишь /usr/bin:/bin:/usr/sbin:/sbin): Homebrew (/opt/homebrew/bin, /usr/local/bin), ~/.local/bin, ~/Library/Python/*/bin, ~/emsdk, $EMSDK, ANDROID_HOME / ANDROID_SDK_ROOT, ~/Library/Android/sdk, ~/Android/Sdk, %LOCALAPPDATA%\Android\Sdk, JAVA_HOME, /usr/libexec/java_home, Visual Studio (vswhere) и свою папку ~/.aiverse/toolchains. Найденные папки добавляются в PATH дочерних процессов.

ПлатформаНужноСтавится автоматически
webCMake, Python 3, Emscripten (emsdk), Ninja — по желаниюemsdk (≈ 400 МБ загрузки, ≈ 1.5 ГБ на диске), CMake + Ninja (≈ 50 МБ)
androidJDK 17–23, Android SDK (platform 35, build-tools, platform-tools), NDK, CMake из SDK, Gradleвсё: Temurin JDK 17, command line tools + sdkmanager (лицензии принимаются), NDK ≈ 700 МБ, Gradle 8.10.2
macosXcode Command Line Tools, CMakeCLT — через установщик Apple (xcode-select --install), CMake
iosXcode (App Store), CMakeCMake
windows (на Windows)Visual Studio 2022 / Build Tools (C++), CMakeCMake; VS — подсказка с командой winget
linuxкомпилятор C++, CMakeCMake
aiversebuild --check-toolchain web            # что есть, чего нет (--json — для редактора и MCP)
aiversebuild --install-toolchain web          # поставить недостающее (или один id: emsdk, cmake, jdk, android-ndk, gradle, ...)
aiversebuild --project ... --target web --install-missing   # поставить и сразу собрать

Без --install-missing нехватка инструментов останавливает сборку с кодом выхода 3 и строкой AIVERSE_MISSING_TOOLCHAIN web: emsdk (её распознаёт редактор). В редакторе окно Сборка показывает для выбранной платформы, что найдено (пути, версии) и чего не хватает, с кнопкой Установить автоматически и галочкой «Устанавливать недостающее автоматически»; ход установки — в Консоли (текст можно выделять и копировать, «Открыть папку логов» — <движок>/logs). Агенты делают то же через MCP: toolchain_check, toolchain_install, build_start {"installMissing": true}.

Всё ставится в ~/.aiverse/toolchains (Windows: %USERPROFILE%\.aiverse\toolchains; другая папка — переменная AIVERSE_TOOLCHAINS_DIR) без sudo и изменений в системе: emsdk/, py/ (venv с cmake и ninja), cmake/, ninja/, jdk-17/, android-sdk/, gradle-8.10.2/. Повторный запуск безопасен (готовое пропускается). Удалить всё установленное — удалить эту папку. Исключения: Command Line Tools ставит установщик Apple, а если найден Android SDK пользователя, недостающие пакеты sdkmanager ставит в него.

Ресурс-паки (.rpak) и размер сборки#

Контент игры (папка игры + engine/assets) попадает в сборку одним файлом content/content.rpak: каждый файл сжат zstd отдельно, одинаковые файлы хранятся один раз, уже сжатые форматы (png, ogg, mp3, …) кладутся как есть. Движок монтирует content.rpak автоматически; файлы из пака важнее файлов в папке, так что без пака (при разработке) всё работает по-старому. platform::mountPack("patch.rpak") подключает пак поверх (патч, DLC). Каждая сборка печатает отчёт о размере и пишет его в dist/<платформа>/size-report.txt.

aiversebuild ... --no-pack          # класть папки как есть (отладка)
aiversebuild ... --pack-level 9     # уровень zstd (по умолчанию 19 для Release, 3 для Debug)

assetpipe pack -o content.rpak ~/.aiverse/packages/templates/skirmish engine/assets=engine   # собрать пак вручную
assetpipe list content.rpak       # файлы, размеры, сжатие
assetpipe verify content.rpak     # распаковать всё и проверить хеши
assetpipe extract content.rpak out/
assetpipe diff old.rpak new.rpak  # что изменилось между версиями (для патчей)

Что не нужно в сборке, перечисляется в .rpakignore в папке игры (маски *, ?; папка/ — только каталоги). Скрытые файлы (.git, .DS_Store), реплеи *.rpl и вложенные *.rpak пропускаются всегда. Сборка пака воспроизводима: одинаковый контент даёт байт-в-байт одинаковый файл; «хеш контента» пака идентифицирует набор данных.

Разбиение сборки и докачка контента#

По желанию сборку можно разбить: в приложение попадает только базовый пак с тем, что нужно для запуска, остальное — в части (content.001.rpkc, …) заданного размера, которые игра докачивает из любого источника. Всё решает автор игры, в game.json (общие настройки и отдельно для каждой платформы) или флагами aiversebuild:

"packaging": {
  "split": true,                 // разбивать ли
  "chunkSize": "8MB",            // размер одной части
  "baseSize": "40MB",            // предел того, что едет внутри приложения
  "totalSize": "1GB",            // предел всего контента
  "fillBase": false,             // true: добить базу до baseSize (меньше докачки)
  "base": ["maps/intro.json"],   // что обязательно в базе (кроме стандартного: game.json, rules, lang, ui, атласы, первая карта)
  "order": ["maps/scena00*"],    // порядок докачки
  "sources": ["https://cdn.example.com/mygame/{hash}/", "file:///Volumes/DLC/"],   // зеркала по порядку
  "autoDownload": true,          // докачивать всё в фоне сразу после старта
  "targets": {"web": {"baseSize": "15MB"}, "windows": {"split": false}}
}
aiversebuild --project templates/x --target web --split --chunk-size 4MB --base-size 15MB   # флаги важнее game.json

Части кладутся рядом со сборкой (dist/<платформа>/chunks/) — их выкладывают по адресу из sources ({hash} — хеш контента сборки, разные версии не путаются). В игре: файл из нескачанной части запрашивается автоматически (на десктопе и мобильных readContentFile ждёт его, в вебе — возвращает false), прогресс — platform::contentProgress(), явный запрос — platform::requestContent(paths). Каждая часть проверяется по SHA-256 (подменённую с зеркала не примет и возьмёт со следующего), хранится в кэше и при следующем запуске не качается. Протоколы: https/http (libcurl на Linux, WinHTTP, NSURLSession, HttpURLConnection на Android, fetch в вебе), file:// и папки, а игра может зарегистрировать свою схему (Steam, Play Asset Delivery, P2P). assetpipe pack --chunk-size 8MB ... делает то же вручную, assetpipe verify проверяет и части.

Импорт чужих архивов (распаковщики)#

Форматы, которых движок не знает (zip, tar, dmg, архивы других игр), подключаются плагинами-распаковщиками без пересборки движка: папка с unpacker.json и программой на любом языке (протокол — tools/unpackers/PROTOCOL.md). Распаковщики работают только в инструментах сборки: чужой архив превращается в файлы внутри .rpak, игра по-прежнему читает только .rpak.

Из коробки: zip (и .oramap), tar, dmg, архивы Warcraft I/II (.WAR/.SUD/.INS), Westwood .PAK (Dune II, Lands of Lore, Kyrandia), Z от Bitmap Brothers (.PAC, .RSC).

assetpipe formats                                   # какие форматы известны
assetpipe probe ~/Downloads/Warcraft2/war2/DATA/*   # что это за файлы
assetpipe list MAINDAT.WAR                          # что внутри
assetpipe import -o war2.rpak MAINDAT.WAR=imported/war2 SFXDAT.SUD=imported/war2/sfx
assetpipe unpackers new tools/unpackers myformat    # заготовка нового распаковщика
assetpipe unpackers check                           # проверить все плагины

У всех команд есть --json — так их вызывает MCP-сервер. В game.json можно перечислить "imports", и aiversebuild сам распакует их в пак при сборке ("optional": true — если файла нет на этой машине, сборка идёт без него). Пак с импортированным сторонним контентом помечается флагом «external»: такие сборки только для личного использования, их нельзя коммитить и распространять.

Импорт игр (importers)#

Импортёр превращает вашу копию старой игры в папку игры для движка. Сейчас есть Dune II и Total Annihilation:

python3 tools/importers/dune2/import.py --source "~/Downloads/Dune II" --out ~/AiverseGames/dune2
aiversebuild --project ~/AiverseGames/dune2 --target macos

Получается 2D-игра в формате движка (docs/game-format.md, «2D games»): камера сверху, 66 миссий кампании с тайловым слоем (tilesets/dune.json из ICON.ICN: песок, скалы, дюны, горы, спайс с автотайлингом), спрайты юнитов из SHP (5 направлений с отражением, башни танков наложены на корпус) и зданий из тайлов ICN (стройка, руины, анимация), цвет дома — оттенки маджента. Плюс rules.json (наш баланс Dune II на блоках движка), картинки CPS и анимации WSA в PNG, звуки VOC → WAV + audio.json, названия на английском и русском. Рельеф приближённый: оригинальный генератор ландшафта не используется, базы стоят на скалах, спайс из Field=, квоты миссий — триггерами. Пехота, орнитоптер и транспортник пока рисуются 3D-фигурами. Папка помечена "external": true — её нельзя коммитить и распространять.

Total Annihilation (tools/importers/ta): архивы вашей копии (.hpi, .ufo, .ccx, .gp3; читает распаковщик hpi: шифр заголовка, чанки LZ77 и zlib) или уже распакованная папка:

python3 tools/importers/ta/import.py --source "~/Games/TotalA" --out ~/AiverseGames/ta

Юниты (units/*.fbi) становятся типами: стоимость, время строительства и сила строителя, здоровье, скорость, обзор, радар / сонар / глушилки, стелс, слои (воздух, вода, ховер, под водой), экстракторы, ветряные и приливные генераторы, металлоконвертеры, авиаремонтные площадки и командиры; меню строительства — из guis/*.gui и download/*.tdf; оружие (weapons/*.tdf) — дальность, перезарядка, урон, площадь, скорость, зенитные и торпедные флаги; накапливаемое оружие (ядерки) — способности со stockpile, перехватчики — intercept, взрывы — урон при смерти; объекты (features/**.tdf) — разбираемые узлы ресурсов; карты (maps/*.tnt + .ota) — карты высот с водой ниже уровня моря, стартовые позиции, объекты, залежи металла, ветер и прилив. Модели .3do и текстуры .gaf копируются рядом (движок читает их сам). Масштаб: 1 клетка = 16 пикселей TA. Не переносятся: скрипты юнитов (.cob; анимация — procedural), звуки, миссии кампании, металл из тайлов (залежи — из объектов металла). Папка помечена "external": true.

Файл проекта .aiverse#

Проект — папка где угодно на диске (game.json, rules.json, maps/, ...). В её корне лежит файл проекта <Название>.aiverse — его открывают двойным кликом, как .uproject в Unity/Unreal или project.godot. game.json остаётся манифестом игры (его читают клиент, aiversebuild, паки); .aiverse только помечает папку как проект и хранит сведения редактора:

{"format": 1, "name": "Моя стратегия", "engine": "0.2.0", "manifest": "game.json", "created": "2026-10-28"}
  • Создаётся вместе с проектом (хаб «Новый проект», MCP create_project); у старого проекта без него — при первом открытии в редакторе. У шаблонов в templates/*/ он уже есть (и в новый проект не копируется: тот получает свой).
  • Везде, где редактор принимает путь проекта, подходит и .aiverse, и папка: aiverse_editor "Моя стратегия.aiverse", --project, «Открыть…» в хабе (показывает .aiverse и папки проектов), недавние, MCP open_game, aiversebuild --project x.aiverse. В сборку .aiverse не попадает.
  • Проекты, созданные до переименования в AIVERSE, сохраняют свой <Название>.rtsproj: он открывается везде так же, перезаписывается на месте и не переименовывается; если в папке есть оба файла, главный — .aiverse.
  • Двойной клик. Редактор при запуске сам связывает .aiverse с собой (для пользователя, без прав администратора), если связи нет или она ведёт к другому экземпляру редактора; выбранную вами другую программу не перебивает. Вручную: «Проект → Сделать редактор программой по умолчанию для .aiverse»; состояние — внизу слева в хабе. Отключить: AIVERSE_FILE_ASSOC=off.
    • macOS: тип com.aiverse.project объявлен в Info.plist AiverseEditor.app (platform/macos/EditorInfo.plist.in; иконку документа rtsproj.icns рисует aiverse_projicon из логотипа редактора apps/editor/branding/icon_1024.png); редактор регистрирует бандл в LaunchServices (lsregister -f) и становится обработчиком по умолчанию. Двойной клик и open -a AiverseEditor x.aiverse открывают проект в уже запущенном редакторе (при несохранённой карте он спросит, сохранить ли её).
    • Windows: HKCU\Software\Classes\.aiverse (+ .rtsproj) → AIVERSE.Project (иконка %USERPROFILE%\.aiverse\icons\rtsproj.ico, команда "<aiverse_editor.exe>" "%1"). Если в Windows для .aiverse уже выбрана другая программа, хаб подскажет «Открыть с помощью → Всегда».
    • Linux: тип application/x-aiverse-project (~/.local/share/mime/packages/aiverse-project.xml), ~/.local/share/applications/aiverse-editor.desktop (Exec=<редактор> %f), иконки в ~/.local/share/icons/hicolor, программа по умолчанию в ~/.config/mimeapps.list; update-mime-database, update-desktop-database, xdg-mime вызываются, если установлены.

Сделать игру (мастер)#

Кнопка «Сделать игру» в окне проектов (и Проект → Сделать игру…): дайте папку или ссылку с артом, музыкой и текстами, опишите идею (или ничего — мастер выберет сам) и получите готовый проект .aiverse: игру на подходящем шаблоне, пошаговое обучение (хард) и подсказки в бою (софт), уровни со звёздами и наградами, мету (меню, улучшения, магазин, награда дня, профиль, настройки), рекламу и покупки по желанию, языки, иконку и заставку из арта. Мастер сам проходит обучение ботом и проверяет уровни; что назначено и что проверить — в WIZARD.md проекта. Агентам — MCP game_make_options / game_make_plan / game_make. Подробно — docs/game-wizard.md.

Локализация#

Игра переводится без изменения rules.json: имена в данных — текст на исходном языке игры, переводы лежат в <project>/lang/<язык>.json под ключами type.footman, resource.gold, map.valley.title… Строки меню и HUD — в engine/assets/lang/ (сейчас English и Русский), игра может переопределить любую.

// game.json
"sourceLanguage": "en",
"languages": ["en", "ru"]
./build/mac/aiverse_i18n extract --project ~/.aiverse/packages/templates/skirmish --lang de --write   # заготовка lang/de.json, новые строки помечены // TODO
./build/mac/aiverse_i18n check   --project ~/.aiverse/packages/templates/skirmish                     # плейсхолдеры, формы мн. числа, непереведённое

Язык выбирается так: выбор игрока в меню (запоминается) → язык системы → исходный язык игры. Для проверки: --lang ru, AIVERSE_LANG=ru, псевдоязык --lang qps (все строки искажены и длиннее — сразу видно непереведённое и то, что не влезает). Формы множественного числа — по CLDR («1 секунду / 2 секунды / 5 секунд»). Подробнее: engine/i18n/README.md.

Интерфейс игры (RmlUi, HTML/CSS)#

Меню, HUD, командная карточка, миникарта и пауза клиента — это документы RmlUi (.rml — разметка, .rcss — стили), а не код. Движок рисует их через свой RHI (GL/Metal), шрифты — через stb_truetype (латиница + кириллица).

  • Стандартные документы: engine/assets/ui/ (menu.rml, hud.rml, theme.rcss).
  • Игра переопределяет любой файл, положив ui/<то же имя> в свою папку: например, только ui/theme.rcss — свои цвета при стандартной разметке. Шрифт игры — fonts/ui.ttf.
  • Данные приходят из модели game (список полей — в комментарии в hud.rml), нажатия кнопок превращаются в команды симуляции (apps/client/ClientUi.cpp).
  • Размеры в dp — интерфейс масштабируется под плотность экрана; на сенсорных устройствах у корня есть класс touch (крупнее кнопки).
  • F8 в клиенте — отладчик RmlUi (дерево элементов, стили, журнал).
  • Скин игры — ui/skin.rcss (подключается после theme.rcss во всех документах: цвета, рамки, кнопки, раскладка) и шрифт заголовков fonts/title.ttf (семейство title). У каждого прототипа в templates/ есть свой скин. Портретная раскладка (@media (orientation: portrait)) — в теме движка; на ПК проверяется флагом --size 540x960.
  • Тексты в документах пишутся ключами @menu.play: перевод берётся из engine/assets/lang (и lang/ игры) при загрузке документа, смена языка в меню перезагружает документы.
  • Экранная клавиатура (engine/ui/UiKeyboard.*): своя, на RmlUi, открывается при фокусе в поле ввода на сенсорных устройствах (на ПК — AIVERSE_OSK=1). Раскладки (en, ru, символы; Shift, Caps по двойному нажатию, смена языка) — в keyboard.json, вид — keyboard.rml / keyboard.rcss; игра заменяет любой из файлов в своей ui/. Если курсор внизу экрана, клавиатура встаёт сверху.
  • Сетевая игра (lobby.rml, apps/client/Lobby.cpp): адрес сервера и имя, быстрая игра по очередям сервера, список комнат (войти / смотреть), своя комната (слоты, боты, готовность, старт, чат). Матч ведёт NetClient: attach(sim), advance(dt) вместо sim.advance(dt), команды — от слота match().localSlot (0 — зритель); боты, которых сервер поручил этому клиенту, считаются здесь же.

Детерминизм#

Симуляция побитово одинакова на всех платформах: только fixed-point, свой RNG, команды в каноническом порядке, контрольные суммы в реплеях. Проверено: Linux x86-64 (GCC, Clang, MinGW), Linux ARM64 (GCC), macOS ARM64 (AppleClang) — одинаковые контрольные суммы матчей.

Графика и мобильные#

Один проход forward-рендера: солнце (Ламберт + блик), карта теней с подгонкой под видимую часть карты и привязкой к текселям, аппаратный PCF (1/4/9 выборок), полусферный эмбиент, туман по дальности, ACES. Качество теней выбирается по GPU (для старых Mali/Adreno/PowerVR — низкое) и меняется в меню паузы.

Сетевая игра#

engine/net — мультиплеер для любой игры на движке, без кода игры. По сети идут только команды: симуляция детерминирована, поэтому у всех одинаковое состояние.

  • Транспорт: UDP со своим слоем надёжности (iOS, Android, ПК) и WebSocket (HTML5; на нативе — запасной вариант, если UDP закрыт). Адрес: host[:27015], udp://…, ws://host:27016.
  • Lockstep с откатами. Сервер подтверждает ввод каждого тика: когда пришли команды всех игроков или вышел дедлайн (lagToleranceMs); опоздавшие команды переносятся на следующий тик — один лагающий игрок не останавливает остальных. Клиент не ждёт подтверждения: играет вперёд со своими командами, а при расхождении восстанавливает снимок и пересчитывает (снимок ~10 мкс). rollbackWindow: 0 — классический lockstep для слабых устройств.
  • Сервер aiverse_server не нужен контент игры: комнаты (слоты, боты, зрители, готовность, проверка версии данных), автоматический матчмейкинг по очередям из server.json (рейтинг Elo с расширением окна, общая карта, баланс команд, добор ботами), сверка контрольных сумм (рассинхрон), реплеи (aiverse_headless --replay их проигрывает), переподключение, зрители с задержкой.
  • Выход = сдача. Ушедший игрок (или не вернувшийся за reconnectGraceSec) сдаётся командой в общем потоке ввода: исход решает симуляция у всех одинаково, и это видно в реплее. Рейтинг при этом списывается.
  • Вердикт сервера. Если исход никто не подтвердил (все ушли, результаты расходятся), сервер в фоновом потоке прогоняет реплей на своих данных игры ("games" в server.json) и сам определяет победителя.
  • Переподключение: после обрыва сети клиент переподключается сам (NetClient(address, …) или setReconnect), симуляция продолжает жить — сервер досылает только ввод после последнего подтверждённого тика. Если игра была перезапущена, клиент получает всю историю и пересчитывает матч с начала.
  • В игре: NetClient (engine/net/NetClient.h) — лобби и матч. Игра строит Simulation по match() и вызывает attach(sim), затем advance(dt) вместо sim.advance(dt); интерфейс по-прежнему отдаёт команды через sim.submit().
  • Тексты: сервер не шлёт готовых фраз — только ключи локализации с аргументами (NetText): у игроков в одном матче могут быть разные языки. Клиент переводит их через net::translate(loc, event.text) и net::displayName(...) из engine/net/NetLocalize.h; строки лежат в engine/assets/lang/*.json под net.*. Названия очередей в server.json — тоже ключи ("@net.queue.1v1").
./build/mac/aiverse_server --config apps/server/server.json            # UDP 27015, WebSocket 27016
./build/mac/aiverse_netbot --server 127.0.0.1 --project ~/.aiverse/packages/templates/mushrooms --queue 1v1   # бот в очередь
./build/mac/aiverse_netbot --server ws://127.0.0.1:27016 --project ~/.aiverse/packages/templates/mushrooms --queue 1v1
./build/mac/aiverse_net_tests                                          # сетевые тесты
docker build -f apps/server/Dockerfile -t aiverse-server .             # сервер в контейнере

Для wss:// (страница игры по HTTPS) поставьте перед сервером TLS-прокси (nginx, Caddy).

Звук#

engine/audio — микшер, банки звуков из данных, процедурный синтез, музыка; вывод через miniaudio (CoreAudio, AAudio/OpenSL ES, Web Audio, WASAPI, ALSA/PulseAudio). engine/audio превращает события симуляции в звуки; в симуляцию ничего не пишет. Нет устройства — игра идёт молча. Нет audio.json — игра просто без звука.

Звук игры — файл audio.json рядом с game.json (другое имя: "audio" в game.json). Полное описание формата — docs/game-format.md, раздел audio.json; коротко:

{
  "volume": { "sfx": 0.9, "music": 0.6, "voice": 1, "ui": 0.7, "ambient": 0.7 },
  "sounds": {
    "sword": { "files": ["sfx/sword1.ogg", "sfx/sword2.ogg"], "pitch": [0.9, 1.1], "maxInstances": 3, "cooldown": 0.06 },
    "alarm": { "file": "voice/under_attack.ogg", "bus": "voice", "priority": 10 },
    "blip":  { "synth": { "wave": "square", "freq": [880, 440], "duration": 0.08 }, "bus": "ui" }
  },
  "music":     { "menu": "music/menu.ogg", "match": { "files": ["music/a.ogg", "music/b.ogg"], "shuffle": true } },
  "events":    { "died": "death", "underAttack": "alarm", "notEnough.gold": "need_gold" },
  "weapons":   { "bow": { "attack": "bow_release", "hit": "arrow_hit" } },
  "abilities": { "heal": "heal_cast" },
  "types":     { "footman": { "select": "footman_what", "move": "footman_yes", "died": "death_human" } }
}
ЧтоСмысл
форматыWAV, OGG Vorbis, MP3, FLAC; "synth" — звук из параметров (sine/square/saw/triangle/noise, свип частоты, огибающая, вибрато, фильтр, слои)
шиныsfx и ambient — позиционные (3D: затухание, панорама, высота), voice, ui, music — нет

поиск звукатип → оружие/способность по id → events

Звуки боя слышны только там, где нет тумана войны; «нас атакуют» — с паузой, и только если камера смотрит в другое место. Громкость (общая и музыка) — в меню паузы, хранится в userDataDir/audio.cfg. На телефоне при сворачивании звук ставится на паузу.

Отладка без звуковой карты: AIVERSE_AUDIO=null (настоящий аудиопоток без железа), AIVERSE_AUDIO=off, AIVERSE_AUDIO_CAPTURE=/tmp/mix.wav — записать всё, что прозвучало, в WAV.

Модели, материалы, анимация#

Тип рисуется по блоку "view": встроенная фигура ("shape") или файл модели ("model") — glTF 2.0 (.glb, .gltf + .bin + картинки) и OBJ + MTL. Всё идёт через один конвейер:

  • Материалы PBR (metallic-roughness): базовый цвет, normal, metallic-roughness, occlusion, emissive; режимы прозрачности opaque / mask / blend, двусторонние, unlit, варианты материалов (KHR_materials_variants), переопределения в "materials". Цвет игрока: на весь материал, по маске-текстуре, по альфе текстуры (как в Warcraft III) или по альфе вершин.
  • Скелетная анимация на GPU (4 влияния, любое число костей), клипы по состояниям юнита (idle, move, attack, gather, build, die, spawn, hit, cast…), плавные переходы, слои с маской по костям (атака верхней частью тела на ходу), скорость шага по реальной скорости.
  • Процедурная анимация на любом узле модели или фигуре: покачивание, вращение (мельницы, винты), колёса по пройденному пути, наведение башни на цель, отдача, наклон в повороте, падение и погружение при смерти и т.д.; срабатывает по состояниям и событиям боя.
  • Уровни качества материалов (low / medium / high) выбираются по GPU, как тени; AIVERSE_MATERIALS=low|medium|high — переопределение для проверки.
  • Толпы: клипы запекаются в текстуру, одинаковые юниты рисуются инстансингом (300 анимированных юнитов — 61 draw call вместо 1801); LOD моделей по дистанции, анимация вне экрана и вдали обновляется реже.
  • Сложная анимация: blend space ходьба/бег, аддитивные клипы (дыхание, отдача), IK ног по рельефу, поворот головы к цели, наклон техники по склону, morph targets (blend shapes) на GPU.
  • Сокеты: оружие в руке, груз на спине (по переносимому ресурсу), точки вылета снарядов, точки эффектов (дым, огонь, выхлоп); события клипов и GameView::events()/effects() для звука и частиц.
  • Стадии: строительные леса и стадии постройки, повреждённый вариант по здоровью, появление и смерть растворением, обводка выделения, полупрозрачный призрак при постановке здания, портреты.
  • Форматы: ещё FBX (ufbx) и сжатые текстуры KTX2 (ETC2/BC/ASTC, остаются сжатыми на GPU); Collada, 3DS, PLY, STL; воксели MagicaVoxel .vox и .vxl/.hva (Tiberian Sun, Red Alert 2); модели классических RTS из копии игры пользователя: Warcraft III .mdx/.mdl (+ BLP), Total Annihilation .3do, C&C Generals .w3d (+ DDS). Остальное, что читает assimp (.blend, .lwo, .x, .ms3d, .md2/.md3, .smd, .b3d…), переводит в glTF утилита modelconv: редактор делает это сам при открытии и сохранении, сборщик кладёт в пакет только результат.
  • Материалы по запросу: общая библиотека materials.json (наследование через base), назначение материала узлу модели ("assign": {"Turret": "steel"}), процедурные бесшовные текстуры с картами нормалей и масками цвета игрока; окно Материалы с превью и MCP-операции material_* / texture_generate для агентов.

Сломанная модель не ломает игру: тип рисуется фигурой, причина пишется в консоль редактора. Просмотр: aiverse_modelview модель.glb@Walk или aiverse_modelview --game ~/.aiverse/packages/templates/showcase (все типы игры так, как их рисует игра); в редакторе — окно Models (клипы, узлы, материалы, портрет, перезагрузка при сохранении файла модели). Пример — ~/.aiverse/packages/templates/showcase, полный формат — docs/models.md.

Освещение#

Динамический свет рассчитан на старые Android (Mali-T, Adreno 3xx/4xx): все источники рисуются в маленькую световую карту над видимой землёй, шейдер берёт свет одной выборкой текстуры, сколько бы источников ни было. Уровни: off, low (карта 128², обновление через кадр), medium (256²), high (+ 8 источников попиксельно с бликом). Выбирается по GPU, как тени; вручную: AIVERSE_LIGHTS=…. Если во время матча кадры стабильно не успевают, клиент сам понижает свет и тени по ступеням (сначала самое дорогое и наименее заметное) и после тяжёлого боя возвращает одну ступень; ручной выбор теней в меню это отключает (AIVERSE_ADAPTIVE=off).

  • Свет типов и боя — view.light (костры, кузницы, светящиеся грибы), вспышки выстрелов, попаданий, взрывов, свет снарядов (attackLight, projectileLight, hitLight, deathLight), способностей (abilityLights; по умолчанию цвет по действию: урон — оранжевый, лечение — зелёный), ореолы halo вместо дорогого bloom. Туман войны скрывает вспышки.
  • День и ночь, погода — блок lighting в game.json или в карте: time, dayLength, nightLevel, clouds, wind, storm (тени облаков и молнии, одинаковые в реплеях), preset: desert, snow, volcanic, overcast, cave (подземелье: вечная ночь, свет только от источников). Ночью эмиссивные материалы светятся ярче, огни бликуют на воде.
  • Свет на карте — массив lights в карте (фонари, костры, лава).
  • Контактные тени и AO — мягкие пятна под юнитами и вокруг зданий, на всех уровнях (contactShadow, contactShape у типа).
  • Редактор — окно «Lighting»: предпросмотр времени суток и грозы, уровень качества света, список источников. Для агентов: light_add, light_update, light_delete, light_list, lighting_set, view_lighting.

Формат полей — в шапке engine/view/game/GameLights.h. Тестовые переменные: AIVERSE_TIME_OF_DAY, AIVERSE_NIGHT, AIVERSE_CLOUDS, AIVERSE_STORM.

Проверка механик через MCP#

Агент, который делает игру без кода, проверяет механику точечно, а не только матчем ботов.

  • scenario_run — сценарий на копии открытой карты (ничего не сохраняется): clear (пустая карта без объектов, волн и стартовых юнитов), spawn с именами ("id": "foot", "count": 3 → foot#1..3, "foot" — все), команды по секундам (те же ключи, что у play_command), bots для части слотов, checks с результатом pass/fail (alive, dead, count, hp, resource, event, trigger, variable, distance, status, result + сравнение), watch + every (состояние объектов во времени), events (журнал событий).
  • play_units / play_command — команды в живой тест в окне Game (раньше были только внутри редактора, теперь видны MCP-клиентам). Ссылки на объекты: id из play_units, имена id из карты или фильтр {type, owner, tags, kind, area, near + radius}; queue: true — очередь (Shift), ability по id.
  • match_run — плюс журнал срабатывания триггеров и events (журнал событий по именам).
  • rules_lint — ключи rules.json и карты, которые загрузчик не читает (опечатки, блок не на месте), с подсказкой («did you mean 'armor'?»). Работает на настоящем загрузчике (JsonAccessLog в engine/data/Json.h); rules_set, rules_merge и map_validate сообщают о таких ключах сразу.
  • rules_schema — part: "keys": все ключи, которые загрузчик спрашивает в каждом блоке (types.*.weapons[]), собранные по всем играм, и ключи, которых нет в docs/game-format.md; part: "doc" — сам документ.
  • Событие симуляции kEvTriggerFired (только для инструментов и представления, не входит в контрольную сумму).
  • Ветка agent-mech-tools.

Постэффекты#

Полноэкранные эффекты поверх 3D-сцены задаются данными: блок "postfx" в game.json (карта может его переопределить). Есть свечение (bloom), цветокоррекция, LUT, виньетка, тилт-шифт, лучи солнца, FXAA, зерно, аберрация, резкость, пикселизация, постеризация, заливка и кинорамка, плюс готовые наборы (кино, сочный, нуар, ретро, миниатюра, закат, зима, ночное видение). У каждого эффекта minQuality. Уровень выбирается по GPU: слабые Android получают «низкое», телефоны «среднее», ПК «высокое»; AIVERSE_POSTFX переопределяет уровень. Без эффектов постобработка ничего не стоит. Лёгкие эффекты собраны в один проход, тяжёлые (bloom, FXAA, лучи) добавляют свои.

Редактор: окно Постэффекты (предпросмотр уровней, таблица стоимости кадра по классам устройств). MCP: postfx_catalog/get/add/set/remove/preset/enable/estimate/lut_neutral, view_postfx. Ответы на изменения содержат оценку мс/кадр и предупреждения о тяжёлых эффектах. Подробности — docs/postfx.md.

Проверено / не проверено#

  • ✅ Linux: клиент, редактор, тесты; Windows .exe (кросс-сборка MinGW, запуск под Wine).
  • ✅ macOS: сборка, тесты, запуск игры на Metal; aiversebuild → .app и проект iOS (+ сборка для симулятора).
  • ✅ Web: собирается (Emscripten 3.1.50), матч запускается в headless Chromium (WebGL2/SwiftShader).
  • ⏳ Android: проект Gradle генерируется; APK и запуск в эмуляторе — в CI (job android), локально не собирался.
  • ⏳ Windows на реальном железе и iOS на устройстве — не запускались (в CI: MSVC-сборка и сборка iOS для симулятора).

Параметры командной строки в web-сборке задаются через URL: index.html?map=0&spectate = --map 0 --spectate.

Экранная клавиатура: platform::startTextInput(area) / stopTextInput() открывают и закрывают её на iOS, Android и в мобильных браузерах (на десктопе — ничего не делают). Текст приходит событиями Char на любом языке, Backspace/Enter — как KeyDown/KeyUp; softKeyboardHeight() и событие KeyboardChanged сообщают, сколько экрана закрыто снизу, TextInputEnded — что пользователь сам закрыл клавиатуру. UI (UiLayer) вызывает это сам при фокусе на <input type="text|password|search|email|number"> и <textarea>.

Остальное в Platform.h для мобильных и браузера:

  • safeAreaInsets() — отступы от выреза камеры, скруглённых углов, полоски «домой» и системных панелей (iOS, Android, мобильный Safari/Chrome; на десктопе 0, на MacBook с вырезом — в полноэкранном режиме).
  • setFullscreen() / isFullscreen(); встроенные переключатели — F11 (Windows, Linux, web), Alt+Enter (Windows). В браузере вместе с полноэкранным режимом фиксируется ориентация (AppConfig::orientation).
  • Android: кнопка «Назад» приходит игре как Key::Escape; полноэкранный режим с прячущимися панелями; физическая клавиатура и мышь (Chromebook, DeX) — обычные события клавиш и мыши.
  • iPad: клавиатура Magic Keyboard / Bluetooth, мышь и трекпад (правая кнопка, наведение, прокрутка).
  • Буфер обмена работает везде; в браузере Ctrl/Cmd+V доходит до игры после того, как браузер отдал текст.
  • Web: userDataDir() хранится в IndexedDB — настройки и сохранения переживают перезагрузку страницы.

Нативные плагины: платежи и реклама#

Любой SDK платформы подключается плагином на её родном языке — Java (Android), Objective-C (iOS/macOS), JavaScript (web) или C++ — через один асинхронный мост engine/platform/Plugins.h. Игра пользуется общими API aiverse::store (покупки) и aiverse::ads (реклама) из engine/services, а провайдер выбирается по платформе в game.json. Готовые плагины в plugins/: App Store, Google Play, RuStore, Яндекс Игры (web: покупки и реклама), Steam (покупки через Inventory Service и DLC, Windows/ Linux/macOS), Yandex Mobile Ads, AdMob, AppLovin MAX, ironSource (Unity LevelPlay). В билд попадают только выбранные игрой плагины ("plugins" в game.json или --plugins): чужих SDK, зависимостей, записей манифеста и ключей Info.plist в нём нет, CI это проверяет. Для отладки на десктопе есть заглушки магазина и рекламы (mock-store, mock-ads; AIVERSE_MOCK_STORE, AIVERSE_MOCK_ADS): весь сценарий покупки проходит без телефона, а в релизные сборки заглушки не компилируются. aiversebuild сам вписывает плагины в Gradle/манифест, Info.plist/Podfile и HTML; для Google Play и RuStore собирайте отдельно: --plugins googleplay,admob и --plugins rustore,yandex-ads. Подробно — docs/plugins.md.

Готовые сборки движка (ветка builds) и aiversemcp без компилятора#

Готовые редактор и инструменты публикуются в ветке builds: <platform>/AIVERSE-<version>-<commit>-<platform>.zip (сейчас windows x86_64 и macos arm64; linux x86_64 — когда интегратор опубликует). Внутри — папка AIVERSE/ с исходниками движка на этом коммите (шаблоны templates/, engine/assets, docs/ — их читает MCP-сервер) и AIVERSE/bin/ с программами. Собирает tools/release/package_engine.py, публикует tools/release/publish_builds.py (AGENTS.md §8); Linux-пакет может быть без редактора — только aiversemcp и aiverse_headless.

MCP-сервер из распакованной папки (матчи ботов и balance_* идут внутри aiversemcp, отдельный aiverse_headless ему не нужен; редактор — по желанию, без него --no-editor):

# ARCHIVE — путь к скачанному архиву AIVERSE из index.json.
unzip "$ARCHIVE" -d ~/aiverse      # unzip сохраняет флаг исполняемого файла
~/aiverse/AIVERSE/bin/aiversemcp --no-editor --engine ~/aiverse/AIVERSE

--engine можно не указывать в сборках с коммита, где aiversemcp ищет движок рядом с собой (engine/platform/EngineDir.h, как редактор); в опубликованных раньше он обязателен. Распаковщики, которые не восстанавливают права (Python zipfile), — chmod +x для файлов из bin/. На macOS скачанный браузером файл может получить карантин: xattr -dr com.apple.quarantine ~/aiverse/AIVERSE.

Программы, которые скачивают движок сами, читают index.json в корне ветки (https://raw.githubusercontent.com/chromealex/AIVERSE/builds/index.json), а не README. Ниже — пример исторической записи AIVERSE; в новых сборках пути содержат AIVERSE, ключ rtsmcp сохраняется:

{
  "schema": 1,
  "repository": "chromealex/AIVERSE",
  "branch": "builds",
  "packages": [
    {
      "platform": "macos",
      "arch": "arm64",
      "version": "0.2.0",
      "commit": "77126fa9",
      "file": "macos/AIVERSE-0.2.0-77126fa9-macos.zip",
      "url": "https://raw.githubusercontent.com/chromealex/AIVERSE/builds/macos/AIVERSE-0.2.0-77126fa9-macos.zip",
      "size": 43055202,
      "sha256": "c08044fd5a13648016f4d0f2184edb6054d338a814c2b2de2caab09b4cf4513d",
      "root": "AIVERSE",
      "rtsmcp": "AIVERSE/bin/rtsmcp",
      "editor": "AIVERSE/bin/RTSEditor.app",
      "headless": "AIVERSE/bin/rts_headless"
    }
  ]
}
  • packages — от новых к старым; первая запись с нужными platform + arch — самая свежая сборка.
  • platform: windows | macos | linux; arch: x86_64 | arm64 | universal (macOS fat) | null (не распознан) — определяется по заголовку aiversemcp внутри zip.
  • rtsmcp, editor, headless — пути внутри архива или null, если программы в пакете нет; --engine — папка root. editor на macOS — бандл .app.
  • url указывает на ветку, которая перезаписывается при каждой публикации (хранятся 5 версий на платформу): старые записи исчезают, поэтому скачивайте по свежему index.json и сверяйте sha256.
  • Новые поля могут добавляться; несовместимое изменение формата увеличит schema.

Проверка: python3 tools/release/test_release.py [build/linux-release/aiversemcp] (CTest release_tools) — формат index.json, а с путём к aiversemcp — упаковка Linux-пакета, распаковка во временную папку и MCP-вызовы из неё без --engine (tools/list, create_project, map_generate, map_validate, map_ascii).

Режим скриншота (AIVERSE_SCREENSHOT, AIVERSE_EXIT_AFTER_FRAMES) шагает ровно по 1/60 с на кадр, поэтому кадр N одинаков на любой машине.

Модули игры на C++#

Помимо Lua, проект может содержать native/CMakeLists.txt и C++20-модули. Они подключаются через aiverse_native_module(...) при сборке и включаются массивом nativeModules в rules.json. Поддержаны тики, команды, rollback и сохранение состояния; Lua и C++ работают вместе. После изменения C++ нужна пересборка игры и редактора. API, пример и инструкция сборки.

Переиспользуемая мета-библиотека C++#

aiverse::meta — настраиваемые магазин/офферы/крафт, валюты и предметы, задания и пассы, ежедневные награды, энергия, почта, рейтинги, чаты и сегменты. Доступна native-коду проекта без Lua/GPU; определения — JSON, алгоритмы не нужно генерировать заново. Старт: python3 tools/meta/scaffold.py --preset mobile --out <project>. Документация: docs/meta-game.md; агентам — skills/meta/meta-game/SKILL.md. Локальные политики работают без сервера; для общения между устройствами и глобальных рейтингов подключается реальный backend. Готовый облачный сервис в пакет не входит.

Пресет full --with-ui добавляет друзей/кланы, коллекцию экземпляров, экипировку, слияние, подписки и турнирные лиги. aiverse::meta::Service выполняет операции атомарно; tools/meta/server.py — локальный HTTP/SQLite-хост с проверкой сессий. В комплекте браузерные экраны меты и каталог коротких рецептов для агентов. Сборка, запуск и ограничения.

В full также входят 15 групп LiveOps: сундуки с pity, альбомы/обмены, очереди работ, исследования/престиж, составные задания, события, войны кланов, асинхронное PvP, матчмейкинг партий, Elo/Glicko-2, рефералы/промокоды, rewarded ads, цепочки офферов, уведомления и офлайн-доход. Все параметры — extensions.liveops; новые отдельные UI-экраны и внешние SDK этим пресетом не устанавливаются. python3 tools/meta/catalog.py describe matchmaking выдаёт только нужную схему и пример. API, политики и ограничения.

Опциональная 3D-физика#

Box3D подключается флагом AIVERSE_ENABLE_PHYSICS=ON; обычным RTS-проектам он не нужен. Отдельный пример aiverse_physics_demo показывает тела, столкновения, маятник и сохранение состояния. Сборка, API и ограничения интеграции.

Визуальная ткань XPBD#

Опциональный модуль AIVERSE_ENABLE_CLOTH=ON: собственный XPBD-решатель ткани на CPU или Metal compute, общие батчи, временной LOD, автоматический сон и отрисовка плотных сеток одним instanced draw. На GPU позиции остаются в видеопамяти; неподдерживаемые backend’ы используют CPU. Пример поддерживает сравнение GPU с CPU-эталоном и проверку сна/пробуждения. Отдельный пример, ограничения и замеры.
