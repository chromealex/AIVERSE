Формат данных игры (AIVERSE)#

Игра — это папка <project>/:

game.json        manifest: name, id, version, rules file, maps list, orientation, desktop window, icon, input
rules.json       resources, types (units/structures/objects), techs, factions, game rules, triggers
maps/*.json      terrain, players, objects, waves, triggers, areas, victory overrides
audio.json       sounds, music and which sound plays on which game event (optional: no file = silent)
models/ ui/ ...  assets (glTF models, textures, UI, sounds); 2D images may be packed into atlases (see Texture atlases)

JSON допускает комментарии //. Числа — обычные десятичные (1.5, никогда 1e3): симуляция работает в фиксированной точке и детерминирована. Секунды — игровые секунды, расстояния — клетки карты. Каждый блок ниже необязателен — набор блоков у типа определяет, что он умеет.

Постобработка сцены и камеры PRISMA#

game.json.postfx сохраняет исходные глобальные настройки HDR/bloom/цветокоррекции. Необязательные game.json.prismaVolumes и prismaVolumes карты добавляют зависящий от позиции вид камеры (без изменения игровой/ECS-симуляции). Каждый блок содержит {"volumes":[{"id":"area","shape":"sphere","center":[0,0,0],"radius":8,"blendDistance":3,"priority":4,"weight":1,"profile":{"effects":[{"type":"colorGrade","saturation":0.6}]}}]}. Карта может переопределить объём игры с тем же id или задать "replace":true, чтобы отбросить объёмы игры. Поддерживаются формы global, sphere и box, выровненный по осям (center + halfExtents). Профиль использует существующую схему эффектов postfx. Только явные hdr/enabled в профиле переопределяют глобальный HDR или включение цепочки. Владельцы в C++ движка/рантайма: engine/render/PrismaVolumeData.{h,cpp} и PrismaVolumes.h; полная семантика и оговорки по качеству — в docs/prisma.md. Операции MCP postfx_* остаются совместимыми.

game.json#

{ "name": "Iron and Gold", "id": "com.studio.ironandgold", "version": "0.1.0", "build": 1,
  "module": "game", "rules": "rules.json",
  "maps": [{ "file": "maps/valley.json", "title": "River Valley (1v1)" }],
  "orientation": "landscape", "icon": "icon.png" }

"audio": другое имя файла звуков (по умолчанию audio.json).

"module": игровой модуль — "rts", "fps", "voxel" или "scene". У проекта "scene" нет игрового модуля: ему нужен только game.json (name, id, version, build, "module": "scene", необязательный "background": "#rrggbb"). aiversebuild упаковывает его с минимальным клиентом сцены (apps/client/SceneMain.cpp, CMake AIVERSE_SCENE_CLIENT): окно или canvas, пакет контента и пустая сцена, залитая цветом фона, — без симуляции, рендерера, UI, скриптов и звука, и без engine/assets в пакете. Web Release с настройками по умолчанию -Oz + LTO, 2026-11-21: около 150 KB на загрузку (brotli: index.wasm 108 KB, index.js 40 KB). Проекты без "module" остаются RTS-проектами.

"icons" и "splash": иконки игры для всех платформ и экран загрузки — см. «Иконки и заставка» ниже (старый единственный "icon" по-прежнему работает как основная иконка).

Необязательный "graphics": бэкенд RHI на Windows, Linux и Android — "gl" (по умолчанию) или "vulkan", либо по платформам {"windows": "vulkan", "android": "gl"}. Если на машине нет драйвера, Vulkan откатывается на GL; --gfx и AIVERSE_GFX переопределяют значение (docs/vulkan.md). macOS / iOS используют Metal, веб — WebGL2.

Необязательный блок "window": как открывается окно игры на десктопах (macOS, Windows, Linux; на телефонах и планшетах всегда полноэкранный режим, веб-сборка заполняет страницу). Редактор: Сборка → Окно игры (окно «Сборка»).

"window": { "mode": "windowed", "width": 1280, "height": 720, "minWidth": 960, "minHeight": 540,
            "keepAspect": false, "allowFullscreen": true, "macos": { "mode": "fullscreen" } }
ключзначение
modewindowed (по умолчанию: обычное окно с изменяемым размером), fixed (ровно width × height, без изменения размера и разворачивания), maximized (вся рабочая область рабочего стола, но всё ещё окно), fullscreen (macOS: нативный полноэкранный режим в собственном Space; Windows / Linux: окно без рамки поверх монитора)
width, heightразмер содержимого в пунктах (1280 × 720); также размер после выхода из полноэкранного / развёрнутого режима
resizableтолько для windowed (true); "mode": "fixed" равнозначен false
minWidth, minHeightнаименьший размер при изменяемом размере (0 = без ограничения)

Запуски с AIVERSE_EXIT_AFTER_FRAMES (скриншоты, CI) и --size WxH остаются оконными с запрошенным размером. Код: engine/platform/WindowSettings.h (парсер, проверки), поля окна в AppConfig, AppCallbacks::configure.

Необязательный блок "ui": как смешивается внутриигровой UI (документы RmlUi). "ui": {"blend": "linear"} заставляет полупрозрачный UI смешиваться в линейном свете, как в проекте Unity с линейным цветовым пространством (блёклые иконки, затемнения, свечения и мягкие края поверх более светлой графики получаются светлее, чем по умолчанию); "srgb" (по умолчанию, также при отсутствии блока) смешивает значения в кодировке sRGB, побайтно идентично сборкам без ключа. В линейном режиме цвета вершин (цвета CSS, opacity, вершинные градиенты) и изображения декодируются в линейный свет (изображения предумножаются в линейном свете и загружаются как sRGB-текстуры), атласы шрифтов остаются покрытием (только альфа), UI смешивается в собственный слой в кодировке sRGB, и один полноэкранный проход накладывает его на сцену в линейном свете (пропускается, если UI ничего не рисует). GPU без sRGB-целей рендера молча остаются на значении по умолчанию. Код: engine/ui/UiColor.h (кривые, ключ), UiLinear.* (слой + композиция, GLSL и MSL), RHI PixelFormat::RGBA8_sRGB, Device::copyColor.

Необязательный блок "camera" (2D-игры, см. «2D-игры» ниже): {"projection": "ortho", "pitch": 90, "yaw": 0, "fov": 43, "zoom": 20, "zoomMin": 8, "zoomMax": 40, "pixelsPerCell": 32, "rotate": false}. Блок может начинаться с пресета ({"preset": "overhead-pixel"}; список: camera-behaviors.md).

Необязательный "playerColors": [neutral, slot 1, ..., slot 8] (синтаксис цвета оверлеев: "#rrggbb", [r, g, b] 0..1 или 0..255; null оставляет слот как есть) заменяет встроенную палитру игроков, используемую для командных цветов, оверлеев и цвета оверлея территории по умолчанию (RtsOverlayData::configurePlayerColors, применяется при старте матча в клиенте и редакторе).

Блок освещения ("lighting" в game.json / карте), ключи для плоской графики: "day": {"sun", "sky", "ground", "fog": [r, g, b], "sunK": k} заменяет поля дневной палитры (пресета или рендерера), "night" (те же ключи) — ночную палитру / палитру лунного света (sunK 0..1: сила луны, чтобы тени оставались различимыми ночью), "fogDensity" (0 = без дистанционного тумана), "tonemap": false (освещённые шейдеры обрезают значения вместо аппроксимации ACES; при sunK 0 и белых sky / ground неосвещённый материал показывает свой цвет без изменений), "modelOutput": "srgb" (шейдеры моделей кодируют линейный результат точной кривой sRGB, как в проекте Unity с линейным цветовым пространством, вместо принятого в движке по умолчанию sqrt, при котором полутона темнее; GLSL и MSL). Ключи карты важнее ключей игры.

Необязательный "editor": {"hierarchy": {...}}: как дерево мира редактора (Hierarchy / Inspector «Детали») показывает объекты этой игры — previewTicks (сколько тиков после setup выполняется предпросмотр в режиме редактирования, по умолчанию 2), label (ключ game.data(h), дающий имя строки), categories (теги в порядке приоритета: категория объекта), groupings ([{"title", "by": [keys]}], ключи owner, type, kind, category, origin, region, parent, tag, component, data:<key>). Читает его только редактор. Подробности: docs/editor-world-tree.md § Game hooks.

Разделение rules.json#

Большая игра не держит всё в одном rules.json. Загрузчик собирает правила из нескольких файлов и позволяет записям наследовать общие базы (engine/data/JsonCompose.h). Симуляция в любом случае видит один документ: те же результаты, те же контрольные суммы, старые однофайловые игры загружаются без изменений.

include — дополнительные файлы, пути относительно файла, который их перечисляет (внутри папки игры):

// rules.json
{"include": ["rules/resources.json", "rules/units.json", "rules/abilities.json"],
 "supplyCap": 200, "victory": "noStructures"}
// rules/units.json (may include further files itself)
{"types": {"footman": {...}, "archer": {...}}, "include": ["heroes.json"]}
  • Объекты верхнего уровня (types, techs, resources, ai, ...) сливаются по ключам; массивы верхнего уровня (playerAbilities, triggers, ...) дописываются в порядке чтения (сначала собственное содержимое файла, затем его включения, в глубину); скаляры (supplyCap) задаются один раз.
  • Записи сохраняют порядок чтения, а порядок types — часть игры (типы нумеруются в нём): перенос типов между файлами в другом порядке — это другая игра для реплеев и сетевых матчей.
  • Ключ или элемент массива с "id", определённый в двух файлах, — ошибка с указанием обоих (rules/b.json: 'types.knight' is already defined in rules/a.json); то же для цикла включений, отсутствующего файла и пути за пределами папки игры.
  • Всё читает собранные правила: клиент, сетевой хост, headless, реплеи, aiversebuild, редактор. Хеши данных сети и реплеев охватывают все включённые файлы. Пакеты поставляют включённые файлы, как любые другие данные.
  • Редактор и MCP правят правила как единый документ (rules_get / rules_set / rules_merge); при сохранении каждая запись пишется обратно в файл, откуда пришла, а неизменённые файлы не трогаются. Новая запись попадает в файл, где находится предыдущая запись её коллекции (новый тип оказывается рядом с другими типами). rules_get возвращает files, если правила разделены; game_file_write отказывается писать файлы правил (используйте операции правил).

extends / abstract — запись коллекции верхнего уровня (член объекта записей, например types, techs, statuses, или элемент массива с "id", например playerAbilities) начинается как копия своей базы (баз) в той же коллекции; её собственные ключи кладутся сверху. Объекты сливаются по ключам, всё остальное (числа, строки, массивы) заменяется. Записи с "abstract": true — только базы: они удаляются до загрузки (не являются типами, не попадают в палитру игры в редакторе).

"types": {
  "_infantry": {"abstract": true, "health": {"max": 420, "armor": 2}, "move": {"speed": 2.6, "radius": 0.4},
                "sight": 8, "cost": {"gold": 135, "time": 15, "supply": 2}},
  "footman":   {"extends": "_infantry", "name": "Footman", "weapons": [{"id": "sword", "range": 0.6, "damage": 12, "cooldown": 1.2}]},
  "spearman":  {"extends": "_infantry", "name": "Spearman", "health": {"armor": 1}, "weapons": [{"id": "spear", "range": 1.2, "damage": 10, "cooldown": 1.4}]}
}

extends принимает имя или список (применяется слева направо, затем сама запись); базы могут расширять другие базы. Неизвестные базы и циклы — ошибки (types 'knight': extends unknown 'cavalry'). rules_get {"resolved": true} показывает записи так, как их загружает игра; rules_lint проверяет разрешённые записи.

Уровни — это переопределения. levels способностей и способностей игрока уже сливаются с базовой записью (объекты — по ключам, массивы одинаковой длины — поэлементно): пишите только то, что меняется на уровне, "levels": [{"cooldown": 37.5, "effects": [{"duration": 5.5}]}], никогда не полную копию способности.

Движение и тела#

"move": {"speed": 2.8, "radius": 0.4, "mass": 0.64, "layer": "ground", "maxSlope": 1.6}

  • maxSlope (только рельеф на карте высот): самая крутая клетка, на которую может зайти этот тип (подъём на клетку); по умолчанию terrain.maxSlope его слоя. Не более 15 разных значений на игру.
  • radius — реальный размер тела (в клетках): юниты держатся на расстоянии r1 + r2, дальность оружия и способностей измеряется от края до края (range + оба радиуса, у строений — по их площади застройки), а пути сохраняют зазор от стен и зданий для тел больше половины клетки (узкие проходы стоят дороже; ничего не становится недостижимым).
  • mass (по умолчанию 4 * radius²) решает, кто уступает при перекрытии тел. Юниты, которые сражаются, удерживают позицию или работают (собирают, строят, копают), заякорены (x8) и почти не сдвигаются; движущиеся юниты (x2) отталкивают стоящих (x1) в сторону. Мёртвая зона 0.03 клетки и ограничение толчка за тик убирают дрожание.
  • При movement.avoidance: "rvo" движущиеся юниты обходят друг друга с помощью взаимных скоростных препятствий (ближайшие neighbors, детерминированный порядок). Стоящих на пути союзников просят уступить: они отходят на свободную соседнюю клетку и возвращаются, когда путь свободен, так что юнит может пройти через щель между стоящими юнитами; юниты, заблокированные заякоренными, перестраивают путь в обход них.
  • movement.avoidance: "none" отключает ORCA и разделение мобильных тел — для игр, где позиции задаёт Lua-логика построений. Это не отключает поиск пути по рельефу и бой. Сохраняйте реальные положительные радиусы тел; не имитируйте этот режим радиусами, близкими к нулю.
  • Юниты ближнего боя (range < 2), атакующие цель, выбирают свободный слот на кольце вокруг неё (слоты по углу, занимаются отдельно для каждой цели, ничьи — по индексу сущности) и обходят уже сражающихся союзников вместо того, чтобы протискиваться в первый ряд; юниты дальнего боя останавливаются и стреляют. Группа, получившая атаку с движением, разворачивается дугой, фланги которой идут впереди.
  • Поля потока (movement.flowField, выключены, пока игра или карта их не включит; docs/pathfinding.md): большие группы и орды используют одно общее поле интеграции на целевую область вместо отдельного поиска пути на каждый юнит. jsonc "movement": {"flowField": {"minGroup": 12, // move / attack-move / patrol / right-click orders of >= 12 units (0 = never) "minCells": 0, // ... only for units at least this many cells from the goal (0 = all) "waves": true, // units released by map waves and lane waves march on fields "spread": 0.4, // goal area radius = 0.3 + spread * sqrt(units) (they arrive spread out) "maxFields": 64, "budgetMB": 32}} // cache: LRU of unreferenced fields beyond these Карта может содержать тот же блок ("movement": {"flowField": {...}} на верхнем уровне карты), чтобы включить поля только для себя (например, templates/lastcolony/maps/horde_plain.json, templates/planets/maps/big_planet.json). Летающие продолжают лететь напрямую; юниты, вытолкнутые с поля или многократно застрявшие, откатываются на собственный путь A*. Последователи располагаются вокруг цели изнутри наружу (заражение прибытием) и не блокируют друг друга.
  • movement.blockedGoals: "nearest" (правила или карта, по умолчанию "search"): пути к цели внутри строения или препятствия (атака здания) заканчиваются в ближайшей к юниту свободной клетке вокруг него — намного дешевле для орд; клетки отличаются от классического поиска, поэтому это включается явно (включено в templates/lastcolony/maps/horde_plain.json).
  • movement.pathfinding: "navmesh" (правила или карта, по умолчанию "grid"): пути юнитов на плоских картах берутся из навигационной сетки движка (engine/nav, docs/navmesh.md): проходимые клетки каждого слоя путей сливаются в прямоугольники, A* работает по ним, а funnel стягивает коридор в путь под любым углом (меньше точек маршрута, на ~7% короче путей по сетке в 8 направлениях, дёшево на картах 1024x1024). Обрывы, пандусы, склоны и строения учитываются; запросы, на которые сетка не может ответить (старт или цель вне сетки, недостижимые цели, пути с окружением союзников), используют поиск по сетке, как прежде. Планеты сохраняют сетку / HPA*. Точки маршрута отличаются от сетки, поэтому это включается явно.
  • movement.pathfinding: "hybrid" (правила или карта): один граф порталов на карту (кластеры HPA* 16x16, при любом размере карты) и решатель на кластер — прямоугольники navmesh в открытых кластерах, A* по сетке в кластерах-лабиринтах (больше movement.hybrid.mazeRatio прямоугольников на клетку, по умолчанию 0.15: "hybrid": {"mazeRatio": 0.15}). Длинные маршруты идут по графу, участки используют решатель своего кластера, результат стягивается (string-pulling); поля потока используют тот же граф кластеров. Для больших или смешанных карт (города, пещеры, лабиринты рядом с открытой местностью); измерьте карту командой aiverse_headless --bench-nav N (docs/navmesh.md § Which solver where).
  • movement.airOverRock: false (по умолчанию true): летающие ограничены открытыми клетками — землёй и водой — поэтому они следуют по туннелям, как все остальные, вместо пересечения невыкопанной породы и # (MapGrid::airSolid; их пути ищутся как у пеших, строения и юниты их по-прежнему не блокируют). Игры-подземелья (underlord).

Компьютерный игрок на слот: players[i].ai = {"preset": "rush", "firstAttackArmy": 3, ...} — пресет (easy, normal, hard, rush, defender, economist), затем любой параметр ai из правил (workersPerBase, firstAttackArmy, armyGrowth, maxAttackArmy, towers, scouts, invasionSize, climbWeight, exposureWeight, escalateSeconds, terrain), плюс thinkTicks (1..3600, время реакции) и aggression (0.1..4). Порядок: значения бота по умолчанию, ai из правил, пресет слота, ключи слота. "ai": true (маркер компьютерного слота, который пишут импортёры) означает отсутствие переопределений. Переопределения правил на карте (rules карты)#

Карта может переопределить настроечные блоки правил для своих матчей: "rules": {"<block>": {...}} сливается поверх rules.json до того, как что-либо его разберёт (modules/rts/RtsMapRules.cpp), поэтому каждый блок проверяет объединённый результат со своими обычными ошибками. Объекты сливаются по ключам (рекурсивно); любое другое значение — числа, строки, списки, например таблица опыта, — заменяет значение из правил; null удаляет ключ ("escape": null отключает побег на этой карте).

"rules": {
  "topDown": {"escape": {"cooldown": 45}, "squad": {"fireWhileMoving": true}, "bot": {"orbRange": "weapon"}},
  "raid": {"duration": 300, "pickupRadius": 2},
  "progression": {"offerAt": "summonPoints", "xp": {"toNext": [10, 20, 35]}, "pauseOnOffer": true},
  "encounters": {"mobs": {"zombie": {"aggroRange": 12}}, "preferTags": ["cargo"]}
}

Переопределяемые: topDown.{respawn, move, aim, abilities, squad, escape, autoFire, bot} (не heroes/input: они решают, кем управляют и как квантуются команды), блоки raid, progression и encounters целиком. Любой другой блок (types, resources, abilities, ...) — ошибка: map rules.types: this block cannot be overridden per map (allowed: ...). Собственный блок raid карты (точки, цели по id) и progression.summonPoints по-прежнему применяются поверх.

audio.json#

Только представление: ничего отсюда не попадает в симуляцию. Отсутствие файла или аудиоустройства означает просто отсутствие звука. spatial — 3D-звук и расстояние#

Позиционные звуки размещаются в 3D вокруг слушателя (RTS-клиент ставит ухо на луче обзора над точкой фокуса камеры; юниты на обрывах и летающие находятся выше). Расстояния — в мировых единицах (клетках карты). При отдалении камеры ухо поднимается, поэтому битва звучит дальше; слышимая область растёт как квадратный корень из масштаба.

ключзначение
modelкривая расстояния: inverse (по умолчанию, естественная), linear, exponential
minDistance, maxDistanceполная громкость до min, тишина на max (12, 60); последние 20 % диапазона всегда затухают
rolloffкрутизна кривой (1)
airAbsorptionГц фильтра нижних частот на максимальном расстоянии: дальние звуки теряют высокие частоты (2500; false = выкл.)
reverbfalse или {"size": 0.5, "damping": 0.5, "wet": 0.35, "near": 0.05, "far": 0.6} — near / far = посыл в реверберацию на min / max расстоянии: дальние звуки становятся объёмнее и теряют атаку
speedOfSoundмировых единиц в секунду; дальние звуки приходят с опозданием (0 = выкл.; не более 3 с)
rear0..1: источники позади слушателя становятся глуше и немного тише (0)

Ключи расстояния (model, minDistance, maxDistance, rolloff) — значения по умолчанию для каждого звука; звук может их переопределить и добавить множители air / reverb (ниже).

groups#

Ограничения, общие для нескольких звуков, чтобы большая битва оставалась различимой: шесть мечей, ударивших одновременно, звучат как схватка, шестьдесят — как шум, и они заглушают важные звуки.

"groups": {
  "melee":      {"max": 6},
  "missiles":   {"max": 6, "cooldown": 0.02},
  "explosions": {"max": 4},
  "deaths":     {"max": 4, "steal": "quietest"},
  "ambient":    {"max": 5, "bus": "ambient"}
}
ключзначение
maxзвуков группы одновременно (0 = без ограничения, только cooldown)
cooldownсекунд между двумя запусками любого звука группы (0)
stealкто освобождает место, когда группа заполнена (ниже; по умолчанию farthest)
busкаждый звук этой шины принадлежит группе: ограничение на шину

Звуки присоединяются через "group": "melee" (или ["melee", "loud"]: место должно быть в каждой группе). Вариации (files) — это один звук; звук с вариантом far считается один раз, и его дальняя половина останавливается вместе с ним.

stealпри заполнении
farthestостанавливается звук, самый дальний от слушателя; новый звук дальше всех играющих не запускается — бой за кадром никогда не обрывает бой в кадре. Непозиционные звуки: самый старый
oldestостанавливается звук, запущенный первым
quietestостанавливается звук, который сейчас тише всех (громкость содержимого, измеренная при загрузке, громкость, шина, расстояние); новый звук тише всех них не запускается
noneничего не останавливается: новый звук не запускается

Играющий звук с более высоким priority, чем у нового, никогда не останавливается ради него; если вся группа важнее, новый звук не запускается. Остановка происходит с затуханием за несколько мс (без щелчка).

music#

Музыка потоково читается из файлов (рекомендуется OGG Vorbis); смены выполняются с плавным переходом. Плейлисты, которые клиент проигрывает по имени, все необязательны: menu, match, battle (заменяет match, пока рядом с камерой идёт тяжёлый бой, возвращается после ~15 с затишья), victory, defeat. Плейлист с именем match.<map> (имя файла карты без расширения, например match.valley) важнее match на этой карте; то же для battle, victory, defeat.

"music": {
  "menu":  "music/menu.ogg",
  "match": {"files": ["music/a.ogg", {"file": "music/b.ogg", "loopStart": 12.0}], "shuffle": true,
            "bpm": 96, "beatsPerBar": 4, "transition": "bar"},
  "match.valley": {"layers": [{"file": "music/valley_base.ogg"},
                              {"file": "music/valley_drums.ogg", "intensity": 0.3},
                              {"file": "music/valley_brass.ogg", "intensity": 0.7}],
                   "loopStart": 4.0, "loopEnd": 68.0, "bpm": 112}
}

Плейлист — это имя файла, массив записей или объект:

ключзначение
filesзаписи, проигрываемые по порядку: имя файла или {"file", "loopStart", "loopEnd"} (секунды). С loopStart трек один раз играет вступление, а затем бесшовно зацикливается от loopStart до loopEnd (по умолчанию: до конца), пока музыка не сменится
layersадаптивная музыка вместо files: синхронизированные стемы одинаковой длины, зацикленные вместе (loopStart / loopEnd на плейлисте). Слой с "intensity": x плавно появляется, когда интенсивность музыки превышает x; в матче интенсивность следует за боем рядом с камерой, поэтому многослойный match нарастает, а не переключается на battle
shuffle, loopперемешать записи (без немедленных повторов) / начать заново после последней (false, true)
volume0..4 (1)
bpm, beatsPerBar, offsetсетка долей (offset: секунд до первой доли); используется transition и синхронизированными стингерами
transitionпереключение с этого плейлиста ждёт следующей beat или bar (по умолчанию bar, если задан bpm, иначе now)

Стингеры — это звуки на шине music: "sync": "beat" или "bar" запускает их по сетке играющей музыки. Любой звук может приглушать музыку, пока звучит: "duckMusic": 0.5 снижает её вдвое (по умолчанию 0.4 для шины voice, чтобы объявления всегда были слышны; иначе 0).

Сжатие при сборке#

aiversebuild перекодирует используемые файлы звуков и музыки для каждой цели перед упаковкой; папка проекта никогда не меняется. Профили: desktop (macOS, Windows, Linux), mobile (iOS, Android), web. --audio mobile принудительно задаёт профиль, --audio off поставляет файлы как есть; aiverse_audiopack --project <game> --profile mobile показывает, что сделал бы профиль.

"build": {
  "desktop": {"sounds": "keep", "music": "vorbis", "musicQuality": 0.6},
  "mobile":  {"sounds": "adpcm", "music": "vorbis", "musicQuality": 0.3, "maxRate": 32000},
  "web":     {"musicQuality": 0.25}
}
ключзначение
sounds, musicкодек: keep (файл как есть), pcm (16-битный WAV), adpcm (IMA ADPCM WAV: 4:1, декодирование почти бесплатно — короткие эффекты), vorbis (OGG: музыка, длинные звуки)
soundQuality, musicQualityкачество Vorbis -0.1..1 (0.5 / 0.4; mobile 0.4 / 0.3, web 0.4 / 0.25)
maxRateпередискретизировать всё, что выше этой частоты (0 = никогда; mobile и web 32000)
monoSoundsпозиционные звуки становятся моно: микшер всё равно их панорамирует (true)
longSoundсекунды: более длинные звуки (фоновые петли, стингеры) используют музыкальный кодек (8)
reencodeLossyперекодировать также файлы, уже являющиеся OGG/MP3 (false: перекодирование с потерями в формат с потерями только ухудшает качество)

Значения по умолчанию без секции build: desktop сохраняет всё как есть; mobile и web используют ADPCM для звуков и Vorbis для музыки на 32 кГц. Звуки на шине music считаются музыкой. Звук или плейлист может переопределить это через "compress" и "quality". Перекодированные файлы получают расширение своего кодека, и audio.json в сборке указывает на них; результат, который не меньше исходного, сохраняет оригинал. Точки петель остаются точными (Vorbis точен до сэмпла; ADPCM дополняет петлю её собственным началом).

Управление подземельем и территория#

О линиях фронта, управляемых из Lua, см. Кисти территории и скриптовые построения. Необязательный визуальный блок terrain.territory также поддерживает smooth: true (по умолчанию false), transition (0..2 секунды, по умолчанию 0.2) и lift (0..2 мировых единицы, по умолчанию 0.045). На плоских картах сглаженный режим фильтрует владение компактным биномиальным ядром, восстанавливает его билинейно, применяет мягкий порог контура и интерполирует изменившиеся клетки в течение transition секунд. Он использует существующий конвейер мешей RHI и на Metal, и на GL; качество материалов выбирает 4 подразделения на клетку (medium/high) или 2 (low). Память тумана учитывается. Прежняя квадратная отрисовка территории/пола комнат остаётся по умолчанию; сглаженный режим предназначен для поверхностей территории и не рисует оттенки пола комнат. Визуализация планет сохраняет свой существующий рендерер. Подсчёты, проверки захвата и победа по-прежнему используют точное владение из симуляции. Шейдер Metal наземных оверлеев использует общий блок освещения LightU (совпадающий с раскладкой U2 в GLSL); старые сборки ссылались на устаревший тип MSL U2 и молча теряли весь слой. Сбои шейдеров/конвейеров теперь выводят ошибку бэкенда в stderr.

Линии (Mushroom Wars 2)#

"lanes": {"left": 4, "right": 2, "spacing": 0.35}: для каждой пары зданий-гарнизонов симуляция находит путь A* в обход препятствий и других зданий, сглаживает его в сплайн Катмулла–Рома с фиксированной точкой (примерно два отсчёта на клетку) и добавляет left + right параллельных линий на расстоянии spacing клеток (там, где они задели бы препятствие, линии подтягиваются к главной). Отправленные юниты распределяются по линиям по кругу и точно идут по своей линии. Линии перестраиваются при изменении зданий-гарнизонов или препятствий (GameState::lanes, lanesDirty, событие kEvLanesChanged).

Маршруты, группы, мультиэкран#

Заданные вручную маршруты между гарнизонами, отправка рядами и окно игры размером с экран поверх большей карты (modules/rts/RtsRoutes*.cpp). Длины — в клетках карты; каждое число — ключ правил / карты, который задаёт игра.

routes карты (если они есть на карте, они заменяют сгенерированные линии и включают lanes):

"routes": [
  {"from": "village_1", "to": "base_a",                  // entity ids (or "#<index>" into "entities"), both garrisons
   "points": [[13.98, 2.62], [12.44, 2.2], {"at": [2.2, 4.58], "offsets": [0,0,0,0.2,0,0,0,0], "zone": 2, "slowdown": 1.5}, [1.74, 5]],
   "lines": [[[13.98, 2.62], [11.47, 1.92], ...], ...],  // optional raw nodes per line
   "blockers": ["rock_3"],                               // the route is closed while any of them is alive
   "towersCoverage": [{"point": "p7", "distances": [0, 0, 0.5, 1.2, 3.4]}],
   "flying": false}                                      // uses the fly column padding
]
  • Каждый маршрут превращается в lanes.routes.lines линий: линия k идёт по своим сырым узлам, если их не меньше двух, иначе по контрольным точкам со смещением колонны k на внутренних точках (чётные линии слева, нечётные справа; 0,5, 1,5, 2,5 колонны columnPadding плюс offsets[k] точки); между точками — Катмулл–Ром со smooth узлами. При trim > 0 узлы ближе trim к обоим концам отрезаются (линии начинаются и кончаются чуть в стороне от точек). Линии сохраняют направление маршрута (Lane::a = from), смещения -1, +1, -2, +2... в порядке линий (lanesBetween возвращает линию 0 первой). Линии существуют весь матч (индексы стабильны).
  • Для отправки нужен открытый маршрут: kCmdSend между гарнизонами без маршрута игнорируется; это сообщают RtsModule::canSend / routeLength (линия 0) / routeAiLength и Lua game.can_send(a, b) / game.route_length(a, b). Закрытый маршрут (жив блокер) только отказывает в новых отправках; юниты, уже идущие по нему, продолжают путь. Встроенный ИИ отправляет только по маршрутам.
  • Каждая линия проходится с прогрессом линии 0 (скорость линии x длина k / длина 0), поэтому ряд держится вровень на поворотах.
  • Юниты на пересекающихся или общих маршрутах сами друг с другом не сражаются; навык может заставить идущих стрелять через RtsModule::routeWalkerTargets (враждебные идущие в эллипсе / переднем секторе, ближайшие первыми) и routeWalkerDistances (пройдено / осталось по линии). Идущие — обычные сущности юнитов с LaneWalker.
  • Маршрута между сущностями, чьи screenGroups (ключ сущности карты, список целых) не совпадают, не существует: два пустых совпадают, один пустой — нет, иначе — любая общая группа.
  • zone (биты, задаваемые игрой, 2 = замедление) / slowdown для точки влияют только на routeAiLength.
  • towersCoverage (для компьютерных игроков): для каждой сущности-башни — длина маршрута внутри её радиуса для радиусов 0, 1, 2 ... x routes.coverageStep (не более 21 значения, последнее действует и дальше). RtsModule::towerCoverage интерполирует; towerUnitsDamage / towerDamageBySpline оценивают потери группы, проходящей мимо неё.
  • Идущие получают случайное диагональное смещение (routes.jitter, одна выборка sim.rng() на юнит), которое нарастает на протяжении routes.fade от обоих концов маршрута; то же затухание — непрозрачность юнита в отображении (SceneObject::fade, routeAlpha).
  • Отправка по воздуху: гарнизон со статусом с флагом flying отправляет по прямому воздушному маршруту, создаваемому при первом использовании для этой пары (точки входа / выхода routes.inOut от концов, колонны flyColumnPadding), даже там, где наземного маршрута нет или он закрыт; ряды идут через flyRowSpacing. groups.flyAll: такая отправка забирает весь гарнизон; groups.flySingle: одна воздушная группа на гарнизон одновременно. Это сообщает RtsModule::sendsFlying(from).

Группы (lanes.groups): отправка создаёт группу (GameState::routes.groups, id = GroupTag), которая выпускает ряд до lines юнитов, по одному на линию, каждый раз, когда ряд впереди прошёл rowSpacing (первый ряд выходит сразу). Гарнизон платит за каждый ряд (юниты остаются дома и обороняют его, пока не выйдут). Вторая отправка по тому же маршруту и с той же стороны, пока группа открыта, сливается с ней (need = min(need + n - spawned, garrison) + spawned). Группа закрывается, когда она укомплектована, когда гарнизону не хватает на полный ряд или когда источник меняет владельца (остальные остаются дома). Без groups отправка работает как прежде (pendingOut, по два за тик).

screen карты:

Игровое окно поверх большей карты: size, стартовый center (по умолчанию центр карты), bounds = [left, right, top, bottom] — насколько центр может сместиться от старта (top = в сторону -z). Гарнизоны за пределами экрана не растут; RtsModule::onScreen публичен (King of the Hill и Domination используют его, когда нет зон игроков). Камера клиента следует за центром (smooth в секунду) и меняет масштаб так, чтобы был виден весь экран. Центр экрана, группы, смещения идущих и концы маршрутов сохраняются и хешируются.

Способности и эффекты#

Всё, что делает навык, — это список эффектов (полезная нагрузка). Эффекты могут нести собственную нагрузку ("effects": [...]): снаряд доставляет её при попадании, область применяет при срабатывании, цепь — на каждом прыжке, статус — на каждом тике, оружие — при попадании. Навыки — это композиции этих примитивов; ничего не программируется под отдельный навык. Все ключи ниже необязательны; игра, не использующая ни одного из них, работает в точности как прежде (побитово одинаковые реплеи).

Режимы матча (доминирование, царь горы, лимит времени, внезапная смерть, зоны)#

Режимы победы на уровне правил и часы матча в виде данных (RtsModes.cpp). Каждый блок необязателен; игры без них сохраняют свои точные контрольные суммы и формат сохранений.

"modes": {
  "points": "garrison",                                     // what a "point" is: structures with a garrison (default) or "structures"
  "conquest": {"team": true},
  "domination": {"hold": 1.5, "rule": "auto", "type": "dom_tower", "garrison": 10},
  "kingOfTheHill": {"score": 300, "teamScore": 300, "rate": 1, "alarm": 100, "type": "koh_tower", "garrison": 10},
  "timeLimit": {"seconds": 120, "win": "maxPoints", "coefficient": 1, "speed": [{"remaining": 30, "speed": 1.5}, {"remaining": 10, "speed": 2}]},
  "suddenDeath": {"at": 300, "preview": 3, "previewSpeed": 0.5, "end": 60, "counter": 5, "status": "sudden_death",
                  "ruleSets": [[{"status": "fast_skills", "when": [{"from": 330, "to": 360}]}], [{"status": "double_income"}]]},
  "zones": {"start": [{"rect": [0, 0, 40, 30], "stay": 60, "move": 20, "next": 0}], "steps": [{"rect": [5, 5, 30, 20], "stay": 9999}],
            "neutralType": "village", "suddenDeathDelay": 30}
},
"matchModes": {"domination": {"modes": {"domination": {"hold": 1.5}}}, "koh": {"modes": {"kingOfTheHill": {}}, "victory": "noEntities"}},
"timedRules": [{"status": "rush", "when": [{"from": 60, "to": 90}, {"every": 30, "duration": 5}]},
               {"status": "underdog", "resource": "morale", "when": [{"levelBehind": 2}]}],
"ruleSets": {"league3": [{"status": "rush"}]},
"matchStats": true

Ключи карты: "modes" (заменяет ключи правил по одному, false выключает режим), "matchMode": "<preset>" (запись matchModes, накладываемая поверх modes правил; её victory применяется, если у карты нет своего), "ruleSets": ["league3"] (именованные наборы правил, включаемые для этого матча, например лобби), у сущности "modePoint": "domination" | "kingOfTheHill" или список обоих ("modePoint" может нести и тип). Стороны — это команды (каждый сам за себя = один игрок в команде; счёт царя горы общий для команды).

блокповедение
conquestteam: true: игрок, у которого ничего не осталось, остаётся в матче, пока у товарища по команде есть база (иначе обычный victory решает для каждого игрока)
dominationтаймер hold точки перезапускается при каждой смене владельца и идёт, пока у неё есть владелец (точки, занятые на старте, начинают с идущим таймером). Когда все точки доминирования заняты (таймеры истекли, нейтральных нет; точки вне зоны или экрана своего владельца пропускаются): holdAny — стороны, не владеющие ни одной, выбывают; holdAll — побеждает сторона, владеющая всеми. auto: holdAny, когда в каждой команде один игрок. type / garrison: чем становятся отмеченные точки, пока режим включён
kingOfTheHillкаждая сторона начинает со score (teamScore, когда в команде несколько игроков) и теряет rate в секунду за каждую точку царя, которой владеет (внутри своей зоны); первая сторона, дошедшая до нуля, побеждает (наименьший счёт, затем наименьший id команды). Событие на alarm
timeLimitотсчитывает seconds игрового времени; при remaining скорость игры становится speed. На нуле — по точкам каждой стороны: maxPoints — побеждает больше всех, ничья среди лучших — ничья; compare — побеждает единственная сторона, у которой points x coefficient > лучшего, иначе ничья. Стороны без точек не участвуют
suddenDeathна at реальных секунд: предпросмотр (preview с, скорость игры previewSpeed), затем каждый игрок получает status (например, модификаторы incomeMult и cooldownRate). При end > 0 сторона с наибольшим числом точек побеждает через end с (все равны: ничья; равенство у части сторон: они побеждают, остальные — ничья; итог матча — ничья). За counter с до начала / конца включается ModesState::sdCounter (экран обратного отсчёта). Один из ruleSets выбирается ГСЧ матча и добавляется к timedRules (временные слоты сдвигаются на zones.suddenDeathDelay)
zonesзона каждого игрока — прямоугольник start, содержащий его первую постройку; прямоугольник держится stay с, затем линейно перетекает в steps[next] за move с (реальное время). Точка вне текущего прямоугольника своего владельца становится нейтральной (и превращается в neutralType; гарнизон сохраняется). Прямоугольники — [x, z, w, h] в клетках, полуоткрытые

Часы: тик остаётся одним тиком. RtsModule::speedScale() (= скорость лимита времени x скорость предпросмотра) заставляет Simulation::advance выполнять столько тиков за реальный тик; игровые таймеры (удержание, царь горы, лимит времени) используют игровое время, зоны / внезапная смерть / timedRules используют ModesState::realTime (сумма dt / speed). Сетевая игра: каждый клиент сообщает скорость своей симуляции (Msg::ClockRate); когда все игроки просят одну и ту же скорость, сервер перебазирует часы матча и отвечает Msg::ClockRateSet, и сессии идут в этом темпе (старые участники игнорируют оба сообщения и играют на номинальной скорости).

timedRules / ruleSets: каждый игрок имеет status (статус игрока: его mods, incomeMult, flags), пока выполняется один из его слотов when (без слотов: всегда). Слот: from / to (реальные секунды включительно; с inverse слот не выполняется вне окна, а внутри его может включить только every), every / duration (t % every <= duration), levelBehind N (с resource: уровень игрока ровно на N ниже уровня лучшего игрока), everyAbilities N (число применений способностей игрока — положительное кратное N). Правила, которым нужно больше, чем статус (фильтры команд, собственные правила улучшений, скриптовые применения), относятся к нативному модулю игры (docs/native-modules.md § Hooks).

levels ресурса (ступени запаса, например звёзды морали):

"morale": {"start": 0, "min": 0, "capped": true, "storage": 8000, "levels": [
  {"at": 0},
  {"at": 1000, "mods": [{"stat": "damage", "mul": 1.1}, {"tags": ["village"], "stat": "defense", "mul": 1.1}, {"stat": "speed", "mul": 1.05}],
   "decay": {"every": 5, "amount": 50, "after": 3}}]}

Уровень игрока — последний, чьего at достиг запас (ниже первого — никакого); его mods действуют на объекты игрока (не складываясь с более низкими уровнями). decay: каждые every секунд текущего уровня запас уменьшается на amount, если более after секунд ничего не было получено.

matchStats (включается вместе с любым режимом): счётчики каждого игрока ModesState::stats (MatchStat: kills, lost, produced, captured, capturedNeutral, structuresLost, upgrades, abilities, maxUnits, maxPoints, points, levelUps, levelDowns, maxLevel, modeScore) и abilityUses по каждой способности игрока. ModesState::outcome для каждого игрока: 1 — победа, 2 — поражение, 3 — ничья. Чтение через RtsModule::matchStat, modeZone (камера на карте зон), speedScale; события kEvModePhase (ModePhaseEvent: отсчёт, предпросмотр, начало, конец, шаг времени, время вышло, тревога царя горы, доминирование удержано, зона потеряна / изменилась); поражения от режима несут kDefeatMode.

Переменные триггеров для наложений HUD (текст {var:NAME}, условия var), скриптов и компьютерных игроков: koth_<slot> (счёт команды слота), koth_max, dom_<slot> (точки доминирования, удерживаемые с истёкшим таймером), mode_time_left, mode_speed, mode_sd_phase (0 до, 1 предпросмотр, 2 внезапная смерть, 3 решено), mode_sd_left (секунд до следующей фазы / конца), mode_sd_counter, zone_<slot>_x / _z / _w / _h. Пример наложения: {"id": "timer", "when": {"var": "mode_time_left", ">": 0}, "anchor": {"type": "screen", "at": [640, 24]}, "shape": "text", "text": "{var:mode_time_left}"}.

Временная башня в точке: навык по точке {"type": "spawn", "unit": "<static type>", "duration": 10}; rangeAspect оружия (по умолчанию 1) делает дальность оружия эллипсом с радиусом по z range x rangeAspect для поиска целей и стрельбы (изометрические карты).

Управление армией (agent-mech): стойки, отступление, транспорт#

Необязательные блоки; игра без них играется в точности как прежде (стойки и команды отступления работают в любой игре).

"stances": {"defendRadius": 6},                          // defensive stance: chase at most this far from where it stood
"retreat": {"speed": 1.25, "damageTaken": 0.75},          // the Retreat command (Company of Heroes / Dawn of War II)
"types": {
  "hq":     {"retreatPoint": true, ...},                  // retreating units run to the nearest own one (else key / producer)
  "archer": {"stance": "defensive", ...},                 // default stance of the type: aggressive | defensive | hold | passive
  "apc":    {"transport": {"slots": 8, "accepts": ["infantry"], "layers": ["ground"], "unloadInterval": 0.5, "killOnDeath": 1}},
  "bunker": {"transport": {"slots": 4, "fireFrom": 4, "heal": 2}},                 // passengers shoot from inside
  "town_center": {"transport": {"slots": 15, "damagePerCargo": 0.2, "accepts": ["villager"]}},   // AoE: more arrows per garrisoned unit
  "ifv":    {"transport": {"slots": 1, "weaponFromCargo": true}},                  // the passenger's weapon fires (RA2 IFV)
  "tank":   {"cargoSize": 4, ...}                                                  // slots a passenger takes (default 1)
}
  • Стойки (команда kCmdStance, параметр 0 — агрессивная, 1 — оборонительная, 2 — удержание, 3 — пассивная): агрессивная = поведение по умолчанию; оборонительная = сражается с врагами в пределах stances.defendRadius от своего места и возвращается; удержание = никогда не двигается сама (постоянный kCmdHold); пассивная = никогда не атакует сама (явные приказы атаковать работают).
  • Отступление (kCmdRetreat, нужен блок retreat): юниты бегут к ближайшей своей retreatPoint (иначе к постройке key, иначе к производителю) со скоростью speed x скорость и уроном damageTaken x урон, не сражаясь; любой новый приказ прекращает его. ИИ отводит бойцов с менее чем 30% hp, которые видят врага.
  • Транспорт (transport на юнитах или постройках): kCmdLoad (units = пассажиры, target = транспорт; правый клик по своему транспорту делает то же), kCmdUnload (units = транспорты; параметр 1 + точка: сначала доехать туда). Пассажиры находятся вне карты (kUnitInCargo): их нельзя выбрать целью, они не рисуются и не толкаются; они едут вместе с носителем. accepts (теги типов) и layers фильтруют пассажиров, fireFrom пассажиров с оружием стреляют изнутри с позиции носителя, damagePerCargo повышает собственный урон носителя за каждого пассажира, heal — hp/с внутри. Когда носитель погибает, killOnDeath пассажиров гибнут вместе с ним (по умолчанию 1 для юнитов, 0 для построек), а остальные выходят. События kEvLoaded / kEvUnloaded (a = пассажир, b = транспорт). ИИ заполняет стреляющие постройки (fireFrom: бойцы; damagePerCargo: рабочие), когда враги ближе 10 клеток, и выпускает рабочих, когда безопасно.

Модели боя и экономики (ключи agent-mech = псевдонимы блоков точности)#

Эти ключи пришли от agent-mech; они разбираются в единственную реализацию каждой механики, описанную в Механиках точности, и означают там то же самое.

"armorModel": "percent",                                               // = "armor": {"model": "percent", "negative": "exponential"}; "factor" = perPoint
"armorModel": {"type": "subtract", "minFraction": 0.2, "min": 0},      // = "armor": {"model": "subtract", "minShare": 0.2, "minDamage": 0}
"armorModel": {"type": "classes", "base": ["melee", "pierce"], "min": 1},   // = "armor": {"model": "classes", "base": [...], "minDamage": 1}
"upkeepResources": ["gold"],                                            // = "resources" of every upkeep tier that names none (Warcraft III)
"types": {
  "spearman": {"weapons": [{"damage": 3, "attacks": {"melee": 3, "cavalry": 15}}], "armors": {"melee": 0, "pierce": 0, "infantry": 0}},
  "knight":   {"armors": {"melee": 2, "pierce": 2, "cavalry": 0}},
  "zealot":   {"shields": {"max": 50, "regen": 2, "delay": 10, "armor": 0}},   // StarCraft shields
  "goldmine": {"resourceNode": {"resource": "gold", "amount": 12500, "maxWorkers": 5}}
}
  • classes (Age of Empires II): урон = max(min, сумма по attacks оружия от max(0, атака - броня этого класса)); классы base учитываются всегда (отсутствующая броня равна 0, улучшения брони повышают её), прочие классы — только против типов, перечисляющих их в armors (бонусный урон прибавляется, а не умножается). Оружие без attacks атакует первый базовый класс своим damage. Таблица урона в этой модели не используется. Без min / minFraction модель классов имеет нижнюю границу 1 и не имеет границы по доле.
  • armorModel percent использует точную кривую Warcraft III для отрицательной брони (2 - (1 - k)^-a); "armor" сохраняет линейную 1 + min(-a·k, 0.71), если в нём не указано "negative": "exponential".
  • "shields": {"max", "regen", "delay", "armor"} типа = health.shields / shieldRegen / shieldDelay / shieldArmor (те же значения по умолчанию: regen 2/с, delay 10 с); один компонент щита (Shield) для обоих написаний.
  • resourceNode.maxWorkers = resourceNode.maxGatherers: следующие рабочие ждут рядом с узлом или берут свободный узел того же ресурса поблизости.

Типы можно собирать из шасси и деталей (Master of Orion, Galactic Civilizations, наборы Supreme Commander). loadRules разворачивает их в обычные блоки типов до разбора (expandDesigns), поэтому все остальные ключи работают как обычно; rules_lint проверяет развёрнутую копию.

"designs": {
  "chassis": {"light": {"move": {"speed": 4}, "health": {"max": 100}, "cost": {"gold": 50}, "slots": {"weapon": 2, "system": 1}}},
  "parts": {
    "laser":   {"slot": "weapon", "weapons": [{"range": 5, "damage": 10, "cooldown": 1}], "cost": {"gold": 20}},

"morale": {"max": 100, "regen": 2, "hitLoss": 100, "allyDeath": 6, "allyRadius": 6, "flankSide": 1.5, "flankRear": 2,
           "waver": 40, "rout": 20, "rally": 60, "routSpeed": 1.25, "waverAttack": 0.85, "tags": ["soldier"],

Большие армии (BA)#

  • Сегмент конвейера переносит по одному пакету на клетку со скоростью speed клеток в секунду в своём направлении (восток, юг, запад, север): задаётся через build_line (вдоль главной оси линии), сущность карты "dir": "e" или команду rotate ({"cmd": "rotate", "units": [...], "dir": "n"}; без dir поворачивает по часовой стрелке).

  • Строение с beltInput (список ресурсов или "any") принимает пакеты в запас своего владельца (событие delivered).
  • Ленты — обычные строения (блокирующие, разрушаемые); пакет на разрушенной ленте теряется. ИИ пока не прокладывает ленты. Состояние MCP: dir и carries ленты, input / output крафтера.

Пошаговый режим (Heroes, XCOM, сражения Advance Wars)#

"turns": {"moveSeconds": 4, "attacks": 1, "timeLimit": 0}: игроки действуют по очереди в одной и той же симуляции. Во время хода двигаются (не дальше скорости типа x moveSeconds клеток) и стреляют (attacks выстрелов на оружие) только юниты активного игрока; остальные стоят на месте и не отвечают огнём; команды других игроков игнорируются. Команда end_turn (или timeLimit секунд) передаёт ход следующему живому игроку; событие turn (игрок, номер хода). Боты раз за ход посылают своих бойцов на ближайшего врага и завершают ход, когда те перестают двигаться.

 "recruit": {"spear": {}, "archer": {"gold": 40}},
 "battle": {"mode": "simulate", "seconds": 240, "size": [48, 32]},
 "provinces": [{"id": "a", "owner": 1, "income": {"gold": 40}, "adj": ["b"], "pos": [0, 0], "terrain": {"rows": [...]}},

Свободный полёт в 3D (Homeworld)#

"altitude": {"min": 0, "max": 30, "climb": 3, "start": 10} на воздушном типе: юнит держит собственную высоту, набирает её или снижается до y своих приказов движения (MCP {"cmd": "move", "x", "z", "y"}), следует высоте атакуемой цели, а дальность оружия до него и от него измеряется в 3D. Радар, сонар и глушилки#

Ключи типов (все необязательные; modules/rts/RtsSensors.h). Радиусы задаются в клетках.

"radar_tower": {"radar": 30, "income": {"energy": -20}},        // enemies inside the circle are contacts of its side
"sonar_buoy":  {"sonar": 25},                                    // the same for underwater units (radar does not see them)
"jammer":      {"jammer": 12},                                   // hides its own side's units inside the circle from enemy radar / sonar
"spy":         {"stealth": true},                                // never a radar contact (still seen in sight)
"submarine":   {"move": {"layer": "naval"}, "underwater": true,  // only weapons with "underwater": true hit it
                "weapons": [{"range": 6, "damage": 80, "underwater": true, "targets": ["naval"]}]},
// rules
"radar": {"targeting": true}   // units pick targets beyond their sight, up to weapon range, that their side sees or tracks
  • Контакт — враг внутри круга радара (сонара, для подводных юнитов) наблюдателя или союзника, не находящийся внутри круга глушилки своей стороны и не скрытный. Обесточенные (kUnitDisabled), недостроенные или перевозимые источники отключены.
  • Представление рисует контакты вне обзора красными точками (без модели: наблюдатель не знает тип). Нативный код: RtsModule::sensors()->onRadar(sim, e, viewer), blips(sim, viewer).
  • radar.targeting: артиллерия и дальнобойные башни стреляют по тому, что видят радар или союзники. Без него ничего не меняется.
  • Боты строят одно строение с radar, как только их база заработает (RtsAI); контакты служат целями для их дальнобойных орудий.
  • Состояния нет: контакты пересчитываются по юнитам, поэтому сохранения и повторы ничего лишнего не несут; игры без этих ключей сохраняют свои контрольные суммы.

Полевые операции#

Необязательные блоки для войн с поточной экономикой (modules/rts/RtsFieldOps.h; состояние в ресурсе FieldOpsStore: хешируется, сохраняется). У игр без них нет дополнительной системы, и их контрольные суммы не меняются.

// rules
"repair": {"cost": 0, "units": true},            // share of the cost for a full repair (default 0.3); mobile units too
"reclaim": {"units": true, "refund": 1},         // builders take units apart (own or enemy) for that share of their cost
"selfDestruct": {"time": 5},                     // kCmdSelfDestruct arms a countdown (again: disarms); death effects apply
"ambient": {"wind": {"min": 0, "max": 25, "every": [15, 45]}, "tidal": 18},   // the map's "ambient" overrides key by key
// types
"con_kbot":   {"assist": true, "patrolWork": true},   // guard a factory: adds build power; patrol: repairs / reclaims on the way
"wind_gen":   {"income": {"energy": 2}, "ambientIncome": {"wind": {"energy": 1}}},   // + wind strength x 1 energy/s
"tidal_gen":  {"ambientIncome": {"tidal": {"energy": 1}}},
"nuke_silo":  {"tags": ["nuke"], "stockpile": {"max": 5, "time": 90, "cost": {"metal": 1000, "energy": 20000}, "abilities": ["launch"]},
               "abilities": [{"id": "launch", "target": "point", "range": 200, "effects": [{"type": "projectile", ...}]}]},
"anti_nuke":  {"intercept": {"radius": 40, "tags": ["nuke"]}, "stockpile": {"max": 3, "time": 60, "cost": {"metal": 500}}},
"bomber":     {"move": {"layer": "air"}, "attackRun": {"overshoot": 5}, "seekRepair": 0.3,
               "weapons": [{"range": 1.5, "damage": 200, "targets": ["ground"]}]},
"air_pad":    {"repairPad": {"heal": 40, "radius": 1.5}}
  • Ремонт / разборка: kCmdRepair (цель = повреждённый свой или союзный юнит; строения всегда, подвижные юниты — при repair.units), kCmdReclaim (цель = узел ресурса: приказ добычи; юнит: OrderType::Reclaim, со скоростью buildPower строителя относительно времени постройки цели, с выплатой стоимости x refund по мере его уменьшения; без обломков и без взрыва при гибели). Smart-клик по повреждённому своему юниту ремонтирует его, если включён repair.units.
  • Помощь: строитель с assist, охраняющий (kCmdGuard) свой производитель в пределах 5 клеток, добавляет свой buildPower к buildPower производителя (step x (1 + sum / producer buildPower)); прогрессивная стоимость оплачивается в ускоренном темпе.
  • Работа в патруле: строитель с patrolWork в патруле сначала ремонтирует повреждённых союзников в поле зрения, затем добывает поточные ресурсные узлы (обломки, камни, деревья), мимо которых проходит; патруль возобновляется после каждой работы.
  • Запас зарядов: заряды строятся по одному за time секунд (медленнее при нехватке энергии), стоимость cost выплачивается по ходу постройки, а при нехватке средств постройка останавливается; способности из abilities (по умолчанию — все способности типа) требуют и тратят заряд. Бот использует их через autocast способности + наведение smart.
  • Перехват: вражеские снаряды, выпущенные типами с любым из tags, уничтожаются внутри radius; при наличии запаса каждый перехват тратит заряд. Событие kEvFieldOp (значение kFieldOpIntercepted, a = перехватчик, b = снаряд).
  • Доход от среды: ветер каждые every секунд меняется на случайную силу в [min, max] (RNG симуляции); tidal постоянен для карты. ambientIncome добавляет к доходу владельца силу x количество в секунду (готовые объекты с энергией). Оставляйте у таких типов небольшой фиксированный income, чтобы бот считал их зданиями дохода.
  • Заходы на атаку: юнит с attackRun пролетает над целью и ещё overshoot клеток дальше, затем разворачивается для следующего захода; его оружие стреляет на пролёте (бомбы малой дальности).
  • Ремонтные площадки: юниты, стоящие неподвижно в пределах radius от своей или союзной repairPad, бесплатно восстанавливают heal здоровья в секунду; seekRepair отправляет свободный юнит, у которого здоровье ниже этой доли, к ближайшей своей площадке.
  • События kEvFieldOp: value & 0xFF = kFieldOpArmed (data = оставшиеся тики) / Disarmed / Stockpiled (data = заряды) / Intercepted / Wind (data = сила). Нативный код: RtsModule::fieldOps() (stockpile, selfDestructAt, wind).

Сохранения состояния (agent-mech)#

Simulation::serialize() возвращает всё динамическое состояние в виде байтов (с версией, little-endian, одинаково на всех платформах: engine/core/Archive.h); deserialize(bytes) загружает его в симуляцию, настроенную по тем же правилам, карте и seed, и проверяет контрольную сумму состояния, записанную в файле. Сохраняются: тик, RNG, игроки и команды, ожидающие и выполненные команды (повторы продолжаются), аллокатор сущностей, все пулы компонентов в плотном порядке и динамическая часть GameState (поклеточные слои кодируются RLE). Не сохраняются: правила, триггеры, поверхность планеты (из настройки) и производные кэши (проходимость, HPA*, перестраиваются по требованию). Компьютерные игроки хранят свою память, поэтому боты продолжают с загруженного состояния со свежими планами. Сторона модуля: RtsModule::serializeState (modules/rts/RtsSave.cpp); тип компонента, отсутствующий в его списке, приводит к ошибке сохранения. aiverse_headless --save F --save-at S / --load F; MCP match_run с saveCheck (секунды). Матч skirmish на 90 с занимает ~150 КБ. С версии сохранения 9 сохраняется и зафиксированный исход матча (MatchOutcome): состояние до конца матча, загруженное в симуляцию, которая уже завершилась, больше не сохраняет старый результат (раньше компьютерные игроки останавливались, а окна --verify-restore-at, пересекающие конец матча, расходились на сериализованном проходе); старые сохранения загружаются без исхода, который снова фиксируется на следующем тике.

Триггеры#

Событие → условия → действия; вычисляются внутри детерминированной симуляции.

{"id": "relic", "once": true, "enabled": true, "forEachPlayer": false,
 "event": {"type": "enterArea", "area": "relic", "player": 1, "unit": "hero"},
 "conditions": [{"type": "count", "player": "triggering", "kind": "structure", ">=": 3}],
 "actions": [{"type": "message", "text": "Реликвия найдена!"}, {"type": "give", "resource": "gold", "amount": 500}]}

События: start, time (seconds), every (seconds), enterArea / leaveArea (area, фильтр юнитов), unitDied, built, trained (фильтр юнитов), researched (tech), captured, wave, regionClaimed, playerDefeated, ability, levelUp, resource (resource, сравнение: срабатывает, когда оно становится истинным), variable (name, сравнение). player события: номер слота, "any" (по умолчанию), "creeps".

Фильтр юнитов (события, условия, действия): "unit": "type", "tags": [...], "kind": "structure"|"unit", "area": "name" или [x,z,w,h].

Сравнения: одно из ">=", ">", "<=", "<", "==", "!=" с числом.

Условия: count (объекты, подходящие под фильтр), resource, variable, researched, random (chance), time (секунды), alive, regions (число принадлежащих). "not": true инвертирует.

Действия: spawn (unit, count, at [x,z] / area, attackMove), give / take (resource, amount), setOwner, kill, remove, damage, heal (amount), buff (stat, add/mul, duration), message (text), setVariable / addVariable (name, value), research (tech), enableType / disableType (unit), victory / defeat, enableTrigger / disableTrigger (trigger), addScore (amount), setRegionOwner (имя region), attackMove / move (юниты, подходящие под фильтр, к at / area), setTickets (amount); триггеры ботов Bunker Wars (agent-bw-ai): setResource (resource, amount: запас становится равным amount, например мораль), resetCooldowns (способности игроков готовы), setProduction (amount: коэффициент скорости производства подходящих строений, заменяющий предыдущий), timeScale (amount: скорость игры, требует режимов матча / matchStats).

player действия: "triggering" (по умолчанию: игрок события), "all", "enemies", "allies", "creeps", "neutral" или номер слота. "target": "triggeringUnit" действует на юнита события.

Текстурные атласы (atlas в game.json, необязательно)#

Окно Build редактора показывает слишком большие кандидаты в атлас в разделе «Не в атласе». «Исправить размеры текстур» применяет предложенные максимальные размеры как точные правила packaging.targets.<platform>.files с наивысшим приоритетом и обновляет оценку размера. Это уменьшает детализацию изображений в собранном паке; исходные ассеты не меняются. Листам спрайтов, атласам тайлов и источникам UI @spritesheet в RCSS с координатами в пикселях это исправление никогда не предлагается. Существующие правила изменения размера для этих источников игнорируются при упаковке, чтобы сохранить координаты их кадров. Прочие исключения (повтор при заворачивании, noAtlas, ошибки декодирования, единственное изображение в группе) требуют ручного решения. Пересчитайте устаревший отчёт, прежде чем применять исправления; кнопка неактивна, пока настройки отличаются от отчёта.

При упаковке игры (aiversebuild, assetpipe pack --atlas <profile>) мелкие 2D-изображения упаковываются в страницы атласа: меньше переключений текстур/вызовов отрисовки, обрезанные прозрачные края, одинаковые изображения хранятся один раз, а страницы сжимаются zstd пака. Код игры продолжает использовать исходные пути (units/orc/grunt/walk_0.png); поиск прозрачен во время выполнения. Сборки в виде папки с файлами (--no-pack, редактор) используют изображения как есть. Весь блок необязателен:

"atlas": {
  "enable": true,                                   // false (or aiversebuild --no-atlas): ship images as is
  "maxPage": { "web": 2048, "android": 2048, "default": 4096 },  // or a single number
  "pageSize": "mul4",          // page sides: multiples of 4 (default) or "pow2"
  "padding": 2,                // empty texels between images
  "extrude": 1,                // edge texels repeated around each image (no filtering seams)
  "trim": true,                // cut fully transparent borders (offsets are kept)
  "maxTextureSize": 0,         // larger images stay standalone; 0 = maxPage / 4
  "mipLevels": 2,              // groups with "mips": padding/alignment safe down to 2^levels
  "pageFormat": "rtex",        // "rtex" (raw RGBA, zstd in the pack, fastest load) or "png"
  "groups": { "units": { "rotate": false, "mips": true }, "tiles": { "trim": false } },
  "files": {                   // glob -> settings; `*` also matches '/'; later rules win
    "ui/splash/*": { "noAtlas": true },
    "units/orcs/*": { "group": "orcs" },
    "textures/water.png": { "wrap": "repeat" },
    "units/*/shadow.png": { "kind": "mask" }
  }
}

Профили — это цели aiversebuild (macos, ios, android, web, windows, linux); встроенные ограничения страниц: 2048 для web/android, 4096 для остальных. Цели с одинаковыми настройками используют один пак.

Что попадает вместе. Ключ группы изображения — группа использования + вид (+ непрозрачное/с альфой, если группа разделяется по альфе, + мипы). Изображения делят страницу только с изображениями с тем же ключом:

группа использованияпапки по умолчанию (первый компонент пути, префикс engine/ игнорируется)по умолчанию
uiui/, icons/, portraits/, cursors/, hud/обрезка
unitssprites/, units/, buildings/, structures/, characters/обрезка
tilestiles/, tilesets/, terrain/без обрезки (сетки листов остаются целыми), непрозрачные тайлы и тайлы с альфой на разных страницах
effectseffects/, fx/, vfx/, particles/обрезка
любое имязадаётся через "group" (или "atlasGroup") в filesкак units

Другие папки (models/, textures/, ...) не попадают в атлас, если правило files не задаёт группу: 3D-меши используют UV за пределами 0..1 и заворачивание. Вид — color, normal (*_n, *_nrm, *_normal, normals/) или mask (*_mask) — карты нормалей и маски никогда не смешиваются с цветом и никогда не обрезаются. Никогда не попадают в атлас: noAtlas, "wrap": "repeat" (а также *_repeat, *_tiling, *_wrap), изображения больше maxTextureSize (после обрезки) и изображение, которое оказалось бы одно в своей группе (одна страница = никакой экономии на переключении текстур, только отступы). Изображения, на которые где-либо в JSON игры ссылаются как на лист спрайтов с сеткой кадров ("sheet": "sprites/tank.png"), никогда не обрезаются и не поворачиваются, поэтому uv кадров линейно отображаются на область атласа. Внутри группы изображения одной папки (кадры одного юнита, одна фракция) остаются на одной странице, если помещаются; страницы ужимаются до наименьшего размера, который их вмещает. Ключи для файлов: group/atlasGroup, noAtlas, wrap, kind, rotate (разрешить поворот на 90°, по умолчанию выключен, чтобы направления никогда не поворачивались), trim, mips, splitAlpha, padding, extrude, mesh, tight, frames, meshVertices; те же ключи (кроме group) работают для групп в groups.

Меши, плотная упаковка, листы с кадрами (по умолчанию всё выключено, только для цветных изображений):

"files": { "sprites/*": { "frames": true, "tight": true, "rotate": true, "meshVertices": 8 } }
  • mesh — выпуклый многоугольник вокруг видимых пикселей (alpha ≠ 0) каждого обрезанного изображения, не более примерно meshVertices вершин (4..32, по умолчанию 8), консервативный (каждый видимый пиксель внутри), сохраняется, только если экономит не менее ~12% прямоугольника. Спрайты рисуются этим многоугольником: меньше перерисовки на большей частью прозрачных изображениях.
  • tight (подразумевает mesh) — упаковка по этим многоугольникам вместо прямоугольников: изображение может оказаться в пустом углу прямоугольника другого изображения (padding по-прежнему разделяет фигуры; тексели, которых касается многоугольник, плюс max(extrude, 1) вокруг него принадлежат его изображению). Раскладка прямоугольниками тоже вычисляется и сохраняется, если она не больше, так что страницы никогда не растут (обычно страницы на 15–20% меньше для диагональных / круглых спрайтов и почти без выигрыша для спрайтов, заполняющих свои прямоугольники). Страница плотной группы корректна только при отрисовке через меши. Выключено в группах с mips. Требует времени сборки: около секунды на 500 уникальных кадров (поиск по битовым строкам), прямоугольники занимают миллисекунды.
  • frames — лист спрайтов ("sheet" + "frame": [w, h] в JSON игры, h = w, если не указано, без frame = всё изображение) разбивается на кадры, каждый из которых обрезается, поворачивается, получает меш и упаковывается отдельно. Лист, используемый с разными размерами кадров или размер кадра которого не делит его нацело, сохраняется целым (и без обрезки, с предупреждением при сборке).

Кто что рисует: 2D-рендерер спрайтов (блоки sprite, Rts2DView) рисует обрезанные, повёрнутые, с мешами и разбитые на кадры изображения прямо со страниц (TextureCache::resolveSprite + SpriteBatch::spriteShape: билборды, вертикальные и наземные спрайты, декали на неровной земле, отбрасыватели солнечной тени). Все остальные потребители (TextureCache::resolve, UI, частицы, оверлеи) получают такое изображение пересобранным в отдельную текстуру (через меш), как раньше — корректно, но без экономии страницы; изображения, которые лежат на странице как есть, по-прежнему разрешаются в страницу.

В паке. Изображения, попавшие в атлас, удаляются; _atlas/ зарезервирован и содержит страницы (_atlas/<group>-<n>.rtex) и _atlas/atlas.json:

{ "version": 1,
  "pages": [ { "file": "_atlas/units-0.rtex", "group": "units", "w": 1016, "h": 864, "alpha": true, "mips": false } ],
  "textures": { "units/orc/grunt/walk_0.png": [0, 3, 3, 30, 38, 33, 29, 96, 96, 0] } }

Необязательно, если используются: "meshes": { "<path>": [x0, y0, x1, y1, ...] } — выпуклый меш в пикселях содержимого × 16 (сетка в 1/16 пикселя, исходная ориентация, начало координат в левом верхнем углу обрезанного содержимого), и "sheets": { "<sheet>": [cols, rows, sourceW, sourceH] } — лист с кадрами, кадр i которого (построчно) — это запись текстуры "<sheet>#<i>" (её sourceW x sourceH = один кадр, смещения внутри кадра).

Запись текстуры: [page, x, y, w, h, offsetX, offsetY, sourceW, sourceH, rotated] — целые пиксели. (x, y, w, h) — обрезанное содержимое на странице (при rotated = 1 оно занимает h x w с поворотом на 90° по часовой стрелке); (offsetX, offsetY) — его положение в исходном изображении sourceW x sourceH, поэтому опорные точки, заданные в пикселях исходного изображения, остаются верными. .rtex: 24-байтовый заголовок (RTEX, версия, ширина, высота, флаги: 1 — альфа, 2 — мипы, 4 — строки с фильтром разности слева) + строки RGBA8 сверху вниз, неумноженная альфа. Для одного и того же входа результат идентичен побайтно.

API времени выполнения (engine/atlas/TextureLibrary.h, линковать aiverse_atlas):

atlas::TextureLibrary lib(dev, [](const std::string& p, std::string& o) { return platform::readContentFile(p, o); });
const atlas::TextureRef* t = lib.get("units/orc/grunt/walk_0.png");   // nullptr if missing
// quad: t->w x t->h source pixels at (t->offsetX, t->offsetY) from the original image's top-left
// (pivot in original pixels: pos - pivot + offset); UVs t->uv = TL, TR, BR, BL (rotation applied);
// t->texture equal for images on one page -> batch by it; t->opaque -> draw without blending.
// t->mesh != nullptr: draw that polygon (content pixels; + offset, map with mapUV), never the quad.
// A framed sheet comes back rebuilt as its own texture.

atlas::mapUV(*t, px, py, u, v) отображает точку в пикселях исходного изображения в текстуру (с учётом обрезки и поворота) — например, углы кадров листа. Для рендерера, который уже отображает кадры через прямоугольник (u0 + (u1 - u0) * lu), прямоугольник листа в атласе — это t->uv[0..1] .. t->uv[4..5]. render::TextureCache::resolve() 2D-рендерера спрайтов/тайлов уже понимает атласы: изображение в атласе разрешается в текстуру страницы + свой прямоугольник (листы спрайтов никогда не обрезаются, поэтому uv кадров остаются точными); обрезанное, повёрнутое, с мешем или разбитое на кадры изображение пересобирается в отдельную текстуру. resolveSprite(path, nearest, base, frameW, frameH) вместо этого возвращает его на своей странице (TextureRef::sprite: кадры с областью, мешем и текстурой страницы) для рендереров, которые рисуют render::spriteShape(ref, uvRect, shape) — выпуклый многоугольник в параметрах прямоугольника плюс аффинное отображение в uv страницы (SpriteBatch::quad / polygon / casterPolygon). Обычные изображения (не в атласе) возвращаются тем же способом (собственная текстура, полные UV, без обрезки). Пиксели CPU исходного изображения: lib.loadImage(path, img) или atlas::ImageSource (его использует UI, поэтому RmlUi <img src> и декораторы продолжают работать с файлами из атласа).

Отчёт сборки. aiversebuild выводит статистику атласа и записывает size-report.json рядом с size-report.txt (<out>/<target>/): pack {rawBytes, packBytes, entries, duplicates, top[]} и atlas {enabled, profile, maxPage, candidates, atlased (кадры листов с кадрами считаются по одному), framedSheets, duplicates, pages, occupancyPercent, sourceBytes, atlasBytes, storedBytes, bytesSaved, gpuBytesBefore, gpuBytesAfter, textureBindsBefore, textureBindsAfter, groups[] {group, textures, unique, pages, occupancyPercent}, excluded[] {path, reason}}. Предпросмотр: assetpipe atlas --profile web -o <dir> <project> engine/assets=engine записывает страницы в PNG вместе с манифестом и отчётом.

  • Слои (сначала базовое изображение, затем logo / logos по порядку, последующие поверх): статичное image, анимация из frames (список изображений) или листа спрайтов sheet (frame [w, h], count, кадры по строкам слева направо), проигрываемая с частотой fps (loopFrames, по умолчанию true). fit: contain (по умолчанию для логотипов), cover (по умолчанию для базового слоя), center (пиксели изображения × dpi), stretch; scale умножает вписанный размер; anchor — центр на экране (в долях). start / duration в секундах (duration 0 = до конца заставки).
  • animation: ключевые кадры [{"t", "opacity", "scale", "x", "y", "rotate" (градусы), "ease": linear|in|out|inOut}] (t от начала слоя; свойство интерполируется между ключами, которые его задают) или эффекты {"fadeIn", "fadeOut", "fade", "pulse": amount | {"amount", "period"}, "rotate": deg/s, "slide": "bottom" | {"from", "distance", "duration"}, "zoom": from | {"from", "duration"}, "keyframes": [...]} — их можно сочетать.
  • Время: заставка уходит, когда загрузка завершена и прошло minSeconds (по умолчанию: до конца последнего слоя с длительностью, так что последовательность логотип студии → логотип игры проигрывается один раз); maxSeconds ограничивает этот минимум (но никогда не загрузку). loop: повторять последовательность, пока загрузка длится дольше. skippable: касание / клик / клавиша прерывает минимум. fadeOut: плавный переход в меню.
  • Полоса прогресса: реальный прогресс загрузки — шаги запуска клиента (правила, рендерер, модели и текстуры всех типов, эффекты, аудио, UI), а при waitForContent (раздельные сборки) — загрузка каждого фрагмента пака (platform::contentProgress).
  • Заставка в движке: рисуется через RHI с первого кадра (engine/splash, один конвейер текстурированного квада, GLSL + MSL; изображения декодируются по одному за кадр и ограничены 2048 px), поэтому работает на любом GPU. AIVERSE_SPLASH=off загружает по-старому; с --map заставка показывается только на время загрузки (AIVERSE_SPLASH=full проигрывает её целиком).
  • Нативный экран запуска (показывается ОС до старта движка; статичное изображение на цветном фоне — native, иначе первый логотип на background): iOS LaunchScreen.storyboard + LaunchImage / LaunchBackground в каталоге ассетов; тема заставки Android 12+ (windowSplashScreenBackground, windowSplashScreenAnimatedIcon: логотип или ваш анимированный векторный drawable androidIcon) и drawable windowBackground для версий до 12, тема activity @style/AiverseLaunchTheme; web: HTML/CSS-заставка в platform/web/shell.html с прогрессом загрузки .data до запуска wasm; macOS и Windows: цвет фона окна.

Материалы ландшафта (визуальный блок terrain)#

Только представление (modules/rts/view/RtsTerrainRender.*). Необязательные ключи в том же блоке terrain, что и оверлеи (rules.json или game.json; game.json побеждает по каждому ключу). Без них каждая игра выглядит точно так же, как раньше (вершинные цвета по виду клетки, плато с резкими стенами утёсов, пандусы, мягкие переходы цвета, кромка, один лист воды).

"terrain": {
  "layers": [                                   // up to 4 tiling splat layers (world-space, mipmapped, wrap)
    {"id": "snow",  "texture": "textures/terrain/snow_repeat.png", "normal": "textures/terrain/snow_n_repeat.png", "scale": 6, "tint": [1, 1, 1]},
    {"id": "earth", "texture": "textures/terrain/earth_repeat.png", "scale": 4}
  ],
  "cells": {"grass": {"layer": "snow", "color": [0.9, 0.93, 0.97]},  // layer id, or {layer, color (vertex colour override)}
            "sand": "earth", "ramp": "earth", "rock": "earth", "blocked": "earth", "lakebed": "earth", "shallows": "earth", "dug": "earth"},
  "cliff": {"texture": "textures/terrain/rock_repeat.png", "normal": "textures/terrain/rock_n_repeat.png",
            "scale": 3, "tint": [1, 1, 1], "slope": [0.3, 0.55]},     // blended in where 1 - normal.y is in that range
  "splatStrength": 1,                           // 0..1: mix of the textures over the vertex colours
  "water": {"mode": "auto", "color": [0.22, 0.45, 0.62, 0.78], "offset": -0.12},
  "lod": "auto", "lodRange": 128                // heightfield maps: CDLOD on above 256 cells per side ("on"/"off")
}
ключзначение
layersслои сплата (≤ 4): альбедо texture (sRGB), необязательная normal (в касательном пространстве, +Y вверх), scale — мировых единиц на повтор, tint. Загружаются через TextureCache::resolve(path, …, tiling): никогда не берутся со страницы атласа (называйте их *_repeat.png, чтобы упаковщик тоже их пропускал)
cellsвид клетки → id или индекс слоя; виды: grass (.), sand (, нельзя строить), ramp (/), rock (R), blocked (#), lakebed (~), shallows (=), dug (пол из выкопанной породы). color переопределяет вершинный цвет вида на всех уровнях качества
cliffтекстура на стенах утёсов и крутых склонах (Medium: одна проекция, High: трипланарная + карта нормалей)
water.modesheet = одна плоскость под всей картой (классика, по умолчанию для карт с уровнями утёсов), bodies = каждая связная водная область получает свою поверхность чуть ниже самого низкого берега (озёра на плато, долины на картах с полем высот; по умолчанию для карт с полем высот), auto
lod, lodRangeбольшие карты с полем высот: чанки рисуются с шагом 2^k клеток (k ≤ 4) в зависимости от расстояния до камеры, с геоморфингом в вершинном шейдере и юбками против трещин

Ключ карты terrainMaterial (необязательный, визуальный): строки из 0..3 (индекс слоя) по клеткам, другие символы = по виду клетки. Рисуется окном редактора Рельеф или terrain_material.

Уровни качества (меню паузы Текстуры земли, Renderer3D::materialQuality(), ограничен значением устройства по умолчанию; AIVERSE_TERRAIN=low|medium|high переопределяет для тестирования): Low = вершинные цвета (слабые Mali / Adreno / PowerVR, а также любая игра без layers), Medium = текстуры сплата + текстура утёсов, High = + карты нормалей и трипланарные утёсы. Шейдеры: modules/rts/view/RtsTerrainShaders.h (GLSL + MSL, солнце + мягкие тени + точечные источники + облака, как в освещённом шейдере).

Производительность: ландшафт разрезан на чанки 32x32 клетки с отсечением по пирамиде видимости; редактор перестраивает только чанки, клетки которых изменились; во время матча ничего не перестраивается: ресурсные поля, крип и (на картах с полем высот) туман войны читаются шейдером из небольших поклеточных текстур. AIVERSE_TERRAIN_STATS=1 выводит чанки / треугольники / время кадра. Пример: templates/frostcrown (сгенерированные текстуры CC0, tools/terrain/make_textures.py).

Редактор / MCP (карты с полем высот, apps/editor/core/TerrainOps.cpp, окно Рельеф): terrain_sculpt {op: raise|lower|smooth|flatten|noise|set, x, y | points, radius, strength, seed} (первая лепка создаёт углы из видимой поверхности: уровни утёсов, пандусы, точные высоты), terrain_heights {points | grid}, terrain_material {layer, x, y, radius}, heightmap_export {file, scale?} / heightmap_import {file, scale, offset} (16-битный PNG в оттенках серого, (w+1) x (h+1) пикселей, высота = offset + value / 65535 * scale). Углы чисто визуальные, если только terrain.model в правилах не равен heightfield (см. ниже).

Детальная поверхность (рельеф мельче клетки)#

"terrain": {"style": "smooth"} в rules.json / game.json рисует ландшафт по визуальной карте высот с несколькими отсчётами на клетку вместо одной высоты на угол клетки: скошенные утёсы с органичными очертаниями, скруглённые плато и пандусы на картах с уровнями утёсов, бикубический рельеф с мелким шумом на картах с полем высот, попиксельное освещение, смешивание материалов с разрешением мельче клетки с автоматической скалой на крутых склонах. Значение по умолчанию "classic" сохраняет старый вид. Карта может нести собственную нарисованную детализацию: terrain.detail = {"scale": 4, "file": "maps/<name>.detail.r16", "splat": "..."} (int16 LE, 1/16 единицы, (w*k+1) x (h*k+1)). Ключи настройки — terrain.detailLook. Редактор / MCP: terrain_detail, terrain_sculpt (мельче клетки, эрозия, штамп), terrain_paint_material, heightmap_import/export {detail: true}. Полное описание и числа: docs/terrain.md § Detail surface. Примеры: starfall (утёсы), metaltide (рельеф), frostcrown.

Ландшафт с полем высот#

rules.terrain.model: "heightfield" + карта с terrain.corners / cornersFile (без углов карта играется как "levels"). Угол (x, y) — левый верхний угол клетки (x, y); высоты в 1/16 мировой единицы. Всё целочисленное / с фиксированной точкой и детерминированное.

  • Поверхность: высота земли в любой точке — билинейная интерполяция между 4 углами её клетки; наземные юниты (и y каждого подвижного юнита) стоят на ней; снаряды стартуют с высоты земли стрелка + 0.6 и целятся в землю цели + 0.4.
  • Склоны: крутизна клетки = max(длина градиента, самое крутое ребро клетки), в единицах высоты на клетку. Юнит не может войти в клетки круче его move.maxSlope (или terrain.maxSlope его слоя; sand для layer: "sand"); поиск пути, локальное уклонение и появление юнитов следуют тому же правилу. Правила утёсов/пандусов (levels, /) заменяются склонами. Строениям нужны клетки не круче terrain.buildSlope.
  • Скорость: speed * (1 - uphillSpeed * climb) при подъёме, * (1 + downhillSpeed * descent) при спуске, где climb/descent = изменение высоты на клетку вдоль движения; ограничивается диапазоном 0.25..2.
  • Обзор: линия видимости от eyeHeight над клеткой юнита до targetHeight над каждой клеткой в радиусе обзора; клетка за гребнем скрыта (heights.blockVision: false отключает это, воздушные юниты видят поверх). Наведение выбирает только врагов в клетке, которую видит игрок.
  • Уровень утёса клетки = floor(высота клетки / levelHeight) (0..9), поэтому правила и триггеры, основанные на уровнях, продолжают работать. Бонусы дальности / урона / промаха используют точную разницу высот (см. heights).
  • Контрольные суммы: углы и модель входят в хеш состояния только для игр с полем высот.
  • Большие карты (256x256 клеток и больше): длинные пути используют иерархический поиск пути (кластеры 16x16 с входами на границах, уточнение A*), построенный в начале матча и перестраиваемый только вокруг строений, блокирующих клетки. aiverse_headless --project DIR --bench-paths N замеряет время запросов пути; python3 templates/_tools/mapgen.py --big 1024 <scratch>/maps/big.json записывает тестовую карту 1024x1024 (не кладите её в templates/).

MCP: map_info.heightfield (corners, min, max, storage, model), map_heightfield {"enabled"} добавляет плоское поле высот или удаляет его, map_validate предупреждает, когда модель — heightfield, а у карты нет углов, и отмечает юниты/строения, стоящие на слишком крутых для них склонах. Лепка: terrain_sculpt, импорт/экспорт PNG карты высот (см. «Материалы ландшафта»). Представление рисует рельеф по углам (два треугольника на клетку, диагональ (0,0)-(1,1)); RtsView::heightAt следует тем же треугольникам, поэтому модели и оверлеи стоят на нарисованной земле.

Планеты: визуальные ключи (блок world карты)#

Сами тела описаны в docs/planets.md §1-2 (world.bodies, kind, radius, faceSize, seaLevel, orbit, terrain.faces / terrain.corners, nereid — море как водоём NEREID для плавучести и течений, §1). Что читает только представление:

{"id": "terra", "kind": "planet", ...,
 "visual": {"color": [255, 220, 160],                        // stars: light colour and glow; others: far-away tint
            "atmosphere": {"color": [110, 170, 255], "height": 0.08}}}   // or false; default: on for planets, off for moons
  • visual.flora: деревья и камни TerraWeave на теле (одно место на клетку суши, вид по климату сферы): {"density": 0..1, "scale": мировых единиц на метр} или false; по умолчанию плотность 0.22 на планетах, на лунах нет, масштаб 0.06.
  • visual.atmosphere.height: толщина оболочки как доля радиуса (0.005..0.5). Оболочка и дымка используют этот цвет; оболочка рисуется начиная с уровня материалов Medium.
  • terrain.faces[f].material: строки цифр 0..3 на каждую грань (. = по виду клетки), как terrainMaterial плоской карты; рисуется через terrain_material с body.
  • Вид поверхности на планетах = визуальный блок terrain игры (слои по видам клеток, текстура скал, цвет воды).
  • Наложения на поверхность планет используют те же визуальные блоки terrain.territory / dig / roads / lanes, что и плоские карты (заливка и границы территорий, каменные блоки с жилами / самоцветами и следами копания, клетки дорог, линии и дороги карты roads между зданиями, натянутые на поверхность). Территории, копаемая порода (символы diggable в terrain.faces[f].rows), комнаты, заявки, захват и линии работают на планетах с теми же ключами правил (docs/planets.md §3).
  • Редактор / MCP: planet_info; terrain_sculpt / terrain_paint / terrain_material с body + face + x, y (клетки на этой грани) или dir [x, y, z] и radius в клетках (3D-кисть, переходит через швы граней).

Планеты: ключи симуляции (блок world карты)#

Карта с блоком world — это карта планет: тела заменяют size / terrain / fields (docs/planets.md). Плоские карты не затрагиваются (те же контрольные суммы).

"world": {"start": "terra", "bodies": [
  {"id": "sun", "kind": "star", "radius": 40},
  {"id": "terra", "kind": "planet", "radius": 16, "faceSize": 24, "orbitAltitude": 4,     // shell of move.layer "orbit"
   "orbit": {"around": "sun", "radius": 400, "period": 1200, "phase": 0.1},               // seconds, turns
   "terrain": {"faces": [{"rows": [...], "levels": [...], "fields": {"metal": ["..19.."]}}, ... 6 faces],
               "corners": [ ... 6 * (N+1)^2 ... ] | "cornersFile": "maps/x.terra.r16"}}]},
"players": [{"name": "Blue", "start": {"body": "terra", "face": 4, "x": 12.5, "y": 12.5}}],
"entities": [{"type": "metal_spot", "at": {"body": "terra", "face": 4, "x": 7, "y": 8}}],
"waves": [{"at": {"body": "terra", "face": 0, "x": 3, "y": 3}, ...}]
  • kind: planet, moon (поверхность: faceSize 2..512), star (без поверхности). radius 2..1200, radius + orbitAltitude <= 1500; orbitAltitude по умолчанию 0.15 x radius. orbit.around должен называть тело, объявленное раньше. Не более 16 тел.
  • Визуальная детализация каждого тела (docs/terrain.md "Planets"): terrain.style (smooth / classic, по умолчанию как в игре), terrain.detailLook {scale, roughness, craters}, terrain.detail {scale, file} (int16 LE в единицах 1/256, 6 x (faceSize*scale+1)^2, пишется редактором). Только для представления: симуляция и контрольные суммы их игнорируют.
  • Позиции на картах планет задаются как {body, face, x, y} (координаты клеток на этой грани, 0..faceSize); [x, z] — ошибка. Поля задаются на грань (fields в грани: строки цифр на каждый ресурс) или как fields: [{center: {body, face, x, y}, radius}].
  • Строки / уровни граней используют символы плоской карты; rules terrain.model: "heightfield" заставляет углы задавать уклоны (подъём на единицу мира), скорость и линию видимости — точно так же, как на плоских картах с картой высот.
  • cornersFile: сырые int16 LE, грани 0..5, каждая (N+1)^2 по строкам; редактор пишет его для тел больше 257² углов. Углы на швах должны совпадать на каждой грани, которая их хранит (map_validate предупреждает; загрузчик усредняет).
  • Юниты: move.layer: "orbit" (летает по орбитальной оболочке, свободно движется по большим кругам, видит поверхность под собой, может быть поражён только оружием, у которого в targets указано "orbit"), move.transitSpeed (единиц мира/с для перелётов; по умолчанию 10 x speed).
  • Команда kCmdTransit (units = орбитальные юниты, param = индекс целевого тела): перелёт по времени, вычисленный по положениям тел в момент отправления, прибытие на обращённую сторону оболочки цели; события kEvTransitStart / kEvTransitEnd.
  • Правило movement.planetHpaCells (по умолчанию 65536): тела, у которых не меньше клеток (6 x faceSize²), используют иерархический поиск пути для дальних поездок (0 = каждое тело).
  • Сооружения стоят в пределах одной грани (контур, пересекающий шов, строить нельзя). Юниты на разных телах встречаются только через орбитальный слой. Пример: templates/planets.

Генерация карт (generate)#

Карту может сгенерировать движок вместо того, чтобы рисовать её вручную (или перед этим): детерминированный целочисленный код (modules/rts/gen/), поэтому один и тот же запрос даёт бит-в-бит одинаковую карту на каждой платформе. Генерация выполняется при старте матча (lockstep-мультиплеер, серверный арбитр, headless, повторы: каждый участник заново генерирует ту же карту из сида матча), в редакторе (окно Генерация) и через MCP (map_generate, gen_presets), где результат можно запечь в статическую карту.

"generate": {
  "preset": "continents",          // gen_presets: built-in + rules "mapgen.presets"
  "seed": "match",                 // "match" = the match seed (a new map every match), or a number (fixed map)
  "players": 4,                    // 1..8; the map's players array is resized to it (names/factions/teams kept)
  "symmetry": "auto",              // auto | none | point | mirror | mirror-y | mirror4 | rot4 | rotational
  "template": "maps/valley.json",  // optional: map whose player-1 objects are the start kit and whose neutral objects decide what is placed

  • Плоские карты: generate верхнего уровня. Планеты: world.bodies[].generate (пресеты rocky, ocean, moon; см. docs/planets.md §4).
  • Что пишет генератор: size, terrain.rows (. ~ # , = / R, копаемые символы для пещер), terrain.levels (правило terrain.model levels), terrain.corners (heightfield), fields, entities, regions (если они есть в шаблоне), roads (игры с гарнизонами), terrainMaterial (по биому и id визуальных terrain.layers игры: grass / forest / sand / dirt / earth / rock / snow / mud ...), start игроков и сводный блок generated (пресет, сид, симметрия, старты, длины путей между стартами, измеренные A* движка, connected, pathSpread в промилле, число объектов, warnings). Все прочие ключи карты (victory, triggers, waves, lighting, ...) сохраняются.
  • Объекты берутся из собственных типов игры: объекты игрока 1 в шаблоне (или в самой карте) — это стартовый набор, он расставляется каждому игроку в симметричной системе координат (с поворотом на четверть оборота, чтобы контуры оставались выровненными); нейтральные объекты подсчитываются возле баз шаблона / вдали / в центре и расставляются так же (шахты и металлические точки возле каждой базы, леса в лесных биомах, лагеря крипов подальше от баз, здания-гарнизоны, порталы...). Без шаблона решают правила: сооружение, производящее рабочих, + 4 рабочих (или юнит key, или самый большой гарнизон), узлы ресурсов, места structure.on, порождатели полей, нейтральные крипы neutral. Ресурсные fields шаблона воспроизводятся (ближние сохраняют своё смещение).
  • Честные старты: старт игрока 1 выбирается в фундаментальной области симметрии и копируется во все её образы; области баз выравниваются (один уровень скал / пологие углы, никогда не вода); старты связаны между собой (пандусы прорезаются сквозь скалы, отмели = — через воду, выровненная дорога — на картах высот, самый дешёвый маршрут — сквозь копаемую породу); объекты никогда не перекрывают маршрут между стартами (проход разблокировки их удаляет); результат проверяется поиском пути. "connect": "none" оставляет острова раздельными (морские / воздушные игры).
  • Детерминизм: только целые числа / Fixed (никаких float), хеширование с сидом, упорядоченные контейнеры; генератор выполняется внутри RtsModule::setup до загрузки карты, поэтому повторы и серверный арбитр генерируют карту одинаково. Эталонные хеши пресетов лежат в tests/tests.cpp (gen_golden_maps и соседние): изменение вывода генератора будет видно там. Тот же сид + параметры + версия движка = та же карта.

  • layout: "shared" (по умолчанию): все игроки на стартовом теле, вращательная симметрия вокруг полярной оси: точная для 2 и 4 игроков (повороты на половину / четверть оборота отображают кубосферу саму на себя, высоты симметризуются угол за углом), усреднённая по поворотам для 3, 5+ (generated.symmetry: polar-exact / polar).   • layout: "separate": каждый игрок на собственной одинаковой планете (тот же рельеф, те же объекты), планеты обращаются вокруг звезды с равными фазами; игроки встречаются через юниты орбитального слоя (предупреждение, если в правилах таких нет).

2D-игры#

Это всё тот же 3D-движок, но с ортографической камерой; объекты могут быть спрайтами, а поверхность — тайловой картой. Два варианта, оба — только данные (примеры: templates/tiles2d, templates/km2d; их временная графика генерируется tools/art2d/make_samples.py):

  • Тайловое 2D (Red Alert, Dune II, Warcraft II): camera смотрит строго вниз (pitch: 90), слой карты tiles рисуется из тайлсета, юниты и здания — спрайты ("mode": "ground").
  • 3D-рельеф + спрайты (Knights and Merchants): обычный рельеф (уровни, пандусы, высоты), camera под фиксированным углом (pitch: 50), спрайты-билборды стоят на поверхности.

Тени и освещение спрайтов (блок sprites)#

Значения по умолчанию для всей игры в game.json (имеет приоритет) или rules.json:

"sprites": { "shadow": "cast", "lit": true }
ключсмысл
shadowshadow по умолчанию для каждого типа спрайтов: "blob" (по умолчанию, классический вид), "cast", "none"
litспрайты принимают свет сцены (по умолчанию false: нарисованные цвета, для приверженцев пиксель-арта): цвет солнца и неба, день/ночь и пресеты, точечные источники, тени облаков и (Medium/High) солнечные тени других объектов, падающие на них. При полном дневном свете по умолчанию освещённый спрайт сохраняет свои нарисованные цвета

Отбрасываемые тени: спрайт рисуется в карту солнечных теней как вертикальный квад с альфа-тестом, стоящий у его основания и повёрнутый по yaw камеры (развёрнутый к солнцу, когда солнце светит почти вдоль него), с текущим кадром анимации и направлением; затем тень падает на рельеф, 3D-модели и другие освещённые спрайты с направлением солнца, мягкостью и уровнями PCF из 3D-игр.

AIVERSE_SHADOWS / уровень тенейспрайты с "shadow": "cast"
Offтолько пятна (классический вид, без прохода теней)
Lowздания отбрасывают тень, юниты сохраняют пятна; спрайты не читают карту теней
Medium / Highтень отбрасывает всё (юниты сохраняют слабое контактное пятно); освещённые спрайты получают тени

Куда падают тени, определяет направление солнца: "lighting": {"sunDir": [x, y, z]} (game.json или карта, в сторону солнца в полдень; суточный цикл качается вокруг него). Плоские рисунки скрывают тени, которые падают прямо за ними, а солнце позади сцены оставляет обращённые к камере стены скал неосвещёнными, поэтому спрайтовым играм обычно нужно солнце сбоку и немного спереди (km2d: [-1.0, 1.2, 0.45], тени вправо). "shadowSoftness" (единицы мира, по умолчанию 0.22) — максимальный радиус полутени. Солнечные тени Medium/High становятся резче у точки контакта и шире с ростом расстояния между отбрасывающим и принимающим объектом (PCSS); игры в пиксель-арте выглядят чище с узкой полутенью (km2d 0.07): ядра в несколько текселей карты теней фильтруются без попиксельного поворота шума, поэтому остаются гладкими на любом уровне.

Пятна и спрайты ground проецируются: пятно (и любой спрайт "mode": "ground") вырезается из треугольников поверхности под ним — точных треугольников сетки рельефа или тайловой карты — и рисуется со смещением глубины, поэтому оно изгибается по склонам и краям скал и никогда не мерцает от z-конфликта и не висит в воздухе. Sprite типы спрайтов не получают от системы освещения дополнительной декали контактной тени (эту работу выполняет их пятно).

tiles карты#

"tiles": {"tileset": "tilesets/desert.json", "rows": ["sssrrr", "..."], "fixed": [[x, y, tile]], "seed": 0}

Когда загружается карта с tiles (игра, headless, игра в редакторе), игровые свойства тайловых поверхностей записываются в terrain.rows, terrain.levels и элемент fields ("fromTiles": true) до старта симуляции — детерминированно и идемпотентно; сама симуляция ничего о тайлах не знает. Редактор тоже запекает это при рисовании, поэтому сохранённые карты в любом случае содержат корректный рельеф. fixed ставит точные тайлы атласа (автотайлинг выключен). Визуально: автотайл на каждую клетку, не более двух квадов на клетку (under + тайл), одна статическая сетка.

Редактор: окно Тайлы (палитра, кисть, автотайлинг вкл/выкл, выбор из атласа; рисует в виде Scene). Агенты: tileset_list, tiles_init {tileset, fill | fromTerrain}, tile_paint {terrain, x, y, radius | rect, tile?}, tile_info {x, y}, tiles_remove.

Окружение карты#

Необязательный блок "environment" в rules.json (значения по умолчанию) и в карте (ключи карты важнее, по каждому ключу). Код: modules/rts/RtsEnv*.cpp. У игры без этого блока нет состояния окружения, и она сохраняет свои контрольные суммы и сохранения. Состояние: ресурс мира EnvState (хешируется, сохраняется после сеточных полей, откатывается вместе с миром). Система environment выполняется перед death (только при наличии блока), environment3 — после vision (только при fog). Только плоские карты (планеты не поддерживаются).

Единицы: позиции — это мировые координаты; каждый ключ расстояния / скорости (lightningKillRange, силы ветра, velocity сплайна, ...) делится на "scale" (авторские единицы расстояния на единицу мира, по умолчанию 1), поэтому импортёр копирует исходные значения как есть и задаёт scale. Время — в секундах. Навыки — это id playerAbilities из правил, применяемые за нейтрального игрока без стоимости.

Молния: каждые lightningKillTime с вероятностью lightningKillFactor % погибает случайный юнит и всё в эллипсе (range, range / 2) вокруг него, либо здание теряет lightningPointKillValue юнитов гарнизона; lightningBurn задаёт там сеточное поле
windзатишье, затем ветер дует в следующем из 8 направлений (угол = dir * 45 градусов от +z к +x) со случайной силой: speed + dot(facing, force)
zonesскорость / slowdown в первой зоне, содержащей наземный юнит; зоны дорог пропускают таблицы скоростей вытаптывания. kind сохраняется как тег зоны, поэтому нативный модуль игры может придать собственным видам смысл
splinesпути (Catmull-Rom через точки). Со skill: способность применяется в первой точке каждые emitPeriod, и её области движутся по сплайну со скоростью velocity (движущиеся опасности); на многоэкранных картах — только пока весь сплайн находится на экране
trampleдвижущиеся наземные юниты добавляют perSecond к сеточному полю (docs/fields.md); таблица speed (побеждает последняя строка со значением <= первого), lerpSpeed, killField (юниты на горящих клетках погибают; в дождь его ядра распространения срабатывают с вероятностью grassRainBurnRandomFactor, GridFields::setSpreadScale), hideStatus
fogmemory: false возвращает клетки, вышедшие из поля зрения, в неразведанные; startFowSize открывает диск вокруг первого здания каждого игрока, который сжимается до нуля за startDuration. fogOfWar.ellipse (правила) сплющивает каждый диск обзора (быстрый и эталонный проходы видимости)

События: kEvEnv (value = EnvEventKind << 16 | data): фазы погоды, молния, ветер. kEvGarrisonChanged для молний по зданиям.

Специфичные для игры действующие лица поверх окружения (боссы, скриптовые режиссёры, особые здания) — это нативные модули (docs/native-modules.md § Gameplay hooks): они читают RtsModule::environment() (зоны, сплайны, состояние погоды, killedByWeather) и собственные ключи того же блока карты через mapData().

Вид тумана войны#

Визуальные ключи "fogOfWar" в rules.json ("fogOfWar" в game.json переопределяет их по ключам; окно редактора Туман войны или rules_merge {path: "fogOfWar", value: {...}} через MCP):

"fogOfWar": {
  "mode": "full",                 // simulation: full | explored | none (see rules table)
  "show": true,                   // false: no fog drawn (enemies outside sight stay hidden)
  "color": [8, 10, 14],           // 0..255 or 0..1
  "unexplored": 0.92, "explored": 0.47,   // opacity over never-seen / seen-before ground
  "style": "smooth",              // smooth | cells | grid (cells + lines) | pattern (dithered edge, classic)
  "softness": 2,                  // blur radius in cells (smooth, pattern)
  "fade": 0.3,                    // seconds for a cell to clear / fog over
  "noise": 0.0,                   // 0..1 cloudy moving edges
  "height": 1.3,                  // sheet height above the ground (covers units and low buildings)
  "grid": {"show": "fog", "color": [255, 255, 255], "alpha": 0.15}   // none | fog | all
}

Слабые GPU (качество теней off/low) рисуют smooth как cells без шума. Карты высот рисуют туман в шейдере рельефа (цвет, прозрачность, клетки, сетка; pattern и noise доступны только для слоя-полотна).

3D-линия видимости#

С "fogOfWar": {"lineOfSight": true} (всегда включено для карт высот с heights.blockVision) каждый наземный юнит видит клетку, только если прямая линия от его глаз до клетки проходит над каждой клеткой между ними. Высоты: поверхность карты высот или уровень скал × levelHeight на картах с уровнями; плюс динамические загораживающие объекты, пересчитываемые на каждом проходе видимости (5 тиков):

ИсточникКлючВысота над поверхностью
Тип юнита или сооружения (стены, леса, высокие здания)"vision": {"blocks": 3} типанад его контуром (сооружения) или его клеткой; исчезает, когда он погибает
Навыки дыма, пыли, стены туманадоставка {"type": "area", "radius": 2, "lifetime": 10, "blocksVision": 4}диск области, пока она существует
Невыкопанная породаfogOfWar.rockHeight (2, 0 = прозрачная)каждая клетка породы

Глаза: terrain.eyeHeight + "vision": {"eye": 6} типа (сторожевые башни видят поверх стен и холмов); для целей учитывается terrain.targetHeight. Воздушные юниты и типы с "vision": {"seesOver": true} видят полный круг. Целочисленная математика, детерминированно; редактор: Туман войны → "3D: линия видимости".

Оверлеи (вспомогательные элементы на экране и в мире)#

Необязательный список "overlays" в rules.json; "overlays" в game.json добавляет записи или переопределяет их по id. Оверлей — это условие (when), место (anchor), форма shape и стиль style, при необходимости порождаемый событиями event симуляции. Только представление: оверлеи никогда не меняют симуляцию. Редактор: окно Оверлеи (список, шаблоны, JSON, предпросмотр); MCP: overlay_templates, overlay_list, overlay_get, overlay_set, overlay_delete, overlay_preview (+ view_screenshot).

"overlays": [
  { "id": "build_grid", "when": "placing", "anchor": "ghost",
    "shape": {"type": "grid", "radius": 4, "predicate": "buildable"},
    "style": {"colors": {"true": "#3cff6450", "false": "#ff3c3c60"}, "lineColor": "#ffffff38", "outerAlpha": 0.55} }
]

Встроенные оверлеи — это обычные записи (тот вид, который у движка был всегда); любой ключ можно переопределить по id (объекты сливаются глубоко, "replace": true заменяет запись целиком), или скрыть запись через {"id": "health_bars", "enabled": false}. Игра без этого блока выглядит точно так же, как раньше.

Ключи записи: id (обязателен, уникален), enabled (по умолчанию true), order (порядок отрисовки, по умолчанию 0, затем порядок в списке), when, anchor, shape, style, event; name / description — произвольный текст. Постэффекты (postfx)#

В game.json и картах может быть блок "postfx": список полноэкранных эффектов (bloom, цветокоррекция, LUT, виньетка, tilt-shift, солнечные лучи, FXAA, зерно, ...) с уровнями качества и моделью стоимости кадра. Формат, параметры, уровни и инструменты MCP: docs/postfx.md.

Начальные переменные скриптов (локальная настройка матча)#

Необязательный объект карты initialVars содержит целочисленные переменные триггеров, которые загружаются до пользовательских скриптов. Пример: "initialVars": {"loadout_support_1": 2}. Не более 128 ключей из ASCII-букв, цифр, подчёркивания, точки и дефиса, длиной 1–128; целые числа в диапазоне −1000000..1000000. Значения попадают в обычное хеширование trig.vars. Клиентский UI может передать переопределения через game.start(..., {initialVars=...}); см. docs/ui-scripting.md. Сохранённая настройка карты или реплея хранит эти параметры, а без них сохраняется прежнее поведение.

Компьютерный игрок (RtsAI, agent-ai-terrain)#

Бот читает состояние и отправляет команды как игрок (реплеи его не перезапускают). Он общий для всех шаблонов; настройки — в блоке правил ai (выше). Что он делает с рельефом:

  • Анализ в начале матча (RtsAITerrain.*, целочисленный, после загрузки сохранения строится заново так же): для каждой клетки — высота в единицах преимущества по высоте (уровень обрыва либо высота heightfield / планеты, делённая на levelHeight), маска проходимости наземного слоя (только рельеф), ширина коридора (шаги до ближайшей стены: узкие места), over (насколько более высокая земля в пределах 4 клеток поднимается над клеткой) и crest (выраженность возвышения). Одинаково для плоских карт, heightfield и планет на кубосфере (соседи через швы граней).
  • Маршруты: взвешенный Дейкстра от нашей базы до ближайшей вражеской: подъём к противнику и клетки, которые просматриваются с более высокой земли, стоят дороже (climbWeight, exposureWeight), поэтому волны идут через седловины и пандусы, а не вверх по хребту под огнём; запасной маршрут обходит главный коридор (используется на нечётных волнах при патовой ситуации).
  • Посты на маршруте: точка сбора на самой высокой хорошо прикрытой земле в 9-14 шагах от базы (армия ждёт там, туда же собираются производящие здания); самая узкая клетка на нашей стороне (башни после набега); наблюдательный пост на самой выдающейся высоте в середине маршрута для разведчика (обзор через хребты). Бездействующие юниты не отправляются повторно к точке сбора (юнит, идущий обратно, не считался бы готовым к следующей волне).
  • Волны идут по путевым точкам каждые 12 клеток, останавливаются на точке осады на возвышенности, не доходя до цели, затем атакуют; они выжидают до 30 с вместо штурма вверх по склону против более сильного противника (и подтягивают подкрепления), отступают к точке сбора, если их стало меньше 25% исходного размера без единого убийства (до уровня пата 3), выходят раньше с тем, что есть дома, когда наша армия вдвое больше всех вооружённых сил противника, останавливаются по сторожу застрявшей волны (30 с без движения), перенацеливаются на следующее здание, атакуют строительные площадки по имени.
  • Защита экономики: собственные места под постройки (проходы между пунктами сдачи и ресурсами остаются свободными, область сбора остаётся свободной, случайный выбор при равенстве), застрявшие строители освобождаются, а их места избегаются, первое производящее армию здание строится рано, преобразователи (metal makers) — только при избытке, ещё одно производящее здание — когда ресурсы копятся, расширение (пункт сдачи у следующего месторождения), когда ближние месторождения исчерпаны, рабочие распределяются по переполненным месторождениям и появляются со стороны своего ресурса.
  • Выход из пата: противника без вооружённых юнитов добивает вся армия (его самое слабое из учитываемых зданий); на уровне пата 1+ волну запускает меньший перевес сил, а на уровне 2+ волны ограничены 3/4 от firstAttackArmy; бот строит / исследует то, что открывает юнитов заметно лучше против самого прочного здания противника (таблица урона, бонусы, броня), и копит на это; при игре гарнизонами сначала отправляются полные гарнизоны, они стягиваются к фронту, а после 10 мин каждый гарнизон может присоединиться к наступлению; в поселенческих экономиках сначала строится основная цепочка производства материалов, затем то, что нужно армии; если заканчивается запас, который потребляет население, строительство жилья прекращается; к регионам, которые нужно сначала увидеть, отправляется разведчик; медленным сборщикам (без workersPerBase в правилах) выделяется больше рабочих.
  • Планеты: орбитальный флот (invasionSize + 2 на каждое вторжение) переходит вместе на тело с вражескими зданиями и сражается там, пока тело не очищено, затем переходит к следующему телу; больше орбитальных верфей, когда до противника можно добраться только через орбиту; башни, бьющие по орбите, когда атаки идут оттуда.
  • Стили по слотам: players[i].ai карты (см. «Карты») задаёт одному слоту пресет и собственные настройки; они применяются до первого размышления (и так же после загрузки), поэтому thinkTicks слота используется с самого начала.
  • Сохранение состояния: RtsAI::saveState() / loadState() (headless --save F пишет F.ai рядом с состоянием симуляции, --load F читает его): восстановленный бот продолжает играть точно так же, как сохранённый.

Герои с видом сверху#

Блок правил topDown (один напрямую управляемый герой на игрока: движение стиком с ускорением и скольжением вдоль стен, конус доводки прицела, политика автоогня, способности по направлению прицела, возрождение) и блок game.json topDown (виртуальный джойстик, стик прицела, кнопки способностей, клавиатура / мышь / геймпад, следящая камера). Ключи, значения по умолчанию и поведение: docs/topdown.md. Пример: templates/topdown_arena.

Прогрессия в матче (progression, agent-df-progression-glue)#

Необязательный блок правил progression: формат библиотеки match-progression (stats, perks, units, deck, xp с toNext / curve / kill, offers с default / levels / variants / preferNewRecruitAtLevel / recruitWeight / recruitAiPriority, summonPoints с id / team / position / radiusMilli / progressTicks / cooldownTicks / singleUse / action; перки с key, hook, scope, bearer, effects (stat, op, value, stage), maxSelections, minLevel, weight, requires, excludes, tags, upgrades, offerable, aiPriority, aiPriorityLowHealth) на реальных юнитах, а также ключи движка: units[].type, perks[].bullet (modifiers: split / ricochet / flyThrough / damage / speed / radius, добавляемые к программам снарядов носителя), perks[].onHit / onHitChance (набор эффектов при попадании: горение, оглушение, ...), players, killXp, orbs, orbOwner, autoOpen, offerAt, offerChoices, offerRerolls, rerollAvoidsRepeat, maxLevel, xpGrowthPerLevel, maxRecruitsPerSlot, maxSquad, pickups (radius, magnetRadius, grabRadius, attractSpeed, attractAccel, maxSpeed, landing, lifetime, maxOrbs), summons (progress, cooldown, maxAllies, charges, chargeRecharge, resetOnExit), squad (follow, lifetime), critDamage, decks, defaultDeck (данные боевой колоды: player, techLevel, choiceCount, enforceUnlocks, slots с slot, unit, level, opened, inTeam, perks). Карта: progression.summonPoints, players[i].deck (данные для старта матча). Опыт героя за убийства и сферы опыта, предложения при повышении уровня с заданным зерном, выбираемые через kCmdProgression (UI, бот, Lua, MCP), характеристики перков для урона / входящего урона / скорости / интервала стрельбы / дальности / максимального здоровья / урона по площади / критов / регенерации, круги призыва и рекруты как реальные юниты. Полный справочник: progression.md; пример: templates/perk_arena.

Бои с боссами#

Блок правил encounters (библиотека boss-encounters на реальных юнитах; справочник docs/encounters.md, пример templates/boss_arena). Им управляются игроки карты с "monsters": true и враждебные крипы (владелец 255) (компьютерный игрок их пропускает).

  • attacks.<id>: shape (circle / cone / line / ring), radius, inner, angle, length, width, anchor (source / aim), offset, windup, active, recovery, interval, cooldown, damage, damageMin, falloff, damageType, statuses (id статусов из правил или {"status", "duration"}), statusDuration, oncePerTarget, trackAim, sweep, cancelOnDeath, friendlyFire, minRange, maxRange, ability (её запускает способность юнита).
  • bosses.<unit type>: engageRange, loseRange, approach, immune, archetype, phases[] (hpBelow, after, damage, speed, cooldown, globalCooldown, transition, mode byRange / sequence / weighted, pattern[] (attack, alternate, minRange, maxRange, weight), adds[] (unit, count, every, maxAlive, minRadius, maxRadius)), enrage (after, hpBelow, damage, speed, cooldown).
  • mobs.<unit type>: aggroRange, loseRange, stopDistance, switchMargin, wanderMin, wanderMax, arriveRadius, leash, wanderDelay, wanderLeg, wanderAttempts, fleeBelow, fleeRecover, fleeRange, fleeTime, wander, spacing, correction, lookAhead, neighbours, attack, think, flowDistance.
  • schedule: personal, rotation, archetypes, spawnDistance [min, max], windows[] (start, end, breather, excludePrevious, pauseWaves, variants[] (boss, weight, archetype)).

События Lua boss_engaged, boss_phase, boss_enraged, boss_adds, boss_defeated, boss_window, telegraph_start, telegraph_strike, telegraph_end (статусы: status_start); таблица encounters.

Городской трафик#

Блок правил traffic (вместе с topDown + driving): машины под управлением компьютера на полосах, построенных из символов тайлов карты, регулируемые перекрёстки с моделями светофоров, пешеходы на тротуарах, которые переходят дорогу на «идите» и паникуют при стрельбе; "traffic": false на карте отключает его. Ключи, значения по умолчанию и поведение: docs/traffic.md.

Упорядоченные программы полёта снарядов#

Оружие и доставки снарядов принимают необязательный объект flight с упорядоченными модификаторами Split, Ricochet, Fly Through и скалярными модификаторами. Схема, правила наследования, границы столкновений, версия сохранений и исполняемый пример — в Программы снарядов. Старые снаряды не меняются, если этого блока нет.
