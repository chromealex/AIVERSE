Запечённое освещение (карты освещения, световые пробы, запекатель света)#

AIVERSE сам запекает глобальное освещение: офлайн-трассировщик путей на CPU (engine/bake) записывает карты освещения для статичных объектов и рельефа, а также сетку световых проб для всего, что движется. Во время выполнения освещённые шейдеры (GLSL + MSL) делают из них выборку и смешивают их с солнцем в реальном времени, как mixed lighting в Unity. Владелец: agent-lightbake.

Быстрый старт#

  1. Отметьте источники света карты, которые нужно запечь: "bake": "mixed" (остаётся в реальном времени, запекается его отражённый свет) или "bake": "baked" (только в карте освещения / пробах; его свет в реальном времени и спрайт ореола выключаются, как только запекание загружено). MCP: light_add / light_update с bake.
  2. Редактор → Графика → Запекание света: режим, плотность, сэмплы, отражения, пробы → Запечь. MCP: lightbake_set {quality: "preview"|"medium"|"high", mode, ...}, lightbake_bake {force?}, опрос lightbake_status, lightbake_get, lightbake_clear.
  3. Результат — maps/<map>.bake/ рядом с картой; игровой клиент загружает его при старте карты.

Повторное запекание пропускается, если ничего не изменилось: запекание хранит 64-битный хеш содержимого всего, что оно использовало (геометрия, материалы, текстуры, трансформы, солнце / небо / источники света, настройки); lightbake_bake без force сначала сравнивает его.

Что считается статичным#

Запекание захватывает то, что вид Сцены рисует с kDrawStatic (Renderer3D::DrawFlags): объекты типов, которые не могут двигаться (structure или скорость 0), достроенные, живые, не летающие, без эффектов сущности. Каждый такой узел модели — приёмник карты освещения и препятствие для света. Всё остальное (юниты, снаряды) освещается пробами. Другие рендереры могут включиться, установив kDrawStatic в своём ModelDraw.

Во время выполнения узел модели находит свою область карты освещения по пути модели + индексу узла + мировой матрице (квантованной до 1/256), поэтому никаких id в карте хранить не нужно: объект, нарисованный ровно там, где он был запечён, получает карту освещения, сдвинутый — откатывается на пробы. Поэтому анимированные узлы карту освещения не получают.

UV карт освещения#

  • Модели со вторым набором UV используют его: glTF TEXCOORD_1, второй набор UV в FBX (UV2 в Unity; значения в [0, 1]). Только примитивы без скиннинга; хранится в ModelVertex::joints как два unorm16 (engine/render/LightmapUv.h), поэтому раскладка вершин не меняется.
  • Иначе запекатель разворачивает меш с помощью xatlas (MIT, third_party/xatlas, зафиксированная версия f700c7790aaa030e794b52ba7791a05c085faf0c) и записывает <model>.lmuv рядом с моделью; loadModel применяет его в дальнейшем (он проверяет хеш исходной геометрии, устаревший дополнительный файл игнорируется с предупреждением). Коммитьте файлы .lmuv вместе с моделями.
  • У каждого меша своё пространство [0, 1]; каждый размещённый узел получает область размером texelsPerUnit × его мировая площадь, упакованную в страницы размером в степень двойки.

Режимы смешивания (mode)#

modeкарта освещения содержитсолнце на статичных объектахдля
indirectнебо, отражения, эмиссию, только запекаемые источники светав реальном времени (карта теней)смены дня и ночи
shadowmask (по умолчанию)как indirect + маска видимости солнцав реальном времени, тень = min(карта теней, маска)статичных теней за дальностью теней и при выключенных тенях
subtractiveвсё, включая прямое солнцезапечено; тени динамических объектов в реальном времени затемняют его до shadowColorслабых телефонов

Динамические объекты всегда получают солнце в реальном времени плюс окружающий свет от проб. Член неба точный: открытый пол запекается в тот же окружающий свет, который вычисляет шейдер реального времени (mix(ground, sky, n.y * .5 + .5)), поэтому объекты с картой освещения и объекты реального времени совпадают там, где ничто не загораживает.

Уровни качества#

Renderer3D::setBakedQuality(Off | Low | High), по умолчанию Low на телефонах (defaultBakedQualityFor), AIVERSE_BAKED=off|low|high переопределяет. Low: карты освещения + маска теней, пробы от ближайшей пробы (3 выборки текселей на вершину). High: трилинейные пробы (24 выборки на вершину). Off: только реальное время. Карты освещения стоят одну выборку RGBM (+ одну выборку маски в режиме shadowmask) на пиксель на любом уровне.

Запекатель#

engine/bake (хост-библиотека aiverse_bake, используется и без редактора — см. tests/bake):

  • SceneBuilder загружает модели (геометрия на CPU), разворачивает их, преобразует материалы (базовый цвет × базовая текстура для альбедо, альфа-тест для маскированной листвы, эмиссия; неосвещаемые материалы светятся), добавляет меш рельефа из функции высоты с планарными UV карты освещения.
  • BVH с binned-SAH, ближайшее / любое пересечение, альфа-тест.
  • Для каждого текселя: пути по полусфере с косинусным весом (последовательность R2, повёрнутая для каждого текселя) с оценкой следующего события для солнца (мягкого, angle) и точечных / прожекторных источников на каждом отражении, небо при промахе; маска видимости солнца (maskSamples); прямой свет только запекаемых источников; опциональное AO; тексели внутри геометрии (попадания в обратную сторону граней) отбрасываются и заполняются дилатацией; учитывающий края шумоподавитель à-trous на непрямом члене.
  • Пробы: регулярная сетка над сценой (probeSpacing, probeHeight над полом, ограничение maxProbes), равномерная выборка по сфере в окружающий свет + градиент (irradiance(n) = a + B n), только запекаемые источники добавляются аналитически; пробы внутри геометрии заполняются от соседей.
  • Многопоточность (threads, 0 = все ядра). Каждый случайный поток привязан к своему текселю / пробе, поэтому результат побитово одинаков при любом числе потоков (проверено тестом).

Предустановки: preview (16 сэмплов, 1 отражение, 2 текселя/м), medium (64, 2, 4), high (256, 3, 8).

Файлы (maps/<map>.bake/)#

lightmap.json (версия, хеш, режим, диапазон RGBM, страницы, области key -> [page, scale.xy, offset.xy], область рельефа, сетка проб, настройки, статистика), страницы RGBM lm<i>.png (линейные, диапазон rgbmRange), mask<i>.png (режим shadowmask, r = видимость солнца), probes.bin (float16 × 12 на пробу). PNG и float16 сохраняют папку маленькой и удобной для упаковки; папка — обычный контент (rpak включает её, как любой другой файл). Настройки хранятся в блоке карты "bake".

Хуки для других рендереров#

  • Модели: автоматически (Renderer3D::drawModel, варианты ModelShaders.h LIGHTMAP / PROBES).
  • Рельеф и другие собственные освещённые шейдеры: AIVERSE_GLSL_BAKED_TERRAIN(block, lmTex, maskTex) / AIVERSE_MSL_BAKED_TERRAIN (engine/render/BakedShaders.h) и Renderer3D::bindBakedTerrain(uniformSlot, lightmapSlot, maskSlot); плоский рельеф (RtsTerrainShaders.h) использует U3 + tex19 / tex20. Рельеф запекателя покрывает [0, w] × [0, h] карты.

Пример (templates/showcase, долина)#

До (только реальное время) / после (запекание shadowmask, AO 1 м, две лампы "bake": "baked") / декодированная страница карты освещения (область рельефа слева, области кристальной башни и мельницы справа вверху):

Запекание: 0.5 с на 4 ядрах VM (medium: 64 сэмпла, 2 отражения, 52k текселей, 2475 проб); второй lightbake_bake сообщает «up to date» (хеш не изменился).

Ограничения / пока нет#

  • Нет направленных карт освещения (карты нормалей используют только освещённость из карты освещения), нет запечённого блика.
  • Альбедо рельефа при запекании постоянно (цвет отражений от splat-материалов не выбирается); цвета вершин в отражениях игнорируются.
  • Рельеф планет, спрайты и процедурные формы (модели shape:* для типов без файла модели, drawMesh) не участвуют в запекании: они не получают карты освещения и не загораживают свет; модели-формы освещаются пробами.
  • Цикл дня и ночи оставляет запечённый непрямой свет неизменным (используйте режим indirect).
  • Импорт карт освещения Bakery / Unity не реализован (перезапеките запекателем движка; UV2 читается).
  • Варианты для Metal (MSL) написаны, но компилируются только в сборках macOS/iOS.
