# Shared graph authoring
Read docs/agents/graph-framework.md, docs/agents/feature-contract.md and the owning subsystem rules. Reuse GraphRegistry, GraphAdapter, validateTopology and GraphCanvas in apps/studio-web/src/graphs. Define domain-specific typed ports, cycle policy and native validation; do not introduce a second runtime or change persisted formats merely to match UI. Use typed Studio bridge and existing MCP operations. The current shader adapter covers three shader domains. DraftHistory is local only; preserve domain commit semantics. This workflow has no runtime target. Run npm run test:graphs, typecheck, build and real native QA. Record handoff and exact evidence. For new authoring domains update graph inventory, feature manifest, catalog, and the owner roadmap.

Use graphSelection.ts for marquee selection and rigid grouped movement. Preserve stable IDs, remap only internal clipboard links, validate domain compatibility, and commit each group edit to local draft history once. Never paste native file paths or bypass domain validation.

GraphCanvas consumes GraphView and PortRef ({node,port}) from graphGeometry.ts. Provide named typed ports, including multiple outputs if the native domain supports them. Use graphGeometry for transient wire positions and domain mutations for real edits; never persist preview geometry or apply another domain's cycle rules. Supply scoped commands and catalog-validated templates as appropriate.

For SpectraFX and MotionWeave, see nativeGraphAdapters.ts and NativeGraphPanel.tsx. Use the allowlisted studio.op bridge with each domain's existing operations. Keep execution/data ports distinct, preserve pose DAG ordering and state transition loops, and use the native validator before any save. MotionWeave supports expected document concurrency checks; SpectraFX published save currently has only a non-atomic read-back preflight. Do not advertise concurrent writer safety for SpectraFX.

For model sources use ModelGraphPanel and modelProjection: distinguish transform-parent edges from geometry operands and embedded pose/state graphs. Native modeling_edit requires expectedRevision and builds the full source before commit. Never write project source from the browser. Visual state links create an explicit unconditional transition draft; configure conditions/order before saving and use native validation.

For geometry dependencies use geometryProjection and connectGeometryOperand rather than transform parent links; native boolean operands must precede consumers, and modifier ordering is semantic. Reuse AnimationConditions/AnimationParameters for declared scalar conditions and preserve vector parameters and all native data. Native validation and revision-safe save are mandatory.

For procedural generators use generatorProjections.ts only as a read-only dependency representation of actual owner recipes. TerraWeave is connected to its existing panel; Building and Caverns projections await their owner branches. Do not treat a diagram as an executable graph. Preserve native material IDs and texture dependencies, revisions and owner validation. Add or remove model modifiers only in draft and compile before commit.

For material dependencies use materialGraph.ts and MaterialGraphPanel. Keep PBR channel meanings distinct; resolve generated texture assets by GUID through Studio Assets, never pass arbitrary project paths to studio.materialPatch. Generate through existing texture_patterns/texture_generate and explicitly assign then save the material draft. The no-overwrite option checks existing files but is not cross-process atomic. Do not confuse the dependency diagram with an executable procedural texture graph or treat PNG creation as undoable material editing.

For STRATA use StrataAnalysisPanel and the native strata_capabilities/strata_model_analyze operations. Never infer GPU timing, live LOD selection, GPU parity or cooked assets from the CPU staging report. Select an actual exported model, not an unsaved source. GraphDiagnostics is advisory; configure the domain cycle policy (SpectraFX separates exec/data, states allow cycles), retain native validation, and label editor timings as editor-only.

Use graph_catalog first for generic MCP graph work. Call graph_list/get, then graph_validate or graph_diagnostics with the returned native graph (or document for modeling). graph_edit currently supports native SpectraFX in-memory edits only; other edits retain their domain contracts. graph_save requires expected original MotionWeave document, expectedRevision for Modeling, or explicit allowUnversionedWrite for shader/SpectraFX; never label unversioned writes concurrency-safe. graph_dependencies returns explicit authoring references, not an asset closure. Native owner APIs remain available; generic shader results omit generated code. Do not bypass the graph catalog or invent support for unregistered domains.

Stage 12 supersedes the earlier SpectraFX-only graph_edit limitation: all four registered families accept one edit or an ordered batch of up to 64 edits. Read graph_catalog.editActions and docs/agents/graph-framework.md for family-specific fields. Modeling uses native op/collection/id/value commands, other families use action commands. Check result.valid and native validation; applied does not mean valid or saved. Use graph_save separately with original expected document/revision or explicit unversioned write consent. Never infer runtime execution or filesystem atomicity from in-memory edit transactions.

Use graph_property_schema for the supported node property subset before graph_edit setProperty (Modeling uses op:setProperty). Do not modify immutable IDs through property edits. Use graph_asset_dependencies for literal references and embedded animation subgraph recursion; file-present means existence only, not valid imports or transitive closure. SpectraFX schema response is native catalog defaults, not exhaustive constraints. Keep native validation and revision guards.

Use graph_runtime_capabilities before graph_runtime_probe. Only MotionWeave and SpectraFX have isolated CPU probes; max 60 fixed steps. The results are actual native owner counters when the probe runs, not live-game telemetry. Do not describe active pose program as per-node execution trace, state changes as all transitions, or CPU times as GPU times. STRATA remains analysis-only. No project writes, runtime attachment or GPU profiling.

Use graph_live_snapshot only for read-only current owner data. MotionWeave requires the exact packed entity generation ID as a decimal string. The native editor adapter is optional; unavailable is not zero or a successful sample. Never map live node IDs onto an unsaved graph without asset/program provenance. SpectraFX counters are shared-owner aggregates and existing GPU preview counts are estimates. No live pause/step/breakpoints or modern ECS runtime attachment are provided by this stage.

For isolated debugging use graph_debug_session start/status/step/continue/breakpoints/stop. Always pass returned session string to commands except start/status. Only explicit calls advance time; max 60 steps per continue, 600 per session. Breakpoints match MotionWeave state/program after a complete step; not per-node execution breakpoints. Session program token is not a content hash. Stop before switching graphs. GraphTelemetry.h is a value-only owner-thread history contract, not a registered ECS telemetry producer; actual live owners must supply world epoch, generation and program identity. No gameplay mutation or live pause.

For shared MotionWeave ECS telemetry call View::animationTelemetry or captureAnimationTelemetry on the committed View after workers join, with the host-owned non-reused world epoch. Never capture a preparation candidate or add another graph evaluator. Native editor graph_live_snapshot captureHistory=true captures requested samples only; history is keyed by lifetime identities, not asset content hashes. Generic host integration requires its own epoch/publication barrier. Distinguish update/evaluation counters from per-node timings and legacy fallback from common ECS source. No continuous collection or live control is implied.

Use graph_live_watch {action:start,domain:motionweave,entity:<packed ID string>} or {action:start,domain:spectrafx,entity:preview} only with supported native editor play owner; status/stop are explicit. One subscription, last 120 published samples, no replacement following, no background process or GPU timing. FX serial pins actual CPU preview instance, not its asset revision. Never infer a live owner in headless/HTML5 host from registry presence. Do not equate viewport frame sampling with simulation ticks.

For actual MotionWeave per-node CPU scopes, start an isolated graph_debug_session, call profileEnable with its session ID, step/continue, then profileRead. Use profileReset or profileDisable explicitly. Report phase totals and max durations are inclusive wall-clock microseconds, with trace of the last step (max 512 intervals); no shader/GPU or FX authored-node timings. Prepared View clones and graph resets drop instrumentation. Do not equate scope calls with all graph execution or profile overhead with gameplay cost. Use the immutable session source for heatmaps, not edited drafts.

For live selected MotionWeave CPU profiling use graph_live_profile {action:enable|read|reset|disable,entity:<exact packed ID string>} only when native editor play host has a committed common View instance. The profile follows one pinned publication identity; graph/Entity replacement disables it. Prepared View copies counters only for that explicit selection, never shares mutable profile storage. Do not read failed candidates, map reports onto unrelated drafts, or interpret inclusive CPU timings as GPU measurements. Stop disables instrumentation; unsupported hosts report unavailable.

Use graph_gpu_profile {action:start|read|stop} for opt-in native editor scope capture. Only valid completed RHI queries are reported; viewport samples cover combined rendering, FX and post-processing, not authored nodes or individual passes. SpectraFX step requires accepted scope and step. Metal/GL33 have existing scope implementations, Vulkan/GLES3 do not in this branch. A backend implementation or pending query is not proof of measured GPU timing. Do not independently drain Device::takeGpuScopeTimings or takeGpuTimings; preserve the existing collection owners. Unsupported hosts return unavailable.
